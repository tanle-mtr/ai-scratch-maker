# 交付前自评清单（Pre-Delivery Self-Review）

> 铁律 + 八层校验是「自动化底线」，能拦废品；但「手感 / 完整度 / 可读性 / 可访问性」需要**软性核查**。
> 本清单是 AI 在 `build_sb3` 之前 / `verify_project.sh` 之后的**逐项打勾表**。
> 每条标注：检查项 → 合格信号 → 出处（铁律 N / 手册 § / 外部来源）。
> 外部来源：Scratch 赛事评分（创意30%·玩法30%·设计20%·打磨20%）、
> Game Accessibility Guidelines（色盲/文字尺寸/不靠颜色或声音单传）、
> LitterBox 静态臭味（Long Script / Busy Waiting / Missing Termination…）。

---

## 1 · 开场与引导（Onboarding）
- [ ] 打开即见**规则与操作**（如「按 ←→ 移动，空格跳」），或开场有说明页 → 合格：标题页含操作提示，可跳过直接玩。
- [ ] 操作方式符合直觉（方向键 / 鼠标），不要求看脚本才知道怎么动 → 来源：赛事评分「清晰指引」。
- [ ] 教学做成**关卡/箭头**而非弹窗（§24）。

## 2 · 边界与稳定（Stability）
- [ ] 角色**不出游戏界面**（用「碰到边缘反弹」或坐标夹紧）→ 来源：赛事评分「界面体验」。
- [ ] **无软锁**：失败/胜利后必有出路（结算页「再来一局」按钮，铁律7）；不出现「卡住只能刷新」。
- [ ] **复位彻底**：点重试时上局石头/子弹/状态全清 → 一切复位挂 `[重置]` 而非绿旗（铁律6 / §45）。

## 3 · 难度与平衡（Balance）
- [ ] 难度**适中**：可经计算设数值（敌机血量、炸弹间隔），既非必败也非无挑战 → 来源：kidscoding8 难度三问。
- [ ] 有**重玩价值**：随机 / 分数系统 / 关卡递进至少满足 2 条（质量门禁 B 层 `replay_value`）。

## 4 · 玩法完整度（Completeness）
- [ ] 有**明确目标**：到达终点 / 解谜 / 分数阈值（质量门禁 B 层 `win_lose`）。
- [ ] **玩家可操控**：至少一个角色有输入帽且帽下挂运动/交互（B 层 `player_control`）。
- [ ] **结算页 + 重玩按钮**必备（铁律7，最高频遗忘）。
- [ ] 胜负有**明确反馈**（广播 `胜利/失败/通关` 或变量 `生命/得分`）。

## 5 · 观感与手感（Juice & Look）
- [ ] 运动用**缓动/速度向量**而非瞬移（§2）；命中/落地有反馈（顿帧、震屏、粒子、放大脉冲，§18）。
- [ ] UI 有**五层体积感**（投影→外描边→渐变→顶高光→底内阴，序不可换，铁律17）；窗口圆角 + 大窗（GHOST25 + 关闭图标）。
- [ ] 配色过 **§198 调色板**（冷灰禁止、深绿仅文字），颜色字面量 6 位 HEX（铁律8/18）。
- [ ] 角色 ≤ 屏高 1/3；造型中心对齐、步长匹配等待（§32）。

## 6 · 可访问性（Accessibility）★新增
- [ ] **色盲安全**：红/绿/棕/橙易混，**不靠颜色单独区分关键信息**（如队别/状态），改用形状/图案/文字标签；安全组合用蓝/黄（Game Accessibility Guidelines）。
- [ ] **高对比**：文字/UI 与背景高对比；若用 SVG 文字（铁律17 本就禁止 `<text>`），须大字号 + 强描边 + 阴影。
- [ ] **信息不只靠声音**：分数/生命等必须有**可见显示**，不能仅靠音效传达（§2 自制聊天框同理）。
- [ ] **无闪烁**：避免高频闪烁图像（光敏风险）；动画过渡平滑。
- [ ] 操作**简单可重映射**：核心操作尽量单一输入，避免同时多键/长按（基础可访问性）。

## 7 · 音效（Audio）
- [ ] 四层响度分层（ui/fx/ev/amb），UI 音效 ≤0.25s、**禁「播放直到结束」**（铁律18）。
- [ ] 音效首尾归零、DC<0.01；BGM 直接挂（§263–§276）。
- [ ] 提供**独立音量/静音**（可访问性「separate volume controls」）。

## 8 · 架构与代码（Architecture）
- [ ] **角色即模块**：控制器 / UI / 数据分离到不同角色（即使不可见）（CS50 / hqwc 工程实践）。
- [ ] 命名一致（中文变量/角色/广播）；初始化与复位集中；关键脚本有 `comment:`。
- [ ] **循环内无重等待**：`wait` 会阻塞整角色；定时重复改用计时器/帧计数（§「减少循环内等待」）。
- [ ] **克隆及时删**：飞出屏/被击中/寿命到立即 `delete_clone_of`，无隐形无限循环克隆（LitterBox / §7）。
- [ ] 无「Long Script」：单脚本积木数过大 → 拆广播子程序（LitterBox 臭味，精度 87%）。

## 9 · 合规与发布（Compliance）
- [ ] 署名 **CC BY-SA**，**不写「禁止改编/请勿复制」**等（铁律3）。
- [ ] 非商业复制：可「受启发」但**不照搬商业游戏/故事**（Scratch 官方 featured 限制）。
- [ ] 项目 Instructions 写清**怎么玩 + 署名/素材清单**（赛事「作品完整性」）。
- [ ] 全量回归绿：`verify_project.sh` 八层 + 铁律 + 质量门禁通过；专属深网探针 `XXX_LOGIC_OK`。

---

### 用法
1. 写 IR 前先过 **§2/§3/§4**（题材能同时展示玩法与观感）。
2. `build_sb3` 成功后，逐条打勾；任何一项「不合格」先改 IR 而非跳过。
3. 最后跑 `verify_project.sh`；本清单第 6/8 条里「静态可检」的部分由新增 `check_a11y.py` / `check_perf_budget.py` 辅助，其余靠人工/AI 自查。
