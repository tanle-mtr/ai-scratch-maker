# 第三十七册：新月事件卡与运行时规则改写引擎（§413–§432）

> 适用范围：狼人杀的「事件卡」机制。涉及**两套不同的东西**，见 §413。
> 前置手册：第三十三册 `werewolf-complete.md`（通用引擎 / 板子表 / 胜负 / 死亡结算）、
> 第三十六册 `werewolf-awakening.md`（现阵营表 / 资源表 / 死因码）。
> 本册要解决的问题是：**规则会在游戏进行到一半时被改写，怎么改才不会把状态机改崩。**

## §413 两套「新月」不是一回事，别混着写

这是本册最重要的辨析。网上搜「狼人杀 新月」会同时出现两套体系的规则，
把它们揉在一起是绝大多数实现崩掉的根因。

| | **经典桌游《狼人与新月》** | **网易《狼人杀》「新月降临」** |
|---|---|---|
| 出处 | 桌游《The Werewolves of Miller's Hollow》第二代的 **New Moon 扩展包** | 网易 **2025-01-17** 上线的限时活动板子 |
| 形态 | 一副 **36 张实体事件卡**，可加入任意板子 | **12 人预女猎愚**板子内置的随机事件系统 |
| 触发次数 | **每回合抽 1 张**（部分规则：无人遇害的次日 / 奇数天） | **每局仅 1 次** |
| 触发时点 | 夜死者（最后一个）或主持人抽卡，讨论前宣读 | **首夜角色行动完成后、天亮之前** |
| 时效分类 | **满月 / 新月（狼牙月）/ 暗月** 三类 | 按**效果**分五类：娱乐 / 信息 / 结算 / 技能 / 身份转换 |
| 生命周期 | 当回合 / 延时到触发 / 永久 | 多为**整局生效**，少数限定第 2 夜起、第 3 天结束 |
| 对胜负的影响 | 多数只改流程，少数改身份 | **有专门的「结算事件」直接增加胜负条件** |
| 卡片可自选 | ✅ 主持人可开局预置 1~2 张暗月卡 | ❌ 系统随机，玩家不能选 |

还有**第三种**早期线上房规（「奇数天发生新月事件」、UFO / 澡堂 / 花粉 / 沉默等中文土味事件名），
属于旧版联众/QQ 房规，既不是经典扩展也不是网易新月，见 §418 末尾。
**做作品前必须先确认用户要哪一套**，三套的抽卡时机和时效模型完全不同。

> ⚠️ 用户说「网易狼人杀还有新月事件卡」时，**主体是右边那套**（网易 2025 活动板子）。
> 但经典 36 张的「三类时效」是更好的工程模型，本册两套都给，
> 实现时**用经典的时效模型去承载网易的事件效果**。

## §414 经典扩展包：36 张卡与三类时效

《狼人与新月》配件表：**36 张事件卡 + 5 张新角色牌**（白痴 / 长老 / 替罪羊 / 守卫 / 吹笛者）
+「丰收节」「黑死病」两个变种玩法。36 张的构成是：

```
满月（Full Moon）  24 张  —— 仅当前回合生效
新月（New Moon / 狼牙月） 7 张  —— 延时生效，挂到条件触发为止
暗月（Dark Moon / 黑月）  5 张  —— 即时生效，持续到游戏结束
                     ──
                     36 张
```

三类时效的官方描述（百科「游戏进程」第 4 步）：

| 类 | 生效方式 | 结束条件 |
|---|---|---|
| **满月** | 立即发动牌面效果 | 发动结束后失效（当回合末清） |
| **新月** | 延时，**等触发条件满足**才发动 | 条件满足后发动并卸载；或超时作废 |
| **暗月** | 立刻生效 | **直到游戏结束**，不被回合清除 |

⚠️ **资料冲突，必须自己定房规**：百度百科同一页里，「事件卡」章节写新月卡
「延时有效，即直到触发条件生效为止」，
但「游戏进程」注又写「新月卡：一回合内生效，若牌面有触发要求，需本回合内满足条件才能发动，
否则该卡无效」。萌娘百科和百度知道都采用前者。

**工程上采用的兼容模型**（§426）：新月卡 = 带**超时时钟**的条件触发器，
默认「挂到条件满足」，同时允许板子开关设 `新月超时 = 1 回合` 退回严格版。
这样两种说法都能表达，不用改代码。

抽卡人：**夜里死去的最后一个玩家**（或主持人）。
若当夜是平安夜（无人死亡），则由主持人抽。
主持人也可在游戏开始时预置 1~2 张**暗月**卡作为开局规则。

## §416 新月（狼牙月）7 张：条件触发卡

| # | 卡名 | 触发条件 | 触发后效果 |
|---|---|---|---|
| 1 | **鬼怪** The Specter | 下一名被狼人指定的玩家 | 该玩家**变成狼人**并立即指定杀死一名老狼；替代原狼 |
| 2 | **小捣蛋鬼** The little Rascal | 第二天回归 | 最年轻玩家离场一回合（不讨论/不投票/不可被杀），回归后**投票值 3 票** |
| 3 | **意外** Backfire | 第二晚狼人指定的若是普通村民 | 该村民不死、变成狼人，并击倒其左手边第一只狼；非村民则无事（狼队未达成一致则无牺牲者） |
| 4 | **群情激奋** Enthusiasm | 下一个被处死者**是狼人** | 立即再投一次票，无讨论，直接吊死第二名嫌疑人 |
| 5 | **不满情绪** Dissatisfaction | 下一个被处死者**不是狼人** | 同上（条件取反） |
| 6 | **满月升起** Full moon rising | 接下来的夜晚 | 狼人变预言家（依次验人）；猎人/女巫/预言家变狼人（夜间共同处死一人）；次日早晨全部复原 |
| 7 | **感染/影响** Influences | 下一次投票 | 改**顺序投票**：最后死者选首位投票者，之后按座位依次指认，结果照常计票 |

⚠️ 7 张里有 **3 张会改写身份或阵营**（鬼怪 / 意外 / 满月升起，
以及满月卡里的奇迹、灿烂的周日）。
凡是改阵营的，**一律写 `现阵营表`，不要改 `身份池`**（第三十六册 §405 同款规则）。

**「群情激奋 / 不满情绪」是一对互补卡**：条件完全一样、判定取反。
实现上不要写两张卡两套逻辑，用 `条件期望 = 1 或 0` 一个字段加 `等于/不等于` 即可。

## §417 暗月 5 张：永久规则

| # | 卡名 | 永久效果 | 改写点 |
|---|---|---|---|
| 1 | **葬礼** Burial | 此后被狼人杀死者**不再公开身份**（明牌局变暗牌） | 信息公布开关 |
| 2 | **死之触** Touch of Death | 此后狼人必须「触摸」受害者才能吞食（面杀限定），否则无受害者 | 狼刀合法性 |
| 3 | **梦游** Somnambulism | 此后主持人**大声读出预言家查验到的身份**，但不公布查的是谁 | 信息钩子 |
| 4 | **双重身份** Double Agent | 第一个死者指定一名非狼人，该玩家**得知全部狼人位置**、阵营变狼、共享狼人胜利（狼队不知道他） | 阵营 + 可见性 |
| 5 | **刽子手** Executioner | 此后被放逐者出局后**不公开身份**，只给刽子手看；刽子手死时指定继任者 | 信息公布 + 角色传递 |

> 中文百科正文只逐条列了前 4 张，第 5 张「刽子手」见「36 张构成」的问答资料；
> 不同译本对第 5 张归属（暗月 / 满月）有出入，**按配件表 24/7/5 = 36 张计数**。

**暗月卡的三条铁律**：
1. **不参与回合清除**。任何「回合末清空事件表」的循环都必须跳过 `时效=永久` 的卡。
2. **允许开局预置**（主持人可放 1~2 张），所以事件表在 `绿旗` 时就可能非空。
3. **可以被后来的卡覆盖，但必须记原值**（§428 快照），否则撤销时会把开局预置的永久规则一起抹掉。

## §418 抽卡时机：三种模式别写串

| 模式 | 触发时点 | 频次 | 抽卡人 |
|---|---|---|---|
| **经典扩展**（主流） | 夜间结算完、公布结果后、讨论前 | 每回合 1 张 | 夜里最后一名死者；平安夜则主持人 |
| **经典起源设定** | 「没有人遇害的第二天」 | 仅平安夜后 | 主持人 |
| **早期线上房规** | **奇数天** | 隔天 1 张 | 系统 |
| **网易新月降临** | **首夜角色行动完成后、天亮之前** | **整局仅 1 次** | 系统随机 |

⚠️ **网易的时点最容易被放错**：是「首夜行动结束 → **天亮之前**」，
也就是**在夜间队列收尾之后、公布出局信息之前**。
放在公布信息之后，事件里的「第一夜公布时随机一名平民变为守卫」就会错过首夜技能；
放在夜间队列之前，事件又会改写还没跑完的技能。

**早期线上房规的事件名**（UFO / 澡堂 / 花粉 / 沉默 / 警长罢免 / 离家出走 / 组团泡妞 / 愚人 / 奇迹）
是另一套中文土味卡，效果与经典卡**不同名也不同效果**（例如「花粉事件」= 神职获得狼刀能力、
狼人获得查验能力，接近经典的「满月升起」但不等价）。
不要把这两套卡名混进同一张表。

## §419 网易「12 人新月降临」板子

**官方规则**（2025-01-17 公告 + 2025-01-26 第二弹攻略）：

```
板子：12 人预女猎愚 = 4 狼 + 4 民 + 预言家 / 女巫 / 猎人 / 愚者
性质：限时活动板子，与经典板子相互独立
触发：首夜角色行动完成后、天亮之前
频次：每局仅触发一次
公布：触发时同时向全场公布该事件的详细内容
分类：娱乐 / 信息 / 结算 / 技能 / 身份转换 —— 共 5 类
```

**几条官方明确写出的共性规则**（比事件本身更重要）：

1. **事件不夺走原有身份与技能**。技能类事件是「增强 / 限制」，不是替换；
   阵营转换类事件也**保留原身份和技能**。
2. **仍然采用屠边规则**。结算类事件是**额外增加胜利条件**，
   不替代原有的屠边/屠城判定。
3. **转换阵营不改狼队可见性**：「长毛了」的平民**不知道狼坑、不能进狼队讨论、不能刀人**；
   「剃毛了」的狼人**知道狼坑、仍可进队讨论和刀人**。
   → 又是 `现阵营表` 与 `见面标志` 分离（第三十六册 §405）。
4. 部分事件**带时间窗**：「从第二夜开始」「存活到第三天结束后」「仅第二晚」，
   需要 `夜数 / 天数` 时钟，不能只用一个布尔。
5. 事件分**集体事件**与**个人事件**（玩家整理的彩蛋规则：只有成为「个人事件目标」
   才计彩蛋进度）。实现上就是 `目标数 = 0（全体）/ 1 / 2`。

> ⚠️ 官方**没有公布完整事件清单**，且是活动板子、随版本增减。
> §420–§423 列的是官方公众号攻略 + 百科 + 玩家实测中**可确认的事件**，
> 名字和效果按资料原文，**以游戏内当前版本为准**。

| 信息 | 与子同袍 / 心有灵犀 / 与子偕老 | 同上，限定两男 / 两女 / 一男一女 | 同上 |
| **娱乐** | **意外碰面 / 夜半惊魂** | 仅第 2 晚最后阶段，随机 1 狼 + 1 好人**见面交流** | 仅第 2 晚 |
| 娱乐 | **悄声密会 / 灵界一瞥** | 仅第 2 晚最后阶段，随机 2 名平民/神职见面交流 | 仅第 2 晚 |
| 娱乐 | 兄弟情义 / 闺房秘话 / 槲寄生下 | 仅第 2 晚，两男 / 两女 / 一男一女见面交流 | 仅第 2 晚 |
| 娱乐 | **光暗相激** | 仅第 3 晚最后阶段，随机 1 狼 + 1 神职见面交流 | 仅第 3 晚 |
| 娱乐 | **葬礼 / 众生皆愚** | 明牌局↔暗牌局互相切换（出局是否公开身份） | 整局 |

玩家实测还提到「每天随机一名玩家给毒药」「平民与狼人夜晚交流」「随机一名狼人/好人与对方阵营一起获胜」
「随机两个神职夜晚交流」——这些与上表的巫术盛行、意外碰面、长毛了/剃毛了、悄声密会
**是同一批事件的不同简称**，不要重复建两条卡。

## §421 信息 / 娱乐类事件的实现要点

这类事件**不改胜负、不改技能**，最容易被做得没人看得见，但它恰恰是玩家感知最强的部分。

```
事件 = { 钩子: 公布出局信息后, 天数: 2/3, 目标数: 0, 效果码: 公布X }
```

三个必须写进校验的边界：

1. **「公布 X 是否存活」要看 `存活表`，不是 `身份池`**。
   白猫延迟死亡、愚者翻牌都仍算存活（第三十三册 §344）。
2. **「存活数量」按 `现阵营表` 统计**，且要用「总民 > 0」守卫处理无民板子。
3. **见面交流类要真的开一个私有频道**：
   把两人编号写进 `私聊组[事件ID]`，UI 只给这两人显示消息；
   **关掉所有列表监视器**（隐藏信息铁律），否则全场都能看见。

⚠️ 时间窗是「**仅第 2 晚 / 仅第 3 天 / 仅第 2 晚最后阶段**」，
不是「从第二晚起」。实现用 `事件.生效日 = n` 精确匹配，
写成 `夜数 >= 2` 会让事件每晚重复触发 —— 这是新月类事件最高频的 bug。

## §422 技能 / 阵营转换类事件的实现要点

**技能类 = 改「次数上限」和「目标合法性」两张表**，不要改身份：

```
快乐星球:  技能次数[狼刀]   = 2
           技能次数[查验]   = 2
           毒药上限        += 1
           猎捕目标数       = 2
           放逐票权[愚者/平民] = 2
咫尺天涯:  目标合法(p, t) = (|座位(p) - 座位(t)| == 1)  # 环形相邻，女巫解药豁免
开火普及:  授予技能[p] = 猎捕    for p where 现阵营 != 狼 and 身份 != 猎人
巫术盛行:  每夜开始时随机 1 名存活者 → 临时毒药[p] = 1（当夜必须用，过期作废）
```

⚠️ **「咫尺天涯」的相邻是环形**（座位 1 与 12 相邻），
写成 `abs(p-t)==1` 会在两端漏掉一对。

**阵营转换类 = 只改 `现阵营表` + 胜利目标，其他都不动**：

```
长毛了:  t = 随机一名「现阵营=民」的存活玩家
        现阵营表[t] = 1         # 胜利目标变狼
        见面标志[t] = 0         # ★ 不进狼队
        可刀[t]     = 0         # ★ 不能刀人
        # 身份池[t] 不变（仍是村民），技能不变
剃毛了:  t = 随机一名「现阵营=狼」的存活玩家
        胜利目标[t] = 好人
        见面标志[t] = 1         # ★ 仍进队
        可刀[t]     = 1
```

⚠️ 「长毛了」有个**隐藏的胜负分支**：官方攻略明确
「在狼人全部出局后，游戏直接结束，被转换阵营的平民不能刀人」——
即**狼全灭时直接结算，不等这个平民**。
如果沿用通用引擎的「存活狼 = 0 → 好人胜」，结果一致，但
**不能让胜负判定去数 `现阵营表` 里的这个平民**，否则会误判成「还有狼，继续」。
结论：转换类事件要同时维护 `胜利目标[p]` 和 `参与狼数统计[p]` 两个独立标志。

**「星体转移」交换身份但阵营不变**，是这一类里最反直觉的：
```
swap(身份池[a], 身份池[b])
# ★ 现阵营表[a] / 现阵营表[b] 保持原值不动
```
如果顺手把阵营也换了，屠边统计会瞬间错两个座位。

## §423 结算类事件：额外胜负条件

四条事件都是「**在原有屠边规则之上再加一条**」，判定顺序是：

```
判胜负(每次死亡结算后 + 每个白天结束时都要跑):
  ① 事件胜负条件（新增，优先级最高）
       盲目之眼:  存活表[预言家座位] == 0        → 狼人胜
       大智非愚:  存活表[愚者座位]   == 0        → 狼人胜
       到点下班:  天数 >= 3 且 存活好人数 > 0    → 好人胜
       掩光入夜:  天数 >= 3 且 存活狼数 > 0      → 狼人胜
  ② 第三方 > 好人胜 > 屠边 > 屠城（第三十三册 §344 原样保留）
```

⚠️ **三个致命点**：
1. **必须重新跑判胜负**。很多实现只在「死亡结算」里判一次，
   于是「到点下班」到了第三天结束时**没人触发判定** → 事件形同虚设。
   正确做法：把判胜负挂到「死亡结算后」**和**「每个阶段末」两个钩子上。
2. **「预言家出局」要按身份查座位，不能按玩家号写死**。
   星体转移、光耀传承会改身份池，得每次现查。
3. **额外条件不能覆盖原有条件**。官方明说「仍然遵循屠边规则」——
   狼人未必非要杀预言家，走屠民照样能赢。
   写成 `if 盲目之眼 then 只判预言家` 会把屠边整条路径吞掉。

## §424 核心模型：事件卡 = 运行时规则改写器

到现在可以给出本册最重要的一句话：

> **板子是「开局静态配置」，身份是「固定行为」，事件卡是「运行中动态改写规则」。**
> 三者是三种不同的东西，**不要放进同一张表**。

| | 板子 | 身份 | 事件卡 |
|---|---|---|---|
| 何时确定 | 开局 | 开局 | **运行中** |
| 会不会变 | 不变 | 少数会变 | **会挂载 / 卸载** |
| 作用范围 | 全局配置 | 单个玩家 | 全局开关 / 一组玩家 / 一个钩子 |
| 数据结构 | 一行配置 | 一个编码 | **一条带生命周期的效果** |
| 撤销 | 不需要 | 不需要 | **必须能撤销**（除永久卡） |

因此事件卡引擎的正确形态不是「一堆 if」，而是：

```
事件表（静态，卡库）
  ↓ 抽卡（一局一次 / 每回合一次）
活动事件栈（运行时，当前挂着哪些效果）
  ↓ 钩子分发（发言前 / 投票前 / 夜间前 / 死亡结算后 / 公布信息后 / 阶段末）
效果应用（改开关，同时把原值压入快照栈）
  ↓ 到期 / 条件满足 / 游戏结束
效果撤销（按快照恢复，不是置 0）
```

**这套模型的价值**：新增一张事件卡 = 往事件表加一行 + 实现一个效果码，
状态机一行都不用改 —— 和第三十三册「板子 = 表不是代码」完全同一个思路。

## §425 事件卡的数据结构

```
事件表（每条一张卡，开局只读）：
  ID          整数，1-based
  名称        文本
  体系        1 经典 / 2 网易 / 3 早期线上房规
  时效        1 当回合(满月) / 2 条件触发(新月) / 3 永久(暗月)
  效果类型    1 娱乐 / 2 信息 / 3 结算 / 4 技能 / 5 身份转换
  钩子码      位掩码：发言前·投票前·夜间前·死亡后·公布信息后·阶段末
  效果码      整数，指向效果实现
  触发条件    「下一个被放逐者是狼」「天数=3」「夜数=2」…
  目标数      0 全体 / 1 / 2
  起始日      0 立刻 / n 从第 n 夜或第 n 天起
  超时        条件触发卡的最大等待回合（0 = 不限）
  互斥组     同组卡片不可同时生效
  优先级     冲突时的仲裁顺序（暗月 > 新月 > 满月）

活动事件栈（运行时）：
  事件ID / 剩余回合 / 已触发次数 / 目标玩家列表 / 快照栈指针
```

**为什么 `钩子码` 用位掩码**：一张卡可能同时挂多个点。
例如「快乐星球」要挂「夜间前」（改技能次数）**和**「投票前」（改票权），
一个整数位或就能表达，不用为每张卡建一张挂载表。

**为什么 `互斥组` 必须有**：「惊人的不信任」「梦魇」都**替换**正常投票，
两张同时生效会打架；「葬礼」和「众生皆愚」一个改暗牌一个改明牌，也是互斥。
抽到互斥卡时按 `优先级` 决定保留哪张，另一张**明确丢弃并公告**（不要静默）。

## §426 三类时效 = 三种生命周期

```
状态机：未挂载 → 已挂载(待生效) → 生效中 → 已撤销
                      │
                      └→ 超时作废（仅条件触发卡）

挂载时:
  时效=1 当回合  → 到期 = 当前回合末
  时效=2 条件触发 → 到期 = 当前回合 + 超时；挂到「条件检查」钩子
  时效=3 永久    → 到期 = ∞（★ 不参与回合清除）

每个「阶段末」钩子:
  for 事件 in 活动栈:
     若 时效=2 且 触发条件满足 → 应用效果 → 标记「已触发」→ 卸载
     若 到期 且 未触发          → 卸载（超时作废）
     若 时效=1                  → 卸载
     # 时效=3 不动
```

⚠️ **「条件触发卡」必须带超时**。经典规则里「群情激奋」等的是
「下一个被放逐者是狼人」——如果之后一直是夜间死亡、再没有放逐，
条件永远不满足，卡就永远挂在栈里，后续每回合都被扫到、慢慢把状态改乱。
**栈泄漏是条件触发类事件最隐蔽的 bug**。

⚠️ **「已触发」标志要独立于「已挂载」**。
条件满足那一帧先打标志再应用效果，否则同一帧两个钩子会各触发一次
（和「两个平级 IF 互相覆盖」同源，见第三十三册 §340）。

**网易事件的时效映射**：
- 「快乐星球 / 咫尺天涯 / 长毛了 / 剃毛了 / 盲目之眼」→ **永久**（时效 3）
- 「星轨存续 / 到点下班 / 仅第二晚见面」→ **条件触发**（时效 2，`触发条件 = 天数/夜数 = n`，一次性）
- 「巫术盛行」→ **每夜重复的条件触发**（`已触发次数` 不置 1，改为按夜数计）

## §427 钩子点：事件挂在哪里

沿用第三十三册 §342 的夜间队列和第三十六册 §409 的 14 个插槽，
事件引擎**只加 6 个钩子**，不改原有顺序：

| 钩子 | 位置 | 典型事件 |
|---|---|---|
| `夜间前` | 夜间队列第 1 位之前 | 快乐星球（改技能次数）、咫尺天涯（改目标合法性） |
| `夜间末` | 收尾之后、**公布出局信息之前** | ★ 网易抽卡点、见面交流、巫术盛行发毒药 |
| `公布信息后` | 出局信息公布完 | 星轨存续、狼军报数、葬礼（不公开身份） |
| `发言前` | 白天发言开始 | 没有我也没有狼、月蚀、沉默事件 |
| `投票前` | 放逐投票计票之前 | 惊人的不信任（替换投票）、小捣蛋鬼 3 票、愚者/平民 2 票 |
| `结算后` | **死亡结算后 + 每个阶段末** | ★ 四类结算事件、群情激奋/不满情绪 |

⚠️ **网易的抽卡点必须在 `夜间末`**，也就是夜间队列收尾之后、公布出局信息之前。
- 放队列之前 → 事件会改写还没跑完的首夜技能（光耀传承来不及生效）
- 放公布信息之后 → 「第一夜公布时」的事件已经错过首夜

⚠️ **`结算后` 要挂两个地方**（第三十三册 §343 死亡结算后 + 白天阶段末）。
只挂前者，「到点下班」的第三天结束条件没人触发（§423）。

## §428 冲突仲裁与快照恢复（最容易被写错的一节）

**问题**：事件 A 把 `放逐票权 = 2`，事件 B 把 `放逐票权 = 3`；
A 先到期撤销时，如果直接 `SET(放逐票权, 1)`（默认值），
就会把 B 的效果一起抹掉。

**正确做法：每个效果在挂载时压一份「原值快照」，撤销时恢复快照而不是置默认值。**

```
挂载(效果 e):
    e.快照 = 读取(e.目标开关)          # ★ 读当前值，不是读默认值
    写入(e.目标开关, e.新值)

撤销(效果 e):
    # 从栈顶往下找：只有「我是最后一个改这个开关的效果」才能恢复
    若 栈顶(该开关的快照栈) == e:
        写入(e.目标开关, e.快照)
        弹栈
    否则:
        只把 e 标记为已撤销，不动开关   # 后面的效果还压着
```

即**每个可改写开关配一个快照栈**，而不是一个全局变量存原值。
这是「多层同名改写」唯一不会互相踩的实现。

**冲突仲裁三条**：
1. **优先级**：暗月/永久 > 新月/条件 > 满月/当回合；同优先级按挂载顺序（后进先覆盖）。
2. **互斥组**：同组只保留优先级高的，被丢弃的要**明确公告**「本回合 XX 事件被 YY 覆盖」。
3. **替换型 vs 叠加型**：`效果码` 要标一个 `是否替换`。
   「惊人的不信任」是**替换投票流程**（要把正常投票整个关掉），
   「小捣蛋鬼 3 票」是**叠加票权**（只改一个人的权重）。
   两者混用会让投票算两遍。

⚠️ 与第三十六册 §405「出局免疫层要有优先级」是同一个道理：
**凡是多层改写，都要有优先级 + 快照**。

## §429 与通用引擎的接口清单

在第三十三册的引擎上，新月体系只需要加这些，**不要重写状态机**：

```
新增列表:
  事件名表 / 时效表 / 效果类型表 / 钩子码表 / 效果码表 / 优先级表 / 互斥组表
  活动事件栈 / 事件目标表 / 快照栈（按开关分）
  胜利目标[玩家] / 参与狼数统计[玩家]      # 阵营转换事件专用
  技能次数[技能] / 放逐票权[玩家] / 目标合法范围[玩家]

新增变量:
  事件已触发        # ★ 一局一次守卫，挂在「重置」上但值由事件引擎自己管
  当前事件ID / 事件生效日 / 事件目标数 / 天数 / 夜数
  随机种子          # ★ 抽卡必须可复现，否则行为校验写不死期望值

新增广播:
  抽新月卡 / 事件生效 / 事件检查 / 事件撤销 / 事件判胜负

原有改动:
  判胜负  → 开头插入「事件胜负条件」（§423）
  投票    → 计票前调用 事件检查(投票前)
  发言    → 开始前调用 事件检查(发言前)
  公布出局信息 → 之后调用 事件检查(公布信息后)
  阶段末  → 调用 事件检查(结算后) + 到期清理
```

⚠️ **`事件已触发` 不能被白天重置**。
铁律 6 说「一局要复位的东西挂重置」——但这里相反：
事件是**整局只抽一次**的，白天的流程重置脚本若顺手把它清 0，
第二天又会抽一张卡。它的复位只能挂在**绿旗 / 新开一局**，不能挂在日循环。

⚠️ **随机种子必须可控**。
直接 `随机数 1~N` 会让行为校验没法写死期望值（这次抽到「快乐星球」、
下次抽到「盲目之眼」），表现为「跑十次红一次」。
用线性同余 `种子 = (种子 * 1103515245 + 12345) mod 2^31` 自己算，
校验里 `setVar("种子", 固定值)` 就能复现。

## §431 校验清单（20 条）

**抽卡与时效**
1. 网易模式一局只抽 1 次；第二天不重复抽。
2. 抽卡点在「首夜行动后、公布出局信息前」。
3. 满月卡回合末被清除、暗月卡**不被**清除。
4. 条件触发卡条件满足后**只触发一次**（`已触发` 标志）。
5. 条件永不满足时按 `超时` 卸载，不留在栈里。
6. 暗月卡可开局预置，且不被后续回合清理。
7. 抽卡用固定种子可复现；换种子能抽到不同卡。

**效果与冲突**
8. 两张卡改同一开关，先撤销者**不抹掉**后者的值（快照栈）。
9. 互斥组冲突时保留优先级高的，且**明确公告**被覆盖的卡。
10. 替换型投票事件与叠加型票权事件不重复计票。
11. 「咫尺天涯」的相邻判定是环形的（座位 1 与 12 相邻）。
12. 「仅第 2 晚 / 第 3 天」事件不会每晚/每天重复触发。
13. 信息类事件读 `存活表` 与 `现阵营表`，不读 `身份池`。
14. 见面交流开了私有频道且**关掉列表监视器**。

**胜负与阵营**
15. 结算类事件在「死亡后」和「阶段末」**都会**触发判胜负。
16. 结算类事件是**额外条件**，不吞掉屠边路径。
17. 「预言家出局」按身份实时查座位（星体转移后仍正确）。
18. 阵营转换只改 `现阵营表` + 胜利目标，**身份池与技能不变**。
19. 「长毛了」的平民**不进狼队、不能刀人**；狼全灭时直接结算。
20. 「星体转移」交换身份但**两个阵营都不变**，屠边统计不错位。

## §432 十二个坑

1. **把三套「新月」揉成一套** → 抽卡时机、时效、事件名全乱。先读 §413 确认是哪一套。
2. **把事件卡当身份或板子** → 事件会挂载/卸载，静态表装不下；它要独立的活动栈。
3. **为每张卡写一段 if** → 24 张满月卡会变成 24 处散落改写，撤销时漏一半。用卡库 + 效果码。
4. **撤销时把开关置默认值** → 抹掉其他事件的效果。必须**快照栈 + 栈顶才恢复**（§428）。
5. **条件触发卡没有超时** → 条件永不满足时永久挂在栈里，状态越跑越乱。
6. **暗月卡被回合末清理** → 开局预置的永久规则第二回合就消失。
7. **「已触发」和「已挂载」共用一个标志** → 同一帧两个钩子各触发一次。
8. **网易抽卡点放错** → 放队列前会改写未跑完的技能，放公布信息后会错过「第一夜」事件。
9. **判胜负只在死亡后跑** → 「到点下班」到第三天结束没有任何死亡，事件永远不生效。
10. **额外胜负条件写成替代条件** → 吞掉屠边路径，官方明说「仍然遵循屠边规则」。
11. **「仅第 N 天」写成 `天数 >= N`** → 信息/见面类事件每晚重复触发。
12. **用真随机抽卡 + 没有种子** → 行为校验「跑十次红一次」，假红比漏测更糟（见项目记忆的 match3 教训）。

> 收尾一句：**事件卡是唯一一种「会在游戏中途改写规则」的东西**。
> 一旦接受这一点，实现就只剩三件事：**卡库是表、效果带快照、钩子挂在正确位置**。
> 剩下的都是往表里加行。
