**第一册 `references/advanced-techniques.md`（§1–§15）**
>
> 📌 **节号是跨册连续的逻辑编号**，正文标题格式并不统一：早期册用 `## 1. 标题`，
> 第十~十三册等用 `## 106. 标题`，后期册用 `## §N 标题`；**第十四~二十四册正文只有 H1 + 段落**，
> 节号仅在册标题里声明、没有对应小标题（历史结构，未强行重排以免破坏内容）。
> 做节号连续性检查时**不要只按 `## §` 窄匹配**，会误报大量缺号。

- **大地图 + 小地图**：世界比舞台（480×360）大时，用「相机变量 + 反向移动」做滚动，
  再配一张缩小世界底图 + 两个置顶小圆点标出玩家/目标位置（§1）。
- **平滑移动**：用「速度 + 摩擦」或「缓动 lerp」取代 `change x by 50` 式瞬移，手感更专业（§2）。
- **开关设计**：用 `game_state` 状态机（title/playing/over）+ 广播调度，并用 0/1 变量
  做可切换开关（如小地图开关 M、音效开关 S）（§3）。
- **视野阴影 / 光照**：恐怖、潜行、探索类作品用「整屏黑幕 + 中央透明洞」做手电筒，
  洞跟着玩家走（§4）。
- **弹窗与「当关闭被点击」**：设置/帮助面板用「面板 + 遮罩 + 关闭按钮」三件套，
  遮罩用来拦截穿透点击（§5）。
- **防搬（合规做法）**：署名卡 + 致谢栏 + 素材清单 + 水印；**不要**写「禁止改编」（§6）。
- **克隆粒子系统**：火花/爆炸/尾迹用克隆做粒子，速度必须是**私有变量**（§7）。
- **触屏适配**：手机端按钮用「鼠标按下 + 碰到鼠标指针」，且要避开多点触控（§8）。
- **血条 / 进度条**：多造型法最省事，克隆拼接法精度高（§9）。
- **关卡数据表**：用一张列表存关卡配置，做「数据与逻辑分离」（§10）。
- **缓动与物理**：落地反弹 `速度 × -0.7`、地形摩擦（§11）。
- **音频控制**：音量渐变、静音开关、切歌（§12）。
- **投影与遮挡层次**：影子用「复制造型 + 亮度 -100 + 置后一层」（§13）。
- **性能红线**：特效 ≤3 层、克隆 ≤300、同屏面板不用画笔实时写字（§14）。
- **碰撞箱**：障碍物必须是**独立角色**才有碰撞箱，画在背景图里的家具挡不住人（§15）。

**第二册 `references/game-systems.md`（§16–§42）**

- **敌人 AI**：视野锥（距离 + ±45° 方向差，角度要归一化到 ±180°）+ 列表巡逻点 + 三态状态机；
  视野检测每 0.1 秒做一次就够，别每帧算（§16）。
- **平台跳跃物理**：重力/地面/跳跃/水平**一条规则一个循环**；地面检测用「脚下感应点」；
  郊狼时间 + 跳跃缓冲是手感提升最大的两招（§17）。
- **打击感 Juice**：受击闪白、屏幕震动、放大脉冲、伤害飘字、无敌帧、Combo 连击（§18）。
- **网格移动**：格↔像素坐标转换、**只在格点转向**（`mod` 判断）、蛇用两条列表当队列（§19）。
- **克隆分身**：一个精灵 + 私有 ID 区分身份 = 四只鬼/55 个外星人；全局变量让克隆同步行动（§20）。
- **拾取物 / 背包 / 商店**：列表当背包 + 名称映射表、磁性吸附、商店按钮状态反馈（§21）。
- **随机生成**：递归回溯迷宫、坐标↔列表索引、**列表当栈**、递归深度熔断、绘制节流（§22）。
- **存档与进度**：云变量存进度/最高分/解锁关卡，只在离散时刻写；检查点与自动存档（§23）。
- **教学引导**：箭头指示、分步提示、把教学做成关卡而不是弹窗（§24）。
- **数学工具箱**：向量与单位向量（长度要夹紧）、角度归一化、缓动曲线、Fisher-Yates 洗牌（§25）。
- **UI 拖拽与滑块**：音量条/难度条，「当角色被点击」后脚本持续运行 = 按住拖动（§26）。
- **敌人波次与难度曲线**：列表存波次数量/间隔，波内间隔递减 + 波间喘息（§27）。
- **分支对话 / 剧情树**：状态 + 广播做分支，对话期间要能跳过与锁操作（§28）。
- **成就与任务**：成就状态用云变量存，提示要写「还差 N 个」而不是「未完成」（§29）。
- **网格解谜与推箱子**：整张地图存**一条列表**（index = (y-1)*列数 + x），
  每格一个数字（0空地/1箱子/2墙/-1目标点）；推箱子要看「右边第二格」（§30）。
- **多人游戏**：云变量**每秒最多 10 次更新**、只能存数字；官方**禁止云聊天室**，
  实时动作游戏不适合，**回合制**最稳（§31）。
- **角色动画**：`next costume` 在有人加造型后会静默崩坏 → 用命名造型；
  步长必须匹配等待时间（否则像滑冰）；造型中心要对齐；挤压拉伸幅度 10%~15%（§32）。
- **投射物与弹道**：克隆子弹发射瞬间瞄准；**子弹 < 10 像素会穿过目标**；
  列表追踪子弹并限制同屏数量（§33）。
- **Cutscene 三段式**：`开始游戏` / `游戏进行` / `演出` 三个帽子，
  「演出」开头 `stop other scripts in this sprite`、结尾广播回「游戏进行」（§34）。
- **镜头关键帧**：4 条列表存关键帧，**用计时器做节拍**（叠加 wait 会累积误差）；
  淡入淡出**不要用亮度特效**（亮度是往白提不是变黑），要用虚像或全屏黑角色（§35）。
- **视差滚动**：每层按不同比例跟随（层系数越大越远）；无限滚动用两张克隆 + `mod`；
  背景图**左右边缘必须无缝**，否则切换会「跳一下」（§36）。
- **寻路**：Wavefront 距离扩散（格子游戏首选）/ BFS / A*（G+H+F，曼哈顿距离）；
  目标会动就**每 0.2~0.5 秒重算一次**（§37）。
- **塔防**：路径存列表（改路径不改代码）、射程用距离平方比较、
  建塔要检查金币 + 不能建在路径上（§38）。
- **音频优先级**：Scratch 音效是**抢占式**的；BGM 必须 `play sound until done`；
  要让音效互不打断就用**克隆**跑音效；`stop all sounds` 停不掉循环，
  必须再 `stop other scripts in sprite`（§39）。
- **八方向移动**：四个方向**分别写 if（不要 else）** → 相反方向互相抵消；
  斜向要归一化；朝向用造型而非转角色；`left-right` 避免整圈旋转（§40）。
- **无尽生成**：分段生成 + 离屏回收，难度递增时**间隔要夹紧**（§41）。
- **云变量编码**：云变量只能存数字 → 列表要编码；**编码值指数级膨胀**，
  列表长就该改用「云变量存索引 + 本地列表存配置」（§42）。

**第三册 `references/game-design.md`（§43–§50）**

- **回合制战斗**：属性变量用 `C_`/`E_` 前缀分组；伤害公式**必须有最低伤害保底**
  （否则高防对高防永远 0 伤害、战斗卡死）；属性克制用**一串独立的 if**（不是 elseif）；
  状态异常用**成对列表**存「状态名 + 剩余回合」（§43）。
- **场景管理**：`switch backdrop to` + `当背景切换到 X`（比广播更可靠）；
  传送门切背景后**要重新定位角色**；跨场景数据靠**全局变量**（§44）。
- **菜单系统**：四态 `state` 变量（标题/游戏/暂停/结算）；
  暂停 = **只改状态变量**（Scratch 没有 Esc 键，社区用 P）；
  ⚠️ **一切「一局开始要复位」的东西必须挂在「当收到 [重置]」下，不能挂绿旗**
  —— 否则点「重试」时上局的石头还压在猫身上，立刻又 Game Over（§45）。
- **节奏游戏**：节拍用**计时器**（`wait until timer > 目标`，必须用 `>` 不是 `=`）；
  判定按**距离分段给分**（不要除以距离，会除零）；长按三段逻辑；
  谱面用列表存「拍号 + 类型」（§46）。
- **敌人 AI 决策进阶**：**效用 AI**（给每个行动打分、选最高，基准分先设成巡逻分）；
  听觉（玩家速度阈值）；**搜索状态**（玩家消失后先去找，别立刻回巡逻）；
  决策延迟 + 随机攻击模式让敌人「像人」（§47）。
- **射线与视线**：Scratch 没有射线，用「步进 + 碰到颜色」模拟；
  探针必须 `ghost 100` + 置后；步长 0.1 是精度与速度的平衡点（§48）。
- **吸引力与物理**：磁力吸取用「距离衰减的吸引」，**力度必须夹紧防除零**；
  ⚠️ **摩擦/阻尼一律用「乘」绝不能用「减」** —— 减法会让速度减到负无穷、
  物体反向加速飞走；只有重力/加速度才用「加/减」（§49）。
- **成长与装备**：经验阈值要**乘系数**（否则后期升级跟前期一样快）；
  装备属性**从基础值重算**而不是增量加减（否则穿脱会累积出怪数值）；
  随机词条用**洗牌**抽（别用「随机到不重复」，会死循环）；局外成长才用云变量（§50）。

**第四册 `references/physics-engine.md`（§51–§58）——手搓物理引擎**

- **AABB 包围盒碰撞**：Scratch 的「碰到」是**像素级比对**，性能差、还会「视觉没碰到却判定碰到」；
  引擎级项目要自己算包围盒（4 个边界 + 4 条比较）；碰撞盒要比造型**小一圈**（手感关键）（§51）。
- **Verlet 积分**：不存速度，只存「当前 + 上一帧」，速度由相减隐式得到 —— 比欧拉法**稳定得多**；
  三步法：Simulate（积分）→ Relax（约束松弛）→ Render（渲染）（§52）。
- **绳索与布料**：位置约束法（Verlet + 松弛）优于弹簧力法；
  布料要**拉伸/剪切/弯曲**三类约束；⚠️ 布料**不要用弹簧-阻尼力**（会变成「super-elastic cloth」）（§53）。
- **万有引力**：教学类作品用**参数化圆轨道**（稳定、绝不飞走）；真引力是 `a = G/r²`，
  ⚠️ **方向必须指向中心（取负号）**，否则会把行星推出去；
  圆轨道初速度 `v = sqrt(G/r)`（§54）。
- **弹性碰撞**：一维等质量 = **交换速度**；二维斜撞要**旋转到法线/切线坐标系**交换法线分量再旋回；
  质量不等时交换的是**动量**不是速度（§55）。
- **斜坡检测**：水平移动后**尝试向上爬 8 像素**，记录爬了多高；爬满还在地面 = 坡太陡 → 退回原位；
  ⚠️ `stop this script` 只能停整个脚本，要跳出循环必须抽成自定义积木（§56）。
- **对象池**：克隆体**存在**不卡，**创建/销毁才卡**；预建 N 个克隆体 + 状态列表（0空闲/1在用），
  用完 `hide` 归还而不是 `delete this clone`（实测 150 弹 20fps → 池化后 200 弹稳定 30fps）（§57）。
- **空间分桶**：两两判定是 O(n²)；把舞台切格子，只和**同格 + 相邻 8 格**判定；
  ⚠️ **格子边长必须 ≥ 最大实体尺寸**（§58）。

**第五册 `references/more-techniques.md`（§59–§66）**

- **数据驱动瓦片地图**：地图存成列表/JSON 式数据，渲染器只负责"读格子 → 画图"，
  改地图不用改代码（§59）。
- **程序化音乐 / 音符序列器**：用音乐扩展的 `play note` + `set tempo` 写旋律，
  零音频素材也能出 BGM（§60）。
- **平滑摄像机**：deadzone（死区）+ lerp（线性插值）+ 边界夹紧，三件套一起做才跟手（§61）。
- **缓动与补间系统**：tween / ease 函数库，做 UI 动画与镜头运动的基础（§62）。
- **昼夜循环与动态光照**：用颜色叠加层模拟时间变化（§63）。
- **分支对话树**：对话/剧情用嵌套列表或列表+编号表驱动（§64）。
- **迷你地图**：小地图 = 缩小的世界底图 + 两个置顶指针（§65）。
- **屏幕过场与转场**：淡入淡出、切背景的节奏控制（§66）。

**第六册 `references/pen-techniques.md`（§67–§74）——画笔扩展与伪 3D**

> 用画笔前**必须**在 IR 根声明 `extensions: [pen]`，否则画笔积木全部报错。

- **画笔基础**：落笔 / 抬笔 / 图章 / 拖尾 —— Scratch 里**唯一**能逐像素矢量绘图的工具（§67）。
- **3D 线框渲染**：顶点用三段平行列表（vx/vy/vz）+ 12 条边的扁平边表，
  绕 Y/X 轴旋转后做透视投影（`屏幕x = 焦距·3Dx/3Dz`）（§68）。
- **等距投影（2.5D）**：`(x−y)·0.866, (x+y)·0.5 − z`，做沙盒 / 建筑（§69）。
- **第一人称射线投射迷宫**：地图存列表，逐列发射线，撞墙后画竖线；
  ⚠️ **必须用垂直距离**（消鱼眼），直线距离会让墙向外鼓包（§70）。
- **星空 / 隧道伪 3D**：星点朝你飞来（§71）。
- **海龟绘图与分形**：递归自定义积木画分形树 / Koch 雪花，
  ⚠️ **递归必须有长度阈值熔断**，否则栈溢出（§72）。
- **贝塞尔曲线**：⚠️ **Scratch 没有 `pow`**，幂要靠乘法展开（§73）。
- **笔刷 / 粒子笔迹**：喷枪、毛笔、发光拖尾（§74）。

**第七册 `references/game-feel-and-interaction.md`（§75–§82）——游戏手感与交互**

> 这一册是「从作业到作品」的分界线：视觉反馈 + 听觉氛围 + 交互设计 + 性能纪律。

- **拖尾系统**：三种方案 —— 画笔拖尾（不产生克隆体）、克隆残影（带寿命与回收）、
  造型拖尾（零克隆）；⚠️ **克隆体也响应本体的事件帽子**，要用**私有标志位**挡住（§75）。
- **背景音乐**：BGM 状态机（场景 → 曲目）+ **淡入淡出**（一个 `forever` 同时管两个方向，
  两个循环会打架）+ 程序化旋律；⚠️ **Scratch 音量是全局的**，BGM 要在素材层面压低（§76）。
- **多角色选项菜单（不用「询问」积木）**：⚠️ 「询问并等待」会**阻塞当前脚本**，
  且样式不可控、移动端体验差；正确做法是**每个选项一个角色按钮**，
  按钮只广播意图、由舞台统一决定去哪（§77）。
- **克隆的正确用法**：四问决策树（造型 / 列表 / 克隆 / 画笔）；
  三阶段生命周期（生产 → 出生 → 消亡）；⚠️ **克隆上限 300，超限会静默丢弃新克隆**（§78）。
- **受击反馈**：闪白 + 击退 + **顿帧**（全局标记，所有角色一起停）（§79）。
- **演出与转场**：缓动滑入（`divide` 指数逼近，必须加停止条件）、遮罩淡入淡出（§80）。
- **节奏输入判定**：时间窗 → Perfect / Good / Miss；⚠️ `and` **只有 2 个输入**（§81）。
- **广播驱动的解耦**：⚠️ **广播是群发**且**高频事件不要用广播**（用 `touching` 直接问）（§82）。

**第二十一册 `references/metro-sim.md`（§167–§176）——地铁 / 交通模拟**

> 做「地铁模拟器、列车驾驶、公交/高铁线路、站台开关门、线路图」时**必须先读**。技术密度最高的品类。

- **§167 一条线就是一张数据表**：`站名 / 里程(米) / x / y / 换乘 / 停车时长`，脚本里一个站名都不硬编码，全按 `站编号` 索引。

- **§172 信号机与限速**：里程越过信号位置就更新 `信号消息`→`限速`，超速累计 → 紧急制动 + 扣分，玩法深度全靠它。
- **§173 速度表针角度映射**：`速度/满量程*180 - 90`；指针角色**必须保持「任意旋转」**，设成不旋转会纹丝不动。
- **§174 报站与线路图**：`下一站 = 站名[站编号+1]`；线路图用每站一个圆点克隆体 + 本段进度推进。
- **§175 客流克隆体**：开门放人、到门边删除；300 上限在此场景最容易撞，必须自己删 + 克隆守卫。
- **§176 五个致命坑**：漏 ÷3.6 / 只判位置不判速度 / 门开着能牵引 / 直接改 x/y 不用里程 / 指针设了不旋转。

**第二十二册 `references/game-architecture.md`（§177–§186）——大型工程架构**

> 作品预估超过 1500 块、或要做「能继续加内容」的项目时**必须先读**。
> 提炼自 5 个万块级工程（19191 / 12731 / 12615 / 10262 / 6118 块）：它们彼此无关却收敛出同一批约定。

- **§177 变量命名前缀**：`#` 配置 / `+` 运行态 / `-` 临时 / `=` 函数返回值 / `@`·`Indiv.` 克隆体私有 / 点分命名空间（`WORLD_`·`CAM.`·`PLAYER.`）/ 类型前缀（`BOOL-`·`CHAR-`·`INT-`）。
- **§178 广播命名空间 `模块-动作`**：`主界面-新存档`·`UI特效-剧情`·`场地-医院`·`数据处理-生成存档码`·`game loop - scroll`·`EDIT - Save`；超过 20 条广播后 `消息1/消息2` 不可维护。
- **§179 类型-属性表**：91 种方块的属性摊成 len=91 的平行列表，**用 ID 当索引**；加一种方块 = 每个列表加一项，代码零改动。所有属性表长度必须严格相等。
- **§180 一维列表当二维地图**：`idx = y×宽+x+1`；越界返回空串（不是报错），必须自己判边界，`mod` 第二操作数不能为 0。
- **§181 对象池 + GC 计数**：`克隆数` 分配/回收/每 60 帧对账三段；只增不减会让玩两分钟后新内容不再出现。
- **§182 存档码**：两级分隔符 `&`（字段）+ `|`（多表），序列化靠 `join` 循环累加，反序列化靠 `letter_of` 逐字符扫描（Scratch 没有 split）。
- **§183 纯计算库角色**：自定义积木没有返回值 → 结果写进 `=` 前缀变量，调用方立刻读；纯计算必须开 `warp`，否则每块刷新一帧直接卡死。
- **§184 字符渲染**：造型表（短句）/ 图章拼字（大段，132 个字符造型）/ 数字拆位（铁律 1 标准实现）。中文别给每个汉字做造型。
- **§185 绘制顺序**：`_order` 广播每帧排序（2.5D）/ `Distances` 距离排序（画家算法）；每帧排 100 个对象会掉帧，按 y 分桶降一个数量级。
- **§186 五个致命坑**：一个角色干所有事 / 配置量被游戏改掉 / 属性表长度不一致 / 克隆数只增不减 / 自制积木不开 warp。

**第二十五册 `references/metro-driving-deep.md`（§207–§221）—— 地铁驾驶模拟：从里程到 ATP**

> 做「列车/地铁/公交驾驶、对标停车、ATP、开关门、移动闭塞、报站」时读这一册。
> 结论来自对真实工程《深圳地铁5号线》的逐块反编译——**驾驶模拟品类的天花板**，
> 难度不在单条公式，而在 6 个子系统靠一个数字（剩余里程）互相同步。

- **§207 用「剩余里程」而不是「累计里程」**：`剩余里程` 从整段长度递减到 0（可为负），一个量同时是到站误差、HUD 距离、限速时钟、制动曲线输入。少一个派生量 = 少一处「三个脚本各说各话」。
- **§208 主 Tick 只有一行**：`剩余里程 += 0 - 速度/4.9`。常数即时间压缩比：`108`=真物理、`36`=3× 慢放（推荐）、`12`=9×、`4.9`=22×（原工程）。**常数只改节奏，不改制动距离 `v²/(2a)`**。
- **§209 手柄是「位移→加速度」**：1 px 死区、10 px 线性（`(鼠标y-y)/10`）、超 10 px 饱和、**制动 1.5 > 牵引 1.0**。用离散档位就做不出「微调」的手感。
- **§210 方向状态存在造型里**：`如果 造型名=向后` 直接当状态用；只适合「玩家可见 + 2~3 个取值」，要存档/跨角色读就必须用变量。
- **§211 制动曲线 `t = 0.185·d/v²`**：每次降 1 km/h，等待时间 ∝ `d/v²` → 允许速度 ∝ √d。循环退出后接**三段收尾**（压到 5 → 爬行到 6 米 → 逐 1 刹停），否则会「停在半路」。
- **§212 到站是三方握手**：`站点 += 1`（d<10 时）→ A 等 `d > 站距[新站点]-10`（此刻为假，卡住）→ B 开门后 `d = 站距[站点]` 重置 → A 的条件成立才报站。**用不变量同步，不用标志位**（标志会卡死，不变量自愈）。
- **§213 冲标 = `d < -5`**：负里程是特性，不是 bug；玩家必须退回窗口才能开门。
- **§214 三显示移动闭塞**：`间距 = 前车里程 - 本车里程 - 1400`（**1400=车长+安全余量，漏了两车穿模**），`>9000 绿 / >5000 黄 / 否则红`。
- **§215 推荐速度 = min(区间限速, 制动曲线, 信号限速, 前车净空)**；**红灯必须让 ATO `停止这个脚本`**（主动交还人工），否则自动带玩家闯红灯。超速保护要写**过零回补 + 夹零**。
- **§216 ATO 三态 `zt`**：`-1` 控车中 / `0` 惰行 / `1` 停稳；配 `连续ATO` 开关做「演示模式」。
- **§217 限速梯度用距离时钟 `d mod 35 < 15`**：与速度无关、复位即同步、省一个变量；负数取模会错乱，必须先判 `d>0`。
- **§218 车门机械缓动 = 线性累加器 + 平方位移**：`移动 (tmp²) 步` + `tmp += 0.042` → 二次缓入；`-= 0.028` → 缓出。梯形速度曲线，零缓动库。
- **§219 里程是真值、像素是假滚动**：远景按 `速度 px/帧` 氛围滚动，近景（站台/屏蔽门/停车标）在**到站前 40~80 米窗口**直接 `goto` 固定坐标，把「视觉对标」退化成「数值对标」。

**第二十六册 `references/polish-and-feel.md`（§222–§235）—— 质感与手感打磨**

> **「打开就觉得是 AI 做的」这个问题，99% 不在美术，在运动曲线和反馈。**
> 交付「看起来廉价 / 操作发飘 / 放技能没感觉」的作品前必读。做任何有动效、有操作反馈的作品都适用。

- **§222 质感三个可量化维度**：**时间**（一切变化都要有帧数，禁止瞬间跳变）/ **曲线**（线性 = 机器，缓动 = 手作）/ **过冲**（到位后微微超出再回来）。
- **§223 缓动公式**：`x += (目标 - x) * 0.2` 一行解决 80% 廉价感；系数 0.15~0.25 是「跟手」区间，>0.4 会抖、<0.08 会拖。
- **§224 Squash & Stretch**：起跳拉长（`size 108 / 92`）、落地压扁（`72 → 88 → 100` 三帧），**只用 3 帧**。
- **§225 过冲回弹**：UI 弹出用 `0.6 → 1.15 → 0.96 → 1` 四帧，比线性放大「贵」一个档次。
- **§226 顿帧（Hitstop）**：命中瞬间冻结 2~4 帧 = 打击感的 70%，比加粒子特效便宜一百倍。
- **§227 预备动作**：危险来临前 10~15 帧给预警（闪烁/放大/影子），玩家会觉得「这游戏讲道理」。
- **§228 错峰（Stagger）**：多个物件同时出现时，每个延迟 2~3 帧，立刻从「批量生成」变成「编排」。
- **§229 输入缓冲**：落地前 6 帧按跳跃有效 → 「不跟手」变「跟手」，是平台游戏手感的第一杀手。
- **§230 屏幕震动**：幅度 2~4 px、衰减到 0，**只在真打击时用**；频繁震 = 廉价。
- **§231 UI 微交互四层**：静止态 → 悬停（放大 1.05）→ 按下（缩 0.95）→ 释放（回弹），缺一层就「像贴图」。
- **§232 分层与深度**：远景/中景/近景三层视差就够，别做五层；影子 + 落点指示是「有物理」的最低成本信号。
- **§233 音效三参数**：音量（距离衰减）/ 音调（随机 ±5 防重复）/ 时长（短促优先）。
- **§234 色彩与留白**：主体不贴边（留 10% 边距）、不做纯色大底（加同色系深色渐变/纹理）。
- **§235 打磨 checklist 20 条**：交付前逐条过，**过不了就别交付**。

**第二十七册 `references/ato-autopilot.md`（§236–§248）—— ATO 自动驾驶：让机器把车停准**

> 做「自动驾驶 / ATO / 全自动运行 / 自动对标停车 / 无人驾驶」时读这一册。
> 与第二十五册分工：**第二十五册讲「人怎么开」（手柄 + ATP 兜底），本册讲「机器怎么开」（控制律 + 精确停车）**。

- **§236 三层结构**：安全层（ATP 只读包络）/ 规划层（目标速度 = 一个 min）/ 执行层（误差 → 档位）。数据流顺序 `包络 → 目标 → 误差 → 档位 → 速度 → 积分` **不可换**（换一步就滞后一帧，落点漂 ±8 米）。
- **§237 不写「牵引/巡航/制动」三状态**：那是把控制律硬编码。状态只描述「车在干什么」（8 个业务态），加减速方向由误差符号决定。**状态名里出现「加速/减速」就是写错了**。
- **§238 目标速度 = min(巡航, 包络, 末段压速)**；`巡航速度` 要略低于 `区间限速`（示例 62/80）。
- **§239 制动曲线 `v = 3.6√(2a·max(0, d-5))`**：`3.6` 忘了会提前 100 米停；`d-5` 的 5 米是安全余量（正常永远停不到 5 米内）；`max(0,·)` 不能省（**`sqrt(负数)` 在 Scratch 里静默返回空**）。
- **§240 末段三段压速**（60m→22 / 22m→9 / 9m→3）：把「追曲线」的滞后一节节吃掉，落点从 ±15 米收进 ±3 米；阶梯不超过 4 级。
- **§241 死区必须非对称**：牵引死区 1.5（防抖）/ **制动死区 ≤ 0.3**（必须停得住）。对称死区会让车**卡在 1.2 km/h 永远停不下来**，里程磨成负数。另加「目标 ≤ 0.5 强制制动」一条兜底。**模式必须用标志位**：靠「`速度 ≤ 0.3 且 d > 5`」这种瞬时条件推断「欠标爬行」→ **脉冲蹭行**（速度在 0↔1.2 抖，58 帧只挪 4 米，红灯停住时还会被重新推起来）。
- **§242 精确停车一个闭环 + 两道保险**：窗口 ±5（`|d| ≤ 5` 且 `速度 ≤ 0.3`，**不能用 `速度 = 0`**）；冲标 `d < -5` 扣分**但照常开门**（卡死比冲标更伤体验）；欠标 → 爬行二次对标。**爬行退出阈值要比窗口更靠里**（窗口 ±5 → 退出 `d ≤ 3`），且爬行段给一套**独立 ATP 余量**（`+6` 而非 `+2`）——否则死锁在 `d = 5.05`：判定进不去、爬行又已退出。
- **§243 过渡状态不能零时长**：`停稳 → 开门` 写在同一帧 = 状态不存在（校验读不到、玩家看到门瞬间弹开）。停稳**占 8 帧**再开门，计数器进入时清零。
- **§244 多站循环**：`剩余里程` 必须**重新置整段长度**（不是 `+= 站距`）；`当前站/下一站` 一起更新；`起步延时` 每段重置；推进只在一处写。
- **§245 车门**：`门位`（0~100）是唯一真相，`车门`（0/1）只是派生布尔；门位每帧 ±6，视觉上 `size = 1 + 门位×1.6`。
- **§246 安全层降级**：红灯**用包络归零表达「必须停」，不写单独刹车指令**（两条叠加会让减速率翻倍）；红灯必须能强制退出爬行。
- **§247 三个评分指标**：对标误差（技术分）/ 牵引能耗占比（教经济驾驶）/ 完美次数（可追求的满分）。全自动运行没有操作，成就感只能来自评分。
- **§248 调参表 + 十个致命坑**：先定 `里程系数` → 再定 `牵引加/制动减` → 最后用 `制动率` + 三段压速调落点（**别反过来**）。

**第二十九册 `references/audio-design.md`（§263–§276）—— 声音设计：让作品「有质感」的另一半**

> **用户说「没游戏感 / 像课件 / 声音很吵」时读这一册。** 静音的作品，代码再好也像半成品。

> ### ✅ 默认做法：音频就是「音效 + BGM」，直接挂进作品
> **用户没有明确要求「音频转乐器 / 扒谱 / 把某首歌做成乐器演奏」时，一律走这条路，不要碰 `audio2notes.py`：**
> 1. `python scripts/gen_sfx_kit.py` 生成 22 个分层音效（ui/fx/ev/amb 四层）；
> 2. 需要 BGM 时 `python scripts/gen_audio.py <mood>` 生成（7 种 mood）；
> 3. 在 IR 里直接挂 `sound_play`（UI/短音，不阻塞）或 `sound_playuntildone`（事件音）；
> 4. `python scripts/check_audio_assets.py` → `AUDIO_ASSETS_OK`。
>
> **判定规则**：音频是「素材」→ 直接用。只有在「用户给了录音/歌曲文件，并要做演奏或改编」时，
> 音频才是「待分析的数据」→ 才用 `audio2notes.py` 转音高表（§319）。
> **不要因为「作品是音乐类」就自动去转乐器** —— 音乐类作品九成情况也只需要音效 + BGM。

- **§263 三类「静音型廉价感」**：点了没声音 / 玩两分钟就关声音（所有音效一样响）/ 有咔哒声。
- **§264 四层响度（全册最重要）**：`ui` −18 dBFS（最高频，必须最轻）/ `fx` −9 / `ev` −3 / `amb` −15。层间差 6~9 dB。⚠️ **全部归一化到同一峰值 = 业余**：点按钮和爆炸一样响。同层内靠**频谱与时长**区分轻重，不靠更响。
- **§265 时长预算**：`ui` **30~250ms（绝不能超 0.25s）** / `fx` 80~600ms / `ev` 300~1600ms / `amb` 1000~4000ms。
- **§266 音色同源**：同层用同一族波形（ui=sine / fx=tri+sine / ev=square / amb=滤波噪声）；全部干声（素材带混响会显脏）；音高基准 440。
- **§267 包络**：首尾**必须归零**，淡入淡出 = `min(10ms, 时长×15%)`；**DC 偏移 < 0.01**（否则低频嗡嗡 + 提前削波）。⚠️ 短音效不能用固定 8ms 淡入（吃掉音头）。
- **§268 音高方向 = 语义**：上行=获得/变强/开启，下行=失去/失败/关闭，平+颤=警报。⚠️ 升级音用下行是「AI 音效」最典型的错。
- **§269 「不要做」八条**：不要每步都配音 / 悬停音**至少间隔 120ms** / 同帧不超过 3 个音效 / 不要 0.5s 以上的 UI 音 / BGM 不能一成不变 / 环境音不可 < 1s 循环 / 暂停要停声 / **UI 音禁用「播放声音直到结束」（会阻塞脚本）**。
- **§270 程序化 BGM**：总长=整数小节、首尾归零、末小节不做收束；四个万能和弦进行（I-V-vi-IV / i-VI-III-VII / I-vi-IV-V）。
- **§271 音量总线 + ducking**：BGM 35% / 环境 30% / 音效 100%；播 `ev_*` 时 BGM 压到 40% 再**缓动**恢复（硬切会「窜一下」）。
- **§272 四个积木的正确用法**：`播放声音`（UI/短音，不阻塞）/ `播放声音直到结束`（事件音，**会阻塞**）/ `停止所有声音` / `设音量为`（角色级）。
- **§273 素材规范**：44100Hz / **单声道** / 16bit / 命名 `{层}_{名}.wav`（层前缀=响度归属，可批量套音量）。
- **§274 波形级七项校验**：格式 / 分层响度 ±2dB / 首尾归零 / 尾部衰减 / DC 偏移 / 削波 / 时长。
- **§275 廉价 vs 专业听感对照**；**§276 音效与 UI 的配合时机**（**按下瞬间响**，不是松开；按钮已有音效+换造型就不要再放大缩小）。

**第三十册 `references/math-and-reasoning.md`（§277–§290）—— 数学与推理：让作品「算得对」**

> 做「数学游戏 / 解题 / 数独 / 24 点 / N 皇后 / 算法可视化 / 概率模拟」时读这一册。
> 数学类有个别的品类没有的优势：**答案唯一，可以自动校验**；劣势是**算错了看不出来**。

- **§277 三个层次**：算得对 → 显示对 → 判得对。先保证第一层，顺序反了会浪费大量时间调显示。
- **§278 浮点**：`0.1+0.2 ≠ 0.3`，**判等必须带容差**（`abs(差) < 1e-9`）；`round(-2.5) = -2`（向 +∞）；整除用 `floor` 不用 `round`。
- **§279 整数除法**：Scratch 只有浮点除。**化简分数必须 `round(分子/gcd)`** —— 用 `/` 会得到 `5.000000001`，用 `floor` 会变成 `4`（灾难）。
- **§280 `mathop` 只有 14 个函数**：没有 `pow`/`log2`/`gcd`/`lcm`/阶乘/`atan2`。`pow` 用 `e^(ln x · y)`（x 必须 > 0，整数指数用循环连乘更准）；**`log` 是 10 为底，`ln` 才是自然对数**（搞反是高频错）。
- **§281 数值范围**：`20!` 已超 2^53；`171! = Infinity`；`C(n,k)` 要**边乘边除**（先算 `n!` 必溢出）。
- **§282 `mod` 符号**：结果跟**除数**走（`-7 mod 3 = 2`），负下标会取空。
- **§283 迭代回溯**：Scratch 没有递归 → 「行号 + 列数组 + 手动回退」。递归的「返回」= `行 -= 1`。
- **§284 回溯三个致命细节**：⚠️ **回退时不要 `+1`**（推进候选只写一处，否则 8 皇后得 14 个解而非 92）；**找到解后 `行` 要归位到 `n`**（否则死循环）；**列表长度必须跟着 `n` 重建**。
- **§285 埃氏筛**：从 `i*i` 开始划、只筛到 `√n`（不是正确性问题，是 Scratch 里的性能=正确性）。
- **§286 辗转相除**：循环不变量 `gcd(a,b)=gcd(b,a mod b)`；**先取绝对值**、`tmp=0` 是退出条件、`gcd(0,0)` 要兜底成 1。
- **§287 几何**：**能不开方就不开方**（比较平方）；`atan` 只有单参数没有 `atan2`，用 `面向 [B]`；⚠️ **Scratch 的三角函数输入输出都是「角度」不是弧度**。
- **§288 排列组合**：无放回抽样用 **Fisher-Yates 洗牌**，「重取」在 k 接近 n 时会卡死；「保底」用计数器不改概率。
- **§289 算法可视化**：回溯**只在找到解时画**；画笔重绘要 `全部擦除` 后重画（逐笔擦会越跑越慢）。
- **§290 校验方法**：**用已知答案当断言**（n=4→2 / n=8→92 / 1..100 质数 25 个 / 第 25 个是 97）；**三步法**：Python 基线 → 比对解数 → **比对节点数**（节点数一致 = 翻译没走样）。含十个致命坑 + 6 问自检。

**第三十一册 `references/tabletop-games.md`（§291–§304）—— 桌游：卡牌、手牌与隐藏信息**

- **§291 棋类 vs 桌游**：桌游最难的不是「规则怎么算」，是**「谁该看到什么」**——所有手牌放一个公共列表且开监视器，玩家一眼作弊。

**第三十二册 `references/music-and-instruments.md`（§305–§319）—— 乐器与编曲：把乐谱变成演奏**

> 做「音乐游戏 / 演奏 / 编曲 / 简谱转乐器 / 多声部」时读这一册。第八册 §83–§85 是入门，
> 这一册专攻**「同一段乐谱换不同乐器演奏」**。

- **§305 音乐扩展只有 9 个积木**，但 `NOTE`/`INSTRUMENT`/`DRUM` 都是「可下拉也可插数字」→ **能用变量驱动**。乐器编号 **1~21**（1=钢琴），VM 内部 0-based。
- **§306 MIDI 音高**：`60=C4`，每 12 一个八度；`MIDI = 12×(八度+1) + 半音`。⚠️ Scratch 的可用音域比标准 MIDI 窄（约 C3~C5），**不要用 24 做低音**，低音靠「降八度 + 贝斯」。
- **§307 「音乐转乐器」的核心**：`设定乐器为 (乐器变量)` —— 换音色只改一个变量，**不复制脚本**。
- **§308 简谱解析**：偏移表 `[0,2,4,5,7,9,11]`，`MIDI = 60 + 偏移 + 12×(八度−4)`；休止符用 0（不是 60）。
- **§309 旋律数据化**：音高/时值/力度三个**平行列表**，长度必须一致。
- **§310 多声部 = 多个角色**：音乐状态是**每个 target 一份**，三个角色各设自己的乐器就是三重奏。⚠️ 一个角色里切乐器做不了多声部（`演奏音符` 阻塞）。
- **§311 和弦**：`0 4 7` 大三 / `0 3 7` 小三 / `0 4 7 10` 属七 / `0 4 7 11` 大七；一个角色只能琶音，真和弦要三个角色。
- **§312 鼓组**：`演奏鼓` 编号 1~18（**以编辑器下拉为准**，版本间有差异，交付前听一遍）。
- **§313 速度**：`一个音秒数 = (60/BPM) × 拍数`；改 BPM 不动谱子。⚠️ `演奏音符` 后**不要再加等待**（积木本身已等）。
- **§314 段落 AABA**，循环点必须落在小节线上。
- **§315 音色三层**：旋律 C4+ / 和声 C3 / 低音 C2，音量 100 / 60 / 80。
- **§316 演奏是阻塞的**：播放器角色只管演奏，界面角色单独一个。
- **§317 实时合成 vs 音频素材**：BGM 用素材（第二十九册），**交互式换音色只能用扩展**。
- **§318 校验 + 十坑**：`getCustomState("Scratch.music").currentInstrument` 可在无头环境读（`_setInstrument` 没有 audioEngine 守卫）；但 `演奏音符` 有守卫且**按虚拟时间阻塞** → **校验不要触发演奏**。
- **§319 音频转乐器（`audio2notes.py`）**：⚠️ **仅在用户明确要求「音频转乐器 / 扒谱」时使用，默认不碰**（默认音频走第二十九册的音效 + BGM）。链路 —— 降采样 8k（**必须抗混叠**）→ 分帧 32ms → **自相关** `r(τ)=Σx[i]x[i+τ]/(N−τ)` → **取第一个显著峰**（防低八度）→ **抛物线插值** `δ=0.5(y₋₁−y₊₁)/(y₋₁−2y₀+y₊₁)` → `MIDI=round(69+12log₂(f/440))` → **MIDI 变化 + 能量低谷双条件切音** → 量化到拍。三条硬限制：同音高连音需 **≥50ms 能量低谷**、和弦只能取最响、噪声会污染。

> 配套 `deploy-tools/gen_music_band.py` → `examples/music_band.yaml`（**4 角色 / 112 块**：简谱解析 + 变量驱动乐器 + 低音声部）、
> `scripts/music_behavior_check.mjs` → `MUSIC_LOGIC_OK`（简谱→MIDI / 休止符 / 八度 ±12 / 乐器切换 5·1·21→4·0·20 / 状态按角色隔离）。
>
> ⚠️ **这一册是「让 Scratch 演奏」，不是「玩家跟着节奏打」**。要写音游（下落式 / 判定窗口 / Combo / 长按 / 校准）

**第三十八册 `references/rhythm-games.md`（§433–§456）—— 音游（节奏游戏）完全手册**

> ⚠️ **音游和「会演奏的 Scratch 作品」是两回事**：第三十二册是程序按谱**发出**声音，
> 本册是程序按谱**等待玩家输入**，核心算法是 `误差 = 输入时刻 − 目标时刻`。
> 全工程只认**一个音乐时间轴 songTime**；音游 90% 的 bug 是「有两个时钟」。

- **§435 能力边界（本册最重要）**：Scratch 30fps ≈ **33ms/帧**，而主流音游 Perfect 窗口只有 ±30ms ——
  **比一帧还窄，物理上不可实现**。必须把窗口设成帧长整数倍（P=1帧 / G=2帧 / Good=3帧 / Miss=4帧），
  且**先量化输入时刻再取误差**，否则「按准了却吃 Great」是随机的。Scratch 能做休闲/教学/派对音游，做不了竞技级。
- **§434/§448 唯一真相**：音符 `y = 判定线Y + (目标时刻 − songTime) × 像素每ms`，
  **由公式重算，绝不每帧 `y +=`**（掉帧即漂移、越玩越偏）。判定窗口用**毫秒不用像素**，否则改下落速度就改了难度。
- **§436–§439 谱面**：五条平行列表（时刻 / 轨道 / 类型 / 时长 / 已判定）；谱面文件存「拍」、运行期读毫秒；
  `拍长=60000/BPM`、`十六分=拍长/4`、**三连音=拍长/3**；`目标时刻=偏移+拍×拍长+细分×十六分`。
  ⚠️ `谱面偏移ms` 与 `校准ms` 必须**两个变量**。谱面按 BPM 网格 × pattern 生成，
  或用 `gen_audio.py` 的鼓点同源生成（音乐与谱面天然对齐，最稳）；`audio2notes.py` 只能当草稿。
- **§441–§443 判定**：纯函数四档（`abs` 对称、`≤` 边界）；找**最近**未判定音符（不是第一个）、
  带窗口剪枝；**已判定表 + 按下沿**双层去重；**空击不算 Miss**；漏击用**扫描指针** O(n) 而非每帧全表扫。
- **§444–§446 输入**：Hold **判头 + 判尾两次**（只看按下 = 点一下就满分的 bug）；
  Flick 只判方向不判位移；同时押给 ±1 帧容差；输入先进队列再在帧里结算；
  校准只减在**输入侧**（改目标时刻表会连画面一起挪）；校准值取 8 次误差的**中值**抗离群。
- **§447/§450 结算与手感**：准确率用**未加成裸分**（含连击会虚高、跨曲不可比）；
  **判定反馈必须 0 帧**（这是铁律 15「位移要缓动」的例外，缓动只用于装饰）；
  判定音禁用「播放声音直到结束」；震屏少用（干扰读谱）。
- **§449/§451 引擎边界**：BGM 用非阻塞 `播放声音`、Scratch **无法 seek/无缝续播**（暂停即重开本局）；
  音符用**预造 32 个角色 + 对象池**，不要每音符造克隆（**上限 300 静默丢弃**）。
- **§456 换皮不改引擎**：下落式 / 太鼓 / osu! / 径向 / 单键，`轨道` 就是输入通道编号，
  `目标时刻` 永远是音乐时间轴上的毫秒，判定函数一行都不用改。

**第三十九册 `references/rhythm-replicas.md`（§457–§478）—— 代表作音游复刻手册**

> 目标：**照着这一册能复刻五款代表作的核心玩法**。
> 五款的差异不在音符皮肤，而在**判定体**：
> ① 线段（Phigros 可动判定线 / PJSK 固定线）② 圆（Milthm 判定圈）③ 格 / 路径（两款亚音游根本没有判定线）。

- **§457–§458 统一抽象**：`判定体 × 时间 × 输入动作`，三层判定顺序必须是
  **空间命中 → 时间分档 → 类型结算**（先比时间会把同时押永远判给第一个音符）。
  五款共用一份引擎 + 五张配置表，**不要写五套状态机**。
- **§459–§463 Phigros（无轨）**：官谱 JSON 结构（`formatVersion:3` / 每条线自己的 `bpm` /
  `time` 单位 **T = 1.875/bpm 秒** / `positionX` 宽度单位 / `type` 1Tap 2Drag 3Hold 4Flick）；
  **事件只有移动/旋转/透明度/速度四类且全是线性插值，官谱没有缓动**；
  ⚠️ **隐藏判定线时只关渲染、判定仍生效**（官方用隐藏线做「双音符重合」）。
  ⚠️ **命中用切向投影**：判定区是「与判定线垂直、向两边无限延展的矩形」，
  `t = dx·cosθ + dy·sinθ`，**法向距离不参与命中**（写成点到线段距离必错）。
  判定 P ±80 / Good ±180 / Bad ±220 / Miss；**Drag/Flick 只有 P/Miss**、**Hold 无 Bad**、单次点击只判一个 Tap/Hold；
  分数 100 万 = 判定分 90 万（P 100%·Good 65%）+ 连击分 10 万（最大连击/物量）。
- **§464–§465 PJSK（定轨）**：**12 格网格**（不是 5 条轨！宽音符用区间匹配）；
  五档精确窗口 **±41.7 / 83.3 / 108.3 / 125ms**；⚠️ **GOOD 及以下断连击**；
  Life 1000（BAD −50 / MISS −80 / Hold 中途 −40，归零后得分 1/10）；
  Tap / Hold（**头尾各判**，尾可平尾·Flick 尾·Trace 尾）/ Flick（**指定方向**）/ Trace（**只出 P/MISS，任何接触即通过**）/ Critical（金音符只改权重 ×2~3）。
- **§466–§468 Milthm（不定轨）**：**判定圈**会随谱面在画面各处移动；
  官方六档 **Exact ±35 / Perfect 70 / Great 105 / Good 140 / Bad 155 / Miss**（区间是并集，用 abs）；
  AccV2 权重 100/100/60/30/15/0；**Ξ（普通）与 Φ（闪电）双序列**，闪电不进 Ξ、不计物量、**最后判定**、Miss 只消耗闪电 HP 且不影响 AP/FC。
  ⚠️ **官方明说「不存在传统长条音符」**：雨丝 Drizzle 走**水面反射** —— 命中后判定范围扩展到**全屏**、可**中途换手**、多个雨丝只需**至少一根手指**留在屏幕，无活跃雨丝时继续按住不惩罚也不产生判定。
- **§469 跳舞的线（亚音游）**：无音符无判定线；线自动前进，**单键点击 = 在当前拐点转 90°**；
  判定是「转向窗口 + 扫描指针」，连点窗口重叠时一次点击只消费一个转角；失败回**最近检查点**。
- **§470 滚动的天空（亚音游）**：**5 列离散赛道** + 球自动前进；判定是「行 × 列」的离散碰撞，

- **§471–§474 对照总表 / 统一引擎 / 命中数学**：三角函数用角度不用弧度；
  Phigros 切向投影、Milthm 圆内、PJSK 格区间、亚音游转角/列，全部给可直接抄的公式。
- **§475 复刻工作流**：每款「最小可玩三步 + 最容易卡住的点」。
