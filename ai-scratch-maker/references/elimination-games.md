## 111. 数据模型与交互总览

三消的核心不是「画水果」，而是一张 **36 元素的棋盘列表** + 一套对它的纯函数式操作。
所有「消除、下落、计分」都是对这张列表做变换，角色只是把列表画出来。

### 三张列表（全部放 stage 全局）

| 列表 | 长度 | 作用 |
| --- | --- | --- |
| `棋盘` | 36 | 6×6 棋盘，元素 1..4 表示 4 种水果，`0` 表示空格 |
| `掩码` | 36 | 本回合要消除的格子标记，`1`=消 / `0`=留 |
| `列缓存` | 6 | 下落时临时存放「某一列从底到顶的非零水果」 |

### 关键变量（stage 全局）

| 变量 | 作用 |
| --- | --- |
| `分数` | 累计得分 |
| `本轮消除` | 本回合被消除的格子数（也是计分依据） |
| `选中` | 已点选的第一个格子序号，0=未选 |
| `交换A` / `交换B` | 本次要交换的两个格子序号 |
| `点击序号` | 格子被点时上报的自身序号 |
| `步数` | 已进行的交换次数 |
| `k` `r1` `c1` `cnt` | 过程计数器（扫描 / 下落用） |

### 坐标换算（Scratch 列表是 1-based）

```
idx(r1, c1)  = (r1-1)*6 + (c1-1) + 1      # 1-based 行列 → 序号 1..36
idx0(r0, c1) = r0*6 + (c1-1) + 1          # 0-based 行 + 1-based 列 → 序号
```

### 交互循环

```
点格子 → 上报[点击序号] → 若 选中==0：选中=点击序号
                        → 否则 若 相邻(选中,点击序号)：交换A=选中, 交换B=点击序号, 广播[交换并检测]
                                                否则 选中=点击序号（改选）
当收到[交换并检测] → 交换棋盘[交换A]↔棋盘[交换B]
                   → 调用[检测并消除]
                   → 若 本轮消除==0：再换回（交换无效）
                   → 步数+1 → 广播[刷新]
```

> **复位挂「当收到[重置]」，不挂绿旗**（见第三册 §45）。绿旗只触发一次；
> 玩家想「再来一局」必须能重新生成棋盘。

### 广播链路

```
当绿旗被点击        → broadcast [重置]
当收到[重置]        → 调用[生成棋盘] → broadcast [生成棋盘克隆] → broadcast [刷新]
格子被点击          → 若 是克隆：点击序号=序号 + broadcast [格子被点]
当收到[格子被点]    → 选中 / 相邻判定 / 交换
当收到[交换并检测]  → 交换 → 调用[检测并消除] → 无效则换回 → 刷新
当收到[刷新]        → 仅克隆体：按 棋盘[序号] 换个造型
```

## 112. 开局生成：保证无初始三连

**纯随机填 36 格一定会天然出现三连**，玩家一开局就白送分、体验崩坏。
生成时必须**主动避免**：逐格填值时，让新格不与「左边两格」或「上边两格」构成同色三连。

```text
repv(r1, 1..6,
  repv(c1, 1..6,
    k    = idx(r1, c1)
    __l1 = 棋盘[k-1];  __l2 = 棋盘[k-2]     # 左邻两格
    __u1 = 棋盘[k-6];  __u2 = 棋盘[k-12]    # 上邻两格
    rep(8,                                   # 最多重试 8 次取合法值
      __cand = random(1, 4)
      if ( 棋盘[k] == 0                                  # 还没填
         and ( __cand != __l1  or  __l1 != __l2 )        # 不会与左两格同色
         and ( __cand != __u1  or  __u1 != __u2 ) )       # 不会与上两格同色
           replace(棋盘, k, __cand)
    )
  )
)
```

**为什么这招一定成功**：4 种颜色下，任一格的「禁止集合」最多 2 个（左邻色或上邻色），
必剩 ≥2 个合法值，所以 8 次重试里必然取到。填过（`棋盘[k]≠0`）后 accept 条件失效 → 停止写入。

> ⚠️ **开局生成必须主动避免三连**，不是「随机后靠检测再重排」——
> 重排会闪屏且无法保证收敛。左/上邻检测是 O(36) 一次成型的最佳解。

## 113. 检测与标记：行/列窗口扫描 + 掩码

检测分两步：**扫描标记**（不动棋盘）和**消除**（清掉被标记的）。
先用 `掩码` 列表标记本回合所有「三连同色」格，再统一消除，避免「边消边扫」错位。

### 行扫描：c1 从 1..4，窗口 [c1, c1+1, c1+2]

```text
repv(r1, 1..6,
  repv(c1, 1..4,
    if ( 棋盘[idx(r1,c1)]   == 棋盘[idx(r1,c1)+1]
       and 棋盘[idx(r1,c1)] == 棋盘[idx(r1,c1)+2]
       and 棋盘[idx(r1,c1)] != 0 )                # 防误消空格
         replace(掩码, idx(r1,c1),   1)
         replace(掩码, idx(r1,c1)+1, 1)
         replace(掩码, idx(r1,c1)+2, 1)
  )
)
```

### 列扫描：r1 从 1..4，窗口 [k, k+6, k+12]（每向下一行 +6 序号）

```text
repv(c1, 1..6,
  repv(r1, 1..4,
    if ( 棋盘[idx(r1,c1)]   == 棋盘[idx(r1,c1)+6]
       and 棋盘[idx(r1,c1)] == 棋盘[idx(r1,c1)+12]
       and 棋盘[idx(r1,c1)] != 0 )
         replace(掩码, idx(r1,c1),   1)
         replace(掩码, idx(r1,c1)+6, 1)
         replace(掩码, idx(r1,c1)+12, 1)
  )
)
```

> **`and` 只有 2 个输入**（见第七册 §82）：3 个及以上要嵌套成 `and[ a, and[b,c] ]`，
> 否则第 3 项起被静默丢弃，扫描会漏判。

### 消除（用 `ife`，条件为真时两段一起跑）

```text
本轮消除 = 0
repv(k, 1..36,
  if ( 掩码[k] == 1 )                 # ife 无 else：条件真时下面两句都执行
     替换(棋盘, k, 0)                  # 清空格子
     本轮消除 = 本轮消除 + 1           # 计数（=被消除的格子数）
)
```

> 注意这里的 `ife(cond, A, B)` **没有 else 分支**——`A` 和 `B` 都在「条件为真」时执行，
> 所以 `本轮消除` 正好等于「被消除的格子数」（一次横/纵三连 = 3）。
> 若要「真做一件事、假做另一件」，用 `if_else`（`do` + `else` 两个列表）。

## 114. 消除 + 下落补充 + 计分

### 计分（消除越多奖励越高，鼓励连锁）

```text
分数 = 分数 + 本轮消除 × 10
分数 = 分数 + 本轮消除 × 本轮消除      # 连锁奖励：4 连比 3 连多得很多
```

### 下落补充：列重力（⚠️ 只在「本轮消除 > 0」时执行）

逐列从底到顶收集非零水果进 `列缓存`，再从底部回填，顶部补随机——这就是「重力下落」。

```text
if ( 本轮消除 > 0 )                      # ★ 没有消除时绝不能跑这段（见 §115.1）
  repv(c1, 1..6,
    cnt = 0
    # 从底(r1=5)到顶(r1=0)扫描：非零格子存进 列缓存[1..cnt]，遇到 0 才让 cnt 自增
    r1 = 6
    rep(6,
      r1 = r1 - 1
      if ( 棋盘[idx0(r1,c1)] != 0 )
          替换(列缓存, cnt+1, 棋盘[idx0(r1,c1)])   # ★ 1-based：cnt+1（见 §115.3）
      else
          cnt = cnt + 1
    )
    # 回填：底部 p=0 对应 列缓存[1]，p < cnt 用缓存，否则补随机
    r1 = 6
    rep(6,
      r1 = r1 - 1
      if ( (5 - r1) < cnt )
          替换(棋盘, idx0(r1,c1), 列缓存[(5-r1)+1])
      else
          替换(棋盘, idx0(r1,c1), random(1, 4))
    )
  )
```

> **连锁（combo）**：掉落后可能又排成三连。把整个「检测并消除」包进
> `repeat until 本轮消除 == 0`（或 `repeat N`）即可做多段连锁，每段都会再计分。

### 垃圾回收 / 无解判定（可选）

- 实时扫描「是否还存在任意可消除交换」：没有则 `broadcast[洗牌]` 重排棋盘；
- 限时/限步模式：`步数` 到 0 或 `timer` 超时 → `broadcast[结算]`。

## ★ 115. 四个致命坑（实测复现过，不是理论）

### 115.1 下落只在「有消除」时才跑 —— 否则全盘随机重填，破坏「交换换回」

这是三消最容易翻车的坑。`检测并消除` 末尾的下落块**必须**用 `if (本轮消除 > 0)` 包住。

原因：无匹配交换时 `本轮消除 == 0`，此时 36 格全部非零 → 下落收集阶段 `cnt` 恒为 0
（只有遇到空格才 `cnt+1`，但没有空格）→ 回填分支 `(5-r1) < cnt` 永远为假 →
**整盘被 `random(1,4)` 重新填满**。这会把「交换无效→应换回」的棋盘彻底洗掉，
表现就是：你点两个不相邻的格子交换，棋盘突然全变、分数乱跳。

✅ 正确做法：下落整段 `ife(gt(var 本轮消除, 0), [下落块])`。
无消除时棋盘原样保留，交换前的「换回」逻辑才能正确复原。

### 115.2 算术里裸变量名会被当成字面量字符串

`add/sub/mul/div` 的操作数如果直接写字符串 `"r1"`，构建器会把它编码成
字面量（等价 `[1,[4,"r1"]]`），运行时读到的不是变量值而是字符串 `"r1"` →
坐标算错、列表读到垃圾、扫描全部落空。

❌ `{ "subtract": ["r1", 1] }`  → 静默得到字符串 "r1"
✅ `{ "subtract": [ { "var": "r1" }, 1 ] }`  → 真正的变量引用

`deploy-tools/gen_match3.py` 里的 `_v(x)` 助手已统一包裹；手写 IR 时务必用 `{"var": 名}`。
（`build_sb3.py` 也已加安全网：数字输入里若字符串恰是已知变量名，会自动转引用。）

### 115.3 Scratch 列表 1-based，索引 0 会绕到最后一项

下落收集写 `列缓存[0]` 时，Scratch 把 0 当成「倒数第一格」→
原本 `[a, b, c]` 存进去会变成 `[b, c, a]`（循环右移一格），整列错位。

✅ 收集一律用 **1-based**：`列缓存[cnt+1]`（cnt 从 0 起，+1 落在 1..6）。
向量/索引换算同理，凡涉及列表下标都先确认是不是从 1 数。

### 115.4 开局必须主动避免三连（呼应 §112）

纯随机 36 格必有天然三连。若靠「生成后再检测重排」，要么闪烁、要么无法保证收敛。
**逐格左/上邻检测**是唯一 O(36) 一次成型的正确解（见 §112）。

### 变体与扩展

| 玩法 | 改法 |
| --- | --- |
| **四消 / 五消** | 窗口改成 4 连 / 5 连；可给更长连击更高奖励 |
| **相邻交换判定** | `相邻(a,b)` = 行差+列差==1（用 `floor/mod` 拆序号），非相邻不交换 |
| **连锁 combo** | 把「检测并消除」包进 `repeat until 本轮消除==0`，每段再计分 |
| **限时 / 限步** | `步数` 到 0 或 `timer` 超时 → 结算；超时与交换共用同一把锁防重复触发 |
| **六边形 / 异形棋盘** | 棋盘改一维列表 + 邻居表（平行列表存每格的相邻序号）；扫描按邻居表走 |
| **特殊水果** | 炸弹（消整行/列）、万能（任意色）、同色爆炸；消除时特判该格值 |
| **无解洗牌** | 实时检测是否还存在可消除交换，没有则重排棋盘（注意仍要满足 §115.4） |

> 无论哪种变体，**§115.1 的 `本轮消除>0` 守卫**和 **§115.2 的变量引用**都适用。

```bash
python scripts/build_sb3.py --ir examples/match3.yaml --out examples/output/match3.sb3 --workdir /tmp/m3build
python scripts/validate_sb3.py --sb3 examples/output/match3.sb3      # 四层
node scripts/match3_behavior_check.mjs examples/output/match3.sb3      # MATCH3_LOGIC_OK
```

`match3_behavior_check.mjs` 会真实模拟「绿旗生成 → 检查满盘/无初始三连/36克隆 →
构造横向三连消除并计分 → 构造纵向三连消除 → 无匹配交换验证棋盘完好换回」，
断言：棋盘满盘、无初始三连、克隆数 36、横/纵三连可消除且 `本轮消除≥3` `分数≥30`、
消除后无空洞、**无匹配交换后棋盘逐格复原不损坏**。

**只过四层校验不算三消作品完成**——`检测→消除→下落` 的核心逻辑必须靠行为校验实跑验证。
