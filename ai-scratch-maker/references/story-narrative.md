## §148 总览与数据模型：对话即「平行列表」

剧情不是把文字硬写进脚本，而是**数据驱动**：把每段剧情做成一个「节点」，用一组**平行列表**描述整张剧情图。
改剧情只改列表，不改逻辑——这是和 §106 答题「平行列表题库」、§142 棋盘「一维列表」同源的思想。

| 列表 | 含义 | 例（6 节点） |
|---|---|---|
| `节点文本` | 该节点显示的文字 | `["你醒来在神秘森林。","精灵：你要往哪走？","左边有一只宝箱！","右边有一只怪物……","【结局一：获得宝藏】","【结局二：险胜怪物】"]` |
| `节点类型` | `0`=对话自动推进 / `1`=需要选择 / `2`=结局 | `[0,1,0,0,2,2]` |
| `自动下一` | 类型 0 时，看完后跳到哪个节点（1-based；无则 0） | `[2,0,5,6,0,0]` |
| `选项A文本`/`选项B文本` | 类型 1 时两个选项的按钮文字（无则 `""`） | `["","向左走","","","",""]` / `["","向右走","","","",""]` |
| `选项A跳转`/`选项B跳转` | 选 A / 选 B 后跳到哪个节点 | `[0,3,0,0,0,0]` / `[0,4,0,0,0,0]` |
| `结局值` | 类型 2 时，这是第几个结局（用于统计） | `[0,0,0,0,1,2]` |

运行时只维护一个 `当前节点` 变量（1-based），所有显示 / 跳转都从列表里读——**这样加一段剧情 = 在六个列表里各加一行，逻辑脚本一行不用动**。

> ⚠️ 列表在 builder 里是「变量存数组」（见 §120.3）：`ITEM(节点文本, 当前节点)` 直接读数组元素，
> 行为校验里要从 `target.variables` 读、按「1-based − 1」换算。别用 `length_of_list`（那是原生列表，这里读不到）。

## §149 打字机逐字显示：REPEAT_UNTIL + letter_of + join

文字要**一个字一个字蹦出来**，不能 `说` 一整段。核心是一个「按字符位置拼接」的循环：

```
SET 显示文本, ""
SET 打字进度, 0
REPEAT_UNTIL( 打字进度 == length_of(当前文本) ):
    显示文本 = join(显示文本, letter_of(打字进度 + 1, 当前文本))   # 取第 (进度+1) 个字接在末尾
    打字进度 += 1
    wait 0.02                                                      # 节流，否则一帧蹦完
```

- `letter_of(n, s)` 取字符串第 `n` 个字符（n 从 1 开始）；
- `join(a, b)` 把新字接到 `显示文本` 后面；
- 循环条件用 **`REPEAT_UNTIL(进度 == 长度)`**，千万别用 `REPEAT(固定次数)`——一旦某段文字改长改短，固定次数就错位（致命坑 ②）。
- 无头逐步推进时 `wait 0.02` 让每步恰好跑一次循环体（同 §141 节流）。

> 把 `当收到 [演节点]` 做成主驱动：每到一个节点先 `SET 当前文本 = ITEM(节点文本, 当前节点)`，再跑上面这段打字机，
> 打完按 `节点类型` 分流（见 §150 / §152）。`演节点` 之间用广播串联：处理完一个节点末尾 `broadcast(演节点)`，由下一段接管。

## §150 分支选择 → 节点跳转

类型 1 的节点需要玩家**二选一**，每个选项是一个独立广播，改写 `当前节点` 后重播：

```
当收到 [选A]:  IF(待选择 == 1): 待选择 = 0; 当前节点 = ITEM(选项A跳转, 当前节点); broadcast(演节点)
当收到 [选B]:  IF(待选择 == 1): 待选择 = 0; 当前节点 = ITEM(选项B跳转, 当前节点); broadcast(演节点)
当收到 [推进]: IF(待推进 == 1): 待推进 = 0; 当前节点 = ITEM(自动下一, 当前节点); broadcast(演节点)
```

- `待选择` / `待推进` 是**守卫标志**：只有打字机打完、进入等待态才置 1，避免玩家狂点连跳好几个节点（同铁律 11 的私有标志位思路）。
- 跳转目标全在列表里，**逻辑脚本不写死任何节点号**——改剧情只动列表。

## §151 选项菜单用「按钮」而非「询问」积木（呼应铁律 11）

选项**绝不能用 `询问` 积木**：它会阻塞整个脚本、弹出的输入框样式不可控、手机端还容易和键盘冲突。
正确做法：**每个选项一个角色按钮**，点击按钮 `broadcast(选A)` / `broadcast(选B)`（按钮造型用 `assets/btnA.svg` / `btnB.svg`）：

```
当收到 [演节点]:
    ...打字机...
    IF(ITEM(节点类型, 当前节点) == 1):
        待选择 = 1
        broadcast(显示选项)          # 让两个按钮角色显形
    ...
# 按钮角色 选项A：
当收到 [显示选项]: show
当角色被点击: broadcast(选A)
```

> 这是铁律 11「选项菜单不用『询问』积木」在叙事里的直接应用。按钮还能做悬停高亮、音效反馈，体验甩 `询问` 十条街。

## §152 多结局与结局统计

类型 2 的节点就是结局。到达时**给结局赋值 + 计数器 +1**，并放开对话锁：

```
当收到 [演节点]:
    ...
    IF(ITEM(节点类型, 当前节点) == 2):
        结局 = ITEM(结局值, 当前节点)
        IF(  结局 == 1): 结局1计数 += 1
        IF(  结局 == 2): 结局2计数 += 1
        对话中 = 0                       # 放开「对话锁」（见 §154）
        broadcast(结算)                  # 进结算页（呼应 §147 返回按钮）
```

- **每个结局都必须能从某个分支真正到达**（致命坑 ③）：写完剧情务必走一遍每条路，确认 `结局1` / `结局2` 都能触发，
  别留「永远点不到」的死支（玩家会以为游戏卡死）。
- 计数器可存档到云变量（呼应 §23），做「已解锁结局收集」。

## §153 flag / 好感度系统影响分支

想让同一段对话因玩家之前的选择而不同？用**变量当 flag**：

```
# 选 A 时记下「救过精灵」
当收到 [选A]:  IF(待选择==1): ...; IF(当前节点==7): 好感 += 1

# 后面某节点按 flag 走不同分支
IF(好感 >= 3): 当前节点 = 12 ELSE 当前节点 = 13     # 用 IFELSE 真正二选一
```

- flag 用普通变量即可；要跨局保留（养成感）就存云变量（§23）。
- 多条 flag 组合判定时，用 `ANDn(...)` / `ORn(...)` 嵌套（Scratch 的 `and`/`or` 只有 2 个输入）。
- ⚠️ 「命中→走这条 / 否则→走那条」是**真 if-else**，必须用 `IFELSE`（我们的 `ir_helpers.IFELSE`），
  写成 `IF(cond, A, B)` 会把 A、B 都并到 `do` 一起跑，flag 判定永远错（同 §145 陷阱）。

## §154 立绘 / 背景切换与「对话锁」

- **立绘**：说话人切换就 `switch costume` 换造型；多个角色同台时各自一个 sprite，按 `当前节点` 决定谁显形。
- **背景**：场景切换用 `switch backdrop`（注意铁律：「一局开始要复位」的东西挂 `[重置]` 广播，不挂绿旗，见铁律 6）。
- **对话锁（最重要）**：对话进行中玩家**不能自由移动 / 操作世界**，否则会穿帮。用 `对话中` 标志位锁住：

```
# 玩家移动（被对话锁挡住）
当收到 [移动]: IF(对话中 == 0): change_x(10)     # 对话中=1 时按了也没用
```

行为校验会验证：对话进行中（`对话中==1`）发 `[移动]` 玩家不动；结局后（`对话中==0`）发 `[移动]` 才真的移动。
这就是「演出时锁操作」的硬标准——§28 / §64 提到的「对话期间要能跳过与锁操作」在此落地。

## §155 五个致命坑

1. **用「询问」积木做选项**：阻塞脚本、样式失控、手机端冲突 → 改用按钮角色广播（§151 / 铁律 11）。
2. **打字机用 `REPEAT(固定次数)`**：文字一改长就漏字、一改短就多等 → 必须用 `REPEAT_UNTIL(进度==长度)`（§149）。
3. **多结局有死支**：某结局永远点不到，玩家以为卡死 → 写完逐条分支走一遍，确认每个结局都能到达（§152）。
4. **对话期间不锁操作**：玩家在对话里乱走、乱点，世界穿帮 → 用 `对话中` 标志位挡住移动 / 交互（§154）。
5. **跳转目标写死在逻辑里**：改剧情要改代码、极易漏改 → 所有跳转都从列表读，逻辑只认 `当前节点`（§148 / §150）。

> 自查三问（交付前必答）：① 每段文字都逐字显示了吗？② 每个结局都能从某条分支真正走到吗？③ 对话进行中玩家确实动不了吗？
