## 16. 敌人 AI：视野锥 + 巡逻 + 状态机

### 三种状态就够用
```
0 = 巡逻（沿预设路线走）
1 = 追击（发现玩家）
2 = 搜索（玩家消失了，去最后看到的位置附近找）
```
用**角色级私有变量** `AI状态` 记录。

### 视野锥判定（不是「睁眼瞎」）
只判距离 = 360° 全向感应，敌人像开了全图外挂。
真正的视野锥要**同时满足**「距离够近」和「玩家在自己正前方 ±45° 内」。

Scratch 没有「朝向某角色的角度」积木，标准做法是**借一下朝向再还原**：
```
set [原方向 v] to (direction)
point towards [玩家 v]
set [目标方向 v] to (direction)
point in direction (原方向)          ← 立刻还原朝向，别让敌人抽搐
set [方向差 v] to ((目标方向) - (原方向))
```

### ⚠️ 角度归一化（0°/360° 跳变）
方向是环形量：`359°` 和 `1°` 其实只差 2°，直接相减会得到 -358，
**必须**折算回 -180..180：
```
if <(方向差) > [180]>  then set [方向差 v] to ((方向差) - (360))
if <(方向差) < [-180]> then set [方向差 v] to ((方向差) + (360))
```
（社区也常用 `((差 + 180) mod 360) - 180` 一步到位，效果一样。）

### 巡逻点用列表，别随机走
随机走 = 没头苍蝇。用两条列表存路点，按索引循环：
```
列表 巡逻点X: [100, 200, 200, 100]
列表 巡逻点Y: [100, 100, 200, 200]
```
```
set [路点序号 v] to [1]
forever:
  go to x: (item (路点序号) of [巡逻点X v]) y: (item (路点序号) of [巡逻点Y v])
  wait until <(distance to [路点序号 v] 的点) < [10]>   ← 到点了才换下一个
  change [路点序号 v] by (1)
  if <(路点序号) > (length of [巡逻点X v])> then set [路点序号 v] to [1]
```

### 进阶：搜索状态与听觉
- **搜索状态**：玩家脱离视野后，**不要立刻回巡逻**——去「最后看到玩家的位置」附近随机徘徊 3 秒，再回巡逻。这一个细节能让敌人显得「有脑子」。
- **听觉**：玩家在身后但跑得快（或触发噪音）→ 直接切追击。
- **性能**：不要每帧都做这套数学。**每 0.1 秒检测一次视野**就够了：
  ```
  forever:
    视野检测一次
    wait [0.1] secs
  ```

### IR 写法要点 ✅
```yaml
- name: 守卫
  variables:
    AI状态: 0        # 私有变量
    原方向: 0
    目标方向: 0
    方向差: 0
    路点序号: 1
  scripts:
    - - when_green_flag_clicked:
        - set_variable: { var: AI状态, value: 0 }
      - when_receive: { message: 游戏开始 }
        - forever:
            do:
              # —— 视野锥检测 ——
              - set_variable: { var: 原方向, value: { direction: null } }
              - point_towards: { TOWARDS: 玩家 }
              - set_variable: { var: 目标方向, value: { direction: null } }
              - point_in_direction: { direction: { var: 原方向 } }     # 还原朝向
              - set_variable: { var: 方向差, value: { subtract: [ {var: 目标方向}, {var: 原方向} ] } }
              - if: { cond: { greater_than: { a: {var: 方向差}, b: 180 } },
                      do: [ { set_variable: { var: 方向差, value: { subtract: [ {var: 方向差}, 360 ] } } } ] }
              - if: { cond: { less_than: { a: {var: 方向差}, b: -180 } },
                      do: [ { set_variable: { var: 方向差, value: { add: [ {var: 方向差}, 360 ] } } } ] }
              - if:
                  cond:
                    and:
                      - less_than: { a: { mathop: { operator: abs, num: {var: 方向差} } }, b: 45 }
                      - less_than: { a: { distance_to: { object: 玩家 } }, b: 150 }
                  do:
                    - set_variable: { var: AI状态, value: 1 }
                    - set_variable: { var: 最后看到x, value: { of: { object: 玩家, property: x position } } }
                    - set_variable: { var: 最后看到y, value: { of: { object: 玩家, property: y position } } }
              # —— 按状态行动 ——
              - if: { cond: { equals: { a: {var: AI状态}, b: 1 } },
                      do: [ { point_towards: { TOWARDS: 玩家 } }, { move_steps: 3 } ] }
              - wait: 0.1
```

## 17. 平台跳跃物理（一条规则一个循环）

### 核心原则：**一个 forever 只管一条规则**
把「重力」「地面检测」「跳跃」「水平移动」拆成**四个独立的 forever**，
不要塞进一个大积木堆。一旦跳起来飘、落地判定乱，你一眼就能看出是哪条规则错了。
（对比 §1 的做法：每个规则一个脚本，而不是一个大 if-else。）

| 规则 | 脚本 |
|---|---|
| 水平移动 | 按键 → 改 x 速度 → 限速 → 摩擦 → 改 x |
| 重力 | 不在地面 → vy += 重力 → 限速 → 改 y |
| 地面检测 | 脚下感应点碰到地面/颜色 → grounded = true，vy = 0，y 上移 1 像素 |
| 跳跃 | 按跳跃键 且 grounded → vy = -跳跃冲量 |

### ⚠️ 地面检测必须用「脚下的点」，不能用整个造型
用 `touching [地面]?` 判断**整个角色**，角色的头发/尾巴像素也会被算进去 →
角色会「浮」在平台上。正确做法：
- 在角色**脚下**放一个很小的感应点角色（1×1 像素），只让它检测；
- 或者用 `touching color? [地面色]?`（颜色法天然只看接触面）。

### ⚠️ 站在地面上时不要施加重力
否则 vy 每帧累加，角色会**在地板上抖动**。标准写法：
```
if <not <在地面上?>> then
  change [vy v] by (重力)
end
```

### 郊狼时间（Coyote Time）—— 手感提升最大的一招
玩家刚走出平台边缘的那几帧，仍然允许按跳跃。哪怕只给 5 帧，
「我明明按了跳跃却没跳」的不满感就消失了。
```
if <在地面上?> then
  set [郊狼计时 v] to [5]          # 在地面上就刷新宽限
else
  change [郊狼计时 v] by (-1)
end
if <and <(按下跳跃键?)> <(郊狼计时) > [0]>> then
  set [vy v] to (跳跃冲量)
  set [郊狼计时 v] to [0]
end
```

### 跳跃缓冲（Jump Buffer）
落地前一点点按了跳跃，落地那一刻应该立刻起跳。
```
if <按下跳跃键?> then set [跳跃缓冲 v] to [6] else change [跳跃缓冲 v] by (-1) end
if <and <(在地面上?)> <(跳跃缓冲) > [0]>> then
  set [vy v] to (跳跃冲量)
  set [跳跃缓冲 v] to [0]
end
```

### 其它要点
- **终端速度**：长距离下落时限制最大下落速度，否则掉太快看不清。
- **落地吸附**：碰到地面时把 y 往上挪 1 像素，防止造型陷进地里。
- **斜坡**：先水平移动，碰到地面就尝试往上爬 `|vx|+1` 像素；
  爬得上就站上去，爬不上（太陡）就水平推回、速度减半。
- **关卡用颜色标记**（经典 Scratch 平台跳跃做法）：
  黑 = 地面/墙（能站），红 = 回到起点，黄 = 到达终点 → 换下一个背景。

### IR 写法要点 ✅
```yaml
- name: 玩家
  variables:
    vx: 0
    vy: 0
    grounded: 0
    郊狼计时: 0
    跳跃缓冲: 0
  scripts:
    - - when_green_flag_clicked:
        - forever:
            do:
              # 规则 1：水平移动
              - if: { cond: { key_pressed: { key: right arrow } }, do: [ { change_variable: { var: vx, by: 1 } } ] }
              - if: { cond: { key_pressed: { key: left arrow } }, do: [ { change_variable: { var: vx, by: -1 } } ] }
              - if: { cond: { greater_than: { a: {var: vx}, b: 5 } }, do: [ { set_variable: { var: vx, value: 5 } } ] }
              - if: { cond: { less_than: { a: {var: vx}, b: -5 } }, do: [ { set_variable: { var: vx, value: -5 } } ] }
              - set_variable: { var: vx, value: { multiply: [ {var: vx}, 0.9 ] } }
              - change_x: { value: { var: vx } }
              # 规则 2：重力（只在空中）
              - if: { cond: { equals: { a: {var: grounded}, b: 0 } },
                      do: [ { change_variable: { var: vy, by: 1 } } ] }
              - if: { cond: { greater_than: { a: {var: vy}, b: 15 } }, do: [ { set_variable: { var: vy, value: 15 } } ] }
              - change_y: { value: { var: vy } }
              # 规则 3：地面检测（脚下感应点）
              - if: { cond: { touching: { object: 地面 } },
                      do: [ { set_variable: { var: grounded, value: 1 } },
                            { set_variable: { var: vy, value: 0 } },
                            { change_y: { value: 1 } } ] }
              - if: { cond: { equals: { a: {var: grounded}, b: 1 } },
                      do: [ { set_variable: { var: grounded, value: 0 } } ] }
```
> ⚠️ 注意上面「地面检测」里两个 if 的条件是互斥写法，实战中应写成
> `if <在地面> then ... else set grounded 0`。分两句写容易出现「同一帧既置 1 又置 0」的顺序坑，
> **优先用 if/else**。

## 18. 打击感（Juice）：让玩家「打到东西了」

同样一个扣血逻辑，加不加反馈，玩家的体感差一个档次。

### 受击闪白
```
将 [亮度特效 v] 设定为 (50)
将 [闪白计时 v] 设定为 (1)
forever:
  将 [闪白计时 v] 设定为 ((闪白计时) * (0.8))
  将 [亮度特效 v] 设定为 ((闪白计时) * (50))
```
- 闪白**只用在角色层**，别用在大量背景上，否则渲染压力大、容易掉帧。
- 也可以更简单：`repeat 3: change color effect by 25 / wait 0.1 / change color effect by -25`。

### 屏幕震动
舞台没有「相机」，震动要**自己偏移所有东西**：
大地图做法 = 改 `camera_x/camera_y`（见 §1），加一个 `震动量` 变量：
```
将 [震动量 v] 设定为 (8)
forever:
  将 [震动量 v] 设定为 ((震动量) * (0.85))
  将 [camera_x v] 设定为 ((目标camera) + (random (-震动量) to (震动量)))
```
小地图做法 = 临时改舞台背景的 x/y，或让所有角色整体偏移一帧。

### 放大脉冲（命中镜头一振）
```
当接收到 [命中 v]:
  将 [缩放脉冲 v] 设定为 (0.08)      # 不建议超过 0.1，否则画面像闪跳
forever:
  将 [缩放脉冲 v] 设定为 ((缩放脉冲) * (0.8))
```
- 衰减系数 0.8 → 几帧内消失，不影响下一次命中。
- 稳定区间 0.05–0.08。

### 伤害飘字
- 每次伤害创建一个**克隆**飘字角色，飘字角色用**私有变量**存自己的
  起始 y、伤害数值、存活帧数；
- 克隆体每帧 `change y by 2` + 逐渐变透明，活完 `delete this clone`。
- 数值不同的飘字用不同造型，或用数字图（见本 skill 的 `digit_display` 素材）。

### 无敌帧（挨打后短暂无敌）
```
当接收到 [受伤 v]:
  将 [无敌计时 v] 设定为 (30)      # 30 帧 ≈ 1 秒
forever:
  if <(无敌计时) > [0]> then
    将 [无敌计时 v] 设定为 ((无敌计时) - (1))
    设为半透明（ghost 50）          ← 让玩家看得出「现在无敌」
  end
```
碰撞判定处要加 `and <(无敌计时) = [0]>`，否则会**连续掉血**。

### Combo 连击
```
set [连击数 v] to (0)
当接收到 [命中 v]:
  change [连击数 v] by (1)
  将 [连击计时 v] 设定为 (60)      # 1 秒内再命中就续上
forever:
  if <(连击计时) > [0]> then
    change [连击计时 v] by (-1)
  else
    将 [连击数 v] 设定为 (0)
  end
```
分数 = 基础分 × 连击数（可设上限防爆分）。

### 视觉层级
普通敌人放底层、精英放中层、Boss 放**最上层**并加阴影 →
玩家一眼能分辨威胁等级（这是「包装」里最便宜也最有效的一条）。

### 命中停顿（Impact Frame）
命中瞬间让整个游戏**卡 2~3 帧**再继续，重击感立刻翻倍。
实现：命中时广播一个「定格」消息，全局脚本收到后 `stop` 一小段再恢复。

## 19. 网格移动（格子游戏、贪吃蛇、RPG）

### 坐标转换
设格子边长 `cell`，舞台被切成 `cols × rows`：
```
格 -> 像素：
x = (左边距) + (col - 1) * cell
y = (上边距) - (row - 1) * cell

像素 -> 格：
col = round((x - 左边距) / cell) + 1
row = round((上边距 - y) / cell) + 1
```

### 吸附到网格
```
set x to (round(x / cell) * cell)
set y to (round(y / cell) * cell)
```
> ⚠️ Scratch 的 `round` 是**四舍五入**，不是「就近取整」；
> 网格中心可能落在半格上，按格子大小微调偏移量。

### ⭐ 只在格点转向（Pac-Man 的关键）
自由移动的角色按一下键就转，格子游戏里会「卡在走廊中间」。
解决办法：**只有当角色正好在格点时才接受转向输入**。
```
if <<(x position mod cell) = [0]> and <(y position mod cell) = [0]>> then
  检查方向输入并转向
end
```
`mod` 给出除法后的余数：x=32、cell=16 → 32 mod 16 = 0 → 在格点；
x=35 → 余 3 → 在半路，继续直走。**一个判断，抖动消失。**

### 贪吃蛇：两条列表当队列
蛇身不是一堆角色，而是**两条列表**（xs / ys）存每节身体的格子坐标：
- 新的头 → `add` 到**第 1 项**（`insert at 1`）
- 尾巴 → `delete` 最后一项
- 画身体 = 遍历列表，每节 `stamp` 一次

列表当队列的三个积木：`insert at 1` / `add` / `delete last`。

### IR 写法要点 ✅
```yaml
# 格 -> 像素
- goto_xy:
    x: { add: [ -225, { multiply: [ { subtract: [ {var: col}, 1 ] }, 30 ] } ] }
    y: { subtract: [ 165, { multiply: [ { subtract: [ {var: row}, 1 ] }, 30 ] } ] }
# 只在格点转向
- if:
    cond:
      and:
        - equals: { a: { mod: { a: { x_position }, b: 30 } }, b: 0 }
        - equals: { a: { mod: { a: { y_position }, b: 30 } }, b: 0 }
    do:
      - if: { cond: { key_pressed: { key: right arrow } }, do: [ { point_in_direction: { direction: 90 } } ] }
```

## 20. 一套精灵，多种行为（克隆分身）

### 模式
画**一个**敌人精灵 → 游戏开始时克隆 N 份 → 每个克隆用**私有变量 ID**区分身份 →
同一份脚本按 ID 走不同分支。
Pac-Man 的四只鬼、太空侵略者的 55 个外星人都是这个模式。

```
Blinky 直追玩家 / Pinky 抢在玩家前方 4 格 / Inky 用 Blinky+玩家算目标 / Clyde 巡逻回家角
```
**一个精灵，四种大脑。**

### 私有变量是身份的关键
`ghost_id` 必须是**角色级私有变量**：
- 选「仅适用于此角色」→ 每个克隆各有一份，可以存不同 ID；
- 选「适用于所有角色」→ 所有克隆共享一个值，**全都变成同一个鬼**。

### 让所有克隆「同步行动」
55 个外星人要一起转向，不能每个自己判断。
用一个**全局变量** `方向`（1=右，-1=左），所有克隆都读它：
```
每个克隆：move (方向 * 2) steps
某个克隆碰到边缘 → broadcast [全体转向 v]
收到 [全体转向 v]：set 方向 to (-1)；change y by (-20)
```
> **一个克隆发现情况 → 广播 → 全体响应。** 这就是「广播」的本质用法，
> 也正是 §3 状态机 + §20 克隆的组合拳。

### 发射物 / 弹幕同理
一个「子弹」精灵 + 私有变量（角度、速度、穿透次数）+ 克隆 → 弹幕系统。

## 21. 拾取物 / 背包 / 商店经济

### 拾取物
| 方式 | 做法 | 适用 |
|---|---|---|
| 碰撞拾取 | 物品用克隆；`touching [玩家]?` → 加分 + `delete this clone` | 最标准 |
| 距离拾取 | `distance to [玩家] < 阈值` → 拾取 | 不想被角色尺寸影响判定时 |
| **磁性吸附** | 距离 < 磁力半径时，把物品**拉向玩家**：`x = 玩家x - (玩家x - x) * 磁力 / 距离` | 收集手感更好 |

### 背包 = 列表
多种物品时**不要**用一堆变量，用一条列表存数量 + 一条列表存名称映射：
```
列表 物品数量: [0, 0, 0]     # 0=金币 1=苹果 2=经验
列表 物品名称: ["金币", "苹果", "经验"]

获得苹果：replace item (item num of [苹果] in [物品名称]) of [物品数量] with (item (item num of [苹果] in [物品名称]) of [物品数量]) + 1
```
> `item num of [X] in [列表]` = 找 X 在列表里的第几项 → **名称 → 槽位**的映射，
> 这样代码里不用硬编码「第 2 格是苹果」。

### 商店
1. **商店按钮** → 切到商店背景（`switch_backdrop`），隐藏游戏角色；
2. **购买按钮**（每个商品一个）：
   ```
   当角色被点击:
     if <(金币) >= (价格)> then
       将 [金币 v] 设定为 ((金币) - (价格))
       将 [已购买xxx v] 设定为 [1]
       播放音效
       隐藏这个按钮        ← 限购商品买完就消失
     else
       提示「金币不够」
     end
   ```
3. **按钮状态反馈**（让商店「活」起来）：
   - 买不起 → `set ghost effect to 40`（变灰）
   - 买得起 → `set ghost effect to 0`
   - 鼠标悬停 → `set brightness effect to 15`（变亮），移开 → 0
   （悬停高亮是让菜单「像菜单」的最便宜一招。）
4. **买到的道具要真的影响游戏**：
   `if <已购买加速> then 移动步数 = 30 else 移动步数 = 15`
   —— 不影响玩法的道具，玩家不会觉得钱花得值。

### 回合制战斗（RPG）
- 切背景进战斗场景 → 广播「进入战斗」；
- `玩家回合` 变量交替：玩家选动作（A 攻击 / D 防御 / H 治疗）→ 敌人回合；
- 敌人行动用随机数决定 → 每场战斗不一样；
- 双方 HP 归零 → 战斗结束，广播回地图。

## 22. 随机生成（迷宫 / 随机关卡）

### 递归回溯（DFS）生成迷宫
经典算法：从一个格子出发，随机挑一个没访问过的邻居，**打通中间的墙**并走过去；
没有未访问邻居了就**回溯**到上一个还有路可走的格子。

### Scratch 里的三个工程难点
1. **没有递归局部变量** → 用**列表当栈**（push/pop 自己实现）。
   社区做法：把 `(x,y,dir)` 拼成一个字符串塞进 `stack` 列表。
2. **坐标 ↔ 列表索引**：
   ```
   index = x + (y - 1) * size
   x = ((index - 1) mod size) + 1
   y = floor((index - 1) / size) + 1
   ```
3. **递归爆栈** → **深度熔断**：
   ```
   if <(调用深度) > [40]> then 停止 [全部 v]
   ```
   每次递归前 `call_depth += 1`，返回后 `-= 1`。

### 绘制
用**画笔扩展**：先铺黑底（画一个大方块），算法每打通一格就 `stamp` 一个白色格子。
生成过程本身就是一段好看的动画。

### 性能与可视化节流
- 网格 ≤ 12×12：每步 `wait 0.02` 实时展示生成过程；
- 更大：每 10 格 `wait 0.1` + 更新进度条，别让浏览器卡死。
- **可视化节流**是随机生成类作品的生死线。

### 其它随机玩法
- **随机房间 + 走廊**：随机放几个矩形房间，再用 L 形走廊相连 → 地牢。
- **随机道具分布**：用 `safe_spawn`（本 skill 内置）避开玩家出生点。

## 23. 存档、进度与云变量

### Scratch 的存档能力（先认清限制）
| 方式 | 能存什么 | 限制 |
|---|---|---|
| 普通变量 | 只在本次运行内 | 关掉就没了 |
| **云变量** | 存在服务器，跨会话、跨设备 | **最多 10 个**；只能存**数字**；更新频率受限；离线编辑器不可用 |

### 云变量存进度
- 最高分、已解锁关卡、金币数、最后到达的关卡编号 → 都是数字，完美适配。
- **不要在快速循环里更新云变量**：更新太频繁会被服务器丢连接。
  只在「关卡结束」「购买成功」这类**离散时刻**写一次。
- 用 `if <(云分数) > (最高分)> then 设定 [☁最高分] 为 (分数)`。

### 检查点 / 自动存档
```
当接收到 [到达检查点 v]:
  将 [☁当前关卡 v] 设定为 (当前关卡)
  将 [☁生命值 v] 设定为 (生命值)
```
游戏开始时读回来：
```
将 [生命值 v] 设定为 (☁生命值)
如果 <(☁当前关卡) = [0]> then 设为新游戏 else 从第 (☁当前关卡) 关继续
```

### 排行榜
- 云变量只能存一个数 → 多人排行榜要**编码**成一个大数：
  `编码 = 分数 * 1000000 + 用户序号`，读取时 `分数 = floor(编码 / 1000000)`。
- 云数据日志在 Scratch 网站的「云数据」页面可查看，作品作者可以清日志。

### ⚠️ 别用代码「防止别人改你的作品」
这违反 Scratch 社区规范（详见 `advanced-techniques.md` §6）。想做存档就用云变量，
想做归属就署名 + 致谢。

## 25. 数学工具箱

### 向量运算
```
dx = 目标x - 自身x
dy = 目标y - 自身y
长度 = sqrt(dx*dx + dy*dy)
单位向量 = (dx / 长度, dy / 长度)
```
> ⚠️ 长度可能为 0（两者重合）→ **必须夹紧**：`if <长度 < 1> then 设为 1`。
> 除以 0 会得到 `Infinity`，Scratch 里会让坐标变成 NaN，角色直接消失。

### 角度归一化（见 §16）
```
((角 + 180) mod 360) - 180
```

### 缓动函数
| 曲线 | 公式（t 是 0→1 的进度） | 感觉 |
|---|---|---|
| 线性 | `t` | 机械 |
| ease-in | `t*t` | 起步慢 |
| ease-out | `1-(1-t)*(1-t)` | 收尾慢 |
| ease-in-out | `t<.5 ? 2t² : 1-2(1-t)²` | 两头慢（最常用） |
| 弹性 | `1 - 2^(-10t) * cos(...)` | 弹跳感 |

### 洗牌
Fisher-Yates：
```
repeat (列表长度 - 1):
  i = random 1 to 列表长度
  交换 列表[i] 与 列表[random 1 to 列表长度]
```
做抽卡、洗牌、地牢房间顺序都靠它。

### 随机范围与去重
- **不要用「不断随机直到不重复」来生成不重复的数**——可能死循环。
  正确做法：**洗牌**（Fisher-Yates）或「用列表记录已用过的值」。

### IR 写法要点 ✅
```yaml
# 单位向量（带长度夹紧）
- set_variable: { var: dx, value: { subtract: [ {var: 目标x}, {var: 自身x} ] } }
- set_variable: { var: dy, value: { subtract: [ {var: 目标y}, {var: 自身y} ] } }
- set_variable:
    var: len
    value: { mathop: { operator: sqrt, num: { add: [ { multiply: [ {var: dx}, {var: dx} ] },
                                                { multiply: [ {var: dy}, {var: dy} ] } ] } } }
- if: { cond: { less_than: { a: {var: len}, b: 1 } }, do: [ { set_variable: { var: len, value: 1 } } ] }
- set_variable: { var: 单位x, value: { divide: [ {var: dx}, {var: len} ] } }
```

## 26. UI 拖拽与滑块（音量条 / 难度条）

### 通用做法：一个「滑块把手」角色 + 拖拽逻辑
```
当绿旗被点击:
  将 [把手最小x v] 设定为 (-140)
  将 [把手最大x v] 设定为 (140)

当角色被点击:
  重复执行:
    将 [把手 x v] 设定为 (x position)
    将 [把手 y v] 设定为 (y position)
    等待 0.02 秒
```
「当角色被点击」触发后，脚本会**持续运行**直到用户停止点击 —— 这就是 Scratch 里
实现「按住拖动」的标准技巧（点击是按住的语义）。

### 把手位置 → 数值
```
进度 = ((把手x - 最小x) / (最大x - 最小x))     # 0~1
数值 = 最小值 + 进度 * (最大值 - 最小值)
```
音量：`set volume to (数值)`；难度：直接喂给游戏的速度/血量/敌人数量参数。

### 轨道
画一条细长矩形当轨道，把把手放在轨道上面。
**轨道两端要有「挡板」**（或把把手的 x 夹紧在最小/最大之间），否则能拖出轨道。

### 悬停与选中反馈
- 鼠标悬停 → `set brightness effect to 15`（变亮）；
- 当前选中项 → 换成高亮造型 + 其余项 `ghost 40`；
- 买不起的项 → `ghost 40`（见 §21 商店）。

### 自定义积木封装
把「把位置换算成数值」写成一个自定义积木（`procedure`），
多个滑块复用同一套逻辑，改一处就全改。

## 27. 敌人波次与难度曲线（Waves）

### 波次数据结构
```
列表 波次数量: [3, 5, 8, 12]        # 第 1~4 波各有几个敌人
列表 波次间隔: [60, 50, 40, 30]     # 每波之间隔多少帧
变量 当前波次: 0
```

### 主循环
```
当绿旗被点击:
  重复执行直到 <(当前波次) > (length of [波次数量])>:
    重复执行 (item (当前波次) of [波次数量]) 次:
      生成一个敌人克隆
      等待 (item (当前波次) of [波次间隔)) 除以 (当前波次) 秒     ← 波内递减，压迫感递增
    等待 2 秒          ← 波与波之间的喘息
    将 [当前波次 v] 设定为 ((当前波次) + (1))
  广播 [全部清空 v]
```

### 难度曲线（比线性更有手感）
| 曲线 | 做法 | 感觉 |
|---|---|---|
| 线性 | 难度 = 波次 | 平庸 |
| 加速 | 难度 = 波次²/ 系数 | 后段压力陡增 |
| 台阶 | 每 3 波一个大台阶，中间缓升 | 有节奏的高潮 |
| 递减间隔 | 敌人间隔随波次缩短 | 最省代码，上手最快 |

### 「喘息」设计（社区经验）
- 一波清空后给 **1~2 秒**的喘息，再出下一波；
- 波内最后 1~2 个敌人**给点缓冲**（间隔加倍），玩家能喘口气收尾；
- 连续高压超过 20 秒，玩家会流失。

## 28. 分支对话 / 剧情树

### 数据驱动：一条列表存「节点」
```
列表 对话节点:
  "你好|1|欢迎来到村庄"
  "1|2|你叫王铁锤吗"
  "2|3|正是|你最近还好吗"
  ...
```
用 `|` 分隔字段，运行时用 `split` 拆分（Scratch 3 没有 split，
可用「一个个字符找 `|`」的方式切，或干脆**用多条列表**并行存字段）。

### 更简单的做法：状态 + 广播
```
玩家选择: 0 / 1 / 2

当收到 [说第一句 v]:
  chat_say 第 1 句
  等待玩家按键 a 或 b
  如果 <(按键 a)> 那么
    广播 [分支 A v]
  否则
    广播 [分支 B v]
  end

当收到 [分支 A v]:
  chat_say 第 3 句
  广播 [继续主线 v]
```

### 注意事项
- **对话要能被打断**：玩家点「跳过」直接跳到下一节点（用 `game_state` 或 `对话中` 标志控制）。
- **对话期间锁操作**：`对话中 = 1` 时忽略移动输入（见本 skill 猫抓老鼠的 `面板开` 冻结写法）。
- **文字别用「说」气泡**（本 skill 铁律）：用自制聊天框角色。
- 分支变量要**存档**（云变量），否则刷新后玩家得重选。

列表 成就ID: ["首杀", "十连击", "零受伤"]
列表 成就名: ["首次捕获", "十连捕获", "毫发无损"]

## 30. 网格解谜与推箱子

### 地图 = 一条列表
整张地图存进**一条列表**，索引公式：
```
index = (y - 1) * 列数 + x
反查： x = ((index - 1) mod 列数) + 1
      y = floor((index - 1) / 列数) + 1
```
每格存一个**数字**代表内容（社区通行约定）：
| 值 | 含义 |
|---|---|
| 0 | 空地 |
| 1 | 箱子 |
| 2 | 墙 |
| -1 | 目标点（旗子） |

> 好处：地图**数据与表现分离** —— 同一张地图可以换不同美术，
> 加新关卡只要往列表里塞数字，不用重画图。

### 推箱子的判定（核心）
玩家要往右走时：
1. 看**右边那格**是啥；
2. 若是箱子（1）→ 再看**右边第二格**是不是空地/目标点（0 或 -1）；
3. 两个条件都满足 → 箱子前移一格、玩家前进一格；
4. 否则玩家不动（箱子也不动）。

```
如果 <(右边格) = [1]> 那么
  如果 <(右边第二格) = [0]> 或 <(右边第二格) = [-1]> 那么
    将 [右边第二格 v] 设定为 (1)      ← 箱子挪过去
    将 [右边格 v] 设定为 (0)          ← 箱子原来的位置清空
    玩家前进一格
  end
end
如果 <(右边格) = [0]> 或 <(右边格) = [-1]> 那么
  玩家前进一格
end
```
> ⚠️ 顺序很重要：**先挪箱子再挪玩家**，否则会用到被覆盖的格子值。

### 胜利判定
遍历所有格，数「箱子数」和「箱子在目标点数」是否相等：
```
箱子数 = 0；就位数 = 0
重复执行 (格子总数) 次:
  如果 <(第 i 格) = [1]> 那么 箱子数 += 1
  如果 <(第 i 格) = [-1]> 那么 就位数 += 1
如果 <箱子数> = <就位数> 那么 广播 [胜利 v]
```
（进阶：目标点单独存一条列表，箱子压上去时把目标点标记清掉。）

### 机关全家桶（Scratch Day 工作坊经典组合）
| 机关 | 做法 |
|---|---|
| **陷阱** | 玩家碰到红色 → 回到起点（`碰到颜色?`） |
| **开关 + 门** | 玩家碰到开关 → `broadcast [开开关一]`；门收到后 `glide` 打开。**用 `wait until` 确保开关只触发一次** |
| **钥匙 + 门** | 钥匙加入背包列表；门每帧检查「背包里有对应钥匙吗」→ 有就 `hide` |
| **传送门** | 碰到 A 门 → 定位到 B 门位置；**必须用 `wait until` 离开**，否则会卡在两个门之间反复传送 |

### IR 写法要点 ✅
```yaml
# 读格子：index = (y-1)*列数 + x
- set_variable:
    var: idx
    value: { add: [ { multiply: [ { subtract: [ {var: 行}, 1 ] }, {var: 列数} ] }, {var: 列} ] }
- set_variable: { var: 格值, value: { item_of_list: { index: { var: idx }, list: 地图 } } }
```

## 31. 多人游戏与云变量同步

> ⚠️ 先认清官方限制，再决定要不要做。

### 云变量的硬限制（Scratch Wiki）
| 限制 | 数值 |
|---|---|
| 每个作品最多 | **10 个**云变量 |
| 只能存 | **数字**（不能存文字/符号） |
| 每个变量长度 | 256 字符 |
| 更新频率 | **每秒最多 10 次** |
| 谁能用 | 必须是 **Scratcher**（完整账号），且用**在线编辑器** |
| 离线编辑器 | **完全不可用** |

### 官方明确不适合的玩法
- ❌ **聊天室**：官方禁止云聊天项目（除非只能用预制句子/表情）。
- ❌ **实时动作游戏**（MMO、实时射击）：延迟不可控。
- ✅ **适合**：最高分排行榜、投票/问卷、**回合制**游戏、简单多人同步。

### 位置同步（最经典的双人写法）
```
云变量：☁P1X  ☁P1Y  ☁P2X  ☁P2Y  ☁P1在线  ☁P2在线

本机：把自己的位置写进云变量
  将 [☁P1X v] 设定为 ((我的x) + (250))     ← +250 保证是正数（云变量不能存负数？实际可存，但编码时更省事）
  将 [☁P1Y v] 设定为 ((我的y) + (250))
对方：读云变量还原位置
  将 [对方x v] 设定为 ((☁P2X) - (250))
```
- **不要每帧都写云变量**：每秒 10 次上限，超了会被服务器丢连接。
  → **每 0.2 秒写一次**（约 5 次/秒）就够顺滑。
- **角色 ID**：用 `sensing_userid`（用户 ID）区分自己是谁；
  或用「先到者为 1 号」的握手逻辑。

### 同步变量 vs 事件（游戏 networking 的经典划分）
| 类型 | 内容 | 可靠性 |
|---|---|---|
| **同步变量**（不可靠） | 位置、朝向、血条 | 丢一包没关系，下一包就追上来了 |
| **事件**（可靠） | 聊天、拾取、开火、得分 | 必须送达，且不能重复 |

Scratch 没有「发事件」积木，**事件系统要自己做**：
1. 发送方把事件追加到云变量后面（带一个随机 ID，避免与旧事件混淆）；
2. 接收方检测到云变量尾部变了 → 读取并执行 → 用「已读 ID」确认；
3. 发送方看到确认 ID 后才发下一个。

### 建议
如果作品要支持多人，**先做回合制**（轮到你才动），再考虑实时同步。
实时同步的延迟会让「手感」比单机差很多，容易被误解成 bug。

### IR 写法要点 ✅
```yaml
# 云变量声明
stage.variables:
  玩家1x: { value: 0, cloud: true }
  玩家1y: { value: 0, cloud: true }
# 写入（每 0.2 秒一次，不要每帧）
- set_variable: { var: 玩家1x, value: { add: [ { x_position }, 250 ] } }
# 计时器归零（做节拍基准用）
- reset_timer: null
```

## 32. 角色动画与动作质感

### 走路动画 = 换造型 + 等待
```
forever:
  next costume
  wait (0.15) secs
```
### ⚠️ 三个必踩的坑
1. **`next costume` 会在别人加造型后静默崩坏**。
   有人往造型列表里加了第 6 张（一个站立姿势），循环就会把它也播进去。
   → **改用命名造型 + `repeat` 里 `switch costume`**，把站立姿势放在列表末尾。
2. **造型中心（rotation center）要对齐**。
   每张造型的中心默认是各自外接框中心，帧之间会「跳」。
   → **复制上一张造型再改**，而不是重新画；或手动把旋转中心设成同一点。
3. **步长必须匹配等待时间**。
   每 0.05 秒换造型、但每次走 20 步 → 脚在原地、身体在飞 → **看起来像滑冰**。
   → 数值要「改一个、试一次」地调。

### 挤压与拉伸（Squash & Stretch）
| 时刻 | 做法 |
|---|---|
| 下落 | 纵向拉长（size y ↑） |
| 着地 | 横向压扁（size x ↑、y ↓），幅度 **10%~15%** |
| 起跳预备 | 先下蹲（压扁）再拉伸起跳 |

> 幅度超过 15% 会显得失真，宁可保守。

### 预备动作与次级动作
- **预备动作**：起跳前先下蹲、出拳前先收臂 → 反向预备让主动作更有力量。
- **次级动作**：跑步时头发飘、说话时耳朵动 → 小动作大幅提升真实感。

### 节奏变化
快动作用**少帧**（2-3 帧），慢速/重要动作**增加帧数**。
建议的走路动画参数：

| 阶段 | 等待 | 造型数 |
|---|---|---|
| 预备 | 0.3 秒 | 1~2 |
| 主要 | 0.15 秒 | 3~4 |
| 收尾 | 0.25 秒 | 1~2 |

### 待机呼吸
角色不动时也要有生命感：
```
forever:
  将 [呼吸 v] 设定为 ((呼吸) + (1))
  如果 <(呼吸) > [20]> then 将 [呼吸 v] 设定为 [0]
  将 [大小 v] 设定为 ((100) + ((呼吸) - (10)) / (10))
```

### IR 写法要点 ✅
```yaml
# 命名造型版走路循环（比 next costume 稳）
- repeat: 4
    do:
      - switch_costume: { costume: 走1 }
      - wait: 0.15
      - switch_costume: { costume: 走2 }
      - wait: 0.15
# 待机呼吸
- set_variable: { var: 大小, value: { add: [ 100, { divide: [ { subtract: [ {var: 呼吸}, 10 ] }, 10 ] } ] } }
```

## 33. 投射物、弹道与射击

### 克隆子弹（最稳的做法）
```
当绿旗被点击: 隐藏
当接收到 [开火 v]:
  create clone of [自己]
当作为克隆体启动:
  go to [玩家 v]
  point towards [准星 v]        ← 发射瞬间瞄准
  show
  play sound [激光 v]
  repeat until <碰到 [敌人 v]?> 或 <出界?>:
    move (15) steps
  if <碰到 [敌人 v]?> then broadcast [命中 v]
  delete this clone
```
### ⚠️ 子弹太小会「穿过」目标
子弹精灵的长度如果 **< 10 像素**，像素级碰撞会漏检。
→ 子弹至少做 10 像素长，或给目标加一个稍大的「受击框」。

### 命中反馈三件套
```
当接收到 [命中 v]:
  change [血量 v] by (-20)
  将 [颜色特效 v] 设定为 (50)      ← 闪一下
  wait (0.1) secs
  将 [颜色特效 v] 设定为 (0)
  if <(血量) < [1]> then broadcast [胜利 v]
```

### 列表追踪投射物（不要给每颗子弹建变量）
```
列表 弹x: []   列表 弹y: []   列表 弹dx: []
发射时：add (x) to 弹x ...
每帧：遍历列表，移动、判定、删除
```
- **必须限制同时存在的子弹数**（5~10 个），否则会卡。
- 子弹飞出屏幕（x > 240 或 x < -240）或命中 → 从列表里 `delete`。

### 抛物线弹道（愤怒的小鸟式）
**拖拽蓄力 → 求初速度 → 抛物线飞行**：
```
鼠标按住时：记录 (起点x, 起点y, 当前鼠标位置)
松开时：
  vx = (起点x - 鼠标x) * 力度系数
  vy = (起点y - 鼠标y) * 力度系数
飞行中（每帧）：
  x += vx
  y += vy
  vy += 重力
```
用**画笔扩展**把轨迹画出来，玩家能看到弹道，瞄准感大幅提升。

### 弹道公式（需要精确射程时）
```
vx = v · cos(β)          水平速度
vy = v · sin(β) - g·t   垂直速度
x  = a + vx · t
y  = b + v·sin(β)·t - 0.5·g·t²
最高点 H = b + v²sin²(β) / 2g
射程   R = v²sin(2β) / g
```

### IR 写法要点 ✅
```yaml
- when_start_as_clone: { clone: _myself_ }
  - goto_xy: { x: { of: { object: 玩家, property: x position } },
               y: { of: { object: 玩家, property: y position } } }
  - point_towards: { TOWARDS: 准星 }
  - show: null
  - repeat_until:
      cond:
        or:
          - touching: { object: 敌人 }
          - greater_than: { a: { x_position }, b: 240 }
      do:
        - move_steps: 15
  - delete_this_clone: null
```

## 34. Cutscene 与演出控制

### ⭐ 三段式脚本头（Scratch 社区经典做法）
把每个角色的脚本分成三类帽子：
| 帽子 | 作用 | 是否重置数据 |
|---|---|---|
| `when I receive [开始游戏]` | 开场/初始化 | **重置**（位置、背包、分数） |
| `when I receive [游戏进行]` | 正常游戏逻辑 | **不重置** |
| `when I receive [演出]` | 过场动画 | 不重置 |

**关键**：`演出` 的**第一句**就是 `stop other scripts in this sprite` →
本角色所有「游戏进行」脚本立刻停掉（玩家失去控制）；
演出的**最后一句**是 `broadcast [游戏进行]` → 恢复。

> 这个结构的好处：加「菜单」「暂停」等新模式，只要再开一个
> `when I receive [菜单]` + `stop other scripts in this sprite` 就行，
> 不需要动任何已有逻辑。

### 对话与打字机
- **不要用「说」气泡**（本 skill 铁律）→ 用自制聊天框角色。
- 打字机效果：
  ```
  将 [文本 v] 设定为 [ ]
  重复执行 (长度 of 台词) 次:
    将 [文本 v] 设定为 ((文本) + (letter (第 i 个字) of 台词))
    wait (0.05) secs
  ```
  （Scratch 3 没有 `length of` 字符串积木 → 用 `letter of` 逐字探测，
  或预先把台词按字拆好放进列表。）

### 演出期间锁操作
用一个全局标志（`演出中 = 1`）让玩家角色的移动脚本整体跳过，
演出结束再置 0（见 §3 状态机、§5 弹窗冻结的同款写法）。

### 常见错误
- 屏幕上文字太多；
- 演出**不能跳过** → 一定要留一个「跳过」按钮（见 §5 关闭按钮）；
- 打字速度太快；
- 多个对话重叠 → 演出脚本要串行，用 `wait` 或广播链。

## 35. 镜头系统与关键帧运镜

### 关键帧 = 4 条列表
```
列表 keyFrameTime: []   关键帧发生的秒数
列表 keyFrameX:    []   目标 X
列表 keyFrameY:    []   目标 Y
列表 keyFrameZoom: []   缩放倍率
```
播放器：
```
当接收到 [开始演出 v]:
  reset timer                    ← 计时器归零，做全局节拍基准
  将 [帧号 v] 设定为 (1)
  重复执行直到 <(帧号) > (length of [keyFrameTime])>:
    如果 <(timer) > (item (帧号) of [keyFrameTime])> 那么
      将 [目标X v] 设定为 (item (帧号) of [keyFrameX])
      将 [目标Y v] 设定为 (item (帧号) of [keyFrameY])
      将 [目标缩放 v] 设定为 (item (帧号) of [keyFrameZoom])
      将 [帧号 v] 设定为 ((帧号) + (1))
    否则
      wait (0.02) secs
```
### ⚠️ 用计时器做节拍，不要叠加 wait
一堆 `wait 0.5` 叠起来，误差会**累积**；演出到后面整体对不上。
计时器是全局时钟，不会累积误差。
**每次演出开始必须 `计时器归零`**，否则上一局留下的时间会让镜头直接跳到列表末尾。

### 镜头插值
`camX += (目标X - camX) * 系数`，系数 0.1~0.3。
- 系数 = 1 → 镜头硬切到目标（节奏游戏里太生硬）；
- 保留一点缓冲，画面更舒服。

### 淡入淡出（黑场）
### ⚠️ **不要用亮度特效做淡入淡出**
Scratch 的亮度特效是**把画面往白色提**，不是变黑。
镜头切换时会有一层「发白」的雾感，配合缩放很像曝光过度。
**正确做法**：用一个覆盖全舞台的纯黑角色，
用**虚像（ghost）**从 100 渐变到 0（淡入）/ 从 0 到 100（淡出），
再切背景 → 就是电影黑场。
（黑场遮罩和镜头切换分开处理，还能单独调速度，配合鼓点。）

### IR 写法要点 ✅
```yaml
- when_receive: { message: 开始演出 }
  - reset_timer: null
  - set_variable: { var: 帧号, value: 1 }
  - repeat_until:
      cond: { greater_than: { a: { var: 帧号 }, b: { length_of_list: { list: keyFrameTime } } } }
      do:
        - if:
            cond: { greater_than: { a: { timer: null }, b: { item_of_list: { index: { var: 帧号 }, list: keyFrameTime } } } }
            do:
              - set_variable: { var: 目标X, value: { item_of_list: { index: { var: 帧号 }, list: keyFrameX } } }
              - set_variable: { var: 帧号, value: { add: [ { var: 帧号 }, 1 ] } }
            else:
              - wait: 0.02
```

## 36. 视差滚动与多层背景（Parallax）

### 原理：每层按不同比例跟随
Scratch Wiki 的经典写法：
```
定义 视差层 (层系数)
  go to x: (mouse x / 层系数) y: (mouse y / 层系数)
```
- **层系数越大 → 该层移动越少**（越远）。
- 前景树木用 1~2，背景远山用 8~20。

### 对「跟着玩家滚」的场景
把鼠标换成玩家自己的位移：
```
定义 视差层 (层系数) (自身x) (自身y)
  go to x: ((mouse x / 层系数) + (自身x))
  go to y: ((mouse y / 层系数) + (自身y))
```
典型的三层速度：远山 -2、中景 -5、近景 -10。

### 无限滚动背景（横版）
两张同宽的图首尾相接，用 `mod` 循环：
```
如果 <(x position) < (-舞台宽)> 那么
  将 x 增加 (舞台宽 * 2)
end
```
- **跳转值 = 舞台宽 × 2**，判断值 = **-舞台宽**。
  如果舞台宽不是 480，这两个数都要改（Scratch 舞台可改尺寸）。
- 两个克隆初始 x 分别是 `0` 和 `舞台宽`。

### ⚠️ 三个必踩的坑
1. **无缝拼接**：背景图最左列像素必须和最右列像素**对得上**，
   否则切换瞬间会「跳一下」。
   → 最保险的做法：画**左右完全对称**或**纹理均匀**（云层、星空、草地）的图。
2. **断层 / 重叠**：坐标算错就会出现白缝或两张图叠在一起。
   → 调试时临时加「显示 x 坐标」看它是不是按 `0 → -480 → 480` 循环。
3. **速度硬编码**：不要写死 `-10`。用一个「滚动速度」变量，
   改一处全局生效；主角加速时背景也要跟着加速（速度感来源），
   变速度用 `在 1 秒内将速度滑行到 (-15)` 做平滑过渡。

### 封装成可复用模块
做成**广播接口**，换场景只改数据不改代码：
| 广播 | 作用 |
|---|---|
| `开始滚动` | 各层启动滚动循环 |
| `设置速度 [值]` | 统一改滚动速度 |
| `停止滚动` | 速度置 0 |
| `切换背景 [造型名]` | 所有层统一切换造型 |

### IR 写法要点 ✅
```yaml
# 视差层（前景/背景各一个角色，只差「层系数」）
- forever:
    do:
      - goto_xy:
          x: { divide: [ { x_position }, 4 ] }
          y: 0
```

## 37. 寻路：BFS / Wavefront / A*

### 三种算法在 Scratch 里的实用度
| 算法 | Scratch 里的做法 | 适合 |
|---|---|---|
| **Wavefront（距离扩散）** | 从终点出发标记每格距离，每步走向距离最小的邻居 | ⭐ **格子游戏首选**，实现最简单 |
| **BFS** | 队列（列表末尾进、第一个出） | 通用最短路 |
| **A\*** | G/H/F 三值 + 开放/关闭列表 + 曼哈顿距离 | 大网格、更短路径 |
| **Simple Line-of-Sight** | 射线旋转着找通路 | 非格子游戏 |

### Wavefront（洪水填充）做法
两条列表：**地图状态**（0墙/1路）+ **距离**（初始 999）。
```
将 [距离(终点格)] 设定为 (0)
重复执行直到 <(距离(起点格)) < [999]>:
  取出队列头 -> 当前格
  对当前格的四个邻居:
    如果 <邻居是路> 且 <(距离(邻居)) = [999]> 那么
      将 [距离(邻居)] 设定为 ((距离(当前格)) + (1))
      把邻居加入队列
```
机器人行走时，每一步选**相邻格中距离值最小**的走 → 天然是最短路。

### 队列 / 栈
- **队列**（BFS）：`add` 到末尾，取走用 `delete 1`（第一个）。
- **栈**（DFS）：`add` 到末尾，取走也用 `delete` 最后一项 → 探索顺序完全不同
  （DFS 像「探险家」，遇岔路先走到底）。

### A* 的三个值
| 值 | 含义 |
|---|---|
| G | 从起点到当前格的实际代价 |
| H | 当前格到终点的**估计**代价（曼哈顿距离：|dx|+|dy|） |
| F | G + H，**优先探索 F 最小的** |

需要**开放列表**（待探索）和**关闭列表**（已探索）两个列表。
Dijkstra 就是 H=0 的 A*。

### 动态目标（追玩家）
目标会动 → 不能只算一次。
**每 0.2~0.5 秒重算一次**，然后沿路径走一步即可 —— 这就是绝大多数游戏 NPC 追人的原理。

### ⚠️ 坑
- **坐标 ↔ 索引转换是最容易出错的地方**，务必单独测：
  `index = (y-1)*列数 + x`，反查 `x = ((index-1) mod 列数)+1`。
- **克隆上限 300** → 用克隆做格子的网格，格子总数必须 < 300。
- 网格大了 A* 会明显变慢 → 优先考虑 Wavefront 或降低刷新频率。

## 38. 塔防（TD）

### 四个角色
| 角色 | 职责 |
|---|---|
| `敌人` | 沿路径走（克隆），有血量 |
| `防御塔` | 自动索敌开火（克隆） |
| `子弹` | 命中即删（克隆） |
| `游戏控制器`（舞台脚本） | 出波、经济、胜负判定（通常不显示造型） |

### 路径用列表存
把路径点存进列表（`路径X` / `路径Y`），敌人按序号走：
```
重复执行直到 <(路径序号) > (length of [路径X])>:
  go to x: (item (路径序号) of [路径X]) y: (item (路径序号) of [路径Y])
  将 [路径序号 v] 设定为 ((路径序号) + (1))
```
**好处**：改路径只要改列表，不用重写所有敌人的代码。
另一种做法：`如果碰到路径色? 那么 面向下一个方向`（用 `右转 15 度` 微调）。

### 索敌与开火
```
forever:
  如果 <(到敌人的距离) < [攻击范围]> 那么
    point towards [敌人]
    create clone of [子弹]
    等待 (开火冷却)
```
> Scratch 没有「取最近的敌人」积木 → 遍历敌人克隆（列表存敌人位置），
> 或给每个敌人一个距离变量，取最小值那个。

### 建造与经济
```
当角色被点击（商店里的塔图标）:
  进入放置模式（下一个点击的位置就是塔的位置）

当角色被点击（地图上的空地）:
  如果 <(金币) >= (建塔费用)> 那么
    如果 <碰到路径色?> = [否] 那么        ← 不能建在路径上
      将 [金币 v] 设定为 ((金币) - (建塔费用))
      在鼠标位置 create clone of [防御塔]
    end
  end
```
- **卖塔退一半钱**；**升级 = 卖掉再重建**（社区常见做法，省代码）。
- 杀敌给钱；敌人走到终点 → 玩家生命 -1。

### 属性克制（进阶）
敌人和塔各有颜色：**同色伤害减半** → 玩家要想配队。
敌人身上的圆圈实心=治疗光环、空心=护盾。

## 39. 音频管理与优先级

### ⚠️ Scratch 的音效是「抢占式」的
新音效会**打断**旧音效。所以：
- ❌ `start sound` 放在循环里 → 每秒触发 30 次 → 噪音甚至浏览器崩溃；
- ✅ **BGM 必须用 `play sound until done`**（阻塞式，播完才继续）。

### BGM 不该被音效打断
标准解法：**用克隆跑音效**，让「音效之间互相打断」，但 BGM 是本体在跑、不受影响。
```
音效本体: hide
当收到 [播音效 v]: create clone of [自己]
当作为克隆体启动:
  play sound [爆 v] until done
  delete this clone
```
（克隆体里用 `play sound until done`，不是 `start sound`。）

### `stop all sounds` 停不掉循环的 BGM
因为它只停「正在播的声音」，**不停止那个 forever 脚本**，
脚本立刻又从头播。正确做法：
```
当背景换成 [客厅 v]:
  stop all sounds
  stop other scripts in sprite      ← 这句才是关键
```
或者用 `backdrop name` 判断：
```
forever:
  如果 <(backdrop name) != [关卡2]> then
    play sound [追逐 v] until done
```

### 音频通道分层（社区/扩展的做法）
Scratch 3 官方没有通道，但社区做法是按**角色**分层，等效于通道：
- 舞台角色 → 只播 BGM
- 音效角色 → 只播音效
- 语音角色 → 只播语音
这样三者互不干扰（不同角色的声音可以同时播）。

### 淡入淡出
- 素材层面：用 Scratch 内置声音编辑器的 **Fade In / Fade Out** 处理音频首尾；
- 运行时层面：`change volume by (-5)` 循环做渐变（见 §12）。

## 40. 八方向移动与朝向动画

### 基础：四个方向分别判断，**不要用 else**
```
forever:
  如果 <按下 右箭头?> 那么 change x by (10)
  如果 <按下 左箭头?> then change x by (-10)
  如果 <按下 上箭头?> then change y by (10)
  如果 <按下 下箭头?> then change y by (-10)
```
- **顺序写 if（不用 else）**，这样「同时按左右」会互相抵消 → 角色不动。
- 用 `change x/y` 而不是 `move`，才能自由组合方向。
- ⚠️ 斜着走会更快 → 用 §2 的**对角线归一化**（×0.707）或把 8 个方向分开写。

### 八方向角度
```
如果 <上 且 右> 那么 point in direction (45)
如果 <上 且 左> 那么 point in direction (-45)
如果 <下 且 右> 那么 point in direction (135)
如果 <下 且 左> then point in direction (-135)
如果 <只上> 那么 90
如果 <只右> 那么 0
...
```

### 用造型表示朝向（而不是转角色）
每个方向一套造型：走0 / 走45 / 走90 / 走135 …
```
如果 <(方向) = [45]> then switch costume to [走45]
```
- **`rotationStyle: left-right`** 避免角色整圈旋转（只做左右翻转）。
- **省造型的技巧**：只画**朝右**的一套，靠 `left-right` 自动镜像 →
  4 方向只需 2 套（0° 和 180° 不对称时再单独处理）。
- 造型顺序不必严格，但要**同一方向的帧排在一起**
  （走45、走45.1、走45.2…），否则循环会串。

### 帧号用 `mod` 循环
```
将 [帧号 v] 设定为 (((帧号) + (1)) mod (该方向帧数))
switch costume to (造型名 + 帧号)
```
### 待机造型（Idle）
用一个「是否在移动」标志：没有任何方向键 → 切回站立造型；
同时 `rotationStyle: left-right` 保证不会转圈。

## 41. 无尽生成与程序化关卡

### 分段生成 + 回收（跑酷、飞行、跑酷类）
```
forever:
  如果 <(最后一段的 x) < (玩家x) - (屏幕宽)> 那么
    生成下一段（克隆）
    回收最老的一段（delete this clone）
```
- **分段要能无缝对接**：每段生成本身带「下一段入口」的偏移。
- 玩家跑过一段 → 那段就离屏太远 → 克隆回收（`delete this clone`），保持克隆总数恒定。

### 难度递增
每生成一段，难度参数 +1：
```
将 [难度 v] 设定为 ((难度) + (1))
将 [障碍速度 v] 设定为 ((基础速度) + ((难度) * (每级加速)))
将 [间隔 v] 设定为 ((基础间隔) - ((难度) * (每级缩短)))
```
⚠️ 间隔不能减到 0 或负数 → **要夹紧**（见 §25 长度夹紧的同类问题）。

### 随机但不重复
- ❌ **不要**用「不断随机直到不重复」→ 可能死循环；
- ✅ **Fisher-Yates 洗牌**后依次取（见 §25），或用「已用列表」记录。

### 道具与捡取
段落生成时顺带按概率放道具：
```
如果 <(random 1 to 100) < [30]> 那么 生成道具克隆
```

## 42. 云变量编码与「云列表引擎」

> Scratch **没有云列表**（官方明确拒绝了该功能），但社区用「把列表编码成一个数字」实现了。

### 为什么需要编码
云变量**只能存数字**（不能存文字），且最多 10 个。
所以任何要存到云端的东西都得先编码。

### 基础编码：字符 ↔ 数字
```
'A' -> 1, 'B' -> 2, ... 'Z' -> 26
编码：把每个字符转成两位数拼起来（用 join）
解码：每两位取出来，用「字符的 ASCII 减 64」还原
```
### 列表编码成一个大整数
```
编码值 = 0
重复执行 (列表长度) 次:
  编码值 = 编码值 * 100 + 第 i 项
解码：
  重复执行 (长度) 次:
    第 i 项 = (编码值 mod 100)
    编码值 = floor(编码值 / 100)
```
> ⚠️ 编码值会**指数级膨胀**，Scratch 数字精度有限 →
> 只适合**很短的列表**（十几项内）。大列表请改存「云变量 = 多个条目的索引」。

### 实用替代方案：把「列表」拆成「索引 + 固定槽位」
与其编码整个列表，不如：
- 用一个云变量存**当前索引 / 关卡号 / 进度**；
- 用另一条普通列表存**这一关的配置**（普通列表不需要编码，因为本地就够）；
- 切关时读云变量的索引 → 从本地列表取对应配置。

这是绝大多数 Scratch 游戏真正该用的做法。

### 排行榜的编码
```
云分数 = 分数 * 1000 + 用户序号
读取：分数 = floor(云分数 / 1000)
```
用户序号用 `sensing_userid`（用户 ID）取模，保证同一分数时也能区分先后。

## 附录：本册用到的积木速查

| 用途 | IR 写法 |
|---|---|
| 自己的朝向 | `{ direction: null }` |
| 面向某角色 | `{ point_towards: { TOWARDS: 角色名 } }` |
| 某角色的属性 | `{ of: { object: 角色名, property: "x position" } }` |
| 取余 | `{ mod: { a: x, b: y } }` |
| 数学函数 | `{ mathop: { operator: abs\|atan\|sqrt\|sin\|cos, num: 值 } }` |
| 列表：加入 | `{ add_to_list: { item: 值, list: 列表名 } }` |
| 列表：替换第 n 项 | `{ replace_item_of_list: { item: 值, index: n, list: 列表名 } }` |
| 列表：某值在第几项 | `{ item_num_of_list: { item: 值, list: 列表名 } }` |
| 列表：插入到第 1 项 | `{ insert_at_list: { item: 值, index: 1, list: 列表名 } }` |
| 列表：长度 | `{ length_of_list: { list: 列表名 } }` |
| 等待直到 | `{ wait_until: { cond: 条件 } }` |
| 亮度/透明特效 | `{ set_effect: { effect: BRIGHTNESS\|GHOST, value: n } }` / `{ change_effect: { effect: ..., value: n } }` |
| 音量 | `{ set_volume: { value: n } }` / `{ change_volume: { value: n } }` |
| 背景名称 | `{ backdrop_name: null }` / `{ backdrop_num: null }` |
| 计时器归零 | `{ reset_timer: null }`（做节拍基准） |
| 用户 ID | `{ userid: null }`（多人区分玩家） |
| 碰到颜色 | `{ touching_color: { COLOR: "#rrggbb" } }` |

> ⚠️ **单操作数运算必须写 `operand:`**：`not` 的输入名是 `OPERAND`，
> 写成 `{ not: { equals: ... } }` 会静默生成空操作数。
