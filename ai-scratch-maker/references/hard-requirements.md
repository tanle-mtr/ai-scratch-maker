# 游戏类作品的 4 条硬性要求

> 由 SKILL.md 拆出。SKILL.md 保留一句话版；
> 涉及首页 / 对话 / 数值展示 / 角色尺寸时，**生成前打开本文件**。

---

## 1. 必须有首页（标题页）

打开作品不能直接进游戏 —— 要先有首页，点「开始游戏」才进正题。

```yaml
project:
  title_screen:
    backdrop: assets/ui/title_bg.png     # 首页背景（整屏 480×360）
    button:
      asset: assets/ui/btn_start.png     # 开始按钮图片
      x: 0
      y: -110
    game_backdrop: 游戏场景              # 点开始后切到哪个背景
    broadcast: 开始游戏
  stage:
    backdrops:
      - { name: 游戏场景, asset: assets/game.png }
```

序列化器会自动生成：把「首页」插到背景列表最前、造一个「开始按钮」角色
（点击后广播 `开始游戏`）、舞台收到广播后切到游戏场景。

**游戏角色要在首页隐藏**，收到广播再出现：

```yaml
  sprites:
    - name: 猫
      scripts:
        - - when_green_flag_clicked: null
          - hide: null
        - - when_receive: { message: 正式开始 }
          - show: null
```

首页背景与按钮用 `scripts/make_ui_assets.py` 生成：

```bash
python3 scripts/make_ui_assets.py titlebg --out assets/ui/title_bg.png \
    --title "猫抓老鼠" --subtitle "用方向键控制猫" --tip "点击「开始游戏」按钮进入"
python3 scripts/make_ui_assets.py panel --out assets/ui/btn_start.png \
    --w 150 --h 50 --text "开始游戏" --fill "#ffb03aff" --border "#c76a00ff" \
    --font-size 26 --text-color "#3a2400ff" --radius 25
```

## 2. 对话要用自制聊天框角色，不要用「说」气泡

**不要用 `say` / `think` 积木做对话。** Scratch 的气泡是内置造型：不能排版中文、
字号不可调、会挡住画面、在正式作品里非常违和。

正确做法是**做一个聊天框角色**：台词预渲染成图片，聊天框角色按序号换造型。

```bash
# 1) 把台词写进文本文件（一行一句）
printf '准备好了吗？\n抓到一只！\n游戏结束啦\n' > lines.txt
# 2) 生成每句台词图 + 空白底板
python3 scripts/make_ui_assets.py chatlines --out-dir assets/ui/chat \
    --lines-file lines.txt --w 260 --h 56 --font-size 20 \
    --blank assets/ui/chat/chat_blank.png
```

```yaml
  sprites:
    - name: 聊天框
      x: 0
      y: -140                        # 固定在舞台底部
      chat_box:
        assets: assets/ui/chat       # 台词图目录
        lines: 3                     # 共有几句
      scripts:
        - - when_green_flag_clicked: null
          - hide: null
        - - when_receive: { message: 正式开始 }
          - chat_say: { line: 1, secs: 2 }   # 显示第 1 句，2 秒后隐藏
          - chat_say: { line: 2, secs: 2 }
```

`chat_say` 是伪积木，序列化器会展开成「换成造型 + 显示 + 等待 + 隐藏」。
聊天框就是普通角色，可以移动、缩放、放在画面上层。

## 3. 变量和列表用角色展示，不要用监视器

Scratch 的变量监视器是舞台角落的小框，做进游戏 UI 里很难看。
用**数字精灵**：一个角色有 0~9 共 10 套造型，按数值换造型。

```yaml
  sprites:
    - name: 分数显示
      x: -180
      y: 140
      size: 110                       # 数字精灵整体缩放（按需调整，确保清晰可读）
      digit_display:
        variable: 分数               # 显示哪个变量
        assets: assets/ui            # 目录里放 d0.png … d9.png
        digits: 2                    # 显示几位数（默认 1）；>1 时自动生成并排的多个数字精灵
        label: 分数                  # ★ 用角色展示「这是什么变量」的文字标签（见下）
        label_side: left             # 标签位置：left（默认）/ right / top
        label_size: 100              # 标签角色缩放
        label_font: 30               # 标签字号
```

序列化器会自动补齐 10 套造型**并生成刷新脚本**（绿旗后循环换造型）。

列表同理：

```yaml
    - name: 长度显示
      digit_display: { variable: 分数 }      # ← 变量
    - name: 榜单显示
      list_display:
        list: 排行榜                   # 显示哪个列表
        list_index: 1                  # 第几项（1 起）
        list_length: true              # 或者显示列表长度
        assets: assets/ui
```

> ## ⚠️ 铁律 1：数字必须**完整显示**，不能裁切、不能重叠
> 这是「数字精灵」最常翻车的地方。根因是：相邻数字之间的间距 `gap`
> 如果小于单个数字在**屏幕上**的实际宽度，多位数字会互相重叠、最右边被吃掉，
> 看起来就是「数字显示不全」（用户实测反馈过的真问题）。
> - 序列化器已**自动把 `gap` 调到 ≥ 数字屏宽 + 6**，正常情况不会再重叠；
> - 数字图本身也要用 `scripts/make_ui_assets.py digits` 生成（已修正为严格居中、
>   不会画到方框外），不要用别处随便来的图；
> - **构建后务必用 Scratch 打开目视确认**：每个数字都完整、不重叠、不超出舞台边界。
>   若数字精灵 `size` 调得很大，自动计算也会相应放大 gap，但仍要人眼复核。

> ## ⚠️ 铁律 2：一定要用**文字标签**告诉玩家这个数字代表什么
> 光摆一串数字，玩家根本不知道是分数、时间还是血量。给 `digit_display` 加
> `label: 分数`（或 `label: 时间`），序列化器会**自动生成一个新的「文字标签」角色**：
> 把文字渲染成图片、放在数字旁边，并随首页一起隐藏/显示。**绝不要只放数字不给说明。**
> 标签位置可用 `label_side`（left/right/top）调整，必要时把数字角色往中间挪一点，
> 给左侧标签留出空间（标签不要超出舞台 ±240 的边界）。

数字图用 `scripts/make_ui_assets.py digits` 生成（d0.png … d9.png）。
多位数不用手工堆叠：声明 `digits: 2`（或更多）后，序列化器会自动为每一位生成一个数字精灵角色，并排摆放、各自刷新对应位（个位永远显示，更高位在数值不足时显示 0）。首页存在时数字精灵会先隐藏，点「开始」后才出现。

> ## ⚠️ 铁律 3：署名与「防搬」必须**合规**
> Scratch 上的作品全部是 **CC BY-SA 授权**，**无法禁止别人改编**，
> 官方团队明确拒绝过「禁止改编」功能。
> - ❌ **不要**在说明/致谢/作品里写「禁止改编」「请勿复制」「私人作品」——官方会警告甚至处理作品；
> - ❌ **不要**用代码检测环境后锁死作品（如校验失败就停止），这违反社区规范；
> - ✅ 正确做法：标题屏放**署名卡**（`panel` 素材写作者）、致谢栏写清作者与素材来源、
>   美术加不显眼水印、核心玩法用命名清晰的自定义积木封装、官方改编署名链会自动保留；
> - ✅ 不想被搬就**不分享**（un-share），作品只有自己能看；
> - 被搬时：先留证据（截图 + 原作品链接）→ 礼貌留言要求署名 → 不听则举报
>   「作品的完全复制」/「未注明出处使用图片、音乐」。
> 详见 `references/advanced-techniques.md` §6。

> ## ⚠️ 铁律 4：障碍物必须有**碰撞箱**——画在图里的家具挡不住人
> **背景图 / 地图精灵里的障碍物没有碰撞箱。** 地图只是一张位图，
> Scratch 的碰撞检测只发生在**角色之间**（「碰到 [某角色]?」），
> 所以把家具直接画进大地图图片，玩家会**直接穿过去**。
>
> **三种做法，按场景选：**
>
> | 方案 | 怎么做 | 适用 |
> |---|---|---|
> | **A. 障碍做成独立角色**（推荐，最合 Scratch 口味） | 每件家具一个 sprite，存自己的世界坐标，每帧 `goto_xy (世界 - 相机)` 跟着地图滚动；玩家用 `touching [家具]?` 检测 | 大多数游戏 |
> | **B. 颜色碰撞** | 玩家 `touching color? [家具色]?` | 要快速实现、且家具颜色唯一 |
> | **C. AABB 碰撞箱（自己算矩形）** | 变量存每件家具的 `x1,y1,x2,y2`（世界坐标），和玩家的半宽半高做矩形相交 | 需要精确碰撞盒 / 非矩形 / 斜坡 |
>
> **A 方案的两个必踩的坑：**
> 1. **判定顺序**：Scratch 的「碰到」比较的是**屏幕坐标**。
>    必须是「**先移动 → 再判定 → 撞了退回**」，
>    如果先改内部坐标、最后才渲染，判定用的还是**上一帧的旧位置** → 漏判穿墙。
> 2. **障碍也要跟着相机滚动**：障碍每帧渲染到 `(世界坐标 - 相机)`，
>    否则世界坐标与屏幕坐标错位，碰撞判定会「隔空撞人」。
>
> 完整配方与 IR 写法见 `references/advanced-techniques.md` §15。

> ## ⚠️ 铁律 5：摩擦用「乘」，绝不用「减」
> 物理/粒子代码里最常见的致命错误：
> ```yaml
> # ❌ 减法摩擦：速度一路减到负数后继续减 → 无限增大 → 物体反向加速飞走
> - change_variable: { var: vx, by: -0.2 }
> # ✅ 乘性阻尼：按比例衰减 → 指数收敛到 0 → 物体自然停下
> - set_variable: { var: vx, value: { multiply: [ {var: vx}, 0.99 ] } }
> ```
> **区别**：减法摩擦让速度**匀速**减少（变负后继续减 → 反向加速）；
> 乘性摩擦让速度**按比例**衰减（收敛到 0）。
> 实测：0.2/帧的减法能让小球 3 秒内跑到 `x = -69000`，飞出天际。
>
> **判据：谁在被改变？**
> - 摩擦/阻尼/衰减 → 改的是**速度本身** → 用「乘」
> - 重力/加速度/推力 → 改的是**速度的变化率** → 用「加/减」
>
> 另外**反弹时要贴回边界**（翻转速度 + `goto_xy` 回边界），
> 否则角色会陷进墙里抖动。
> 详见 `references/game-design.md` §49.3。

> ## ⚠️ 铁律 6：「一局开始要复位」的东西挂在广播上，**不能挂绿旗**
> 点「重试」不是点绿旗。如果石头/敌人的出生位置写在「当绿旗被点击」下，
> 点重试时它们不会归位 —— 上局的石头还压在猫身上，
> 一进游戏立刻又 Game Over，玩家永远重试不出正常局面。
>
> **正确结构：**
> ```yaml
> # 绿旗：只做全局初始化（进标题页）
> - - when_green_flag_clicked:
>   - set_variable: { var: state, value: 0 }
>   - switch_backdrop: { backdrop: 标题页 }
> # 重置：所有「一局开始要复位」的东西
> - - when_receive:
>     message: 重置
>   - set_variable: { var: state, value: 1 }
>   - set_variable: { var: 分数, value: 0 }
>   - broadcast: 玩家出生
> # 开始/重试按钮
> - - when_this_sprite_clicked:
>   - broadcast: 重置
> ```
>
> **最佳分数要反过来**：它**绝不能**挂在绿旗上（绿旗会清空它，
> 最好成绩只活到下一次绿旗）。只在「新纪录」时更新，其他时候完全不碰它。
>
> 详见 `references/game-design.md` §45.3。

> ## ⚠️ 铁律 7：结算页必须有「返回 / 再来一局」按钮
> 做「有胜负 / 结束态」的作品（游戏、测验、答题、棋类、闯关）时，**结算页不能只是显示分数**。
> - ❌ 常见翻车：胜负判定做完就收工，结算页只有分数、没有按钮 → 玩家卡死，无法重开或回首页。
> - ✅ 结算页至少要有「再来一局」按钮（广播 `[重置]`，**不挂绿旗**，呼应铁律 6）和「返回首页」按钮
>   （`switch backdrop 标题页` + `hide 游戏角色` + 广播 `[重置]`）。
> - ✅ 按钮只广播意图，复位逻辑集中在舞台 `when_receive 重置` 里——首页「开始」和结算页「再来一局」复用同一套。
> - ✅ 交付前自检三问：结算页有按钮吗？点了有反应吗？是回首页还是直接重开？
> 完整规则与清单见 `references/results-screen.md` §147。

> ## ⚠️ 铁律 8：界面配色与窗口形态必须从设计规范取，不许自由发挥
> 做任何有界面的作品（菜单 / 设置 / 结算 / 弹窗 / 主操作键）时：
> - ❌ 常见翻车：随手挑个 RGB / 用普通矩形当窗口 / 用浅灰做背景 / 半透明直接写 8 位 HEX。
> - ✅ 颜色**只能**从 `references/ui-design-spec.md` §198 的 18 个 HEX 里取（`#FFCF4D` 主操作、
>   `#3A8E7D` 主体、`#5FD100` 次要、`#7F7F7F` 设置弹窗）；**冷灰禁止**、**深绿不得做填充**、
>   **黄色不得做主体色**（地铁类主体色取线路色）。
> - ✅ **所有窗口都是圆角矩形**（矢量造型 `rx` = 短边 × 0.06~0.10），大窗口居中 + 25% 透明底色
>   （`GHOST=25`）+ 右上角 ≥80% 透明的关闭图标（高度 ≥ 窗口高 30%）。
> - ✅ 颜色字面量必须是 **6 位 HEX**；要半透明就「颜色不透明 + 角色 GHOST」，带 alpha 会直接 `SCHEMA_FAIL`。
> - ✅ 交付前自检七问见 §206。完整规范见 `references/ui-design-spec.md`。

> ## ⚠️ 铁律 9：「AI 味」不来自美术，来自「没有曲线」
> 用户说「质感不好 / 互动太粗糙」时，**不要先换素材、加特效**——先查这四件事：
> - ❌ 常见翻车：位置/大小/透明度的变化是**瞬间跳变**（`移到 x: 100` 一帧到位）、
>   菜单项**同时出现**、按下按钮**没有任何反馈**、命中**没有停顿**、震屏每帧都在震。
> - ✅ **一切变化都要有帧数**：位移/缩放/透明度至少 6~12 帧，用 `x += (目标-x)*0.2` 缓动（§223）。
> - ✅ **到位要有过冲**：UI 弹出 `0.6 → 1.15 → 0.96 → 1`（§225）；落地压扁 `72 → 88 → 100` 三帧（§224）。
> - ✅ **多个物件错峰 2~3 帧**出现（§228）；**命中顿帧 2~4 帧**（§226）；**震屏幅度 2~4px 且只在真打击时用**（§230）。
> - ✅ **UI 四层微交互**：静止 → 悬停 ×1.05 → 按下 ×0.95 → 释放回弹（§231）。缺一层就「像贴图」。
> - ✅ 交付前过 §235 的 20 条 checklist。完整方法见 `references/polish-and-feel.md`。

> ## ⚠️ 铁律 10：自动控制类作品必须分三层，不许把控制律写进状态机
> 做「自动驾驶 / 自动寻路 / 自动瞄准 / 自动生产 / 任何自己跑起来的东西」时：
> - ❌ 常见翻车：状态里写「牵引/巡航/制动」；速度到不了目标就卡住；目标为 0 但速度永远剩 1.2；
>   欠标/欠量时用「瞬时条件」补一点点，结果一帧一帧地蹭。
> - ✅ **三层分离**：安全包络（只读，取 min）/ 规划层（目标值）/ 执行层（`误差 = 目标 - 实际` → 输出）。
> - ✅ **死区必须非对称**：加速侧宽（防抖）、收敛侧窄（必须能归零）。死区对称 = 永远有残值。
> - ✅ **跨帧持续的行为必须有标志位**；退出条件只能看稳态量，不能看「速度 ≤ 阈值」这种瞬态。
> - ✅ **收敛阈值与判定窗口必须错开**（退出阈值更靠里），否则会锁死在窗口外侧。
> - ✅ **状态不能零时长**：过渡态至少占 1 帧，否则外部观测不到。
> - ✅ 写完必须跑行为校验（如 `ATO_LOGIC_OK`）——这四类错**肉眼看不出来**。完整方法见 `references/ato-autopilot.md`。

> ## ⚠️ 铁律 11：UI 素材必须矢量 + 五层体积感，不许用「色块 + 一条描边」交差
> 用户说「素材太丑 / 像 PPT」时，**问题不在审美，在工艺**：
> - ❌ 常见翻车：按钮就是一个圆角矩形 + 一条描边；用生图模型画按钮（高光随机、改字要重画）；
>   SVG 里写 `<text>` 放中文（换台机器变豆腐块）；拿一张图拉伸当进度条（圆角拉成针尖）；
>   面板只有一种尺寸，放哪都硬拉。
> - ✅ **UI 控件全部走 SVG**（按钮 / 面板 / 图标 / 进度条 / 角标），画面主体（背景 / 立绘）才用位图。
> - ✅ **按钮五层**：投影 → 外描边 → 渐变主体 → 顶部高光 → 底部内阴影（顺序不能换，§253）。
> - ✅ **四状态换造型不缩放**：hover 提亮 / pressed **渐变反转**（上暗下亮）/ disabled 去饱和 0.62（§254）。
> - ✅ **SVG 禁用** `text` / `filter` / `mask` / `clipPath` / `pattern` / `image`（`check_ui_assets.py` 直接判错）。
> - ✅ **颜色只调明度不调饱和度**：从 §198 的 18 色派生 5 阶（§252）。
> - ✅ **面板预出四档**（Scratch 没有九宫格）；**进度条预出 10 档**（不拉伸）。
> - ✅ 交付前跑 `python scripts/check_ui_assets.py` → `UI_ASSETS_OK`，并做一次
>   「**整屏截图缩到 25%，还能分出按钮/背景/弹窗**」的终检。完整方法见 `references/ui-asset-craft.md`。

> ## ⚠️ 铁律 12：音效必须分四层响度，不能都归一化到同一峰值
> 用户说「没游戏感 / 声音吵 / 像课件」时，问题几乎总是**响度不分层**：
> - ❌ 常见翻车：所有音效都 `normalize(peak=0.85)` → **点按钮和爆炸一样响**，玩家两分钟就关声音；
>   首尾没归零（咔哒声）；DC 偏移（低频嗡嗡 + 提前削波）；UI 音用「播放声音直到结束」（**阻塞脚本**）；
>   每个动作都配音（走路每步都响）。
> - ✅ **四层响度**：`ui` −18 dBFS（最高频，最轻）/ `fx` −9 / `ev` −3 / `amb` −15。层间差 6~9 dB（§264）。
> - ✅ **时长上限**：`ui` 30~250ms（**绝不能超 0.25s**）/ `fx` 80~600ms / `ev` 300~1600ms（§265）。
> - ✅ **首尾必须归零**、淡入淡出 = `min(10ms, 时长×15%)`、DC 偏移 < 0.01（§267）。
> - ✅ **音高方向 = 语义**：上行=获得/开启，下行=失去/关闭，平+颤=警报（§268）。
> - ✅ **UI 音用「播放声音」（不阻塞）**；悬停音**至少间隔 120ms**；同帧不超过 3 个音效（§269）。
> - ✅ 交付前跑 `python scripts/check_audio_assets.py` → `AUDIO_ASSETS_OK`。
>   完整方法见 `references/audio-design.md`。

> ## ⚠️ 铁律 13：数学/算法类作品必须「先有 Python 基线，再用已知答案断言」
> 数学类最大的陷阱是**算错了看不出来**：画面照常动，数字照常显示，只有懂的人知道它错了。
> - ❌ 常见翻车：直接对着界面调回溯（看不到中间状态，只能靠解数猜）；校验写「跑出来多少就断言多少」（等于没校验）；
>   化简分数用 `/`（显示 `5.000000001`）；判等用 `=`（`0.1+0.2 ≠ 0.3`）。
> - ✅ **先写 `math_reference.py` 把算法跑对**，记录「解数 + 访问节点数」两个基线，再一比一翻成积木。
> - ✅ **校验里写死已知答案**（n=8 皇后 92、1..100 质数 25 个、1/2+1/3=5/6），不要写「跑出来的值」。
> - ✅ **比对节点数**：解数对但节点数不对 = 剪枝逻辑变了，现在没出错只是运气。
> - ✅ 化简必须 `round(分子/gcd)`；判等必须带容差；`log` 是 10 为底不是自然对数。
> - ✅ 交付前跑 `node scripts/math_behavior_check.mjs` → `MATH_LOGIC_OK`。
>   完整方法见 `references/math-and-reasoning.md`。

> ## ⚠️ 铁律 14：桌游必须先定「牌值编码」，再定「判定顺序」
> 做斗地主 / UNO / 狼人杀 / 卡牌对战：
> - ❌ 常见翻车：牌值直接用点数（2=2），导致「2 比 A 大」和「2 不能进顺子」都要特判；
>   判定顺序错（`6666` 被判成三带一）；UNO 只判同数字忘了同色；把已出局玩家投出局；平票只取一人。
> - ✅ **牌值编码**：`3..10` 直用、`J=11 Q=12 K=13 A=14`、**`2=15`**、`小王=16 大王=17` —— 大小与顺子都能用数值自动判断。
> - ✅ **判定顺序**：王炸 → 炸弹 → 单/对/三 → 三带X → 四带二 → 顺子 → 连对 → 飞机 → 飞机带单。
> - ✅ **主值取该牌型的值**：飞机带单取「三最小」，不是全局最小。
> - ✅ **隐藏信息**：手牌放角色私有列表，**交付前关掉所有列表监视器**。
> - ✅ 交付前跑 `node scripts/card_behavior_check.mjs` → `CARD_LOGIC_OK`。完整方法见 `references/tabletop-games.md`。

> ## ⚠️ 铁律 15：乐器演奏要用变量驱动，多声部要用多角色
> 做音乐 / 演奏 / 编曲类作品：
> - ❌ 常见翻车：为每种乐器复制一套脚本；乐器编号当成从 0 开始；`演奏音符` 后面又加 `等待`（双倍时长）；
>   一个角色里切乐器做多声部；在主循环里演奏导致画面卡死。
> - ✅ **`设定乐器为 (变量)`** —— 换音色只改变量（`INSTRUMENT` 槽位接受数字/变量）。
> - ✅ **乐器编号 1~21**（1=钢琴），VM 内部 0-based；**越界是环绕不是钳制**（设 99 得到 14），赋值前自己判范围。
> - ✅ **多声部 = 多角色**（音乐状态是 target 级）；一个角色只能有一条时间线。
> - ✅ **演奏是阻塞的**：播放器角色只管演奏，界面另开一个角色。
> - ✅ 音高换算：`MIDI = 60 + 偏移表[简谱] + 12 × (八度 − 4)`；休止符用 `0` 而不是 60。
> - ✅ 交付前跑 `node scripts/music_behavior_check.mjs` → `MUSIC_LOGIC_OK`。完整方法见 `references/music-and-instruments.md`。

> ## ⚠️ 铁律 16：狼人杀的「板子」是数据，「警徽流」和「自爆」必须有

> - ❌ 常见翻车：只做 4 个身份（狼/民/预言家/女巫），玩家三分钟看穿；**一个板子写一套脚本**；

## 4. 角色尺寸要算清楚

舞台只有 **480×360**。角色太大会有两个典型后果：

1. **判定条件恒成立** —— 角色在屏幕中间时，别的角色一出现就「碰到」，
   表现为「猫在中间一直加分」。
2. 角色几乎占满屏幕，看不见别的角色。

经验值：**可移动角色在屏幕上占屏高不超过 1/3（约 120px）**。

```yaml
  sprites:
    - name: 猫
      size: 35        # ← 268×300 的原图 @35% → 屏幕 94×105（占屏高 29%）
    - name: 老鼠
      size: 25        # ← 240×240 的原图 @25% → 屏幕 60×60（占屏高 17%）
```

校验器会自动检查这一点，超过 1/3 会给出警告。

配套的还有**安全生成点**：角色重新出现时必须离玩家足够远，
否则「刚出现就判定被抓」。用 `safe_spawn` 伪积木：

```yaml
        - - when_receive: { message: 重新出现 }
          - safe_spawn: { avoid: 猫, min_distance: 150 }
```

它会展开成「反复随机落点，直到离 `猫` 的距离 > 150」。
