## §291 桌游和棋类的根本差别：谁知道什么

| | 棋类（第十七册） | 桌游（本册） |
|---|---|---|
| 信息 | **完全公开**，双方看到同一棋盘 | **隐藏**，每人只看到自己的手牌 |
| 状态 | 一个棋盘 | 每人一份手牌 + 公共牌堆 + 弃牌堆 |
| 判定 | 「这步是否合法」 | 「这手牌是什么牌型」「能不能压」 |
| 失败 | 走错一步 | 出牌违规（会被判负） |
| 最难的部分 | 胜负判定 | **牌型识别 + 隐藏信息管理** |

**一条设计原则**：桌游里「谁该看到什么」比「规则怎么算」更容易翻车。
如果你把所有玩家的手牌都放在同一个列表里、又让所有人可见，玩家一眼就能作弊。

## §292 牌值编码：一套编码同时解决顺子、大小、王牌

先定编码，后面所有逻辑都靠它：

```
3 4 5 6 7 8 9 10  →  3..10
J=11  Q=12  K=13  A=14
2=15   小王=16   大王=17
```

**为什么用 15 表示 2**（而不是 2）：

1. **大小顺序天然正确**：`2 > A`，数值 `15 > 14` ✓ 直接比大小即可
2. **顺子天然排除 2**：顺子要求连续，`3..14` 连续，加上 15 就断了 → 规则「2 不能进顺子」用数值自动表达
3. **王牌只需要「比 2 大」**：16/17 天然最大

如果用真实点数（2=2, A=14），就要写一堆特判：`如果 值=2 则…`。
**编码选对了，一半的规则判断可以省掉。**

⚠️ 列表下标要用「牌值」直接寻址时，列表长度要开到 18（索引 0..17），空出 0/1/2。

## §293 牌堆与洗牌：Fisher-Yates，不要「随机取 + 去重」

```
洗牌(牌堆, n):
  对 i 从 1 到 n-1:
      j = 随机(i, n)
      交换 牌堆[i] 和 牌堆[j]
```

**为什么不用「随机抽一张，重复就重抽」**：抽到最后几张时会大量空转，甚至卡死。
Fisher-Yates 一遍过，且**每种排列等概率**（数学上可证）。

发牌就是「从头部连续取」：

```
对 玩家 p 从 1 到 人数:
    对 k 从 1 到 每人张数:
        加入 手牌[p], 牌堆[指针]
        指针 += 1
```

⚠️ **牌堆要用「指针」而不是「删除第一张」**：删除会让列表不断左移，N 张牌是 O(N²)。
Scratch 里列表删除是数组操作，牌多了会卡。

## §294 手牌管理：排序、选中、多选

| 功能 | 做法 | 坑 |
|---|---|---|
| 排序显示 | 按牌值插入排序（手牌通常 ≤20 张，O(n²) 足够） | 每次出牌后要重排，不能只排一次 |
| 单选 | 变量 `选中 = 下标` | 点同一张牌是「取消」，不是「再选一次」 |
| 多选（出牌） | 列表 `选中表` + 点一次切换 | 出牌后要清空选中表 |
| 显示 | 每张牌一个克隆，`x = 起点 + 间距 × 下标` | 手牌超过 12 张要缩间距或分两排 |

**手牌显示建议**：不要给每张牌做 54 个造型（体积大、改牌面要重画），而是
**牌面 = 牌背造型 + 数字/花色两个小造型叠加**，或者用画笔写字。

## §295 牌型识别：计数直方图（本册核心算法）

不要用「排序后逐个比较」——那样要为每种牌型写一套判断，14 种就是 14 段代码。
**一次性统计，然后按条件组合判断**，代码量差 5 倍：

```
① 计数：计[牌值] += 1            // 长度 18 的列表，下标就是牌值
② 归并：单数/对数/三数/四数       // 有多少个「只出现 1 次 / 2 次 / 3 次 / 4 次」的值
③ 极值：最小非零 / 最大非零       // 顺子用 (最大 - 最小 + 1 = 张数) 判连续
④ 关键值：三值 / 四值 / 三最小    // 「三带一」的主值是三张那个值，不是最小
⑤ 组合判断：按固定顺序套条件
```

**为什么需要「三最小」**：
牌 `555 888 3 4` 是「飞机带单」，主值应该是 **5**（飞机的起点），
但全局最小是 **3**（带的单张）。用错会让「比大小」判错。
这个 bug 在本工程的校验里被抓到过（`应为 飞机带单/5，实为 飞机带单/3`）。

## §296 判定顺序就是正确性

同样的条件集合，顺序错了结果就错。**固定按「张数由少到多、特型优先」排**：

```
1. 王炸（2 张，双王）
2. 炸弹（4 张，四数=1）        ← 必须在「三带一」前，否则 4 张炸弹会被当三带一
3. 单张 / 对子 / 三张
4. 三带一（4 张）/ 三带二（5 张）  ← 必须在「飞机带单」前
5. 四带二（6 张）
6. 顺子（≥5 张，全单张且连续）
7. 连对（≥6 张，全对子且连续）
8. 飞机（≥6 张，全三张且连续）
9. 飞机带单（≥8 张，张数能被 4 整除，三数组数 = 张数/4）
```

**三个必须记住的顺序陷阱**：

- 炸弹判在「三带一」之后 → `6666` 会被判成「三带一」✗
- 飞机带单判在「三带一」之前 → `5553` 会被判成「飞机带单」✗
- 顺子判在「连对」之前 → 不会冲突（张数不同），但顺子判在「飞机」之后 → 纯三张的连续会被当飞机（这也是对的）

## §297 比大小：三层规则，不能混

```
① 王炸 > 一切
② 炸弹 > 一切非炸弹（王炸除外）
③ 同型比主值；不同型不能压（炸弹/王炸除外）
```

⚠️ **「不同型不能压」是最容易漏的一条**：玩家出一对 3，你不能用「三张」压。
很多 AI 生成的卡牌游戏会漏掉这条，导致任何牌都能压任何牌。

⚠️ **主值的定义要统一**：
- 单/对/三/顺/连对/飞机 → 最小（或起点）
- 三带一/三带二 → 三张的值
- 四带二 → 四张的值
- 炸弹 → 值 + 50（保证炸弹永远大于同点数普通牌）

## §298 UNO：双维匹配 + 万能牌

规则只有三条，但实现时最容易只写一条：

```
能出 = (牌色 = 台面色) 或 (牌数 = 台面数) 或 (牌色 = 万能)
```

⚠️ **只判同数字、忘了同色** 是最高频的错。
本工程的校验特意用了一手「红5 / 红9 / 黄5 / 蓝2 / 万能」：
正确答案是 **4 张可出**（红5 同色同数、红9 同色、黄5 同数、万能），蓝2 不能出。

特殊牌的处理：
| 牌 | 效果 | 实现 |
|---|---|---|
| 跳过 | 下家不行动 | 回合 +2 而不是 +1 |
| 反转 | 方向反转 | `方向 = -方向` |
| +2 | 下家摸 2 张并跳过 | 摸牌 + 回合 +2 |
| 变色 | 玩家指定新颜色 | 需要一次「选色」交互，别忘了解除选中态 |
| 王牌 +4 | 下家摸 4 张 + 变色 | 同变色 + 摸牌 |

## §299 狼人杀：三段式（夜间 / 白天 / 投票）

狼人杀不是「一个循环」，是**三个明确阶段**，每个阶段有固定的行动顺序：

```
阶段 1：夜间
    狼人 → 女巫 → 预言家 →（守卫）
    每人「醒来」时要检查「我还活着吗」，死了就跳过
阶段 2：白天讨论
    公布死讯 → 玩家发言（可以简化成固定台词）
阶段 3：投票
    收集票 → 统计 → 最高票出局 → 平票则 PK 或无人出局
```

### 投票统计的三个细节

```
① 只统计「被投者仍存活」的票     ← 死人不能被投（也常常被漏）
② 最高票要单独扫一遍求 max       ← 不能边统计边比，会漏掉后面的高票
③ 平票要返回**全部**并列者       ← 只取第一个是最常见的错
```

本工程校验里有一条专门测这个：`存活=[1,3,4]`、`票箱=[2,2,3]`，
两票投给已出局的 2 号 → 正确答案是「最高 1 票，出局 3 号」。
如果漏了第 ① 条，会算成「2 号 2 票出局」（把死人投出局了）。

### 身份体系：26 个身份，不止狼人/女巫/预言家

只做「狼人 + 村民 + 预言家 + 女巫」会让作品一眼假。主流板子里的身份分三类，
下表按**技能触发时机**归类（这也是代码里最该用的分类方式）：

**好人 · 神职（夜间主动）**

| 身份 | 技能 | 触发 |
|---|---|---|
| 预言家 | 每晚查验一人：好人 / 狼人 | 夜 |
| 女巫 | 解药 + 毒药各一瓶，**每晚最多用一瓶，不可自救** | 夜 |
| 守卫 | 每晚守一人；**不能连续两晚守同一人**；与女巫解药同时作用会「奶穿」（该玩家仍死） | 夜 |
| 魔镜少女 | 每晚查验一人**是否狼人阵营**（与预言家区别：查不出具体身份，但能吃隐狼） | 夜 |
| 守墓人 | 每晚得知**前一天被放逐者**是否为狼人 | 夜 |
| 摄梦人 | 每晚摄梦一人；被摄者死亡时摄梦人一同出局（部分板子为保护） | 夜 |
| 白兔 | 得知每晚/每白天的**死因**，并可与死者交流 | 夜 |
| 奇迹商人 | **仅首夜**给一人一项技能（验人/毒/守护）；若给到狼人，商人自己死 | 首夜一次 |
| 蜂之狂猎 | **第二晚起**每晚蜂刺两人：双狼命中 → 两狼直接出局；一狼一好人 → 无效；双好人 → 永久失去技能 | 夜（第 2 晚起） |
| 红月 | 照耀一人，使其技能不受「区域限制」；红月死亡则下一夜所有神与蓝狼都无法行动 | 夜 |
| 追魂者 | 探查一人是否有「复活痕迹」；自身**免疫一次致命效果** | 夜 |

**好人 · 神职（白天/触发式）**

| 身份 | 技能 | 触发 |
|---|---|---|
| 猎人 | 被狼刀或被放逐时可开枪带走一人；**被女巫毒杀不可开枪** | 死亡时 |
| 白痴 | 被投票出局可翻牌免死，之后**可发言不可投票**，需再被杀一次才死 | 放逐时 |
| 骑士 | 白天翻牌决斗一人：对方是狼 → 狼出局；否则骑士出局 | 白天主动 |

**狼人阵营**

| 身份 | 技能 | 触发 |
|---|---|---|
| 狼人（普狼） | 每晚与狼队共同刀一人 | 夜 |
| 狼王 | 出局时可开枪带走一人（被毒不可） | 死亡时 |
| 白狼王 | **白天可自爆**带走一人，并结束当天进入黑夜 | 白天主动 |
| 狼美人 | 每晚魅惑一人；狼美人出局时**被魅惑者同死** | 夜 |
| 石像鬼 | **与狼队不见面**，靠验人获取信息；小狼全死后可独自刀人 | 夜 |
| 隐狼 | 白天**不被查验为狼人**（预言家查为好人） | 被动 |
| 恶灵骑士 | **免疫夜间死亡**；被预言家查验时**反杀预言家** | 被动 |
| 红狼 | 每当有狼人以任何形式死亡，**下一晚可额外刀一人**（一次，可被守卫防住） | 夜 |
| 饿狼 | 每晚**吞噬**一名玩家：该玩家白天不能发言/投票/被投，也不能被任何技能针对 | 夜 |
| 蓝狼 | 把玩家划成两个区域；若两区域内都有活狼，**可各刀一人** | 夜（一次） |
| 猩红狼王 | 每晚给一人附着「猩红之子」（最多 3 人）；被附着者成为神职技能目标时夜里出局；狼王出局则附着者同死。**不能自爆、不与狼队互认** | 夜 |

**平民**：无技能。

> ⚠️ 身份名称与技能以**官方当前版本**为准 —— 板子是会随版本更新的
> （例如九周年新板「猩红蜂舞」引入了猩红狼王与蜂之狂猎）。
> 上面这张表的价值不在「穷举」，而在**按「夜间主动 / 白天主动 / 死亡触发 / 被动」分类**，
> 因为这四种定时直接决定了你的状态机怎么切。

板子池 = [1,1,1,1, 2,2,2,2, 3,4,5,6]
          └─狼人×4─┘ └─村民×4─┘  预言家 女巫 猎人 白痴

（本工程的编号见 `card_game.yaml` 的 `身份名表`：1 狼人 / 2 村民 / 3 预言家 /
4 女巫 / 5 猎人 / 6 白痴 / 7 守卫 / 8 骑士 / 9 狼王 / 10 白狼王 / 11 狼美人 /
12 石像鬼 / 13 隐狼 / 14 恶灵骑士 / 15 魔镜少女 / 16 守墓人 / 17 奇迹商人 /
18 摄梦人 / 19 白兔 / 20 红狼 / 21 饿狼 / 22 蓝狼 / 23 红月 / 24 猩红狼王 /
25 蜂之狂猎 / 26 追魂者。**这套编号是工程自定义的，不是官方标准**。）

发牌就是「复制板子池 → 洗牌」：

```
人数 = 长度(板子池)
对 i = 1..人数: 身份池 加入 板子池[i]
对 i = 1..人数-1:                    // Fisher-Yates
    j = 随机(i, 人数)
    交换 身份池[i] 和 身份池[j]
```

⚠️ **不要「随机抽身份、重复就重抽」**：抽到最后几张时会大量空转（10 人局最后 2 张可能重抽几十次）。

### 夜间行动顺序：防守 → 狼刀 → 情报

顺序错了会出逻辑 bug（女巫看不到刀口、守卫白守）。通用顺序：

```
守卫（先守）
  → 狼人 / 狼王 / 白狼王 / 狼美人 / 红狼 / 蓝狼 / 猩红狼王（狼刀 + 狼技）
  → 女巫（看刀口 → 解药 / 毒药）
  → 预言家 / 魔镜少女 / 守墓人 / 追魂者（情报类）
  → 摄梦人 / 白兔（收尾类）
```

**为什么是这个顺序**：
1. **守卫先手**，否则「先刀后守」等于没守；
2. **女巫在狼人之后**，因为她要看到刀口才能决定救不救；
3. **情报类最后**，因为它们要看「今晚发生了什么」；
4. **猎人 / 白痴 / 骑士** 是触发式，**不占夜间序列**，谁死亡/翻牌谁插队。

⚠️ **每个身份醒来第一件事是「我还活着吗」**：死了就跳过，否则会出现「死人开药」。

⚠️ **死亡要延后结算**：夜间多人可能同时死（狼刀 + 毒药 + 狼美人连带），
先把「今晚死亡名单」收集完，天亮再统一公布 —— 边杀边公布会提前泄露信息。

## §300 隐藏信息：谁该看到什么

Scratch 里没有「权限」，只能靠**显示 / 隐藏 + 变量隔离**：

| 信息 | 存放 | 谁能看 |
|---|---|---|
| 自己的手牌 | 角色私有列表（每个玩家一个角色） | 只有自己 |
| 牌堆 | 舞台列表 + `显示列表` 关闭 | 无人（但能被读） |
| 身份（狼人/村民） | 每人私有变量 | 只有自己（狼人可互看 → 广播告知） |
| 公共弃牌堆 | 舞台列表 | 所有人 |

⚠️ **列表监视器默认是可见的**！把「牌堆」「所有人手牌」放在舞台列表里并勾选显示，
玩家一眼看穿。**交付前一定要关掉所有列表监视器**（或在 IR 里不声明 monitor）。

⚠️ 更彻底的隔离：**每个玩家的手牌放在各自的角色私有列表里**，
而不是一个 `手牌[玩家]` 的二维结构。二维结构在 Scratch 里没有访问控制。

## §301 回合状态机：不要用「等待点击」

```
状态：等待出牌 → 判定中 → 结算 → 下一家 → 等待出牌
```

| 写法 | 问题 |
|---|---|
| ❌ `重复执行直到 鼠标按下` | 会卡死在等点击，玩家不出牌游戏就停了 |
| ❌ 每个玩家一个 `重复执行` | 多个循环同时跑，谁都判定 |
| ✅ **单一回合变量 + 帧广播分发** | 只有 `当前玩家 = 我` 时才响应输入 |

```scratch
当收到 [帧]
  如果 <当前玩家 = 我的编号> 且 <状态 = 等待出牌>:
      如果 <鼠标按下 且 点到我某张牌>: 处理选中
```

## §302 AI 出牌：贪心就够，别做搜索

桌游 AI 不需要极小化极大（那是棋类）。**贪心 + 一点随机**体验最好：

```
跟牌策略：
  ① 找所有「同型且主值更大」的组合，取**最小的那个**（省牌）
  ② 没有则考虑炸弹（手里炸弹 ≤2 时保留，别乱炸）
  ③ 都没有 → 过
先手策略：
  ① 出最小的单张 / 对子
  ② 手里有长顺子时优先出（减少手牌数）
```

⚠️ **AI 不要「拆牌」拆得太狠**：把 `555` 拆成三张单张出，玩家一眼看出「这 AI 很蠢」。
简单的约束：**优先出「完整牌型」，不要在手里还有别的选择时拆三张/炸弹**。

## §303 桌面呈现：卡牌的三个层次

| 层次 | 做法 | 成本 |
|---|---|---|
| 牌背 | 一张矢量圆角矩形 + 花纹（`assets/uikit/panel_card` 可改造） | 1 个造型 |
| 牌面（数字） | 数字用「拆位造型」或位图文字条（第二十八册 §258） | 10 个造型 |
| 牌面（花色） | 4 个矢量图标（♠♥♦♣ 用 path 画） | 4 个造型 |

**不要做 54 张独立造型**：体积大（每张 2~5 KB → 200 KB+）、改牌面要重画 54 次。

手牌排布：
```
x = 起点 + 间距 × (下标 - 1)
间距 = min(牌宽 + 4, 可用宽度 / 手牌数)
```
手牌 >12 张时间距会小于牌宽 → 自动叠压（后画的盖住前面的），这是**正常的**，玩家能看清边缘。

## §304 校验方法 + 十个坑

### 桌游最好校验：判定是纯函数

「牌组 → 牌型」「手牌+台面 → 可出牌」「票箱 → 出局者」都是**输入输出确定**的，
可以直接写死期望值：

```
node scripts/card_behavior_check.mjs <card_game.sb3>  →  CARD_LOGIC_OK
```

26 条断言：
- 牌型 14 例（含 `JQKA2` 不能成顺、`555 888 3 4` 是飞机带单、王炸）
- 比大小 7 例（同型/炸弹通吃/王炸最大/不同型不能压）
- UNO 2 例（4 张可出 / 只有万能可出）
- 投票 3 例（一边倒 / 平票两人 / 已出局不计票）

### 十个坑

| # | 坑 | 症状 | 修法 |
|---|---|---|---|
| 1 | 判定顺序错 | `6666` 被判成三带一 | 炸弹判在三带一之前 |
| 2 | 飞机带单用全局最小做主值 | `555 888 3 4` 主值算成 3 | 用「三最小」 |
| 3 | 顺子把 2 算进去 | `JQKA2` 判成顺子 | 编码用 15 表示 2，且判 `最大 ≤ 14` |
| 4 | 炸弹不通吃 | 炸弹压不过对子 | 单独一条「炸弹 > 非炸弹」 |
| 5 | 不同型也能压 | 三张压对子 | 同型才比主值 |
| 6 | UNO 只判数字 | 同色牌出不了 | 色/数/万能三个条件取或 |
| 7 | 投死人 | 已出局玩家被投出局 | 统计前查存活 |
| 8 | 平票只取一人 | 两人同票只出局一个 | 并列全部记入候选 |
| 9 | 洗牌用「重抽去重」 | 最后几张卡死 | Fisher-Yates |
| 10 | 列表监视器没关 | 玩家看到所有人手牌 | 交付前关掉全部监视器 |

### 交付前自检（7 问）

1. 牌值编码统一了吗？（2 用 15 还是 2）
2. 判定顺序是按「特型优先、张数由少到多」排的吗？
3. 主值取的是「该牌型的值」还是「全局最小」？
4. 洗牌是 Fisher-Yates 吗？
5. 隐藏信息真的藏住了吗？（监视器关了？）
6. 回合是靠变量分发，还是靠「等点击」？
7. `node scripts/card_behavior_check.mjs` → **`CARD_LOGIC_OK`**？
