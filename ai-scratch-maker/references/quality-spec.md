# 作品规格表与质量门禁（§C7）

> 目标：让**默认路径**产出作品级成果，而不是靠某次手工精雕。
> 配套脚本 `scripts/quality_gate.py`，档位定义在 `references/quality-profiles.json`。

---

## 为什么需要它

对比实测（45 个 skill 示例 vs 11 个真实社区作品）：

| | skill 示例中位数 | 社区作品 | 结论 |
|---|---|---|---|
| 积木数 | 最多 1566 块 | FNAF 1005 块 | **逻辑不输，不是瓶颈** |
| 造型数 | 2–4 | Ultra100 478 | 差 1–2 个数量级 |
| 音效数 | **0（82% 示例）** | 双阶乘 45 | 差最多 |
| 角色数 | 1–3 | FNAF 29 | 差一个数量级 |
| 产物体积 | ~90 KB | 9–62 MB | 差 100–1000 倍 |

而原有七层校验只检查「ZIP 结构 / 编码 / schema / 运行时 / 语义」——
一个零音效、2 个几何造型的 demo 可以**全过前七层**被交付。
第 8 层门禁因此分两层：**A. 资产密度**（玩家看得见的东西，所有品类都查）
和 **B. 玩法完整度**（像不像能玩的完整作品，仅 `genre=game` 强制）。
前者保证「量够」，后者保证「不是零交互幻灯片 / 不能操控的展示」。

---

## A. 六项资产密度指标与四档门槛

| 档位 | 适用 | 造型 | 音效 | 角色 | 体积 | 场景 | 积木 |
|---|---|---|---|---|---|---|---|
| `demo` | 技术验证 / 单元测试 | 1 | 0 | 1 | 0 | 1 | 1 |
| `mini` | 小作品 / 课件片段 | 6 | 2 | 2 | 150 KB | 1 | 40 |
| `game` | **游戏 / 互动作品（默认）** | 20 | 8 | 4 | 1 MB | 2 | 150 |
| `showcase` | 展示级大作 | 60 | 20 | 12 | 8 MB | 4 | 500 |

数值是**起点不是教条**：某些题材（音游、纯动画）天然角色少，
用 `--init` 生成规格表后逐项覆盖 `min_*` 即可。关键是**设计阶段就把话说清楚**，
而不是交付后凭感觉说「不够好」。

参照锚点：`猫抓老鼠` 造型 67 / 音效 4 / 角色 24 / 2.85 MB → `game` 档资产 5/6 达标；
`双阶乘` 1 角色 211 积木却 62 MB（全靠 45 个音频）→ 提醒不要把角色数当唯一指标。

---

## B. 玩法完整度（仅 `genre=game` 强制）

资产密度只保「量」，保不了「好玩 / 完整」。下列三项用**启发式**扫描 `project.json`
的脚本与广播 / 变量名，判断作品是否像个能玩的完整游戏。**音乐 / 动画 / 剧情类**
把规格表 `genre` 设为 `music` / `animation` / `story` 即自动跳过（避免误杀数字方块乐队这类作品）。

| 指标 | 判定启发式 | 说明 |
|---|---|---|
| **玩家可操控** | 存在 `当按下[键]` / `当角色被点击` / `当舞台被点击` 输入帽，**且**帽下挂了运动 / 传感 / 变量等交互逻辑 | 只有绿旗+广播、玩家插不上手 → 判「无」 |
| **胜负 / 目标条件** | 广播名含 胜利/失败/通关/过关、变量含 生命/血量/得分/分数/关卡，或用了 `停止全部` 收尾 | 让玩家知道赢没赢 |
| **重玩价值** | 以下至少满足 2 条：有 `随机数`（每局不同）、有 分数/得分 系统、有 关卡/难度 递进 | 否则通关即弃、无复玩动力 |

> 启发式必然有边界：极简实验性游戏（如纯计时反应）可能被判「重玩不足」，
> 这时**手改规格表把 `genre` 设为 `animation` 或用 `--profile demo` 豁免**，并在交付说明注明。
> 完整度是辅助红线，不是玩法评分——真正的手感仍靠目视（见末节无头盲区）。

## 在工作流里的位置

**第 1 步（设计）先定规格**：

```bash
python scripts/quality_gate.py --init --profile game --out mywork.quality.json
```

生成的 JSON 可直接手改，例如音游把 `min_sprites` 降到 2、`min_sounds` 提到 16，
且 `genre` 设为 `music`（跳过玩法完整度）：

```json
{
  "profile": "game",
  "label": "节奏音游",
  "genre": "music",
  "min_costumes": 20, "min_sounds": 16, "min_sprites": 2,
  "min_bytes": 2000000, "min_scenes": 2, "min_blocks": 150
}
```

**第 3 步素材必选**：先查社区素材包（§C6）与 5 个模板，按规格凑够资产密度。

**第 6 步（交付前）验收**：

```bash
python scripts/quality_gate.py --list                      # 看内置档位
python scripts/quality_gate.py --sb3 x.sb3 --profile mini  # 不阻断，只出报告
python scripts/quality_gate.py --sb3 x.sb3 --spec mywork.quality.json --strict
python scripts/quality_gate.py --sb3 x.sb3 --profile game --json report.json
```

`--strict` 下有任何未达标项就返回退出码 1，可用于 CI / 交付脚本阻断。
纯技术验证用 `--profile demo` 显式豁免，**并在交付说明里注明档位**（不允许悄悄降级）。

## 报告长什么样

```
指标                      实测          门槛  结果
造型数                      2          20  不足
音效/音乐数                   0           8  不足
角色数                      1           4  不足
产物体积                 11 KB     977 KB  不足
场景/背景数                   1           2  不足
积木数                     43         150  不足
玩家可操控                    无          必有  不足
胜负/目标条件                  无          必有  不足
重玩价值                     无          必有  不足
...
达标 0/9 · 评级：DEMO 级

补齐建议（按差距排序）：
  · 玩家可操控 无 < 必有：至少有一个角色用「当按下[方向键/空格]」等输入帽，且帽下挂运动/交互逻辑
  · 胜负/目标条件 无 < 必有：广播名含 胜利/失败/通关、变量含 生命/血量/得分/分数/关卡、或用「停止全部」收尾
  · 音效/音乐数 0 < 8：asset_pack.py search "" --kind sound；或 gen_audio.py <mood>
  · 造型数 2 < 20：asset_pack.py search "" --kind costume；或 gen_community_template.py --template numberblock_band
```

每条建议都指向**现成可执行的东西**，与社区素材包（§C6）形成闭环：
检索 → 引用 → 重新编译 → 重新验收。

## 门禁查不到的（仍需人工）

- 首页 / 标题页是否齐全、结算页是否有返回与再来一局按钮（铁律 7）
- 素材尺寸与旋转中心、中文排版、UI 五层体积感
- 质感曲线（缓动 / 顿帧 / 震屏）、音效四层响度、音高方向语义
- 逻辑手感：判定窗口、死区、跨帧标志位

这些属于无头盲区（size / 克隆 / 画笔 / 音频 / 悬停测不到），
门禁只负责拦住「一眼就是 demo」的资产密度，不替代目视验收。

## C. 观感质量（所有品类都查，软评分 + 明确违规 WARN）

A/B 两层管「量够不够 / 像不像能玩」，但**拦不住"技术完整但观感拉胯"**。
第 8 层门禁因此再加一层 **C. 观感质量**，把铁律 8/9/11 里**可静态检**的维度量化成
`观感质量分（0–100）`，并在 `genre=game/showcase` 档对**明确配色违规**阻断交付。

| 维度 | 静态判据 | 来自 |
|---|---|---|
| 渐变体积感 | 含 `linearGradient`/`radialGradient` 的 SVG 占比 | 铁律 11 |
| 窗口圆角 | 带 `rx` 的 `<rect>` 占比（窗户/面板）；无 rect 的作品不罚 | 铁律 8 / §200 |
| 缓动/过渡 | `glide` / `GHOST` 渐显 / `operator_multiply` 阻尼 / 缓动关键词 | 铁律 9 |
| 配色合规 | 冷灰（三通道接近且 B 明显 > R，即低饱和冷调灰）禁止；深绿 `#216E09`/`#2F7365` 仅作文字、不得做 `fill`（渐变 stop-color / 描边 / 文字均合法） | 铁律 8 / §198 |

评分：`0.35×渐变 + 0.15×圆角 + 0.35×缓动 + 0.15×配色`，满分 100。
（任一 SVG 含渐变 → 渐变分满分；无 rect 用 path 画圆角的作品 → 圆角分满分，不罚。）

- **所有档**：冷灰/深绿填充命中 → `[违规]` 警告；评分 < 60 → `[建议]` 回看清单。
- **`game`/`showcase` 档（strict）**：出现冷灰或深绿**填充**这类明确 §198 违规 → 计入未达标，**阻断交付**；
  纯启发式观感分只作建议、不硬拦（避免误杀标杆，旗舰 fruit_basket 观感分 68 仍放行）。
- **`demo`/`mini` 档**：C 层只给评分与建议，不阻断。

> 配色判据已校准：深绿只查 `fill=` 属性（共享素材里的渐变 stop-color 不算违规），
> 冷灰要求三通道接近（纯蓝/饱和色不算灰），全 54 作品零误杀。

> 观感质量分是**软指标**，不是"好看"的充要证明——真正的手感/质感仍靠
> `references/quality-checklist.md` 的实战清单与目视。C 层负责拦住
> "全无渐变、全无缓动、随手冷灰"这类一眼廉价的明确失误。
