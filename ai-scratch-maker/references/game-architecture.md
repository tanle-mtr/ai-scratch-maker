# 大型工程架构（第二十二册，§177–§186）

> **作品预估超过 1500 块、或要做「能继续加内容」的项目时先读这一册。**
> 小作品靠堆积木，大作品靠**约束**。本册是从 5 个万块级工程的组织方式里提炼的通用骨架：
> `双人Apple跑酷`（19191 块 / 31 角色）、`忍者冒险`（12731 块 / 24 角色）、
> `挖矿猫4`（12615 块 / 34 角色 / 101 变量 / 88 列表）、`我的世界S`（10262 块）、
> `忍者3D`（6118 块）、`UP主模拟器`（4186 块）。
> 这些工程彼此毫无关系，却收敛出**同一批约定**——说明它们是这个规模下的必然解，不是个人口味。

- **§177 变量命名前缀：给变量加上「类型/生命周期」**
  没有类型系统的 Scratch 里，**变量名就是唯一的类型声明**。四个工程各有一套，本质相同：

  | 前缀 | 含义 | 实例（出处） |
  |---|---|---|
  | `#` | **配置/静态数据**，只在初始化写一次 | `#关卡`、`#地图 x长`、`#设置  光影`、`#方块属性（挖掘硬度）` |
  | `+` | **运行时状态**，每帧可能变 | `+玩家  x`、`+摄像机  dx`、`+光线状态`、`+背包  子Y` |
  | `-` | **临时/局部**，函数用完就丢 | `-地图  x`、`-克隆体  类型`、`-存档码：加载i` |
  | `=` | **函数返回值**（模拟 return！见 §183） | `=方块ID`、`=在矩形内？`、`=两线段相交？`、`=out:两点之间距离` |
  | `@` / `Indiv.` / `_` | **每个克隆体私有** | `Indiv. Xv`、`@BOSS HP`、`@Non-sense types` |
  | 点分命名空间 | 子系统分组 | `WORLD_`、`CAM.`、`PLAYER.(-POS-)`、`CURSOR_`、`Blocks.type`、`Item.name` |
  | 类型前缀 | 值类型 | `BOOL-暂停？`、`CHAR-UI提示`、`INT-切换时间` |

  **本项目统一用中文名前缀写法**（和既有铁律一致）：`#设置_xxx` / `+玩家x` / `-临时i` / `=计算结果`。
  最重要的两条：**① 配置量一律 `#`**（一眼看出「这个变量不该在游戏中被改」）；
  **② 每个克隆体私有量一律用角色私有变量**（铁律 9，别图省事用全局变量 + 编号后缀）。

- **§178 广播命名空间：`模块-动作`**
  `UP主模拟器` 的广播表是这套的教科书：
  ```
  主界面-新存档 / 主界面-旧存档 / 主界面-新手教程 / 主界面-关于
  界面-主界面 / UI-返回主菜单 / UI-初始化 / UI-成就系统
  UI特效-剧情 / UI特效-结局 / UI特效-你寄了
  场地-室内 / 场地-室外 / 场地-医院 / 场地-超商
  数据处理-生成存档码 / 数据处理-备份存档码 / 数据处理-门诊判断
  打印-玩家数值 / 打印-计划 / 打印-进度 / 打印-真删除
  互动软件/背景-CS3 / 互动软件/背景-Dilidili / 互动软件/背景-丑团
  ```
  `双人Apple跑酷` 用英文同一套：`game loop - scroll` / `game loop - players` /
  `game loop - spawn` / `game loop - particles` / `game loop - obj`、
  `Menu - setup` / `Menu - Show Scores` / `Menu - Off`、
  `EDIT - Reload` / `EDIT - Save` / `EDIT - New Level` / `EDIT - Import Level`。
  **规则**：`<模块>-<动作>`，模块名固定不超过 8 个字，动作优先用**动词**。
  好处：广播列表按名字排序时自动按模块聚簇，第 60 条广播也能一眼找到。
  ⚠️ 别用 `消息1`/`消息2`/`广播3`——超过 20 条广播后不可维护。

- **§179 类型-属性表：把「每种东西的属性」摊成平行列表**
  `挖矿猫4` 有 91 种方块，属性全部摊在 len=91 的平行列表里，**用方块 ID 当索引**：
  ```
  Blocks.type.name            Blocks.type.collider   Blocks.type.health
  Blocks.type.mineable        Blocks.type.ItemDropType
  Blocks.type.colisionHeight  Blocks.type.fall?      Blocks.type.sourcedistance
  ```
  同一套还有物品：`Item.type.stackSize / usetype / name / droppable / buildblock.type`（len=1020）。
  `我的世界S` 是同款：`#方块属性（名称）/（碰撞箱类型）/（挖掘硬度）`（len=42）。
  查询就是一次列表取值：
  ```yaml
  - set_variable: {var: 硬度, value: {item_of_list: {list: 方块属性（挖掘硬度）, index: {var: 方块ID}}}}
  ```
  **价值**：加一种方块 = 每个属性列表末尾加一项，**代码零改动**。
  这是体素/沙盒/经营类作品的唯一正确数据组织方式。
  ⚠️ 所有属性列表**长度必须严格相等**，少一项就会整体错位（ID 全串）。
  自检：绿旗时断言 `所有属性列表长度都 == 名称表长度`。

- **§180 一维列表当二维地图（索引公式 + 边界钳制）**
  `我的世界S`：`地图（方块ID）len=100000`，世界 800 × 125。
  `挖矿猫4`：`Blocks.type` 世界数组 `len=180000`。
  统一公式（**1-based**）：
  ```
  idx = y × 宽 + x + 1      →  ITEM(地图, idx)
  x = (idx-1) mod 宽        y = floor((idx-1) / 宽)
  ```
  `第一人称` 册（§137）用的是同一公式。**边界必须自己判**，Scratch 列表越界会返回空串而不是报错，
  空串参与运算会静默变成 0：
  ```yaml
  - if: {cond: {or: [
       {less_than: [{var: x}, 0]}, {greater_than: [{var: x}, {subtract: [{var: 宽}, 1]}]},
       {less_than: [{var: y}, 0]}, {greater_than: [{var: y}, {subtract: [{var: 高}, 1]}]}
     ]}, do: [{set_variable: {var: 方块ID, value: 0}}]}    # 出界当空气
  ```
  ⚠️ `mod` 的第二个操作数不能是 0（宽为 0 会得到 NaN，之后所有坐标都坏了）。

- **§181 对象池 + GC 计数：把 300 上限工程化**
  克隆上限 300 且**超限静默丢弃**（铁律 12）。三个工程的处理方式：
  - `挖矿猫4`：`ITEMS.Droppeditemclonesamount`（当前掉落物数）+ `ITEMS_oldest item timer`
    （最老物品计时，超时就删）→ **FIFO 淘汰**。
  - `忍者3D`：`Clone Count = 71` + **`GC Counter = 24`**（专门的垃圾回收节拍器）。
  - `忍者冒险`：`Global Next ID#`（ID 分配器）+ `ID# JUST GOT DELETED`（回收通知）+
    `delete all clones!!` 广播 + `Able to delete still? >:((`（删除闸门）。
  最小可用版（三段，直接照抄）：
  ```yaml
  # ① 分配
  - if: {cond: {less_than: [{var: 克隆数}, 200]}, do: [
      - change_variable: {var: 克隆数, by: 1},
      - create_clone_of: {clone: _myself_}]}
  # ② 回收（每个克隆体销毁前都要走这里）
  - when_receive: {message: 回收}
  - change_variable: {var: 克隆数, by: -1}
  - delete_this_clone: null
  # ③ 兜底：每 60 帧对账一次
  - if: {cond: {greater_than: [{var: 克隆数}, 280]}, do: [{broadcast: {message: delete all clones!!}}]}
  ```
  ⚠️ **`克隆数` 只增不减是这类作品最常见的崩坏原因**——玩家玩 2 分钟后敌人不再出现，
  但代码看起来完全正确。必须配「③ 对账」。

- **§182 存档码：把整个游戏状态压成一段可复制的字符串**
  `光线 v8` 的 `存档码复制板` = `["存档码是该列表的第二项，请复制：", "3725106", "再次按下w关闭"]`；
  `UP主模拟器` 的 `存档码` = `["0&0&|100&150&500&1…", "电脑点击三次复制，手机长按复制", "click three times…"]`，
  并配套广播 `数据处理-生成存档码` / `数据处理-备份存档码`。
  它的 `游戏数据-玩家数值`（len=12）就是**所有属性的平铺表** —— 存档 = 存这个列表。
  **编码规则**（两级分隔符，够用且可靠）：
  ```
  字段之间用 '&'        例：100&150&500&1.5&1000
  多张表之间用 '|'      例：0&0&|100&150&500&1.5&
  ```
  ```yaml
  # 序列化：遍历列表拼字符串（join 只能拼 2 个，必须循环累加）
  - set_variable: {var: 码, value: }
  - set_variable: {var: i, value: 0}
  - repeat: {times: {length_of_list: {list: 玩家数值}}, do: [
      - change_variable: {var: i, by: 1},
      - set_variable: {var: 码, value: {join: {a: {var: 码},
          b: {join: {a: {item_of_list: {list: 玩家数值, index: {var: i}}}, b: &}}}}]}
  ```
  **反序列化**必须用 `letter_of` 逐字符扫描累加（Scratch 没有 split）：
  遇 `&` 就「把当前累积串 push 进列表并清空」，否则 `累积串 = 连接(累积串, 当前字符)`。
  配合 `references/story-narrative.md` §151 的打字机写法是同一套字符遍历。
  ⚠️ 存档码**不要用云变量**（云变量只适合排行榜这类单值，见 §129）；存档码给玩家自己保管。

- **§183 纯计算库角色（`=` 前缀变量的真正用途）**
  Scratch 的自定义积木**没有返回值**。三个工程的解法一致：
  **把结果写进一个 `=` 前缀的变量，调用方读它**。
  `我的世界S` 甚至专门开了一个**只放函数、不画任何东西**的角色 `纯计算库`（325 块 / 7 个自制积木）：
  ```
  =点在矩形内?   =两线段相交?   =线段矩形碰撞?   =两点之间距离
  =两点曼哈顿距离  =点线距离     =线段与圆相交?
  ```
  ```yaml
  - define: {name: 两点之间距离, params: [x1, y1, x2, y2]}
  - set_variable: {var: =距离, value: {mathop: {operator: sqrt, num: {add: [
      {multiply: [{subtract: [{var: x2}, {var: x1}]}, {subtract: [{var: x2}, {var: x1}]}]},
      {multiply: [{subtract: [{var: y2}, {var: y1}]}, {subtract: [{var: y2}, {var: y1}]}]}
    ]}}}}
  # 调用方
  - 两点之间距离: {x1: 0, y1: 0, x2: {var: 玩家x}, y2: {var: 玩家y}}
  - set_variable: {var: 距离, value: {var: =距离}}
  ```
  ⚠️ `sqrt` 必须走 `mathop` 积木（`operator: sqrt`），没有以 sqrt 为键的简写积木。
  ⚠️ **两个坑**：① 自定义积木默认「不刷新屏幕」，几何计算要勾上 `warp`（立即执行）否则每块都渲染一帧，
  300 次调用直接卡死；② 返回值变量**必须调用后立刻读取**，中间插一个会改它的调用就被覆盖了。
  这就是 `光线 v8` 里 `=out:` 前缀的由来——一眼看出「这是临时返回值，不是游戏状态」。

- **§184 字符渲染：造型表 + 图章（Scratch 没有文字积木）**
  三种落地方式，按文本量选：
  - **单角色多造型**：`超级玛丽` 的 `Text`（37 造型 + `Letters` 列表 a..z + `ShowText` / `ListOfLetters`），
    `纪念碑谷` 的 `诗`（21 造型）。适合短句/标题。
  - **图章拼字**：`我的世界S` 的 `图章 绘制字符 %s (字符)` + `显示字符 %s %s %s %s %s (字符,x,y,size,间距)`，
    132 个字符造型，靠 `stamp` 批量成段。适合大段说明/UI。
  - **数字拆位**：`跳一跳3D` 把分数拆成 `得分千位/百位/十位/个位` 四个角色，纪录/总纪录再各拆四位。
    这是铁律 1「数字必须完整显示」的标准实现。
  ⚠️ 中文字符集很大，别给每个汉字做造型（几百张图直接爆包体）→ 长中文用 §202 的对话框 + `say`。

- **§185 绘制顺序（2.5D 的分层渲染）**
  Scratch 只有 `移到最前/后` 和 `前移/后移 N 层`，没有 z-index。
  `双人Apple跑酷` 为此开了一整套广播：`_order`（24 个接收者）/ `Report Order`（25）/ `order`（3）——
  **每帧把所有可见对象按 y 坐标排序，依次 `移到最前`**，就得到正确的遮挡关系。
  `忍者3D` 的 `Distances`（len=70，每个物体到相机的距离）是同一件事的 3D 版：
  **画家算法，远的先画**。
  ```yaml
  - when_receive: {message: _order}
  - go_to_front_back: {front_back: front}
  # 更省的做法：只对「可能重叠的同类对象」排序，别每帧排全场
  ```
  ⚠️ 每帧对 100 个对象排序 = 每帧 100 次「移到最前」，会明显掉帧。
  按 y 分桶（把屏幕切成 8 条横带，桶内才排序）可以把开销降一个数量级。

- **§186 五个致命坑**：
  1. **一个角色干所有事**：`忍者冒险` 最大的角色 1765 块、`双人Apple跑酷` 19191 块摊在 31 个角色上。
     特征是**按职责拆角色**（渲染/数据/计算/UI 各一个），不是按「看起来像什么」拆。
  2. **配置量被游戏改掉**：`#` 前缀的意义就在这。自检：搜一遍所有 `set_variable`，
     凡是改 `#` 开头的都在初始化脚本里，别处不能出现。
  3. **属性表长度不一致**（§179）→ ID 全错位，且**不报错**。加绿旗断言。
  4. **克隆数只增不减**（§181）→ 玩两分钟后新内容不再出现。必须有对账。
  5. **自制积木不开 `warp`**（§183）→ 几何计算每块刷新一帧，卡到没法玩。纯计算的一律开。
