# 第一人称（第十六册，§137–§141）

> 用户要「第一人称迷宫、射线投射、FPS 视角、第一人称探险」类作品时**先读这一册**。
> 配套可运行工程 `examples/firstperson.yaml`（5×5 迷宫 + 方向探测 + 撞墙守卫）+ 行为校验
> `scripts/firstperson_behavior_check.mjs`（`FP_LOGIC_OK`）。
> 严谨射线光追见 `references/deep-shadow-raycasting.md`、瓦片相机见 `references/deep-tile-camera.md`。
> 所有结论都经 scratch-vm 实跑验证，不是纸上推演。

- **§137 地图用一维列表 + 索引换算**：迷宫写成一行数字 `[1,1,1,1,1, 1,0,0,0,1, …]`（1=墙 0=地板）；
  格子索引 = `行*宽 + 列 + 1`（Scratch 列表 1-based）。示例 5×5，外圈留墙、内部留通道。
- **§138 前方探测 = 位置数学，不用 touching**：正前方 `(fx,fy) = (px + round(cos pdir), py + round(sin pdir))`。
  若 `fx/fy` 越界 **或** `ITEM(迷宫, fy*宽+fx+1) == 1` → `前方墙=1`；否则读地图得 0。
  ⚠️ **越界与读墙是「二选一」**，必须用真正的 if/else 区分（见 §141 坑），否则两者会被一起执行、
  把 `前方墙` 永远写成「读地图的值」。
- **§139 撞墙守卫移动**：收到 `[前进]` 时先 `IF 前方墙==0` 才更新 `px/py`——朝墙走不会穿透。
  转向用 `pdir = (pdir ± 90) mod 360`；左右键各自广播 `[左转] / [右转]`，方向键只发意图、舞台算数学。
- **§140 朝向与三角函数**：约定 `pdir=0` 东、`90` 北、`180` 西、`270` 南（y+ 朝上）；
  `round(cos/sin)` 把连续角度量化到 4 向网格。要「能看到墙的远景」用射线光追（第九册 §70 / §99、
  专项 `deep-shadow-raycasting.md`），要平滑跟随视角用瓦片相机（`deep-tile-camera.md`）。
- **§141 两个致命坑**：
  1. **`IF(c, A, B)` 没有 else 分支**——builder 的 `if` 只有 `do` 一个子栈，`A`、`B` 都会被并到 `do`
     一起执行。真正的「越界→墙 / 否则→读地图」必须写 `if` + `else`（我们的 `ir_helpers.IFELSE`
     生成的就是这种结构），否则 `前方墙` 永远被最后的「读地图」覆盖，撞墙检测失效。
  2. 列表读写在无头下走「变量存数组」——`ITEM` 能拿到值，但要在**同一轮计算里写完再读**，
     别跨帧假设地图已变；行为校验直接用 `setStageListArr` 注入棋盘后立刻广播探测。
