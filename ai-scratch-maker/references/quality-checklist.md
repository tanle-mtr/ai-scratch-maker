# 高质量 IR 编写实战清单（治本）

> **这份清单是「让 AI 默认写出高质量作品」的治本手段。**
> 铁律（`hard-requirements.md`）告诉你"不能做什么"，本清单告诉你
> **"写一个作品时必须主动做哪些事，才能从『能玩』变『像样』"**。
>
> 用法：**每写一个作品，按模块对照；交付前跑末尾三条命令。** 时间不够时
> 只做「优先级」里标 ★ 的 8 条——它们全是不加美术资源、只改数值和加中间变量，
> 却能吃掉 70% 的「粗糙感」（详见 `references/polish-and-feel.md` §235 优先级）。

---

## 0. 交付前三条自检（必跑，零美术成本）

```bash
# ① 观感质量门禁（渐变/缓动/圆角/配色合规，见 quality_gate C 层）
python scripts/quality_gate.py --sb3 examples/output/<作品>.sb3 --profile game
# ② UI 矢量资产合规（铁律 11：SVG 禁 text/filter/五层体积感）
python scripts/check_ui_assets.py examples/output/<作品>.sb3
# ③ 音效波形合规（铁律 12：分层响度/首尾归零/DC 偏移）
python scripts/check_audio_assets.py examples/output/<作品>.sb3
```

三条都出 `OK`，且 ① 的「观感质量分」≥ 60，才算过观感关。
（①②是脚本硬闸；③的观感分是软评分，低于 60 必须回看模块四。）

## 模块一 · 配色与窗口（铁律 8 / §197–§206）

> 用户说"丑 / 像 PPT / 蓝灰感"时，先查这一节，不要先换素材。

| # | 触发 | 常见翻车 | 正确做法 |
|---|---|---|---|
| 1.1 | 任何有界面的作品 | 随手挑 RGB、用浅灰做背景 | 颜色**只**从 `ui-design-spec.md` §198 的 **18 个 HEX** 取（`#FFCF4D` 主操作、`#3A8E7D` 主体、`#5FD100` 次要、`#7F7F7F` 设置） |
| 1.2 | 灰色出现时 | 用了冷灰（B 明显大于 R） | **冷灰一律禁止**；暖灰 `(x+7,x,x)`、正常灰 `(x,x,x)` |
| 1.3 | 绿色填充时 | 深绿 `#216E09` 做填充 | 深绿/深蓝绿**仅限文字**，不得做填充/边框 |
| 1.4 | 黄色做大面积时 | 黄色铺满主体 | **黄色不得做作品主体色**（只做主操作键/署名点缀）；主体取蓝绿 |
| 1.5 | 任何窗口/面板/弹窗 | 普通矩形 + 描边凑数 | **一切窗口都是圆角矩形**（`rx` = 短边 × 0.06~0.10） |
| 1.6 | 大窗口（弹窗/菜单） | 不透明矩形压画面 | 25% 透明底色（`GHOST=25`）+ 右上角 ≥80% 透明的关闭图标（高度 ≥ 窗口高 30%） |
| 1.7 | 任何颜色字面量 | 写 `#FC4` 或 `#FFCF4D80` | **必须是 6 位 HEX**；半透明只走「颜色不透明 + 角色 GHOST」（带 alpha 直接 `SCHEMA_FAIL`） |

**自检**：颜色字面量扫一遍，确认没有冷灰、深绿填充、三位缩写。§206 七问逐条过。

## 模块二 · UI 矢量与体积感（铁律 11 / §252–§254）

> 用户说"素材太丑 / 像色块"时，问题在工艺不在审美。

| # | 触发 | 常见翻车 | 正确做法 |
|---|---|---|---|
| 2.1 | 按钮/面板/图标/进度条/角标 | 用生图模型画按钮（高光随机、改字要重画） | **UI 控件全部走 SVG**（画面主体才用位图） |
| 2.2 | 每个按钮 | 圆角矩形 + 一条描边 | **按钮五层**：投影 → 外描边 → 渐变主体 → 顶部高光 → 底部内阴影（**顺序不能换**） |
| 2.3 | 每个可交互控件 | 只有 normal 一态 | **四状态换造型不缩放**：hover 提亮 / pressed **渐变反转**（上暗下亮）/ disabled 去饱和 0.62 |
| 2.4 | 写 SVG 时 | 里面写 `<text>` 放中文（换台变豆腐块） | **SVG 禁用** `text` / `filter` / `mask` / `clipPath` / `pattern` / `image`（`check_ui_assets.py` 直接判错） |
| 2.5 | 派生色时 | 调饱和度做出一堆荧光色 | 颜色**只调明度不调饱和度**：从 §198 的 18 色派生 5 阶 |
| 2.6 | 面板/进度条 | 一套尺寸硬拉、一张图拉伸当进度条 | **面板预出四档**（Scratch 无九宫格）；**进度条预出 10 档**（不拉伸，圆角拉成针尖） |

**自检**：`python scripts/check_ui_assets.py` → `UI_ASSETS_OK`；再做一次
「整屏截图缩到 25%，还能分清按钮/背景/弹窗」的终检。

## 模块三 · 质感与交互曲线（铁律 9 / §222–§235）★核心

> **核心结论：质感不是加特效，是消灭瞬变。** 粗糙作品里所有量都是
> 「这一帧 A、下一帧 B」；高级作品里任何量从 A 到 B 中间都有帧。
> 用户说"AI 味 / 太粗糙"时，**先查这一节，别换素材**。

| # | 触发 | 常见翻车 | 正确做法（参数） |
|---|---|---|---|
| 3.1 ★ | 任何位移/缩放/透明度变化 | 瞬间跳变（`移到 x:100` 一帧到位） | **一切变化有帧**：用 `x += (目标-x)*0.2` 指数逼近，3–5 帧到位（角色跟随 k=0.35 / UI k=0.25 / 镜头 k=0.12） |
| 3.2 ★ | UI 弹出/奖励图标 | 精准停在目标，像贴图 | **到位有过冲**：`0.6 → 1.15 → 0.96 → 1`（小+12% / 中+6% / 全屏+3%，越大越收敛） |
| 3.3 ★ | 按钮 | 点了没反馈 | **UI 四态微交互**：静止 → 悬停 ×1.05 → 按下 ×0.95 → 释放回弹（**按下必须 1 帧内响应**） |
| 3.4 ★ | 分数/金币/血量 | 直接 `显示值=真实值` | **数字滚动**：`显示值 += (真实值-显示值)*0.25`，差值<1 时吸附 |
| 3.5 ★ | 血条/进度条 | 单条直接变 | **双层追赶**：即时条（红）立刻变 + 追赶条（白）`+= (当前-长度)*0.10` 慢半拍 |
| 3.6 | 有力动作（跳/落/击） | 匀速电梯感 | **Squash & Stretch**：落地 `size 72→88→100` 三帧；或用造型序列（正常/压扁/拉长） |
| 3.7 | 打击命中 | 像打空气 | **顿帧 1–5 帧**（轻1/中2–3/重4–5/杀6–8），且**必配闪白或击退**（只有顿帧=掉帧） |
| 3.8 | 多元素同时出现 | 8 个一起蹦 = 噪音 | **错峰**：第 i 个延迟 `i×3` 帧，总时长 < 0.6s |
| 3.9 | 危险/敌人出场 | 突然冒出 = 不公平 | **预备动作**：边缘警示闪烁 + 音效 10–20 帧；Boss 攻击蓄力圈 20–40 帧 |
| 3.10 | 震屏 | 每帧都在震 | **震屏 2–4px 衰减归零**（普通2–3/爆炸6–8/落地3），用 `random` 非 `sin`；幅度显式清零 |
| 3.11 | 场景有纵深时 | 画面平 | **三层视差** 0.2/1.0/1.5+ + **影子**（复制角色 y-6~-10、GHOST 55~70、size 85~95，不跟 squash） |
| 3.12 | 跳跃/攻击手感 | 不跟手 | **输入缓冲**（落地前 6 帧按下也算）+ **土狼时间**（离台 6 帧内可跳），成本 2 变量 |

**自检**：过 `polish-and-feel.md` §235 的 20 条打磨 checklist；把画面截图**去色**，
灰度下还能分清主次 = 配色合格。

⚠️ **帧率无关**：Scratch 默认 30fps。若按 60fps（TurboWarp）调过 k 值，
回 30fps 会慢一倍，补偿 `k_30 = 1-(1-k_60)²`（k=0.2→0.36）。

## 模块四 · 音效四层响度（铁律 12 / §263–§276）

> 用户说"没游戏感 / 吵 / 像课件"时，问题几乎总是响度不分层。
> **默认音效 + BGM 即可**（铁律 17），只有明确要"扒谱/演奏"才用 `audio2notes.py`。

| # | 触发 | 常见翻车 | 正确做法（参数） |
|---|---|---|---|
| 4.1 ★ | 任何音效 | 全归一化到 0.85 → 点按钮和爆炸一样响 | **四层响度**：`ui` −18 / `fx` −9 / `ev` −3 / `amb` −15 dBFS，层间差 6~9 dB |
| 4.2 ★ | UI 音 | 用「播放声音直到结束」（阻塞脚本） | **UI 音用「播放声音」（不等待）**；悬停音**≥120ms 节流**；同帧不超 3 个音效 |
| 4.3 ★ | 任何短音效 | 首尾不归零 → 咔哒声 | **首尾必须归零**，淡入淡出 = `min(10ms, 时长×15%)`；**DC 偏移 < 0.01** |
| 4.4 | `ui` 层音效 | 超过 0.25s 像拖音 | **ui ≤ 0.25s**（fx 80~600ms / ev 300~1600ms / amb 循环 1~4s） |
| 4.5 | 得金币/升级/胜利 | 音高方向反了（下行=获得） | **音高方向=语义**：上行=获得/开启，下行=失去/关闭，平+颤=警报 |
| 4.6 | 连续同音效 | 像机关枪 | **音高随机 ±5**（半音左右），超过 ±15 走调 |
| 4.7 | BGM | 从头播到尾不变化 | 4 小节循环 + 音量随状态起伏（战斗 60 → 探索 35）；用 `gen_audio.py bgm` |
| 4.8 | 重要事件音 | BGM 压不住 | **ducking**：播 `ev_*` 时 BGM 瞬间压到 40%，缓动 0.3s 恢复（非硬切） |

**自检**：`python scripts/check_audio_assets.py` → `AUDIO_ASSETS_OK`
（查格式/分层响度/首尾归零/尾部衰减/DC 偏移/削波/时长，22 音效 0 错 0 警）。
命名 `{层}_{名}.wav`（`ui_click`/`fx_coin`/`ev_win`/`amb_rain`）让脚本自动套音量。

## 模块五 · 逻辑红线速记（呼应铁律，不重复全文）

| 铁律 | 一句话 | 翻车现场 |

| 1 | 数字精灵必须完整显示 + 文字标签 | 多位数字重叠/被切，玩家不知是分数还是时间 |

## 优先级 · 时间不够时先做这 8 条（★ 标）

```
第 1 优先（决定「跟手」，只改输入）：       3.3 按钮四态 · 3.1 缓动 · 4.2 UI 音不阻塞
第 2 优先（决定「顺滑」，只改数值）：       3.4 数字滚动 · 3.5 双层血条 · 4.1 四层响度
第 3 优先（决定「有力」，加几行 wait）：    3.7 顿帧 · 3.10 震屏衰减
```
**这 8 条全是不加美术资源、只改数值 + 加中间变量，但吃掉 70% 粗糙感。先做这 8 条，再谈特效。**

## 与验收网的关系

- 本清单是**编写侧**引导（治本）：AI 写 IR 时主动应用，作品天然高质量。
- `quality_gate.py` 的 **C 层「观感质量」** 是**验收侧**兜底（治标）：把本清单里
  **可静态检**的维度（渐变体积感 / 缓动过渡 / 窗口圆角 / 配色合规）量化成评分，
  交付时拦住"技术完整但观感拉胯"的作品。
- 二者互补：**清单让 AI 默认写好，门禁保证没写好的不会被悄悄交付。**
