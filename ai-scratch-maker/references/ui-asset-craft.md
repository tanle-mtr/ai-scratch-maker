# UI 素材制作：从「能看」到「能卖」（第二十八册，§249–§262）

> **用户说「素材太丑 / 看着廉价 / 像 PPT / 不如别人做的好看」时读这一册。**
>
> 第二十四册（`references/ui-design-spec.md`）管的是**规范**：用什么色、什么形状、什么字号。
> 这一册管的是**工艺**：同样的规范，怎么做出「有体积、有厚度、有状态」的素材 —— 以及
> 哪些做法看着没问题、装进 Scratch 一定翻车。
>
> 配套工具（都在 `scripts/`）：
> - `gen_ui_kit.py` —— 生成 164 个纯矢量素材（按钮 / 面板 / 进度条 / 图标 / 角标 / 装饰 / 文字条）
> - `check_ui_assets.py` —— 素材合规闸门（结构 / 配色 / 网格 / 一致性），跑出 `UI_ASSETS_OK`
> - `prep_asset.py` —— 位图素材后期（裁透明边 / 抠背景 / 统一尺寸 / 镜像）
>
> 预览：`examples/assets/uikit/preview.html`（**装进 960×540 的一整屏里看**，不是素材清单）。

## §249 素材是作品的一半：廉价感的五个真实来源

「代码很好但看着廉价」不是审美问题，是**工艺缺失**。按出现频率排：

| # | 症状 | 真实原因 | 在哪一节修 |
|---|---|---|---|
| 1 | 按钮像色块 / 像 PPT 形状 | 只有「填充 + 一条描边」，**没有投影、没有高光、没有渐变** | §253 |
| 2 | 点击没反应 / 反应很假 | 只有一种状态图，靠缩放 0.9 假装按下 | §254 |
| 3 | 字糊、锯齿、有白边 | 直接按目标字号画，或把大字图缩小复用 | §258 |
| 4 | 一屏里三个东西风格不同 | 有的矢量有的位图、有的圆角有的方角、描边粗细不一 | §251 §257 |
| 5 | 面板一放大就变形 | 拿一张图硬拉伸（**Scratch 没有九宫格**） | §255 |

**一条判断标准**：把界面截图缩小到 25%，如果还能看出「哪块是按钮、哪块是背景、哪块是弹窗」，
说明层次是够的；如果糊成一片同色，缺的就是投影和描边（§253）。

## §250 矢量 vs 位图：这张表决定你该用哪个

| | 矢量 SVG | 位图 PNG |
|---|---|---|
| 缩放 | **无损**（放到 400% 依然锐利） | 糊（尤其放大 >150%） |
| 体积 | 1~3 KB | 20~200 KB |
| 改色 | 改一行字符串 | 要重画 |
| 能做渐变/多层 | 能，且文件不变大 | 能，但要在 PS/PIL 里做 |
| 能做插画细节 | 不能（要人写路径） | **能**（生图/手绘） |
| 适合 | **UI：按钮/面板/图标/进度条/角标** | **背景/角色立绘/贴图** |

**结论：UI 全部走矢量，画面主体走位图。** 混着来没问题，但不能在同一个控件里混。

⚠️ 最常见的翻车：**用生图模型画一个按钮**。生图出来的按钮有随机的高光位置、不一致的圆角、
莫名的纹理，而且**改一个字要重画整张**。按钮是「几何 + 五层叠加」，用矢量 20 行代码就能做到位。

## §251 Scratch 的安全 SVG 子集（这条不遵守，素材会「看着好好的，装进去就坏」）

Scratch 的造型不是「浏览器直接渲染一个 SVG」那么简单：它要经过舞台/角色/克隆的缩放、
不同运行环境（官方 / TurboWarp / 移动端）的光栅化路径。所以只能用**确定可控**的子集：

### ✅ 可以放心用

```
<svg> <g> <defs>
<path> <rect> <circle> <ellipse> <polygon> <polyline> <line>
<linearGradient> <radialGradient> <stop>
属性：fill / stroke / stroke-width / stroke-linecap / stroke-linejoin
      opacity / fill-opacity / stop-opacity
      transform="translate/scale/rotate"
```

### ❌ 不要用（`check_ui_assets.py` 会直接报错）

| 特性 | 为什么不能用 | 替代做法 |
|---|---|---|
| `<text>` / `<tspan>` | 中文字体在造型链路里不可控：换台机器可能变豆腐块、可能不居中、可能丢字 | 文字条位图 / 拆位造型（§258） |
| `filter` / `feGaussianBlur` | 模糊与阴影在不同渲染路径下不一致，缩放时边缘会糊成一圈 | **多层半透明叠加**（§253） |
| `mask` / `clipPath` | 支持不稳定，某些环境直接丢 | 直接画成需要的形状 |
| `pattern` | 同上 | 用循环画多个小图形 |
| `<image>` | **sb3 只打包外层文件**，内嵌位图会丢，造型变空白 | 单独做一张 PNG 当造型 |
| `font-family` | 同 `<text>` | —— |

**这条不是「保守」，是「可预测」**：你无法在 Scratch 里调试一个「在你这台机器上没事」的 SVG。
用确定支持的子集，行为就只有一个。

### 阴影怎么做（没有 filter 的正确姿势）

```
第 1 层：黑色 18%，形状整体向下偏移 3px，圆角比本体大 1     ← 投影
第 2 层：基色暗 42%，同尺寸                                  ← 外描边
第 3 层：渐变主体，内缩 2.5px（正好等于描边宽度）            ← 本体
第 4 层：白色 26%，贴顶部，左右再内缩 4px                    ← 高光
第 5 层：黑色 10%，贴底部，短一点                            ← 内阴影
```

五层「平涂」叠起来，观感等价于一个带阴影的立体按钮，而且**任何缩放级别都不会糊**。

## §252 18 色做出 5 阶明度：一套配色怎么撑起整套素材

§198 只给了 18 个 HEX。硬用这 18 个颜色画控件，会得到「一堆同色度的色块」。
正确做法是**只改明度、不改色相**：

```
shade(color, f)   f > 0 朝白走，f < 0 朝黑走
    外描边   = shade(基色, -0.45)
    渐变顶   = shade(基色, +0.12)
    渐变底   = shade(基色, -0.15)
    按下顶   = shade(基色, -0.16)
    按下底   = shade(基色, +0.10)
```

这样 18 个颜色能派生出 **18 × 5 = 90 个可用色阶**，而且整套素材看上去同源。

**唯一例外**：§199 的状态暖红 `#D9603F`（错误 / 危险 / BOSS 血条）。
它是「状态色」不是「配色」，可以突破 18 色限制，但只能用在错误语义上。

⚠️ **不要靠调饱和度制造层次**。饱和度一降，颜色就变「灰扑扑的塑料」，这正是廉价感的来源之一。
层次靠明度，不靠饱和度。

## §253 体积感五层结构：这是「不像色块」的全部秘密

以 180×56 的按钮为例（`gen_ui_kit.py: button_svg()`）：

```
① 投影      rect(0, 3, w, h, rx=r)              fill=#000  opacity=0.18
② 外描边    rect(0, 0, w, h, rx=r)              fill=shade(base,-0.45)
③ 主体      rect(2.5, 2.5, w-5, h-5, rx=r-2.5)  fill=linearGradient(顶+12% → 底-15%)
④ 顶部高光  rect(6.5, 4, w-13, h*0.42, rx=…)    fill=#FFF  opacity=0.26
⑤ 底部内阴影 rect(4.5, h-sh-1, w-9, sh)         fill=#000  opacity=0.10
```

四个必须遵守的比例（不是随手写的）：

| 参数 | 值 | 为什么 |
|---|---|---|
| 圆角 | 短边 × **0.30** | 按钮比窗口更圆（窗口 0.08），才有「按下去软」的感觉 |
| 描边宽 | **2.5px**（尺寸无关） | 细了像没边，粗了像贴纸 |
| 顶部高光高 | 本体高 × **0.42** | 模拟圆柱受光面；超过 0.55 就变成「上下两半」 |
| 内阴影高 | 本体高 × **0.22** | 只贴底一点点，多了像污渍 |

**层级顺序不能换**：投影在最下、高光在最上。顺序错了会出现「高光被描边切掉」这种硬伤。

## §254 按钮必须有四种状态，而且差别要一眼看得出

| 状态 | 做法 | 视觉检验 |
|---|---|---|
| `normal` | 标准五层 | —— |
| `hover` | 基色 +10%，投影保持 | 比 normal **明显亮一档** |
| `pressed` | 基色 −10%，**去掉投影**，整体下移 2px，**渐变反转**（上暗下亮），高光 0.26→0.05 | 像「陷进去」 |
| `disabled` | 去饱和 0.62 + 白色蒙版 0.30 | 灰但**还能认出是哪个按钮** |

### ⚠️ 坑 1：pressed 只是「变暗一点」

只调暗 4% 的话，玩家根本感觉不到按下去了。**关键在于渐变反转**：
光从上面来，凹进去的东西**上沿在阴影里、下沿在反光里**。

```
normal :  顶 +12%  →  底 -15%     （上亮下暗 = 凸起）
pressed:  顶 -16%  →  底 +10%     （上暗下亮 = 凹陷）
```

### ⚠️ 坑 2：disabled 白成一片

去饱和 0.8 再加 0.42 白色蒙版 → 五个按钮全变成同一个白色，玩家分不清哪个是「设置」哪个是「删除」。
**去饱和到 0.62、蒙版 0.30** 是经验值：既明显「不可用」，又保留色相识别。

### ⚠️ 坑 3：靠 `size` 缩放假装按下

`按下 → 大小设成 90` 会让**文字一起缩**，而且按钮边缘会糊。
正确做法是换造型（四张图），缩放只用于「悬停轻微放大 1.05」这种微交互（§231）。

## §255 Scratch 没有九宫格：面板只能出成套固定尺寸

Web 里一个 `border-image` 就能让面板任意拉伸。**Scratch 没有这个能力**：
造型只能整体缩放，一拉宽圆角和描边就变形。

所以正确做法是**预出四档**，用的时候选最接近的那一档：

| 名字 | 尺寸 | 用途 |
|---|---|---|
| `panel_toast` | 260×72 | 底部一行提示 |
| `panel_tip` | 320×96 | 两行提示 / 奖励弹窗 |
| `panel_card` | 360×200 | 关卡卡片 / 角色介绍 |
| `panel_dialog` | 440×280 | 大窗口（设置 / 结算 / 暂停） |

**为什么是这四个数**：舞台 480×360。
- 320 = 屏宽 2/3，两行字刚好不挤；
- 360 = 屏宽 3/4，放得下「标题 + 图 + 一行说明」；
- 440 = 屏宽 92%，留 20px 边距，正是大窗口的常见比例（§201 要求留边）。

### 大窗口必须配遮罩

`decor_mask.svg`（480×360 半透明黑，默认 0.55）。没有遮罩，弹窗和背景糊在一起，
玩家看不出「现在被这个窗口挡住了」。

顺序：`遮罩 → 面板 → 内容 → 关闭按钮`。遮罩用 0 号图层（最底），关闭按钮在最上。

### 圆角分三档，不要一律 12

| 元素 | 圆角 | 观感 |
|---|---|---|
| 窗口 / 面板 | 短边 × **0.08** | 稳重（§200 规范值） |
| 卡片 | 短边 × **0.12** | 轻盈 |
| 按钮 / 标签 | 短边 × **0.30** | 亲和、可按 |

一律用同一个圆角，界面会显得「一个模子刻出来的」。

## §256 进度条：换档，不要拉伸

血条 / 经验条最常见的错误写法：

```
把「满条」造型的宽度设成 当前值/最大值 × 满宽
```

问题：**圆角会被拉扁**。10% 的时候，一个胶囊变成一根两头尖的针。

正确做法：**预出 10 档图（0/10/…/100），按档换造型**。

```
档位 = round(当前值 / 最大值 * 10)      // 0~10
换成造型 [join "bar_hp_" (补零到三位 档位*10)]
```

代价是 10 张图（每张 1~2 KB），收益是**任何百分比都保持完整圆角**。

结构上分三层：
1. 轨道：外描边 + 内凹（顶部压暗 22%，模拟凹槽）
2. 填充：渐变 + 顶部高光 34%
3. （可选）分段刻度：每 25% 一条 1px 竖线

⚠️ 填充色的**长度变了，圆角不能跟着变**。所以填充条要按「当前宽度」重新算 `rx = 高/2`，
而不是复用满条的 `rx`。

## §257 图标：24 网格 + 2px 线宽 + round 端点

一套图标丑，90% 是这三个不统一：

| 规则 | 值 | 违反后的样子 |
|---|---|---|
| 画布 | **24 × 24** | 大小不一，一排看过去参差不齐 |
| 线宽 | **2px** | 有的粗有的细，像从不同图标库拼的 |
| 端点/拐角 | `round` | 直角端点看着「硬」，圆角端点看着「手作」 |
| 视觉重心 | 内容占 4~20（留 4px 内边距） | 贴边 = 显小；太满 = 显胖 |
| 颜色 | 一套浅色（白）+ 一套深色（`#4F4A47`） | 每个图标单独调色 → 不统一 |

```svg
<g fill="none" stroke="#FFFFFF" stroke-width="2"
   stroke-linecap="round" stroke-linejoin="round">
  <path d="M7 7 L17 17 M17 7 L7 17"/>
</g>
```

**线性图标（stroke）比实心图标（fill）更容易做统一**，因为线宽是全局参数。
只有 `play` / `pause` / `stop` / `star` / `heart` 这类「形状即语义」的适合实心。

⚠️ 图标放大到 40px 会暴露路径精度问题（比如齿轮的齿变成锯齿）。
`gen_ui_kit.py` 里的齿轮是**用极坐标算出来的 8 齿**，不是手画的近似多边形 —— 放大依然工整。

## §258 文字：三条路线，选错了必糊

Scratch 里显示中文只有三条路，各有明确适用面：

| 路线 | 做法 | 适合 | 代价 |
|---|---|---|---|
| **A. 位图文字条** | PIL 按 3× 画好再缩回，导出 PNG，贴到按钮上 | 按钮字、标题、固定短语 | 改字要重出图 |
| **B. 拆位造型** | 每个汉字一个造型（或几十个常用字），拼字 | 数字、血量、分数、可变文本 | 中文字库大，只适合小字符集 |
| **C. 气泡** | `说` / `想` 积木 | **不要用于 UI** | 样式不可控、会遮挡、手机端位置飘 |

### ⚠️ 坑 4：直接按目标字号画中文

28px 的中文，横画只有 2~3 px 高，直接画会掉笔画、出锯齿。**必须 3 倍超采样再缩回**：

```python
big = font_px * 3
font = ImageFont.truetype("msyhbd.ttc", big)      # 3× 字号
d.text(..., font=font, stroke_width=2*3)           # 描边也 3×
img = img.resize((W//3, H//3), Image.LANCZOS)      # 缩回，等于免费拿到 3× 抗锯齿
```

`gen_ui_kit.py: render_text_png()` 就是这么做的。

### ⚠️ 坑 5：把一张大字图缩小当小字用

缩到 60% 时，**描边一起被缩到 1.2px**，笔画开始发虚，深色描边变成一圈灰边。
正确做法：**按每个字号分别出图**（`text_开始游戏_20_d.png` / `text_开始游戏_30_d.png`）。

### ⚠️ 坑 6：白字配浅底

白字 + 深描边贴在米白面板上，会变成「灰字 + 一圈脏边」。
**文字条必须分深浅两版**：
- `_d`（deep）：深字 `#4F4A47` + 浅描边 `#FFFDF7` → 配浅底（面板 / 黄按钮）
- `_l`（light）：白字 `#FFFFFF` + 深描边 `#4F4A47` → 配深底（青按钮 / 大窗）

## §259 位图素材的后期：四步把「生图直出」救回来

生图模型给的图不能直接用，`scripts/prep_asset.py` 做四件事：

1. **裁透明边**：生图常带一圈空白，不裁会导致角色「看着小、判定大」（铁律 4 的隐形杀手）。
2. **统一尺寸**：同一批素材缩到同一高度（如角色 120px、图标 64px），否则一屏里大小不一。
3. **抠背景**：纯色背景用色差抠；复杂背景要重画或换生成提示词。
4. **加描边/投影**：位图角色加 2px 深色描边，立刻和矢量 UI「同一个世界」。

⚠️ **位图不要缩放超过 1.5 倍**。Scratch 里 `size` 设到 150 以上，边缘就开始糊 ——
需要大图就重新生成大图，不要放大。

⚠️ **透明背景的 PNG 要检查 alpha**：有些生图工具导出的是「白底」而不是「透明」，
在深色背景上一眼看出白框。用 `prep_asset.py --check-alpha` 查。

## §260 背景与插画：生图用在这里才划算

背景是唯一「值得用生图」的地方 —— 它要的是氛围和细节，不是精确的形状。

三条硬要求：

1. **尺寸必须是 480×360 的整数倍比例**（或直接 480×360 / 960×720 再缩），否则会被拉伸变形。
2. **主视觉要留白**：标题和按钮会压在中间 60% 区域，背景的「内容」（人物/建筑）要放在边缘。
3. **降低对比度**：背景饱和度比 UI 低 20~30%，否则会和按钮抢注意力。

⚠️ **背景不要带文字**。生图模型生成的中文 100% 是乱码，看起来像水印。

| 3 | 颜色都在 §198 四色系内（黄/绿/青绿/暖灰） | `check_ui_assets.py` |
| 4 | 按钮有 4 个状态，且差别一眼看得出 | 并排贴出来看 |
| 5 | 按钮尺寸在 120×44 / 180×56 / 260×68 三档 | `check_ui_assets.py` |
| 6 | 面板有 4 档尺寸，大窗配了遮罩 | 数一下 |
| 7 | 进度条是 10 档图，不是拉伸 | 看 10% 档圆角是否完整 |

## §262 廉价 vs 专业：同一屏的对照

| 元素 | 廉价做法 | 专业做法 |
|---|---|---|
| 按钮 | 一个圆角矩形 + 一条描边 | 投影 / 描边 / 渐变 / 高光 / 内阴影 五层 |
| 按钮状态 | 只有一张图 | 4 张图，pressed 渐变反转 |
| 面板 | 白色圆角矩形 | 双描边 + 角饰 + 顶部内高光 + 遮罩 |
| 标题 | 直接写字 | 缎带底 + 文字条 + 描边 |
| 进度条 | 拉伸一张图 | 10 档换图，圆角恒定 |
| 图标 | 每个单独调 | 24 网格 / 2px / round / 两套颜色 |
| 文字 | 按目标字号直接画 | 3× 超采样 + 描边 + 深浅两版 |
| 配色 | 随手挑 RGB | 18 色 + 明度派生 5 阶 |
| 装饰 | 没有 | 光斑 / 星芒 / 角标，2~3 个就够 |

**一张图的差距不在「画得多细」，在「有没有那五层」。**
`gen_ui_kit.py` 里每个按钮 20 行 SVG、1.5 KB，观感不输手绘素材 —— 因为它该有的层都有。
