# UI 设计规范（第二十四册，§197–§206）

> **做任何有界面的作品（菜单/设置/结算/弹窗/主操作键）之前先读这一册。**
> 本册不是「审美建议」，是一套**可直接取色的设计系统**——源自杰森工作室
> 《新UI设计规范、取色及风格公告》（2025.12.28），含精确 HEX 值与强制约束。
> 配套素材生成器 `scripts/make_ui_assets.py`（数字/计数器/对话框底板）。

- **§197 四色系分工（先定优先级，再取色）**：工作室把颜色按**模块重要性**分成四档，
  取色的第一件事不是「好不好看」，而是判断这个模块属于哪一档：

  | 档次 | 色系 | 用在哪 | 硬约束 |
  |---|---|---|---|
  | 最高 | **黄色系** | 内置模块、开屏动画、主操作按键、排行榜、工作室/成员署名 | 饱和度越高 = 重要性越大；**黄色不得作为作品主体色** |
  | 次 | **绿色系** | 次要功能、验证类（防盗验证、开关门、副操作按键、大站快车） | 不得大范围使用；深浅要覆盖均匀 |
  | 主体 | **蓝绿色系** | 单功能程序主体、按钮、突出文字、副功能、**大模块填充** | **大模块必须用蓝绿**；替换色必须蓝绿而非亮绿 |
  | 辅助 | **灰色系** | 设置、弹窗提示、插件 | **插件功能必须灰色**，不得用其他色系；不用浅灰（底色除外） |

  ⚠️ 题目本身有主体色时（如地铁模拟）——**主体色应取线路颜色**，黄色只做点缀。

- **§198 调色板（直接抄这 18 个 HEX）**：

  ```
  黄色系  #FFCF4D  标准黄（工作室名/成员名/主按钮）
          #FFEDB3  浅黄（底色/次级）
          #FAF19B  浅黄替代（搭配不佳时换）
          #4F4A47  深灰棕（压在黄色上的文字）
          #876C26  深黄——已从工作室色系移除！场景不冲突时才可考虑

  绿色系  #32AF00  标准绿
          #5FD100  亮绿
          #8CE243  浅绿
          #C6FF2A  替代亮绿（必须亮绿，不许偏蓝绿）
          #216E09  深绿——**仅限文字**，不得做填充/边框

  蓝绿色  #3A8E7D  标准蓝绿
          #5CD9BA  亮蓝绿
          #C4FFE3  极浅蓝绿（底色）
          #67F6D5  替代蓝绿（必须蓝绿，不许变亮绿）
          #2F7365  深蓝绿——仅限文字

  灰色系  #767171  暖灰（配黄/亮绿时用）
          #675D5D  深暖灰
          #7F7F7F  正常灰（配蓝绿时用）
  ```

  灰的取法有数学定义，别乱取：**暖灰 `R=G+5~10, G=B`**（即 `(x+7,x,x)`），
  **正常灰 `R=G=B`**（即 `(x,x,x)`）。**冷灰（B 明显大于 R）一律禁止**。

- **§199 状态色（出错/通过/提示）**：
  - **出错**三选一：① 暖黄 + 暖红（大型报错模块）；② 仅亮红或橘红（小型报错提示）；
    ③ 仅肉黄（非重要的小提示）。
  - **通过**：亮绿色系。
  - **其他弹窗**：用其所属功能的色系；无归属时用灰色系。

- **§200 窗口铁律：一切窗口都是圆角矩形**。规范原文「所有窗口均需使用圆角矩形，而非普通矩形」。
  Scratch 里的三种做法（按推荐度排）：
  1. **矢量造型**（最好）：`scripts/make_ui_assets.py` 生成 SVG 底板，或在编辑器里给矩形设
     `rx`（圆角半径建议 = 短边 × 0.06~0.10）。一个角色一套造型，换造型即可换尺寸。
  2. **画笔**：`pen` 画圆角 = 四条直线 + 四个 1/4 圆弧（`pen` 无圆弧积木 → 用小步长折线近似）。
  3. **图章**：`stamp` 一次成型，避免每帧重画。
  ❌ 别用「普通矩形 + 描边」凑数——这是规范明确禁止的。

- **§201 大窗口规范**：居中；**25% 透明的底色**（`GHOST = 25`，注意 Scratch 的 GHOST 0=不透明、
  100=全透明，想要 25% 透明就设 25）；**右上角必须有 ≥80% 透明度的关闭图标**，
  且图标**高度 ≥ 窗口高度的 30%**（`图标大小 = 窗口高 × 0.3`，别靠肉眼估）。
  → 关闭图标点击后广播 `[关闭弹窗]`，不要直接 `stop this script`（会把整个弹窗逻辑打断）。

- **§202 小型提示规范**：位置**在作品下方**（y 取负半屏偏下）；动画**从底部向上弹出 + 从完全透明渐显**。
  Scratch 写法（两段滑行 + 透明度收尾）：
  ```yaml
  # 出现：初始 y 在屏幕外，GHOST=100；目标 y 与 GHOST=0
  - set_y: -260
  - set_effect: {effect: GHOST, value: 100}
  - show:
  - glide_secs_to_xy: {secs: 0.25, x: 0, y: -150}
  - repeat: {times: 12, do:
      - change_effect: {effect: GHOST, value: -8}}   # 100 → 4，近似渐显
  ```
  ⚠️ `GHOST` 必须**大写**（`change_effect{effect:GHOST}`），小写会静默不生效。

- **§203 颜色写的必须是 6 位 HEX**：`#FFCF4D` ✅、`#FFCF4D80` ❌（带 alpha 直接 `SCHEMA_FAIL`）、
  `#FC4` ❌（三位简写不认）。半透明**只有一条路**：颜色给不透明值 + 角色设 `GHOST` 特效。
  这条和铁律「颜色字面量必须 `#rrggbb` 六位」同源。

- **§204 界面字体与数字显示**：Scratch 没有文字渲染积木，两种落地方式——
  ① **造型表**：每个字符/数字一张造型，角色按值换造型（呼应铁律 1「数字必须完整显示」，
    分数拆成 千/百/十/个 四个角色是最稳的做法，见 `references/game-architecture.md` §184「字符渲染」）；
  ② **图章拼字**：`图章 绘制字符 %s (字符)` + `显示字符 (字符,x,y,size,间距)`，
    适合大段文字（我的世界S 就是用 132 个字符造型 + 图章拼出整个界面）。
  字号层级建议：标题 = 屏高 × 0.09、小标题 × 0.06、正文 × 0.045、注释 × 0.035。

- **§205 各品类的取色配方**（把 §197 落到具体作品）：
  | 作品类型 | 主体 | 主操作键 | 次操作键 | 设置/弹窗 |
  |---|---|---|---|---|
  | 地铁/交通模拟 | 线路色（官方色） | `#FFCF4D` | `#5FD100`（开关门/验证） | `#7F7F7F` |
  | 平台跳跃/动作 | `#3A8E7D` | `#FFCF4D`（开始/重开） | `#5FD100` | `#767171` |
  | 解谜/休闲 | `#5CD9BA` | `#FFCF4D` | `#8CE243` | `#7F7F7F` |
  | 教育课件 | `#C4FFE3`（底色）+ `#3A8E7D` | `#FFCF4D` | `#32AF00` | `#767171` |
  | 剧情/视觉小说 | `#4F4A47`（文字） | `#FFCF4D`（选项） | `#5FD100` | `#675D5D` |

- **§206 交付前 UI 自检七问**：
  1. 每个窗口都是**圆角**吗？（不是普通矩形）
  2. 大窗口有 **25% 透明底色** + **右上角 ≥80% 透明的关闭图标**（高度 ≥ 30%）吗？
  3. 颜色是**四色系里的 HEX** 吗？有没有出现**冷灰**、**深绿做填充**、**黄色做主体**？
  4. 插件/设置类**全是灰色系**吗？（规范是强制的）
  5. 小提示是**从底部向上弹出 + 渐显**吗？
  6. 所有颜色字面量都是 **6 位 HEX** 吗？（带 alpha 会 SCHEMA_FAIL）
  7. 出错/通过的颜色走的是 §199 的方案吗？
