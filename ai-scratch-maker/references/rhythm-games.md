# 第三十八册：音游（节奏游戏）完全手册（§433–§456）

> 适用范围：**玩家跟着音乐按键**的节奏游戏（下落式 / 太鼓式 / 点击式 / 径向）。
> 和第三十二册 `music-and-instruments.md` 完全不同：那一册是**让 Scratch 演奏音乐**（输出声音），
> 本册是**玩家对节奏输入**（判定时间）。两册可组合，但不要互相代替。
> 前置：第三十二册（BPM/鼓组/音频素材）、第二十九册（音效分层）、第二十六册（手感曲线）、
> 铁律 1/2（数字带标签）、铁律 7（结算页返回按钮）。

---

## §433 音游不是「会演奏」，是「判时间」

一句话分清两件事：

| | 演奏类作品（第三十二册） | **音游（本册）** |
|---|---|---|
| 时间方向 | 程序按谱**发出**声音 | 程序按谱**等待**玩家输入 |
| 核心数据 | 音高 / 时值 / 乐器 | **目标时刻 / 轨道 / 音符类型** |
| 核心算法 | 简谱→MIDI、多声部 | **误差 = 输入时刻 − 目标时刻** |
| 失败条件 | 演奏错音（通常不判） | 漏按 / 按太早太晚 → Miss |
| 时间精度 | 节拍级（几十 ms 无所谓） | **窗口级（30~120ms 定生死）** |

所以音游最值钱的不是画面、不是音符造型，而是**一个所有人都读同一份的时钟**。

> 常见错误顺序：先做「音符从上面掉下来」，再在碰撞/位置里判命中。
> 正确顺序：**先有音乐时间轴和判定函数，画面只是把时间轴画出来**。

## §434 唯一真相：音乐时间轴

全部逻辑只读一个数：

```
songTime = 从 BGM 开始播放到现在的毫秒数（已扣除校准 offset）
```

**音符位置、按键判定、漏击扫描、特效时机、结算，全部由 songTime 推出来。**
不要有第二套独立时钟（帧计数、`y` 坐标、另一个计时器变量）。

```
音符 i 的 y = 判定线Y + (目标时刻[i] - songTime) × 像素每毫秒
     ↑ songTime = 目标时刻 时恰好落在判定线上
     ↑ 负数 = 还没到（在上方），正数 = 已经过了
```

⚠️ **位置必须由公式重算，不能每帧 `y += 速度`**。
帧累加会掉帧就漂移：卡 3 帧，音符就比音乐慢 100ms，而且**越玩越偏**。
公式重算时掉帧只是画面跳一下，下一帧立刻归位。

这与地铁册「里程是唯一真相、像素是假滚动」、ATO 册「主 Tick 常数即时间压缩」是同一个原则。

## §435 Scratch 的能力边界：30fps 决定了窗口下限（本册最重要的一节）

主流音游的判定窗口是：

| 档 | 常见 ×±ms | 说明 |
|---|---|---|
| Perfect | 20~50 ms | 30ms 是人耳分辨「合拍」的阈值 |
| Great | 50~80 ms | |
| Good | 80~120 ms | 新手可放宽到 150 |
| Miss | > 120 ms 或漏按 | |

**但 Scratch 默认 30fps → 一帧 ≈ 33.3ms。**
`timer` 虽标 0.01 精度，实际由渲染帧刷新；`当按下键` 帽子也只在一帧内被检查一次。
所以：

> ⚠️ **±30ms 的 Perfect 窗口在 Scratch 里物理上不可实现** ——
> 它比一帧还窄，玩家「按准了」和「差一帧」会被采样成同一个值。

**工程结论（必须照做）**：把判定窗口设成**帧长的整数倍**，并让行为校验按帧量化：

```
帧长ms = 1000 / 30 ≈ 33
窗口P    = 1 帧 =  33 ms
窗口G    = 2 帧 =  66 ms
窗口Good = 3 帧 = 100 ms
窗口Miss = 3 帧以上 / 漏按
输入时刻 = round(原始时刻 / 帧长ms) × 帧长ms      # ★ 先量化再判
```

两条硬约束：
1. **先量化、再取误差**。用未量化的原始时刻判，会假装自己有 30ms 精度，
   实际玩家感知到的档位是随机的（表现为「明明按准了却吃 Great」）。
2. **窗口随帧率变**。开 Turbo / 高刷设备时帧长会变，窗口要按 `1000 / 实测帧率` 重算，
   或者干脆把游戏锁在固定帧（广播帧循环 + `wait 0.02` 节流）并把这个值写进板子配置。

⚠️ 与项目记忆里的「广播帧循环：一帧 = `broadcast(帧)` + `stepN(2)`」配套：
无头校验里 `songTime` 不是真实时间，而是**脚本推进的虚拟时间**，
这样判定函数才是可复现的纯函数（§454）。

> 诚实边界：Scratch 做不了「竞技级音游」。它能做的是**休闲 / 教学 / 派对音游**，
> 靠宽松窗口、清晰的节奏、强反馈来好玩。别拿 osu! 的 ±20ms 去要求它。

## §436 谱面数据结构：五条平行列表

沿用全 skill 的「平行列表」范式（第三十三册板子表、第三十二册旋律表同款）。
**一个音符 = 五张表同一索引的一行**：

```
音符时刻表[i]   目标时刻(ms，音乐时间轴上的绝对位置)
音符轨道表[i]   0..轨道数-1（或 1..N，全工程统一 1-based）
音符类型表[i]   1 单击 tap / 2 长按 hold / 3 滑键 flick / 4 同时押标记
音符时长表[i]   仅 hold：尾巴相对头部的 ms；tap 填 0
已判定表[i]     0 未判 / 1..4 判定档（★ 去重用，见 §442）
```

运行时还要三张表：

```
误差表[i]       本次命中的有符号误差(ms)，用于结算页显示「偏早/偏晚」
判定档表[i]     1 Perfect / 2 Great / 3 Good / 4 Miss
输入队列        轨道 + 时刻，帧卡顿时不丢输入（§445）
```

**为什么时间存「绝对毫秒」而不是「第几小节第几拍」**：
运行期判定只需要 `abs(输入-目标)`，存毫秒最快、最不容易错。
**但谱面文件里要存「拍」**（§437），因为 BPM 变化时拍不会变、毫秒会变。
→ **解析时把「拍」换算成毫秒，运行期只读毫秒**。两处都存会变成两个真相源。

## §437 BPM / 拍号 / 偏移的数学

```
拍长ms      = 60000 / BPM
十六分ms    = 拍长ms / 4
八分ms      = 拍长ms / 2
三连音ms    = 拍长ms / 3                  # ⚠️ 不是 /2 也不是 /4
一小节ms    = 拍长ms × 每小节拍数(通常 4)

目标时刻(ms) = 偏移ms + 拍号 × 拍长ms + 细分 × 十六分ms
             ↑ offset：音频开头到第一个节奏点的空白
```

| BPM | 拍长 | 16 分 | 说明 |
|---|---|---|---|
| 120 | 500 ms | 125 ms | 教学曲常用 |
| 150 | 400 ms | 100 ms | Perfect ±50ms = 半个 16 分 |
| 180 | 333 ms | 83 ms | 窗口必须跟着缩，否则「很肉」 |

⚠️ **窗口要按 BPM 反推，不能全曲一个死值**。
180BPM 下 Good ±120ms 会跨到下一个 16 分音符，玩家乱按也能连击。
经验式：`窗口Good ≤ 十六分ms × 0.8`。

⚠️ **offset 是「第一个音符相对音频起点的偏移」，不是校准值**。
这两个概念常被混成一个变量，结果一调校准整张谱就平移。
- `谱面偏移ms`：谱面作者写死，随曲子走。
- `校准ms`：玩家按设备调，只改**输入时刻**（§446）。
两者必须分开存。

⚠️ **BPM 变化（变速 / soflan）**：谱面用「拍」存，逐段解析成毫秒；
不要在运行期改 BPM 变量再重算全部音符，那会让已出现的音符跳位。

## §438 谱面生成：从 BPM 网格到 pattern

不要手写几百个数字。定义几种 pattern，按小节拼：

```
pattern 表（每格 = 该 16 分位上要按的轨道集合，0 = 空）
  单键:   [1,0,2,0, 3,0,4,0, 1,0,2,0, 3,0,4,0]
  楼梯:   [1,0,0,0, 2,0,0,0, 3,0,0,0, 4,0,0,0]
  交互:   [1,0,2,0, 1,0,2,0, 3,0,4,0, 3,0,4,0]
  同时押: [1,0,0,0, 24,0,0,0, 1,0,0,0, 24,0,0,0]   # 24 = 2轨+4轨
  长按:   类型=2，时长 = 2 拍 = 拍长ms × 2
```

生成：
```
for 小节 m in 0..小节数:
    for 位 k in 0..(每小节16分位数-1):
        lane = pattern[小节类型[m]][k]
        若 lane ≠ 0:
            目标时刻 = 偏移ms + (m×每小节拍数 + k/4) × 拍长ms
            append 到五条平行列表
```

⚠️ 三条规则：
1. **谱面必须按时刻升序**。判定函数找「最近音符」时依赖有序扫描；乱序会漏判。
2. **同时刻不同轨 = 同时押**，要生成两条记录（同 `目标时刻`），不能合并成一条。
3. **密度按难度**：1 分钟 128BPM 的入门谱约 60~120 个音符；
   超过每分钟 300 个在 Scratch 的 30fps 下已经无法分辨。

## §439 从音频生成谱面：复用 `audio2notes.py`

项目里已有 `scripts/audio2notes.py`（第三十二册 §319）：
自相关基频 + 能量低谷切音 → 音符序列（音高 / 时值 / 起始拍）。
它输出的是**旋律**，把它转成音游谱面只需一步映射：

```
音高 → 轨道:   轨道 = (MIDI % 轨道数) + 1        # 低音在左、高音在右
时值 → 类型:   时值 ≥ 2 拍 → hold，时值 = 时值ms；否则 tap
起始拍 → 时刻: 偏移ms + 起始拍 × 4 × 十六分ms
```

⚠️ **自动谱面只能当草稿**：
- 和弦只取最响的一个音（工具限制），和弦密集的曲子谱面会稀疏；
- 同音高连音需 ≥50ms 能量低谷才切得开，否则长音会黏成一整条；
- 鼓点（最适合做音游谱面的东西）**不是音高**，自相关检不出来。

**更好的路子：直接用 `gen_audio.py` 合成的 BGM 反推谱面**。
既然鼓组 pattern 是我们自己写的（第三十二册 §312），
就把「鼓点列表」同时输出成谱面——**音乐和谱面同源，天然对齐**，
不存在音画不同步。这是 Scratch 音游最稳的做法。

## §440 判定窗口：为什么用时间不用像素

新手最容易写成：

```
❌ if abs(音符.y - 判定线Y) < 20 像素 → Perfect
```

这会把判定宽容度绑在**下落速度**上：换一首快歌、调一次速度设置，
同样的 20 像素对应的毫秒数就变了，「Perfect」悄悄变成另一个游戏。

```
✅ 误差ms = 输入时刻 - 目标时刻
   if abs(误差ms) ≤ 窗口P → Perfect
```

**像素只负责画**，判定只读毫秒。这是 §434「时间轴唯一真相」的直接推论。

窗口表本身要**数据化**（四条变量或一个列表），方便难度切换和自动试打：

| 难度 | P | G | Good | Miss |
|---|---|---|---|---|
| 入门 | 66ms(2帧) | 100ms(3帧) | 166ms(5帧) | >166 |
| 标准 | 33ms(1帧) | 66ms(2帧) | 100ms(3帧) | >100 |
| 困难 | 33ms | 50ms | 66ms | >66 |

⚠️ 困难档的 50ms 不是帧长整数倍 → 量化后会退化成「1 帧 / 2 帧」两档。
**要么接受这个量化，要么别在 Scratch 里做困难档**（§435）。

## §441 判定函数（纯函数，四行）

```
判一击(输入时刻ms, 轨道, 校准ms):
    有效时刻 = 输入时刻 - 校准ms                # ★ 校准只作用在输入侧
    有效时刻 = round(有效时刻 / 帧长ms) × 帧长ms  # ★ 先量化（§435）
    i = 找最近未判定音符(轨道, 有效时刻)          # §442
    若 i = 0 → return「空击，不判不计分」          # ★ 别把乱按算 Miss
    误差 = 有效时刻 - 目标时刻[i]
    a = abs(误差)
    档 = a ≤ 窗口P ? 1 : a ≤ 窗口G ? 2 : a ≤ 窗口Good ? 3 : 4
    ...写回 已判定表[i] / 误差表[i] / 分数 / 连击 / 各档计数
    return 档, 误差
```

四条必须写进校验的性质：
1. **用 `abs`**：早按和晚按对称。别写成 `误差 > 0` 才判。
2. **档位是 `≤` 边界**：正好 33ms 归 P，34ms 归 G；写成 `<` 会把边界挪一帧。
3. **空击不算 Miss**：玩家在没有音符的轨道乱按，不应断连击（否则挫败感极强）。
4. **纯函数**：不读渲染状态、不改 songTime，才能拿已知答案硬校验（§454）。

## §442 找最近音符与去重（按下沿）

### 找最近，不是找第一个

同一轨上可能前后两个音符都在窗口内（16 分连打）。
**必须选误差最小的那个**，否则连打时永远打到前一个：

```
i = 0; 最小误差 = 无穷
for k in 1..音符数:
    若 轨道表[k] ≠ 输入轨道 或 已判定表[k] ≠ 0 → 跳过
    若 abs(目标时刻[k] - 有效时刻) > 窗口Miss → 跳过    # ★ 提前剪枝
    若 abs(...) < 最小误差: 最小误差 = ...; i = k
return i
```

⚠️ 剪枝条件里的 `窗口Miss` 不能省：不剪枝会把**两小节以后的音符**判成 Good。

### 去重：已判定表 + 按下沿

`key pressed?` 是**电平**（按住的每一帧都为真），
`当按下键` 帽子在部分实现里也会因键盘重复而连发。
所以要有两层守卫：

```
① 按下沿:  本帧按下 = key_pressed; 上帧按下 = 私有变量
           若 本帧=1 且 上帧=0 → 才产生一次输入
           上帧按下 = 本帧按下                       # 每帧末
② 已判定表: 判一击前查 已判定表[i] = 0；判完立刻写档位
           即使 ① 漏了，同一音符也不会被计两次分
```

⚠️ 这两层**不能只做一层**。只做 ① 会在无头/低帧率下丢输入；
只做 ② 会让按住不放时每帧都去扫全表（性能 + 空击噪音）。

## §443 漏击扫描与 Miss

Miss 有两种来源，都要处理：

```
A. 按了但太偏  → §441 里档=4（误差 > 窗口Good）
B. 根本没按    → 每帧推进时扫描：
       for k in 1..音符数:
           若 已判定表[k] = 0 且 songTime > 目标时刻[k] + 窗口Miss:
               已判定表[k] = 4 ; 各档Miss数 += 1 ; 连击 = 0
```

⚠️ **「窗口Miss」要 ≥ 「窗口Good」**，且扫描阈值用 `>` 不是 `≥`
（正好在边界那一帧还给玩家一次机会）。

⚠️ **漏击扫描不能每帧全表扫** 到后期几千音符会卡。
用**扫描指针**：谱面按时刻升序，指针只前进，
`while 目标时刻[指针] + 窗口Miss < songTime: 判 Miss; 指针++`。
复杂度从 O(n·帧) 降到 O(n)。

⚠️ Miss 断连击、Good 续连击：
不同游戏房规不同（有的 Good 也断），**要在板子/难度配置里做成开关**，
并在结算页写明规则，别默默选一种。

## §444 长按 / 滑键 / 同时押

### Hold 长按：判两次

```
按下: 按 §441 判「头」，但 已判定表[i] 只写「头已接」(比如 5)，不结算分数
保持: 每帧检查该轨是否仍按住；松开且 songTime < 尾时刻 - 容差 → 长按失败(Miss)
抬手/到尾: 尾时刻 = 目标时刻[i] + 时长表[i]
           误差尾 = 抬手时刻 - 尾时刻
           尾误差 ≤ 窗口Good → 整条结算为头的档位；否则降档或 Miss
           已判定表[i] = 最终档
```

⚠️ **只看按下时间是错的**：玩家点一下就松也能拿满分的 bug 就是这么来的。
⚠️ 长按期间**同一轨不能再生成新音符**（谱面生成时校验），否则按下沿冲突。

### Flick 滑键

方向 = 这一帧的 `鼠标x/y` 或触摸相对上一帧的位移符号，
**只要方向对即可，不要求位移大小**（否则不同屏幕尺寸手感不同）。
判定时刻取「方向成立的那一帧」，仍走 §441。

### 同时押 Multinote

同一 `目标时刻` 的两条记录，由**两个不同轨道的独立输入**各自判定。
⚠️ 不要用「同时按」的复合条件，Scratch 30fps 下两个键几乎不可能落在同一帧；
正确做法是给一个**同时押容差窗口**（如 ±1 帧 = 33ms），
先到的那条记下时刻，后到的那条若在容差内就沿用同一时刻。

## §445 输入缓冲与按键队列（防掉帧丢输入）

渲染卡顿时，一帧内可能来了两次输入；或者输入发生在两帧之间。
**不要把输入判定直接写在按键帽子/帧循环里**，先进队列：

```
事件「按键」:  append(输入队列, [轨道, 量化时刻])      # 只记录，不判定
事件「帧」:    while 队列非空: 取一条 → 判一击(...)     # 统一在帧里结算
```

⚠️ 队列长度要有上限（如 8），超了丢**最旧**的，不要丢最新的
（最新的才是玩家当前的节奏）。

⚠️ **输入缓冲**（与 §26 册同款但方向不同）：
若按下时该轨最近的音符还差 1~2 帧才进窗口，
可暂存 100ms，等它进窗口再判。这对 30fps 尤其重要，
能救回大量「明明按对了却因为采样在窗口外而空击」。
缓冲**只在更早方向**生效，晚按不补。

## §446 校准：三种 offset 别混

音游 Wiki 把 offset 分成三类，实现上只用一个变量会出事：

| 类型 | 改什么 | 用途 |
|---|---|---|
| **Audio offset** | 音频相对画面平移 | 设备音频输出延迟（蓝牙 150~300ms） |
| **Visual offset** | 音符下落相对音频平移 | 显示延迟 |
| **Timing offset** | **不改画面不改声音，只平移判定窗口** | 玩家习惯性偏早/偏晚 |

Scratch 没有独立音频时钟，所以**统一用 Timing offset** 最简单：

```
有效输入时刻 = 原始输入时刻 - 校准ms - 谱面偏移ms
                ↑ 玩家可调        ↑ 谱面写死
```

⚠️ **校准只作用在输入侧**（减在输入时刻上），
不要去改 `目标时刻表` —— 改表会同时移动画面上的音符，玩家看到音符跟着跑，
等于 visual offset，和自家判定又对不上。

### 测量校准值

```
校准界面：节拍器每 500ms 响一次，让玩家跟着敲 8 次
          记录每次 误差 = 敲的时刻 - 节拍时刻
          校准ms = 中值(误差)              # ★ 用中值不用平均，抗离群
          范围钳制到 ±200ms
```

⚠️ 用**中值**：8 次里有一次走神晚 300ms，平均会被拉偏 37ms，中值不会。
⚠️ 校准值要**按设备存**，不要按曲子存。

## §447 分数 / Combo / 准确率 / 评级

```
单音符满分 = 300
得分(档)   = 1→300, 2→200, 3→100, 4→0
连击加成   = 1 + min(连击, 100) / 100 × 0.5      # 上限 1.5×，别无限涨
本音符得分 = 得分(档) × 连击加成

准确率 = 累计得分(不含连击加成) / (300 × 音符总数) × 100%
        ⚠️ 分子必须用「未加成」的裸分，否则准确率会随连击虚高、跨曲不可比

评级:   S ≥ 98% 且 全连 / A ≥ 90% / B ≥ 75% / C ≥ 60% / D 其余
全连(Full Combo) = Miss数 = 0 且 Good数 = 0?  ← 房规开关，写清楚
```

⚠️ **Combo 数字和准确率必须有文字标签**（铁律 1/2）：
「COMBO」「准确率」单独做文字造型角色，别只显示裸数字。
⚠️ **结算页必须有「返回 / 再来一局」按钮**（铁律 7），
广播 `[重置]`、不挂绿旗、按钮回到标题页。

## §448 下落渲染：位置由时间算，不由帧累加

```
每帧:
    for 可见音符 k（用滑动窗口，只画 目标时刻 ∈ [songTime - 预滚出, songTime + 提前量]）:
        y = 判定线Y + (目标时刻[k] - songTime) × 像素每ms
        若 y 超出屏幕 → 不画（不删除，谱面数据不动）
```

⚠️ **「提前量」决定音符从屏幕顶端到判定线的时间**：
一般 1.2~2.0 秒。`像素每ms = (判定线Y - 顶端Y) / 提前量ms`。
改「下落速度」设置 = 改这个提前量，**不要改判定窗口**（§440）。

⚠️ **判定线不要做缓动**。铁律 15 说一切位移要 6~12 帧缓动，
但**音符下落和判定线是铁律 15 的例外**：它们必须严格按时间公式瞬时定位，
任何缓动都会造成音画不同步。缓动只用在**判定特效、菜单、连击数字**上。

⚠️ **不要用 `碰到` 积木判命中**：无头测不到，且像素碰撞与时间轴无关（物理册同款坑）。

## §449 音画同步与 BGM 播放

Scratch 音频能力的三条硬限制：

1. **「播放声音 [BGM] 直到结束」会阻塞脚本**（第三十二册 §316）
   → BGM 必须用非阻塞的 `播放声音 [BGM]`，由 `songTime` 自己管进度。
2. **没有 seek / 暂停续播**：Scratch 只能 `停止所有声音` 再重播。
   → 暂停时记下 `暂停时刻 = songTime`；继续时**从头重播 BGM 并把 songTime 设为暂停时刻**
     会造成音乐对不上。正确做法：**暂停即重开本局**，或把 BGM 切成
     若干小段（按小节）用 `播放声音` 逐段接，暂停后从当前小节重播。
     做不了无缝续播，要在设计上避开。
3. **`timer` 会被引擎重置/受绿旗影响**
   → 用项目记忆里的「广播帧循环 + 虚拟时间」：
     每帧 `songTime += 帧长ms`，并加 `自动帧` 开关让校验脚本逐帧驱动。
     ⚠️ 这与 §434「不要帧累加」冲突吗？**不冲突**：
     帧累加的是**虚拟时间**（由固定帧长推进，可复现），
     音符位置仍由 `(目标 - songTime)` 公式算，不是 `y +=`。
     真实浏览器里应改用 `timer` 差值作为 songTime，帧循环只做渲染。

> 推荐双模式：`时钟源 = 0 虚拟(校验/演示) / 1 timer(真机)`，
> 一处切换，判定函数完全不动。

## §450 手感：判定反馈必须 0 帧

音游的反馈延迟会被玩家直接感知成「不跟手」：

| 元素 | 时机 | 时长 |
|---|---|---|
| 判定文字（PERFECT/GREAT/…） | **命中当帧立刻显示** | 0.25~0.4s 后淡出 |
| 判定线闪光 / 轨道亮 | 命中当帧 | 2~4 帧 |
| 打击音效（ui/fx 层） | 命中当帧 | ≤0.25s，**不能盖过 BGM** |
| 连击数字弹一下 | 命中当帧 | 3 帧 Squash&Stretch |
| 音符消失 | 命中当帧 | 无渐隐 |

⚠️ **判定音效走 `fx` 层 −9 dBFS 且必须短**（第二十九册四层响度）。
用「播放声音直到结束」会把下一帧卡住 → **绝对禁止**。
⚠️ **震屏少用**：音游靠读谱，震屏会干扰下一个音符的位置判断。
⚠️ **Miss 反馈要克制**：整屏变红会打断节奏，判定线局部变灰即可。

> 这条与铁律 15 的分工：**反馈瞬时，装饰才缓动**。
> 判定文字从 0 帧出现、用 6 帧淡出是可以的；但**不能延迟出现**。

## §451 对象池：300 克隆上限与平行列表

音符数量很容易超 300（1 分钟中等难度 100~200 个，长曲更多），
而 Scratch **克隆上限 300，超限静默丢弃**（铁律 12）。
所以：

```
❌ 每个音符造一个克隆 → 长曲后半段音符凭空消失
✅ 预造「轨道数 × 可见行数」个角色（如 4×8 = 32 个），
   每帧按滑动窗口给每个角色分配一个谱面索引 → 换造型 → 定位
```

```
可见窗口 = { k | songTime - 200 ≤ 目标时刻[k] ≤ songTime + 提前量ms }
每帧:
   按轨道分组，取各自窗口内前 8 个
   for 槽位 s: 槽位角色[s].显示索引 = 对应 k ; 定位到公式算出的 y
   空槽 → 隐藏（不要删除）
```

⚠️ 角色是**私有变量**存「我当前代表哪个音符」（铁律 9），
不要用舞台级变量，否则多轨道互相覆盖。
⚠️ 克隆体也会响应本体事件帽子 → `是克隆` 私有标志位（铁律 11）。

## §452 谱面编辑器与自动试打

### 编辑器（可选但强烈建议）

最小可用的谱面编辑器不需要独立工具，用 Scratch 自己就能做：
- 时间轴横向滚动、按 16 分网格吸附
- 点格子 → 往五条平行列表 append 一条
- 「试听」按钮：从当前时刻播 BGM 段 + 逐帧推进
- 导出：把列表拼成 `时刻,轨道,类型,时长;` 字符串，用变量存（存档码范式，§22 册）

### 自动试打（校验的核心工具）

**让程序自己按固定偏差序列打一遍**，逐条打印落档：

```
for 偏差 in [-200, -150, ..., 0, ..., +200] step 5:
    输入时刻 = 目标时刻 + 偏差
    判一击(输入时刻, 轨道)
    记录档位
断言: 各档数量与手算一致；边界 ±窗口值处正好换档
```

这比「人工玩一遍看看」强两个数量级，而且**能在无头环境跑**。
对应到行为校验就是 §454 的边界断言表。

## §454 校验清单（20 条）

**时间与谱面**
1. `拍长ms = 60000/BPM`：120→500、150→400、180→333（取整策略要一致）。
2. `十六分ms = 拍长/4`，三连音 = 拍长/3（不是 /2 或 /4）。
3. `目标时刻 = 偏移 + 拍号×拍长 + 细分×十六分`，谱面按时刻升序。
4. `谱面偏移ms` 与 `校准ms` 是**两个变量**，改校准不移动谱面时刻。
5. 变速曲用「拍」存、解析时换算；运行期不改 BPM 重算全表。

**判定**
6. 边界：误差 0/33/34/66/67/100/101 → P/P/G/G/Good/Good/Miss（标准档）。
7. 早按与晚按对称（`abs`）。
8. 找**最近**未判定音符，不是第一个；16 分连打两音符各自命中。
9. 超出 `窗口Miss` 的音符不参与候选（剪枝）。
10. 同轨道类型隔离：按 1 轨不命中 2 轨的音符。
11. 已判定音符不再计分（按下沿 + 已判定表双层去重）。
12. 空击（该轨无候选）**不判 Miss、不断连击**。
13. 漏击扫描：`songTime > 目标 + 窗口Miss` 的未判定音符 → Miss、连击归零。
14. 扫描指针只前进，长按谱 O(n) 不卡。

**校准与量化**
15. 输入时刻**先按帧长量化再判**；同一帧内 10ms 与 20ms 误差落同档。
16. 校准 +50ms 能把「晚 50ms」修正为 Perfect；校准 −50 反之。
17. 校准只减在输入侧，目标时刻表数值不变。

**长按 / 结算 / 渲染**
18. Hold 按下判头、抬手判尾；过早松手 → 长按失败，不能只按一下就满分。
19. 准确率用**未加成裸分**；全 P → 100%，全 Good → 33.3%；评级阈值正确。
20. 音符 y 由 `(目标-songTime)` 公式算；跳过 3 帧后 y 与音乐时间仍一致（不漂移）。

## §455 十四个坑

1. **把音游当演奏类做** → 花时间调音色，判定却用 `碰到` 积木。先读 §433。
2. **位置每帧 `y +=`** → 掉帧即漂移、越玩越偏。必须公式重算（§434）。
3. **判定用像素不用毫秒** → 改下落速度就改了难度（§440）。
4. **假装 Scratch 有 30ms 精度** → 用未量化时刻判 ±30ms，档位随机（§435）。
5. **谱面时刻与校准共用一个变量** → 一调校准整张谱平移（§437）。
6. **谱面用「第几拍」直接判** → 每次判定都做 BPM 换算，变速必错（§436）。
7. **判定函数不是纯函数** → 读了渲染坐标，行为校验没法写死期望值（§441）。
8. **找第一个而不是最近的音符** → 16 分连打永远打到前一个（§442）。
9. **只做按下沿或只做已判定表** → 前者低帧率丢输入，后者按住不放每帧扫全表（§442）。
10. **空击算 Miss** → 乱按一下断连击，休闲玩家直接关游戏（§441）。
11. **漏击每帧全表扫** → 长曲后期卡顿，反而制造更多 Miss（§443）。
12. **长按只看按下** → 点一下就松也满分（§444）。
13. **「播放声音直到结束」放 BGM / 判定音** → 阻塞脚本，下一帧卡住（§449/§450）。
14. **判定文字延迟出现 / 判定线做缓动** → 音游反馈延迟会被直接感知成不跟手（§448/§450）。
    铁律 15 的缓动只用于装饰，不用于判定链。

> 收尾：**音游 90% 的 bug 是「有两个时钟」**。
> 只要全工程只认一个 `songTime`，剩下的都是往五条平行列表里填数据。

## §456 品类速查：换个皮不改引擎

| 品类 | 轨道/输入 | 音符运动 | 引擎改动 |
|---|---|---|---|
| **下落式**（DDR / DJMAX / maimai） | 4~8 键 | 上→下 | 本册默认，只改轨道数与键位 |
| **太鼓** | 2 类（咚/咔） | 右→左 | 把「轨道」换成「音色」，滑键换成连打 |
| **点击式**（osu! / Phigros） | 屏幕坐标 | 无下落，缩圈 | 音符表加 `x/y`，判定时刻仍是 songTime |
| **径向**（Lanota / WACCA） | 圆周角 | 中心→圆周 | 把 y 换成极径，公式不变 |
| **单键**（节奏医生 / 拍点类） | 1 键 | 横向条 | 轨道数=1， hardest 在于 offset 校准 |
| **长按谱 / 滑键谱** | 混合 | 同 | 类型表 2/3 + §444 |

**统一抽象**：`轨道` 就是「输入通道的编号」，
不管它是键、屏幕区域还是圆周角度；`目标时刻` 永远是音乐时间轴上的毫秒。
换品类 = 换渲染与输入映射，**判定函数一行都不用改**。
