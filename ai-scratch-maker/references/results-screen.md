# 结算页与返回按钮（第十八册，§147）

> 用户做任何「有胜负 / 有结束态」的作品（游戏、测验、答题、棋类、闯关）时，**必须先读这一条**。
> 这是 agent 最高频的遗忘点：**做完胜负判定就收工，结算页只显示分数、没有返回入口，玩家卡死在结算页。**

- **§147 结算页必须有「返回 / 再来一局」按钮**：

  1. **结算页（state = over）绝不能只是「显示分数」**。必须至少有一个按钮：
     - 「再来一局」→ 广播 `[重置]`（**不是绿旗**），回到可玩状态；
     - 「返回首页」→ `switch backdrop 标题页` + `hide 游戏角色` + 广播 `[重置]`。
  2. **复位一定要走广播 `[重置]`，不要走绿旗**（铁律 6）：点结算页按钮时不会触发绿旗，
     挂在绿旗下的复位逻辑永远不执行，玩家点「再来一局」毫无反应。
  3. **按钮只广播意图，复位逻辑集中在舞台**：按钮角色 `when_this_sprite_clicked → broadcast 重置`；
     舞台 `when_receive 重置` 里统一清分数、清棋盘、复位角色、切回游戏场景。这样「首页开始」和
     「结算页再来一局」复用同一套复位，不会两套逻辑打架。
  4. **首页也要能从结算页回来**：很多作品首页有「开始游戏」、结算页有「返回首页」，但忘了把
     「返回首页」也接上 `switch backdrop 标题页`——结果能开始、不能回，体验断头。

  > 自检清单（交付前必过）：结算页有没有按钮？按钮点了有没有反应？点完是回到首页还是直接重开？
  > 如果三个问题有一个答不上来，就是漏了返回按钮。
