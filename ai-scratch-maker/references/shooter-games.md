> 面向「飞机大战、纵版射击、太空射击、弹幕、打砖块（子弹向）」类作品的一整套可照抄范式。
> 配套可运行工程：`examples/shooter.yaml`（纵版射击：玩家 + 子弹 + 敌人）、
> 行为校验 `scripts/shooter_behavior_check.mjs`、生成器 `deploy-tools/gen_shooter.py`。
>
> **本册所有结论都经过 scratch-vm 实跑验证**（`SHOOTER_LOGIC_OK`），
> 不是纸上推演。§120 的五个坑是会真实让克隆爆炸 / 碰撞失效 / 无头校验跑飞的，务必先看。

## 116. 数据模型与交互总览

射击游戏的本质 = **若干会飞的精灵（子弹 / 敌人）+ 一组坐标列表做碰撞追踪**。
所有「发射、移动、命中、扣血」都是对坐标与列表做变换，角色只是把数值画出来。

### 关键变量（stage 全局）

| 变量 | 作用 |
| --- | --- |
| `分数` | 累计得分（击中敌人 +1） |
| `血量` | 玩家生命，归零 → 结束 |
| `游戏结束` | 标志位，1=结束 |
| `玩家x` `玩家y` | 玩家「意图坐标」变量（与精灵实际位置解耦，避免直接改坐标的抖动） |
| `敌计数器` | 已生成的敌人数；同时是敌人的唯一编号来源，也用作碰撞扫描的循环上界 |
| `__spawn` | 敌人生成节奏计数器（每 20 帧生成 1 个，节流用） |

### 三张列表（**本 IR 里列表实际以「变量存 JSON 数组」形式存在**，见 §120.3）

| 列表 | 长度 | 作用 |
| --- | --- | --- |
| `敌x` `敌y` | 60 | 每个敌人的实时坐标，下标 = 敌人编号 |
| `敌死` | 60 | 敌人是否已死标记，`1`=命中待删 / `0`=存活 |

> ⚠️ 这里的「列表」在 builder 里被实现成**舞台变量里的一串数组**，不是 Scratch 原生列表。
> 好处是跨克隆共享、无头可验；坏处是你不能在 JS 校验脚本里用 `target.lists`，要读 `target.variables` 里的那个数组。
> 初始化写成块式 YAML（`- 0` 每行一个），别写 `[0,0,...]` 行内式。

### 关键角色

| 角色 | 职责 |
| --- | --- |
| `玩家` | 左右键改 `玩家x`；`set x` 同步到精灵；空格广播 `[发射]` |
| `子弹` | 只有**本体**响应 `[发射]` 生成克隆；克隆向上飞、出界回收、扫描敌人打 `敌死` 标记 |
| `敌人` | 只有**本体**响应 `[生成敌人]` 生成克隆；克隆向下落、撞玩家扣血、被标记后删自己 |

### 广播链路

```
当绿旗被点击        → 复位 分数/血量/游戏结束/玩家x/玩家y/敌计数器/__spawn + 清 敌死 列表
玩家 按空格         → broadcast [发射]
当收到[发射]        → 仅本体：create clone of [myself]
子弹 当作为克隆     → 设 是克隆=1，取 玩家x/玩家y 为初速坐标，show
子弹 forever        → by+10；goto(bx,by)；出界删；扫描 敌x/敌y 命中则 分数+1 + 敌死=1
当收到[生成敌人]    → 仅本体且 敌计数器<60：敌计数器+1 + create clone of [myself]
敌人 当作为克隆     → 设 是克隆=1，编号=敌计数器，ex/ey 随机，写入 敌x/敌y/敌死
敌人 forever        → ey-2；goto(ex,ey)；回写 敌x/敌y；出界删；敌死=1 删自己；撞玩家则 血量-1(见底广播[结束])
当收到[结束]        → 游戏结束=1
```

> **复位挂「绿旗」即可**（射击游戏一局通常就重置一次）；但若要「再来一局」按钮，
> 把复位逻辑收进 `当收到[重置]` 再让按钮广播它，和消除游戏同款做法（见第十一册 §111）。

## 117. 玩家控制：意图坐标变量 + set_x

玩家不直接在事件里 `change x`，而是把「想去的 x」存进变量 `玩家x`，再每帧 `set x to 玩家x`。
这样移动和精灵位置始终一致，碰撞判断也只用变量，不依赖渲染器。

```text
当绿旗被点击        → goto(0, -150)；show
当绿旗被点击        → forever：
    若 按下[←]：玩家x = 玩家x - 8
    若 按下[→]：玩家x = 玩家x + 8
    若 玩家x >  220：玩家x =  220      # 边界夹紧
    若 玩家x < -220：玩家x = -220
    set x to 玩家x
    set y to -150
    wait 0.02                          # ★ 每帧节流（见 §120.1）
当按下[空格]        → broadcast [发射]
```

> **为什么用变量而非直接改坐标**：无头 scratch-vm 没有渲染器，`x/y` 位置变化在头less 下读不到；
> 用变量驱动则任何逻辑都可被行为校验实跑断言，命中判定也只算数。

## 118. 子弹系统：克隆守卫 + 列表追踪碰撞

### 生成守卫（防指数爆炸）

`[发射]` 广播会被**本体和所有现存的子弹克隆**都收到。如果没有守卫，克隆也会去生成克隆 →
一帧炸出 2 倍数量。用 `是克隆` 标志位挡住：

```text
当收到[发射]        → if (是克隆 == 0)  create clone of [myself]   # 克隆不响应，杜绝指数爆炸
当作为克隆          → 是克隆 = 1
                       bx = 玩家x；by = 玩家y；goto(bx, by)；show
当作为克隆          → forever：
    by = by + 10                       # 向上飞
    goto(bx, by)
    if (by > 180)  delete this clone   # 出界回收
    敌序 = 0
    repeat (敌计数器)：                 # 扫描所有敌人（敌计数器=当前敌人数）
        敌序 = 敌序 + 1
        if ( 敌死[敌序] == 0
           and abs(bx - 敌x[敌序]) < R
           and abs(by - 敌y[敌序]) < R )
              分数 = 分数 + 1
              敌死[敌序] = 1            # ★ 只打标记，由敌人自己删自己（race-free）
    wait 0.02
```

> **命中用「位置数学 + 列表」，不用 `touching`**：`touching` 依赖渲染器，无头环境测不到
> （见 SKILL.md「无头盲区」）。位置距离 `abs(dx)<R and abs(dy)<R` 是等价的、可验证的写法。
> 命中后**只置 `敌死` 标记**，让敌人自己读到标记再删自己，避免「子弹删敌人 / 敌人删自己」
> 双写竞争。

### 命中半径 R

精灵约 36px，半宽 18，取 `R = 18` 即可。两轴都要判定（矩形近似圆），不要只判一轴。

## 119. 敌人系统：唯一编号 + 撞玩家 + 被击中自杀

### 生成守卫 + 唯一编号

```text
当收到[生成敌人]    → if (是克隆==0 and 敌计数器<60)  敌计数器 = 敌计数器 + 1
                       if (是克隆==0 and 敌计数器<60)  create clone of [myself]
当作为克隆          → 是克隆 = 1
                       编号 = 敌计数器                 # 本敌人专属槽位
                       ex = random(-200, 200)；ey = 170
                       敌x[编号] = ex；敌y[编号] = ey；敌死[编号] = 0
                       goto(ex, ey)；show
当作为克隆          → forever：
    ey = ey - 2                          # 向下落
    goto(ex, ey)
    敌x[编号] = ex；敌y[编号] = ey        # ★ 每帧回写列表（碰撞追踪靠这个）
    if (ey < -180)  delete this clone    # 出界回收
    if (敌死[编号] == 1)  delete this clone   # 被子弹打中 → 删自己
    if ( abs(ex - 玩家x) < R  and  abs(ey - 玩家y) < R )  # 撞玩家
        血量 = 血量 - 1
        敌死[编号] = 1
        if (血量 < 1)  broadcast [结束]
        delete this clone
    wait 0.02
```

> ⚠️ **生成守卫拆成「两个单分支 IF」**：先 `if(是克隆==0 and 敌计数器<60) 敌计数器+1`，
> 再 `if(是克隆==0 and 敌计数器<60) create clone`。
> 不要写成「嵌套 IF 的 do 里放 CLONE」——实测 builder 会把内层 CLONE 漏编译，
> 表现就是 `敌计数器` 一路涨到 60、却一个敌人都不生成（见 §120.2）。

### 生成节奏（节流）

舞台 forever：`__spawn = __spawn + 1`；`if(__spawn > 20) { __spawn = 0; broadcast [生成敌人] }`。
每 ~20 帧补一个敌人，避免同屏爆量。`敌计数器 < 60` 是硬上限，防止克隆数超限被丢弃。

## ★ 120. 五个致命坑（实测复现过，不是理论）

### 120.1 forever 不加 wait → 无头逐步推进被放大 / 每步跑多次

头less 校验里我们是「手动 `_step()`」驱动运行时。若 `forever` 内**没有 `wait`**，
开着 `turbo` 时一个 `_step` 会把 `forever` 身体跑几十次；不开 `turbo` 也会一帧跑好几遍。
结果：子弹瞬间飞出屏幕、敌人节奏一帧生成一堆、计数全乱。

✅ **每个 `forever` 末尾加 `wait 0.02`**（≈ 每帧一次）。这同时让游戏在真实编辑器里也
按帧率稳定推进，是好习惯。`stepN(n)` 就能精确等于「推进 n 帧」。

### 120.2 嵌套 IF 的 do 里放 CLONE 会被漏编译

`if (是克隆==0) { if (敌计数器<60) { 敌计数器+1; create clone } }` 这种嵌套里，
外 IF 的 do 只有一个内层 IF，而内层 IF 的 do 里第二个元素是 `CLONE`——
builder 实测只执行了 `敌计数器+1`，**`CLONE` 静默消失**，敌人永远造不出来。

✅ 拆成两个**平级单分支 IF**（如 §119）：一个只做 `+1`，一个只做 `create clone`，
各自独立判定守卫。子弹的 `if(是克隆==0) create clone` 是单 do 单积木，一直没问题。

### 120.3 列表在 builder 里是「变量存 JSON 数组」，且必须块式声明

本 IR 的 `stage.lists` 在 builder 中**不生成原生 Scratch 列表**，而是一只舞台变量，
其值是一个数组（`敌x` = `[0,0,...]`）。`item_of_list` / `replace_item_of_list` 操作的就是它。

- **声明**：必须块式 YAML（每行 `- 0`）。写成 `[0,0,...]` 行内式会被误当成逗号拼接的
  字符串变量，数组语义全失、碰撞读不到值。
- **写校验脚本**：别用 `target.lists`（它是空的）；要从 `target.variables` 里取那个数组，
  并按 **1-based 索引 - 1** 读写（Scratch 列表 1-based）。
- 初始化空槽位是 `0,0`，所以「把敌人放在原点附近」会误判空槽命中；校验碰撞时把
  `敌计数器` 设为 1（只扫槽位 1）最干净。

### 120.4 碰撞用位置数学，别用 touching（无头测不到）

`touching [enemy]` 依赖渲染器，头less 下永远 false。用 `abs(bx-敌x)<R and abs(by-敌y)<R`
的位置判定，既能跑真游戏，也能被行为校验断言。子弹与敌人**反向运动**（一个 +10/帧、一个 -2/帧）
会很快拉开距离，校验时让二者初始坐标差落在 `R` 内（如子弹 by=-5、敌人 ey=0），
保证第一帧就命中，避免时序抖动。

### 120.5 克隆守卫必须有，否则指数爆炸 + 无头克隆回收

- 子弹、敌人的「接收生成广播」都必须 `if(是克隆==0)` 守卫，否则克隆会响应本体事件帽子
  继续生成克隆 → 指数级。
- 无头 scratch-vm 里克隆会被**立即回收**（依赖渲染器），所以「克隆数」「出界回收」
  这类只能做**结构级**断言；真正的效果（子弹飞、敌人落、命中）要靠列表 / 变量数值断言，
  而不是数克隆。本册校验正是这么做的：`子弹克隆数==3`（生成守卫防止多生）、
  `碰撞得分>=1`（列表数值判定）、`游戏结束==1`（撞玩家数值判定）。

## 变体与扩展

| 玩法 | 改法 |
| --- | --- |
| **横版射击** | 敌人从左/右进场，`ex ±2`；玩家上下移动改 `玩家y` |
| **Boss 战** | 单个大敌人 + 多段血量；`敌死` 改为「血量槽」，归零才删 |
| **多向子弹 / 弹幕** | 子弹克隆初速按角度分 `vx/vy`，`bx+=vx; by+=vy` |
| **道具掉落** | 敌人死时按概率 `create clone of [道具]`；道具 forever 下落、碰玩家生效 |
| **波次 / 关卡** | 用 `敌计数器` 上限 + `关卡` 变量控制每波数量与速度 |
| **得分连击** | 短时间内连续命中 `分数` 倍率递增（用计时器变量记录上次命中帧） |

> 无论哪种变体，**§120.1 的 `wait` 节流**、**§120.2 的双 IF 守卫**、
> **§120.5 的克隆守卫** 都适用，且必须靠行为校验实跑验证。

## 交付前自检

```bash
python scripts/build_sb3.py --ir examples/shooter.yaml --out examples/output/shooter.sb3 --workdir /tmp/shooter_build
python scripts/validate_sb3.py --sb3 examples/output/shooter.sb3      # 四层
node scripts/shooter_behavior_check.mjs examples/output/shooter.sb3     # SHOOTER_LOGIC_OK
```

`shooter_behavior_check.mjs` 会真实模拟「绿旗生成 → 检查玩家存在 / 分数=0 / 血量=3 /
游戏结束=0 → 连发 3 次发射验证子弹克隆守卫(==3) → 生成 2 敌人(==2) → 验证子弹上飞 /
敌人下落 → 位置碰撞计分(≥1)且敌人被销毁 → 撞玩家扣血触发游戏结束」，全部断言通过才输出
`SHOOTER_LOGIC_OK`。

**只过四层校验不算射击作品完成**——发射守卫、位置碰撞、撞玩家结束这三条核心逻辑
必须靠行为校验实跑验证。
