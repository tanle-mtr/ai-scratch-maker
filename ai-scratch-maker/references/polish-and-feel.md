# 质感与交互打磨（第二十六册，§222–§235）

> **读这一册的时机**：功能已经跑通、但「看起来像学生作业」的时候。
> 这一册不讲新玩法，只讲**同一套玩法怎么做出两种观感**。
>
> 核心结论先给：**质感不是「加特效」，是「消灭瞬变」。**
> 粗糙的作品里，所有量都是「这一帧还在 A，下一帧已经是 B」；
> 高级的作品里，任何量从 A 到 B 中间都有帧。
> 把这句落实，30 行代码就能让作品从「能玩」变「像样」。

## §222 质感的三个可量化维度

不要用「好看」「流畅」这种词评价，用这三个量：

| 维度 | 定义 | 度量方法 | 及格线 |
|---|---|---|---|
| **响应延迟** | 玩家输入 → 屏幕可见变化 | 数帧 | ≤ 2 帧（66ms） |
| **过渡帧数** | 状态 A → 状态 B 之间的中间帧数 | 数帧 | ≥ 4 帧（除刻意瞬变） |
| **层次数** | 同一画面里可区分的前后层 | 数层 | ≥ 3 层（远/中/近） |

**为什么是这三个**：它们分别对应「跟手」「顺滑」「不扁平」——玩家说不出这三个词，
但缺任何一个都会立刻觉得「粗糙」。

**反例诊断**（最常见的 AI 生成作品）：
- 按下方向键，角色当帧 `change x by 10` → 响应延迟 0 帧（合格），但过渡帧数 0（不合格）→ 观感是「贴图在平移」。
- 正确：`x += (目标x - x) * 0.25`，3–5 帧到位 → 有「加速起步」的重量感。

⚠️ **过渡不是越慢越好**。超过 8 帧就开始「发飘」。手感类（角色移动）3–5 帧，
UI 类 4–6 帧，镜头类 8–15 帧。

## §223 缓动：一条公式解决 80% 的「廉价感」

### 223.1 指数逼近（唯一必须记住的一条）

```
当前值 += (目标值 - 当前值) × k
```

| 用途 | k | 达到 95% 所需帧数 |
|---|---|---|
| 角色跟随（灵敏） | 0.35 | 7 |
| UI 元素（顺滑） | 0.25 | 11 |
| 镜头跟随（有重量） | 0.12 | 24 |
| 背景漂移（几乎察觉不到） | 0.05 | 58 |
| 血条追赶 | 0.10 | 29 |

**为什么用「乘」不用「减」**（呼应铁律 5）：减法是线性的，会在目标附近来回抖；
乘法是渐近的，永远收敛、永不越过。**指数逼近天然无过冲**。

IR 写法：

```python
# 角色 x 追随目标
CHG_X(MUL(SUB(V("目标x"), X_POS()), 0.35))
```

Scratch 里角色自身坐标就是变量，直接用：

```scratch
变量 [目标x] 设为 (鼠标的 x 坐标)
重复执行
  面向 (90 v) 方向
  将x坐标增加 ((目标x) - (x坐标)) * (0.35)
```

### 223.2 减速到停（乘性阻尼）

```
速度 = 速度 × 0.88        ← 每帧衰减 12%，10 帧后剩 28%
```

**刹车、镜头滑行、转盘停转都用这条**。和指数逼近是同一个数学，只是一个追目标、一个追 0。

⚠️ 用 `速度 = 速度 - 0.5` 会：① 永远停不到 0（会变成负的）；② 快慢不同的物体减速时间一样（不真实）。

### 223.3 缓入缓出（要精确控制时长时用）

需要一个 0→1 的进度 `t`，然后：

```
缓出（快起慢收，最常用）：e = 1 - (1 - t)²
缓入（慢起快收，用于「蓄力」）：e = t²
缓入缓出（两端都慢）：e = t² × (3 - 2t)
```

用于「面板从下面滑入」「数字从 0 涨到 100」这类**有明确起止点**的动画。
指数逼近适合「持续跟随」，缓动函数适合「一次性演出」。

### 223.4 ⚠️ 帧率无关性（30fps 与 60fps 的错觉）

Scratch 默认 30fps。如果你在 60fps 环境（TurboWarp）测试过 k=0.15，
回到 30fps 会**慢一倍**（每帧间隔翻倍，但 k 没变）。

补偿公式：`k_30 = 1 - (1 - k_60)²`

| k (60fps) | k (30fps) |
|---|---|
| 0.10 | 0.19 |
| 0.20 | 0.36 |
| 0.35 | 0.58 |

**结论**：调好的 k 值写进 `#配置` 变量，并在注释里标明「按 30fps 调」。

## §224 Squash & Stretch：让「有生命」只用 3 行

任何有生命的东西在加速/减速时都会形变。这是迪士尼 1981 年总结的十二原则里投入产出比最高的一条。

### 224.1 三个阶段

| 阶段 | 形变 | 数值 |
|---|---|---|
| 起跳前（蓄力） | 压扁变宽 | `size_y 0.80, size_x 1.18` |
| 上升/下落（最快） | 拉长变窄 | `size_y 1.16, size_x 0.88` |
| 落地（冲击） | 压扁 | `size_y 0.72, size_x 1.25` → 2 帧后回 1.0 |

### 224.2 Scratch 的硬限制与两种绕法

Scratch 的 `set_size` 是**等比**的，做不出非等比缩放。两种绕法：

**绕法 A：造型序列**（推荐，最省）
把角色做成 3 个造型：`正常` / `压扁` / `拉长`。切换造型就是形变，零额外角色。
代价：要画 3 个造型。

**绕法 B：两个角色叠放**
角色 A 只改宽度（用 `set_size` 会等比，所以 A 用「横向拉伸的造型 + 改 size」），
角色 B 只改高度。复杂，只在必须连续形变时用。

**绕法 C：用「大小」+「y 坐标」模拟**
压扁时 `size → 88` 且 `y → y - 2`（视觉上像被压下去了）。
这是最省事的近似，**80% 的场合够用**。

```python
# 落地冲击：3 帧序列
SET("形变帧", 0),
REPEAT(3, CHG("形变帧", 1)),
# 帧 1: size 72  帧 2: size 88  帧 3: size 100
```

⚠️ **不要给所有动作都加 squash**。只有「有力」的动作（跳、落地、被击、重击）才加。
走路、滑动加了会像果冻。

## §225 过冲回弹（Back Easing）：让 UI 有「弹性」

一次性动画（弹窗、奖励图标、数字）到位时**冲过头再回来**，比精准停在目标更高级。

```
目标 100
帧 1-4:  100 → 112   （冲过头 12%）
帧 5-7:  112 → 96    （回弹到 96%）
帧 8-9:  96  → 100
```

IR 写法（用计数器而不是缓动函数，因为要「冲过头」）：

```python
# 弹窗出现
SET("弹出帧", 0), SET("弹出值", 0),
REPEAT(9,
  CHG("弹出帧", 1),
  IFELSE(LE(V("弹出帧"), 4),      SET("弹出值", MUL(28, V("弹出帧"))),        # 0→112
    IFELSE(LE(V("弹出帧"), 7),    SET("弹出值", SUB(112, MUL(5.3, SUB(V("弹出帧"), 4)))),  # 112→96
                                  SET("弹出值", ADD(96, MUL(2, SUB(V("弹出帧"), 7)))))     # 96→100
)
```

**幅度参考**：小元素（图标）+12%，中元素（面板）+6%，全屏（转场）+3%。
**越大越要收敛**，否则会晕。

## §226 顿帧（Hitstop）：打击感的 70%

打击感不是来自特效，是来自**「打到的那一瞬间时间变慢」**。

### 226.1 数据

| 力度 | 冻结帧数 | 时长（30fps） |
|---|---|---|
| 轻击（普通子弹） | 1 | 33ms |
| 中击（近战） | 2–3 | 66–100ms |
| 重击（暴击/大招） | 4–5 | 133–166ms |
| 击杀 | 6–8 | 200–266ms |

⚠️ 超过 8 帧就变成「卡了」，不是「有力」。

### 226.2 两种实现

**局部顿帧**（只冻结受击方，最常用）：

```python
[RECV("受击"),
 {"wait": {"secs": 0.07}},      # 冻结 2 帧
 CHG("击退x", 12),
 ...]
```

**全屏顿帧**（全局冻结，用于大招）：
停发 `帧` 广播 N 帧即可（呼应 §156 唯一时钟架构）：

```python
[RECV("大招命中"),
 SET("顿帧剩余", 4),
 FOREVER(IF(GT(V("顿帧剩余"), 0), [CHG("顿帧剩余", -1), {"wait": {"secs": 0.033}}]), W())]
```

配合舞台：`IF(EQ(顿帧剩余, 0), BR("帧"))` —— 顿帧期间**整个游戏停摆**，
但特效/音效脚本（不挂 `帧` 的）继续跑，于是「世界静止而火花还在飞」。

### 226.3 顿帧必须配「视觉变化」，否则玩家以为卡了

三件套：**顿帧 + 闪白 + 击退**。只有顿帧没有视觉变化 = 掉帧。

## §227 预备动作（Anticipation）：让危险「有礼帽」

真实世界的动作都有预备：跳之前下蹲，打之前抬手。

### 227.1 三个必需预备

| 事件 | 预备动作 | 时长 |
|---|---|---|
| 敌人出场 | 屏幕边缘警示闪烁 + 音效 | 10–20 帧 |
| Boss 攻击 | 身体后仰/变色/蓄力圈 | 20–40 帧 |
| 平台消失 | 抖动 + 闪烁 | 15 帧（每 3 帧切一次颜色） |

**没有预备 = 玩家觉得「不公平」**。这是「难」和「赖」的分界线。

### 227.2 IR

```python
# 平台消失前 15 帧警告
[RECV("平台预警"),
 SET("预警帧", 15),
 REPEAT_UNTIL(LE(V("预警帧"), 0),
   IFELSE(EQ(MOD(V("预警帧"), 6), 0), {"set_effect": {"effect": "GHOST", "value": 60}},
                                       {"set_effect": {"effect": "GHOST", "value": 0}}),
   CHG("预警帧", -1),
   W())]
```

`mod 6` 做闪烁（呼应 §217 的「距离时钟」思路：**用取模做周期性，比计时器省一个变量**）。

## §228 错峰（Stagger）：消灭「一堆东西同时出现」

同时出现 8 个元素 = 视觉噪音。依次出现 = 有节奏的铺陈。

```
第 i 个元素的延迟 = i × 3 帧     （3 帧是「能感知到先后」的最小间隔）
```

**必须错峰的场合**：结算面板逐条显示、卡牌依次翻开、菜单项依次滑入、
伤害数字连续弹出（间隔 2 帧，否则叠在一起看不清）。

```python
# 5 个菜单项依次滑入
*repv("i", 5,
   SET("项x", -300),
   REPEAT(20, CHG("项x", 22)),        # 或者用指数逼近
   {"wait": {"secs": 0.1}})            # 每项间隔 3 帧
```

⚠️ 错峰总时长不要超过 0.6 秒。8 项 × 3 帧 = 24 帧 = 0.8 秒，已经让人等得不耐烦。

## §229 输入缓冲（Input Buffer）：让操作「不跟手」变「跟手」

玩家在落地前 6 帧按了跳，如果不缓冲，这次输入就丢了 —— 玩家的感受是「我明明按了」。

```
缓冲计时 = 8   （按下时设）
每帧 缓冲计时 -= 1
落地时：如果 缓冲计时 > 0 → 立刻起跳，缓冲计时 = 0
```

配套的是**土狼时间**（Coyote Time，呼应 §159）：离开平台后 6 帧内仍可跳。

这两个加起来 = 「这个游戏的操作很跟手」，成本 2 个变量。

## §230 屏幕震动：用得越少越有力

### 230.1 参数

| 事件 | 幅度（像素） | 衰减系数 | 持续帧数 |
|---|---|---|---|
| 普通命中 | 2–3 | 0.85 | 6 |
| 爆炸 | 6–8 | 0.88 | 10 |
| 落地（重） | 3 | 0.80 | 5 |
| 濒死心跳 | 1 | 1.0（持续） | ∞ |

### 230.2 实现

**关键**：震动的是**摄像机**，不是每个角色。Scratch 没有摄像机，两种替代：

**方案 A（推荐）：只震「非 UI」层**
所有场景角色每帧 `x = 基准x + 震动x`，UI 角色不动。
需要一个 `震动x/震动y` 全局变量，场景角色在 `帧` 里加上它。

**方案 B：震背景**
只震背景角色。省事，但「只有背景在抖」会显得假。

```python
# 震动发生器
[RECV("震屏"),
 SET("震动幅度", 6),
 REPEAT_UNTIL(LE(V("震动幅度"), 0.3),
   SET("震动x", RAND(SUB(0, V("震动幅度")), V("震动幅度"))),
   SET("震动y", RAND(SUB(0, V("震动幅度")), V("震动幅度"))),
   SET("震动幅度", MUL(V("震动幅度"), 0.85)),
   W()),
 SET("震动x", 0), SET("震动y", 0)]
```

⚠️ 用 `random` 而不是 `sin`：随机的抖动更像物理冲击，正弦像洗衣机。
⚠️ 幅度必须衰减到 0 并**显式清零**，否则角色会永久偏移。

## §231 UI 微交互：按钮「活着」的四个层次

| 层次 | 触发 | 变化 | 时长 |
|---|---|---|---|
| 1. 悬停 | 鼠标碰到 | `size 100 → 106` | 4 帧 |
| 2. 按下 | 鼠标按下 | `size → 93` | 1 帧（**必须立刻**） |
| 3. 释放 | 鼠标松开 | `size → 108 → 100`（回弹） | 6 帧 |
| 4. 呼吸 | 常驻（重要按钮） | `size = 100 + 2·sin(t×3)` | 持续 |

**层次 2 必须 1 帧内响应** —— 这是「跟手」的唯一来源。悬停可以慢，按下不能慢。

### 231.1 数字滚动（分数/金币必须做）

```
显示值 += (真实值 - 显示值) × 0.25
如果 |真实值 - 显示值| < 1 → 显示值 = 真实值
```

直接 `显示值 = 真实值` 会让加分毫无存在感；滚动能让「+50」变成一段可感知的过程。

⚠️ 最后那行「吸附」不能省，否则会永远差 0.3 显示成 `99`。

### 231.2 双层进度条（血条必备）

```
即时条（红）：长度 = 当前值          ← 立刻变
追赶条（白）：长度 += (当前值 - 长度) × 0.10   ← 慢半拍
```

白色追赶条在红色后面慢慢缩，让玩家**看见自己掉了多少血**。
这是格斗游戏和 RPG 的标配，成本 1 个变量 + 1 个角色。

### 231.3 按钮必须有的三个状态

`normal` / `hover` / `disabled`。缺 `disabled` 是最常见的疏漏 ——
玩家点了没反应，会以为游戏卡了。**禁用态要变灰 + 降低不透明度到 40%**。

## §232 分层与深度：三层就够，别做五层

### 232.1 标准三层

| 层 | 视差系数 | 颜色处理 | 内容 |
|---|---|---|---|
| 远景 | 0.2 | 亮度 +25，饱和 -30% | 天空、远山、城市剪影 |
| 中景 | 1.0 | 原色 | 玩法元素、角色 |
| 近景 | 1.5–1.8 | 亮度 -20，加透明 | 前景草丛、柱子、雨 |

近景要**盖住中景**（用「移到最前面」），并且有 20–40% 透明度，
否则会挡住玩法。

### 232.2 影子：最便宜的高级感

复制角色 → `y 偏移 -6~-10` → `GHOST 55~70` → `size 85~95` → `移到最前面`（在角色后面一层是错的，
Scratch 的层级是全屏统一的，影子要「移到后面」）。

⚠️ 影子**不跟随 squash & stretch**，否则会一起变形，穿帮。
影子只跟随 x/y 和「大小」，不改形变。

### 232.3 层级管理

Scratch 的 `go to front` / `go to back` 是**全屏统一**的，容易打架。
建议约定固定层级：

```
背景(-1000) < 远景(-500) < 影子(-100) < 玩法角色(0) < 特效(100) < UI(500) < 弹窗(900) < 转场(1000)
```

每次 `show` 的时候顺手 `go to front`，并在 `帧` 里不重复调用（每帧调会闪）。

## §233 音效打磨：三个参数解决「刺耳」

| 参数 | 做法 | 效果 |
|---|---|---|
| **音高随机** | 每次播放 `pitch = random(-5, 5)` | 连续音效不再像机关枪 |
| **音量分层** | 距离越远越轻：`volume = 100 - dist × 0.1` | 世界有纵深 |
| **静音留白** | 关键台词前 0.3 秒音乐淡出到 0 | 注意力被强制拉回 |

**音高随机的正确范围**：`±5`（半音左右）。超过 ±15 会变成「走调」，低于 ±2 听不出差别。

**同一音效连续播放的硬限制**：Scratch 同一角色的同一音效**连续触发会互相打断**。
快速连发（每秒 > 10 次）必须用**多个克隆体轮流播放**，或者接受「听起来像一次」。

## §234 色彩与留白：不做「纯色 + 贴边」

呼应第二十四册（`references/ui-design-spec.md`）：

1. **不用纯黑纯白**：暗部用 `#1A1A2E`（偏蓝），亮部用 `#F5F5F7`（偏灰）。
2. **不用纯红纯绿**：`#FF0000` → `#E5484D`；`#00FF00` → `#46A758`。
3. **暗部不是「更黑」，是「更冷」**：阴影里加 5–10% 蓝/紫。
4. **留白**：屏幕边缘 8% 内不放关键信息（不同设备会裁切）。
5. **对比度**：文字与其背景的亮度差 ≥ 4.5:1（WCAG AA）。浅色文字压深色底。

**一条自检**：把画面截图**去色**（转灰度）。如果还能分清主次，配色就是合格的；
如果全糊成一团，说明只靠颜色区分层次，要补亮度和大小差异。

## §235 打磨 checklist（20 条，交付前逐条过）

**响应层**
1. ☐ 所有输入都在 ≤ 2 帧内产生可见反馈
2. ☐ 按钮有 hover / press / disabled 三态
3. ☐ 按下反馈是 1 帧内（不是「等松开才变」）
4. ☐ 跳跃/攻击有输入缓冲（落地前 6 帧内按下也算）
5. ☐ 有土狼时间（离开平台 6 帧内仍可跳）

**过渡层**
6. ☐ 没有任何量在单帧内从 A 跳到 B（除刻意的瞬变，如切场景）
7. ☐ 角色移动是指数逼近或缓动，不是匀速直线
8. ☐ 关键动作有 squash & stretch（至少用 size 近似）
9. ☐ 弹窗/奖励有 3–12% 的过冲回弹
10. ☐ 数字（分数/金币）是滚动的，不是跳变
11. ☐ 血条/进度条有追赶层

**节奏层**
12. ☐ 打击有顿帧（1–5 帧），且配了闪白或击退
13. ☐ 危险有预备动作（≥ 10 帧警示）
14. ☐ 多元素出现是错峰的（间隔 3 帧），总时长 < 0.6 秒
15. ☐ 震屏幅度有衰减且会归零

**空间层**
16. ☐ 至少 3 层视差（0.2 / 1.0 / 1.5+）
17. ☐ 有影子或接触阴影（角色不「浮」在空中）
18. ☐ 层级固定，不每帧重复 `go to front`

**声音与颜色**
19. ☐ 高频音效有 ±5 音高随机
20. ☐ 没用纯红/纯绿/纯黑/纯白；灰度截图后主次仍清晰
