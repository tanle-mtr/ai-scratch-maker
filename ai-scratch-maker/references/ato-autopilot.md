## §236 三层结构：安全层、规划层、执行层

ATO 不是「一个脚本控制速度」，是**三层串联**，每层只做一件事：

```
┌ ① 安全层（ATP）  输入：剩余里程、信号、前车   输出：推荐速度（允许速度包络）
│                  职责：算出「这一帧最多能跑多快」。它永远取 min，ATO 无权改它。
├ ② 规划层（ATO）  输入：推荐速度、巡航速度、剩余里程   输出：目标速度
│                  职责：算出「这一帧想跑多快」。正常情况下 = min(巡航, 包络)；
│                        末段压速、欠标爬行也都在这一层。
└ ③ 执行层（控制） 输入：目标速度、当前速度   输出：牵引 / 惰行 / 制动（加速度）
                   职责：把「想跑多快」变成「这一帧加多少速」。
```

**为什么必须分三层**（而不是一个 `如果 速度 < 目标 就加速`）：

| 混在一起会怎样 | 分层的收益 |
|---|---|
| 安全逻辑被规划逻辑覆盖 → 闯红灯、超速 | ATP 是**只读包络**，任何层都不能写它 |
| 想改「开多快」要去翻加速代码 | 规划层是纯策略，一行 `min` 就能改驾驶风格 |
| 想改「加减速多猛」要去翻到站代码 | 执行层是纯参数（`牵引加`/`制动减`），调参不动逻辑 |
| 播放演示 / 玩家接管无法切换 | 换掉规划层即可 → 手动模式 = 目标速度由手柄给 |

**数据流顺序（一帧内，不可换）**：

```
① 算包络 → ② 定目标 → ③ 算误差 → ④ 定档位 → ⑤ 改速度 → ⑥ 硬钳制 → ⑦ 积分里程 → ⑧ 停车判定 → ⑨ 车门
```

⚠️ **顺序错了就是「慢一帧」**：本次开发第一版把「积分里程」放在「算包络」前面，
结果推荐速度永远用上一帧的里程算，进站制动整体滞后一帧，落点误差从 ±3 米漂到 ±8 米。
**包络必须用本帧的里程算，速度必须在包络之后改，里程必须在速度之后积分** —— 这是一个环，只能单向走。

## §237 不写「牵引 / 巡航 / 制动」三个状态

教程里最常见（也是最糟）的写法：

```scratch
如果 <状态 = 牵引>:  速度 += 1.2
如果 <状态 = 巡航>:  如果 <速度 > 目标> 状态 = 制动
如果 <状态 = 制动>:  速度 -= 1.5
```

问题不在于能不能跑，而在于**它把控制律硬编码进了状态机**：
- 想加「惰行」要加第四个状态；
- 想改「误差小于 2 就不动」要改三处；
- 想在牵引时也做限速保护，得再写一遍。

**正确写法：状态只描述「车在干什么」，加减速方向由误差符号决定。**

```
误差 = 目标速度 - 速度
如果 误差 > 牵引死区:            档位 = 牵引
如果 误差 < -制动死区:           档位 = 制动
如果 -制动死区 <= 误差 <= 牵引死区: 档位 = 惰行
如果 档位 = 牵引:  速度 += 牵引加
如果 档位 = 制动:  速度 -= 制动减
```

于是状态只需要 **8 个**，全部是「业务动作」，不含任何控制语义：

| 值 | 状态 | 车在干什么 |
|---|---|---|
| 0 | 待发车 | 静止，倒计时 `起步延时` |
| 1 | 运行 | 由控制律驱动（含爬行子模式） |
| 2 | 停稳 | 已对标，静止保持 8 帧 |
| 3 | 开门 | 门位 0→100 |
| 4 | 停站 | 门开，dwell 倒计时 |
| 5 | 关门 | 门位 100→0 |
| 6 | 完成 | 终点，结算 |
| 7 | 冲标 | 越过停车标，扣分后照常开门 |

**这是一个可以照抄的判断标准**：状态名里如果出现「加速/减速/匀速」，说明你在用状态机写控制律，删掉。

## §238 目标速度：一个 min，四路输入

规划层的全部内容：

```
目标速度 = 巡航速度                              // 运营策略：想跑多快
目标速度 = min(目标速度, 推荐速度)                 // 安全包络：最多能跑多快
目标速度 = min(目标速度, 末段压速)                 // 对标：最后 60 米一级一级往下压
```

`推荐速度` 来自安全层（第二十五册 §215）：

```
推荐速度 = 3.6·√(2a·max(0, d - 5))     // 制动曲线，a = 制动率
推荐速度 = min(推荐速度, 区间限速)
推荐速度 = 信号=绿 ? 推荐速度 : (信号=黄 ? min(推荐速度,45) : 0)
```

**`巡航速度` 要略低于 `区间限速`**（本示例 62 / 80）。理由：
- 贴着限速跑，包络和巡航会频繁互相压制，速度在限速线上抖；
- 留 5~20 km/h 余量，玩家看得见「还有提速空间」，也符合真实运营（经济巡航）。

## §239 制动曲线为什么在 `d - 5` 处归零

```
推荐速度 = 3.6 · √(2 · a · max(0, d - 5))
```

`d` 是本段剩余里程，`a` 是制动率（km/h 每秒…这里按「每帧减多少 km/h」折算，见 §248 调参表）。

三个必须理解的细节：

1. **`3.6` 是单位换算**（m/s → km/h）。忘了它，推荐速度会小 3.6 倍，车会提前 100 米停住。
2. **`d - 5` 的 5 米是安全余量**：包络在停车标前 5 米就归零 → 正常情况下车永远停不到 `d < 5`，
   只会停在 `d ≈ 5~8`。这是**故意的**：ATP 的第一职责是「绝不冲标」，不是「停得准」。
   「停得准」是 ATO 规划层的事（§242）。
3. **`max(0, ...)` 不能省**：`d < 5` 时 `d - 5` 为负，开根号在 Scratch 里直接返回空/NaN，
   整条链路静默失效（速度变成空字符串，`速度 < 目标` 恒假，车不动）。

```scratch
// IR 写法（Scratch 没有 max()，用「先减后夹零」）
临时 = 剩余里程 - 5
如果 临时 < 0: 临时 = 0
推荐速度 = 3.6 * sqrt(2 * 制动率 * 临时)
```

⚠️ **`√` 的输入必须是非负数**，这是 Scratch 里最容易静默失败的一类：`sqrt(-1)` 不报错，返回空。
凡是「减法后开方 / 开方后除法」的地方，前面一定要夹零。

## §240 末段三段压速：把「追曲线」的滞后一节节吃掉

只靠制动曲线，落点误差通常在 **±8~15 米**，因为控制律永远滞后：包络降下来，速度要几帧才跟上。

不加复杂预测，只用**三段阶梯压速**就能收进 ±3 米：

```
如果 剩余里程 <= 60: 目标速度 = min(目标速度, 22)
如果 剩余里程 <= 22: 目标速度 = min(目标速度, 9)
如果 剩余里程 <= 9:  目标速度 = min(目标速度, 3)
```

原理：每级阶梯都让「实际速度」提前降到下一段的入口速度，
于是进入下一段时误差已经很小，不需要再追。

**阶梯怎么定**（拿本示例的 `牵引加 1.2 / 制动减 1.5 / 系数 30` 算）：

| 阶梯 | 距离 | 目标速度 | 从上一级降下来要几帧 | 会多走几米 |
|---|---|---|---|---|
| 一级 | 60 m | 22 | (62−22)/1.5 ≈ 27 帧 | ≈ 12 m |
| 二级 | 22 m | 9 | (22−9)/1.5 ≈ 9 帧 | ≈ 3 m |
| 三级 | 9 m | 3 | (9−3)/1.5 = 4 帧 | ≈ 0.6 m |

**经验公式**：某级阶梯的距离 ≈ 上一级速度降到本级速度所需帧数 × 平均速度 ÷ 系数 × 1.5（安全系数）。

⚠️ 阶梯不要超过 4 级。级数多了，每级只差 1~2 km/h，控制律的分辨率不够，会变成连续小抖动。

## §241 执行层：误差 + 回差（死区），死区必须非对称

```
误差 = 目标速度 - 速度

如果 误差 > 牵引死区:     档位 = 牵引      // 加速侧宽：防抖、省能耗
如果 误差 < -制动死区:    档位 = 制动      // 制动侧窄：必须停得住
否则:                     档位 = 惰行

如果 目标速度 <= 0.5 且 速度 > 0: 档位 = 制动     // ★ 目标归零就不留余量
```

**`目标速度 <= 0.5 且 速度 > 0 → 强制制动` 这一条是「停得住」的最终保证**，单独一条，不能被死区覆盖。

### ⚠️ 坑 1：对称死区 → 速度卡在 1.2 km/h，永远停不下来

第一版写的是 `牵引死区 = 制动死区 = 1.5`，结果：

- 目标速度 = 0（红灯 / 到站），当前速度 = 1.2；
- 误差 = `0 - 1.2 = -1.2`；
- `-1.2 > -1.5` → 落在死区内 → **既不牵引也不制动**；
- 车以 1.2 km/h 永远往前蹭，`剩余里程` 一路磨到 **−37.94 米**，停车判定只判 `|d| <= 5`，永远不触发。

**物理上说得通**：死区是对「误差」的容忍带，加速侧容忍 1.5 km/h 是为了不频繁切档；
但制动侧容忍 1.5 km/h，意味着**允许 1.5 km/h 的永久残速** —— 这在真实列车上是「溜逸」，是要出事故的。

**结论：死区必须非对称。**
- 牵引死区 `1.5`（宽）：避免在目标附近反复牵引/惰行；
- 制动死区 `0.3`（窄）：残速最多 0.3 km/h，一帧就刹住。

### ⚠️ 坑 2：用「瞬时条件」推断模式 → 脉冲蹭行

第一版「欠标爬行」写成了：

```
如果 状态 = 运行 且 速度 <= 0.3 且 剩余里程 > 5:  目标速度 = 5
```

看着没问题，实际是**脉冲蹭行**：

```
帧 1: 速度 0 → 条件成立 → 目标 5 → 牵引 → 速度 1.2
帧 2: 速度 1.2 > 0.3 → 条件不成立 → 目标回 0 → 制动 → 速度 0
帧 3: 速度 0 → 条件成立 → 目标 5 → 牵引 → 速度 1.2
...
```

速度在 `0 ↔ 1.2` 之间抖，每 2 帧只前进 `1.2/30 ≈ 0.04` 米，58 帧才蹭 4 米。
更糟的是：**红灯停住时它也会把车重新推起来** —— 红灯测试里速度永远停在 1.2，`ATO_LOGIC_FAIL`。

**根因**：把「模式」写成了「瞬时条件的副作用」。只要某个行为要跨帧持续，就必须有标志位。

```
// 进入：够近 + 已停 + 不是红灯
如果 状态 = 运行 且 剩余里程 <= 40 且 剩余里程 > 3 且 速度 <= 0.3 且 信号 ≠ 红:
    爬行 = 1
// 退出：到标 / 信号变红 / 不在运行 / 包络被按死
如果 状态 ≠ 运行 或 剩余里程 <= 3 或 信号 = 红 或 (推荐速度 = 0 且 剩余里程 > 8):
    爬行 = 0
// 应用：爬行中目标速度恒为 5，不会一帧一变
如果 爬行 = 1: 目标速度 = 5
```

三条铁律：
1. **进入条件用「瞬态」（速度 ≤ 0.3）没问题，但退出条件只能看「稳态」（到标 / 信号 / 状态）**；
2. **进入和退出之间必须有共享的标志位**，否则进入条件自己就把自己推翻了；
3. **子模式要服从安全层**：`信号 = 红` 必须能强制退出爬行，否则 ATO 会顶着红灯往前蹭。

## §242 精确停车：一个闭环 + 两道保险

### 闭环

```
停稳判定（窗口 ±5 米，铁标 ±1）：
  如果 速度 <= 0.3 且 |剩余里程| <= 5:
      对标误差 = round(剩余里程)
      分值：|误差| <= 1 → 100「完美对标」
            |误差| <= 3 → 70「对标良好」
            否则     → 40「对标合格」
      速度 = 0
      状态 = 停稳
```

⚠️ **判「停稳」不能用 `速度 = 0`**：浮点永远精确不到 0，必须用 `速度 <= 0.3`。
同一条规则适用于所有「等到速度为 0」的地方。

### 保险 1：冲标单独判（负里程是特性）

```
如果 速度 <= 0.3 且 剩余里程 < -5:
      停车结果 = 「冲标」，分值 -= 30
      状态 = 冲标 → 下一帧照常开门
```

**冲标也要开门，不能卡死**。卡死比冲标更伤体验（玩家会以为游戏坏了）。冲标 → 扣分 → 继续跑完，这是正确的失败处理。

### 保险 2：欠标爬行（§241 坑 2 的产物）

停在 `5 < d <= 40` 之间时，用爬行子模式推到标上。**这是「二次对标」**，真实列车也这么干
（一次对标没对准，司机会「对标调整」：牵一下、溜一点、再停）。

### ⚠️ 坑 3：退出阈值 = 停车窗口边界 → 死锁在 5.05 米

爬行退出条件写成 `剩余里程 <= 5`，停车窗口是 `|d| <= 5`。看着对齐了，实际：

- 爬行把车推到 `d = 5.05`（因为包络在 d=5 归零，推荐速度只剩 0.88，推不动了）；
- `5.05 > 5` → 爬行没退出，但包络把目标速度压到 0.88，小于牵引死区 1.5 → 不牵引；
- `|5.05| > 5` → 停车判定不成立；
- **死锁：速度 0、状态运行、永远停在离标 5 厘米处。** 校验跑满 1200 帧后报 `停车1_状态 = 1`。

**修法两条，缺一不可**：

1. **退出阈值必须比窗口更靠里**：窗口 ±5，退出阈值设 `d <= 3`。这样「退出爬行」意味着「已经进了窗口」。
2. **爬行段用独立的 ATP 余量**：正常 ATP 钳制 `速度 <= 推荐速度 + 2`；
   爬行时把余量放宽到 `+6`（因为爬行速度只有 5，仍远低于任何风险值）。

```
钳制余量 = 爬行 ? 6 : 2
如果 速度 > 推荐速度 + 钳制余量: 速度 = 推荐速度
```

**这是本册最值得记的一条工程直觉**：
> 安全包络和业务目标在空间上错开时（包络在标前 5 米归零，但业务要停到 0 米），
> 必须显式声明「最后这段谁说了算」。
> 不声明，两条曲线就在边界上互相锁死 —— 一个要停、一个要进，谁都动不了。

## §243 停稳要「占 8 帧」：状态不能零时长

第一版状态机：

```scratch
如果 状态 = 运行 且 到达标: 状态 = 停稳
如果 状态 = 停稳:          状态 = 开门      // ← 同一帧！
```

结果 `停稳` 这个状态**存在时间为 0**：`运行 → 停稳 → 开门` 全在同一帧完成。
后果：
- 校验脚本 `while (状态 === 1)` 退出时读到的是 3，`停车1_状态 = 3`，断言「应停稳」失败；
- HUD 上永远看不到「停稳」，玩家感觉「一到站门就炸开了」；
- 想加音效 / 想等玩家确认 / 想存档，全都没机会。

**修法：停稳保持 8 帧再开门。**

```scratch
如果 状态 = 停稳:
    开门帧 += 1
    如果 开门帧 >= 8: 状态 = 开门; 开门帧 = 0
```

`开门帧` 这个变量在「停稳 → 开门 → 停站」三个状态里复用（各自进入时清 0），省一个变量。

**通用规则**：
> 任何「过渡状态」都必须至少占 1 帧，且在进入时清零自己的计数器。
> 零时长的状态等于不存在 —— 外部观测不到，就等于你没有这个状态。

## §244 多站循环：握手用「不变量」，不用标志位

关门后要推进到下一站，这一段是全程最容易出 bug 的地方（第二十五册 §212 有原工程的三方握手）。

本示例的写法（顺序不可换）：

```scratch
如果 状态 = 关门:
    门位 -= 6                                  // 门位从 100 降到 0
    如果 门位 <= 0:
        门位 = 0; 车门 = 0
        站点 += 1; 完成数 += 1
        如果 站点 > 总段数:
            状态 = 完成; 广播 结算
        否则:
            剩余里程 = 站距[站点]               // ★ 用列表重新置初值
            区间限速 = 限速表[站点]
            当前站 = 站名[站点]
            下一站 = 站名[站点 + 1]
            状态 = 待发车; 起步延时 = 20
```

四个要点：

1. **`剩余里程` 必须重置为「整段长度」**，不是 `+= 站距`。用列表置初值，让「唯一真相」重新归零。
2. **`当前站`/`下一站` 一起更新**。只更新一个，HUD 会显示「桂湾 → 桂湾」。
3. **`起步延时` 在新段进入时重置**（`= 20`），不能只在初始化时设一次 —— 否则第二段会立刻发车，
   玩家看不到「停站」这个状态。
4. **推进动作只在一个地方写**（关门完成的 `门位 <= 0` 分支）。如果在「状态切换」和「门位归零」两处都写，
   会推进两次，直接跳站。

⚠️ **列表必须块式声明**（`- 0` 每行一个）。写成行内 `[0, 0, 0]` 会被当成逗号拼接的字符串变量，
`item_of_list` 读出来是字符，`站距[2]` 得到的是 `,`，里程直接变 0 → 车瞬间到站。

## §245 车门：门位是唯一状态，动画是它的函数

```
停稳(8帧) → 开门: 门位 += 6，到 100 置 车门 = 1 → 停站
停站: 开门帧 += 1，到 60 帧 → 关门
关门: 门位 -= 6，到 0 置 车门 = 0 → 推进站点
```

- **`门位`（0~100）是唯一真相**，`车门`（0/1）只是给判定用的派生布尔。
- **门位推进用「每帧加常数」**，不用「等待 0.5 秒再瞬间置 100」：后者玩家看到的是「门凭空出现」。
- **视觉上用尺寸映射门位**：`大小 = 1 + 门位 × 1.6`（本示例），门就是「撑开」的。
  比换 20 张造型便宜得多，且任意中间值都能画出来。

⚠️ **`车门` 标志不要用 `门位 > 50` 现算**：判定和显示要用同一个数，
否则会出现「门看起来开了一半但判定说没开」的时序缝。

## §246 安全层降级：红 / 黄 / 绿三档，红灯要「主动让位」

```
信号 = 绿: 信号名 = 绿，推荐速度不变
信号 = 黄: 信号名 = 黄，推荐速度 = min(推荐速度, 45)
信号 = 红: 信号名 = 红，推荐速度 = 0        // ★ 包络归零 = 唯一的停车指令
```

**红灯不需要写「制动」**。包络归零 → 目标速度归零 → 执行层自然制动。
**用包络表达「必须停」，而不是用一条 `如果红灯就刹车`** —— 后者会和执行层打架（两条制动指令叠加，减速率翻倍）。

⚠️ **红灯必须能强制退出爬行子模式**（§241 坑 2）。否则「欠标爬行」会在红灯时继续推车。

真实工程的进阶做法（第二十五册 §215）：红灯**直接 `停止这个脚本`**，把控制权交还玩家。
本示例选择「包络归零 + 自动停车」，因为全自动运行（GoA4）无人可交还。
**两种都可以，但要明确选一种**：既停又让位，玩家会不知道该干什么。

## §247 让玩家看见「开得好不好」：三个指标

全自动运行没有操作，玩家的成就感只能来自**评分**。三个廉价但有效的指标：

| 指标 | 算法 | 为什么有效 |
|---|---|---|
| 对标误差 | `round(剩余里程)`，逐站累计 | 唯一的「技术分」，玩家会为了 ±1 米反复重开 |
| 牵引能耗占比 | `牵引帧数 / 总帧数 × 100%` | 教玩家「早断电、多惰行」，比讲物理有用 |
| 完美对标次数 | `完美数 / 总段数` | 让「满分」成为一个可追求的目标 |

⚠️ 能耗率的分母要 `总帧数 + 1`，否则第一帧除零 → 空值 → HUD 显示空白。

**结算页必须有「再来一局」按钮**（铁律 13）：点面板 → 广播 `重置` → 所有状态复位。
复位清单要包含**每一个**运行态变量（含 `爬行`、`钳制余量`、`开门帧`），漏一个就会出现「第二局开局就在爬行」。

## §248 调参表 + 十个致命坑

### 参数表（本示例的值，可直接照抄再微调）

| 参数 | 值 | 调大的后果 | 调小的后果 |
|---|---|---|---|
| `里程系数` | 30 | 车走得慢，一段要跑很久 | 一帧跨几十米，抖动明显 |
| `牵引加` | 1.2 | 起步猛、乘客舒适度差 | 起步肉，加速段长 |
| `制动减` | 1.5 | 停车点头、易冲标 | 刹不住，进站距离不够 |
| `制动率`（包络用） | 0.6 | 包络收得早，提前减速 | 包络收得晚，冲标 |
| `牵引死区` | 1.5 | 速度更稳但响应慢 | 频繁切档，速度抖 |
| `制动死区` | 0.3 | 残速大，可能停不住 | 一帧一刹，抖动 |
| `巡航速度` | 62 | 逼近限速，易被包络压 | 太慢，玩家觉得没劲 |
| `爬行速度` | 5 | 补标快但可能冲过 | 补标慢，玩家等得不耐烦 |
| `停稳保持` | 8 帧 | 到站后停顿明显 | 门弹得太快 |
| `dwell`（开门帧上限） | 60 帧 | 停站久，节奏拖 | 来不及看清就关门 |

**调参顺序**：先定 `里程系数`（决定时间尺度）→ 再定 `牵引加`/`制动减`（决定手感）→
最后用 `制动率` + 三段压速调落点。**别反过来**，否则每调一次手感都要重调落点。

### 十个致命坑（按踩坑频率排序）

| # | 坑 | 症状 | 修法 |
|---|---|---|---|
| 1 | 对称死区 | 速度卡在 1.2 km/h，里程磨成负数 | 制动死区 ≤ 0.3，且「目标 ≤ 0.5 强制制动」 |
| 2 | 用瞬时条件推断模式 | 脉冲蹭行，58 帧只走 4 米；红灯时被推起来 | 显式标志位 + 进入/退出分离 |
| 3 | 爬行退出阈值 = 窗口边界 | 死锁在 5.05 米，状态永远「运行」 | 退出阈值更靠里 + 独立钳制余量 |
| 4 | 状态零时长 | 校验读不到「停稳」，门瞬间弹开 | 过渡状态至少占 1 帧 + 进入时清计数器 |
| 5 | `sqrt(负数)` | 推荐速度变空，车不动（不报错） | 减法后必须夹零 |
| 6 | 判 `速度 = 0` | 永远不触发停稳 | 用 `速度 <= 0.3` |
| 7 | 数据流顺序错 | 进站制动滞后一帧，落点漂 ±8 米 | 包络 → 目标 → 误差 → 档位 → 速度 → 积分 |
| 8 | 列表写成行内 `[a,b,c]` | `站距[2]` 读出来是逗号，里程变 0 | 块式声明，每行一个 |
| 9 | 复位漏变量 | 第二局开局就在爬行 / 门是开的 | 复位清单对着变量表逐条核 |
| 10 | 冲标后不开门 | 流程卡死，玩家以为崩了 | 冲标 → 扣分 → 照常开门跑完 |

### 交付前自检（7 问）

1. 牵引、巡航、制动是不是**没有**出现在状态名里？（§237）
2. 死区是不是**非对称**，制动侧 ≤ 0.3？（§241）
3. 有没有哪个行为跨帧持续、却只靠瞬时条件维持？（§241 坑 2）
4. 停车窗口和爬行退出阈值是不是**错开**了？（§242 坑 3）
5. 每个过渡状态是不是至少占 1 帧？（§243）
6. 红灯能不能强制停住（并且退出爬行）？（§246）
7. `node scripts/ato_behavior_check.mjs` 是不是 **`ATO_LOGIC_OK`**？

> 第 7 问不能跳。本册四个坑（对称死区 / 脉冲蹭行 / 5.05 死锁 / 零时长状态）
> **全部是在无头校验里抓到、肉眼完全看不出来的**。
> 无头环境的跑法见 `references/platformer.md` 开头的说明：**一帧 = `broadcast("帧")` + `stepN(2)`**，
> 用 `stepN(1)` 会让控制律隔帧才推进，所有收敛速度都会算错一倍。

## §529 换线路：把「线路数据」和「控制逻辑」彻底分开

> 本节是 2026-11-19 补写的。起因是 `scripts/gen_ato.py` 落地时发现的一个真问题：
> **配套工程的绿旗脚本把初始值写死成了 `1200` / `前海湾` / `桂湾` / `80`**，
> 于是「换一条线路」这件事根本做不到——改了列表，初始里程还是 1200。

### 529.1 哪些是「线路数据」，哪些是「控制逻辑」

| 类别 | 内容 | 换线路时 |
|---|---|---|
| **线路数据** | 站名 / 站距 / 限速表（三个列表） | **必须变** |
| 控制调校 | 牵引加 1.2 / 制动减 1.5 / 制动率 0.6 / 牵引死区 1.5 / 制动死区 0.3 | **不变**（人工标定） |
| 控制逻辑 | 状态机、限速钳制、末段压速、精确停车、开门时序、评分 | **不变**（通用） |

⚠️ **生成器绝不能「顺手按限速推算制动率」**——那是控制调校，不是线路数据。
实测教训：生成器曾用 `制动率 = 限速/100` 推算，把 0.6 改成 0.8，
作品表面「生成成功」，行为却变了。**越权即 bug**，宁可少做。

### 529.2 模板必须自己读列表，不能写死初值

写死的版本（换线路即失效）：

```yaml
- set_variable: {var: 剩余里程, value: 1200}      # ← 写死
- set_variable: {var: 当前站, value: 前海湾}      # ← 写死
```

线路无关的版本（初始值从列表取）：

```yaml
- set_variable:
    var: 剩余里程
    value: {item_of_list: {list: 站距, index: 1}}
- set_variable:
    var: 当前站
    value: {item_of_list: {list: 站名, index: 1}}
- set_variable:
    var: 下一站
    value: {item_of_list: {list: 站名, index: 2}}
- set_variable:
    var: 区间限速
    value: {item_of_list: {list: 限速表, index: 1}}
```

> Scratch 列表是 **1-based**，`站距` 第 1 项 = `index: 1`。
> 模板里其余按站点取值的写法（站点推进时读第 N 段）本来就用 `item_of_list`，
> 只有**绿旗初始化**这几处漏了——因为它们在写第一版时线路还是固定的。

### 529.3 行为校验也必须跟着解绑

校验脚本里若写死「总段数应为 2 / 剩余里程应重置为 1500 / 当前站应为 桂湾」，
**换线路后必然假红**。正确做法是从产物里读列表再断言：

```js
function getList(name) { /* 遍历 vm.runtime.targets 找 type==='list' 的变量 */ }
const LINE_站距 = getList("站距").map(Number);
const LINE_站名 = getList("站名");
if (snap.初_总段数 !== LINE_站距.length) bad.push(...);
if (Math.abs(snap.站点2_剩余里程 - LINE_站距[1]) > 0.5) bad.push(...);
```

改完之后，**同一条校验脚本对任意线路都成立**——这才是「数据驱动」的完整闭环：
生成器能换线 → 模板自己读线 → 校验从线读期望值。三者缺一，换线路就是假绿或假红。

### 529.4 gen_ato.py 用法

```bash
# 列出内置线路
python scripts/gen_ato.py --list-lines

# 用默认线路重新生成（幂等：产物与模板语义等价）
python scripts/gen_ato.py

# 换一条线路
cat > my_line.yaml <<'EOF'
name: 深圳地铁 5 号线（ATO 段）
stations:  [前海湾, 桂湾, 前湾]
distances: [1200, 1500]
speeds:    [80, 75]
EOF
python scripts/gen_ato.py --line my_line.yaml --out examples/my_line.yaml
python scripts/build_sb3.py --ir examples/my_line.yaml --out examples/output/my_line.sb3 --workdir <tmp>
node scripts/ato_behavior_check.mjs examples/output/my_line.sb3   # 应 ATO_LOGIC_OK
```

**输入校验（缺一即报错，不静默降级）**：
`len(distances) == len(stations) - 1`、`len(speeds) == len(distances)`、站名 ≥ 2 站、站距/限速必须为正数。
