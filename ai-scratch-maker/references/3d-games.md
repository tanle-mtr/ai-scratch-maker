# 3D 游戏（第十五册，§132–§136）

> 用户要「伪 3D、透视投影、飞向 / 飞过镜头、3D 线框、等距 2.5D」类作品时**先读这一册**。
> 配套可运行工程 `examples/3d_demo.yaml`（伪 3D 透视 + 无限逼近镜头）+ 行为校验
> `scripts/3d_behavior_check.mjs`（`D3_LOGIC_OK`）。
> 所有结论都经 scratch-vm 实跑验证，不是纸上推演。

- **§132 伪 3D 的本质是透视除法**：屏幕坐标 = `世界坐标 / 深度 × 焦距 K`，即
  `屏幕x = obj_x * K / obj_z`、`屏幕y = obj_y * K / obj_z`。物体越近（z 越小）屏幕越大、
  越靠中心。示例 `球` 精灵每帧用 `SET obj_sx = (obj_x*K)/obj_z` 等三式把世界坐标投到屏幕。
- **§133 深度 z 的物理方向要固定**：Scratch 的 y+ 朝上，但「深度」是你自己定义的坐标轴。
  朝镜头逼近 = `obj_z` 递减；**`z <= 0` 会除零崩溃**，所以必须在 `obj_z < 阈值`（示例 20）
  时把 `obj_z` 重置到远处（示例 `obj_z=200`）并打 `passed` 标记，形成无限循环逼近的伪 3D 感。
- **§134 尺寸 ∝ 1/z**：用 `set_size`（示例 `obj_ssize = 40*K/obj_z`）表现远近。
  ⚠️ 无头环境下 `Renderer` 缺失，`set_size` / `set x` / `set y` 的**赋值发生在 `if (this.renderer)` 内**，
  校验脚本读不到画面变化——所以行为校验只能断言**数值**（obj_ssize 随 z 递减而递增），
  最终视觉效果必须回 Scratch 编辑器目视确认。
- **§135 无头节流与步进断言**：FOREVER 必须 `wait 0.02` 节流（铁律 / §120.1），但无头下
  每步只推进 ~0.4 次迭代。因此行为校验要**持续步进直到触发**（示例 `while passed!=1` 封顶 300 轮），
  **不能写死 60 步**——否则深度下不到阈值、`passed` 永远 0，假失败。
- **§136 三个致命坑**：
  1. 摩擦 / 阻尼用「乘」绝不用「减」（铁律 5）；
  2. `change_variable` 的 `by` 不能对变量取负——`CHG(x, -V(v))` 会 `TypeError`，
     改用 `SET(x, x - v)`（即 `set x = (x) - (v)`）；
  3. 真·3D 线框 / 体素光线步进见第六册 §68、第九册 §98、专项 `deep-tile-camera.md`，
     别在「伪 3D 透视」里硬塞完整 3D 引擎。
