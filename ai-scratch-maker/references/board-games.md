# 棋类游戏（第十七册，§142–§146）

> 用户要「五子棋、围棋、象棋、棋盘对弈、落子判定」类作品时**先读这一册**。
> 配套可运行工程 `examples/board_gomoku.yaml`（9×9 五子棋，含落子 / 换手 / 五连珠判定 / 重开）
> \+ 行为校验 `scripts/board_behavior_check.mjs`（`BOARD_LOGIC_OK`）。
> 所有结论都经 scratch-vm 实跑验证，不是纸上推演。

- **§142 棋盘即一维列表**：9×9 = 81 格，列表初值全 0；格子索引 `idx = 行*9 + 列 + 1`（1-based）。
  落子 = `replace_item(棋盘, idx, 轮到)`；读子 = `ITEM(棋盘, idx)`。围棋 / 象棋同理，只是
  初值与「同色判定」换成各自的规则（围棋比气、象棋比走法）。
- **§143 落子四段式**：① 外层守卫 `局结束 == 0`（已分胜负就别再落）；② 内层守卫目标格
  `ITEM(棋盘, idx) == 0`（格子被占就忽略）；③ 写子 + `连数=1` + 四方向扫描；④ 换手
  `轮到 = 3 - 轮到`（1↔2）。两层守卫缺一不可（呼应铁律 6「一局复位挂广播不挂绿旗」）。
- **§144 五连珠判定（win scan）**：从落子点沿 `(+1,0)(0,+1)(+1,+1)(+1,-1)` 共四轴，每轴
  **正反各数 4 格**——连续同色 `连数+1`，一旦不同色或越界就把 `继续=0` 停掉本方向。
  ⚠️ **`连数 >= 5` 才算赢**（六连、七连也是赢），别写死 `== 5`，否则长连判不出来。
- **§145 扫描的 if/else 陷阱（同 §141）**：「命中同色 → 计数并继续 / 否则 → 停止」是**真 if-else**，
  必须写 `if` + `else` 两个分支。写成 `if(cond, 计数, 停止)` 会把两个分支都并到 `do` 一起跑 →
  一命中就顺手把 `继续` 置 0，连数永远到不了 5，胜负永远判不出。我们的 `ir_helpers.IFELSE` 就是为这写的。
- **§146 三个致命坑**：
  1. 列表在 builder 里是「变量存数组」，行为校验读 `target.variables` 而非 `target.lists`，
     索引按「1-based - 1」换算（呼应 §120.3）；
  2. 棋盘初始必须**主动清空**（绿旗 `repv` 全 0），否则残留子上局、判定串味；
  3. 棋子用克隆渲染时，**本体才生成、克隆才显形**（铁律 / §78 克隆守卫），
     `when_start_as_clone` 里从棋盘读自身颜色 `1=黑 / 2=白`。
