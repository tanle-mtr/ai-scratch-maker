## §305 音乐扩展只有 9 个积木，但够用

| 积木 | 输入 | 说明 |
|---|---|---|
| `演奏音符 [NOTE] [BEATS] 拍` | MIDI 音高、拍数 | **阻塞**：等到时值结束 |
| `演奏鼓 [DRUM] [BEATS] 拍` | 鼓编号、拍数 | 同上 |
| `休止 [BEATS] 拍` | 拍数 | 静音等待，用来做停顿 |
| `设定乐器为 [INSTRUMENT]` | 乐器编号 1~21 | **不阻塞** |
| `设定节奏为 [TEMPO]` | BPM | 全局速度 |
| `将节奏增加 [TEMPO]` | 增量 | 变速（加速段） |
| `节奏` （取值） | —— | 读当前 BPM |
| `演奏音符（MIDI）` / `设定乐器（MIDI）` | MIDI 编号 0~127 / 音色号 | 与上面两个的区别见 §306 |

**两条最关键的事实**：

1. **`NOTE` / `INSTRUMENT` / `DRUM` 都是「可下拉但也能插入数字」的输入** ——
   这意味着**可以用变量驱动**。这是「音乐转乐器」的技术基础（§307）。
2. **乐器编号从 1 开始**（1=钢琴），但 VM 内部存的是 0-based（`currentInstrument = 4` 表示用户选了 5）。
   写校验或读状态时要减 1（§318）。

### 21 种乐器（Scratch 内置音色）

```
1 钢琴     2 电钢琴   3 管风琴   4 吉他     5 电吉他
6 贝斯     7 拨弦     8 大提琴   9 长号    10 单簧管
11 萨克斯  12 长笛   13 木笛    14 巴松    15 合唱
16 颤音琴  17 八音盒 18 钢鼓    19 马林巴  20 合成主音
21 合成铺底
```

**选音色的三条经验**：
- **旋律**：1 钢琴 / 12 长笛 / 17 八音盒（清亮）/ 19 马林巴（有颗粒感）
- **低音**：6 贝斯（唯一真低音）/ 8 大提琴（温暖）
- **和声铺底**：21 合成铺底 / 15 合唱 / 16 颤音琴
- ⚠️ **不要把 3 管风琴和 20 合成主音叠在一起**：两个都是强持续音，会糊成一团噪音。

## §306 MIDI 音高：60 = C4，每 12 一个八度

```
C4 = 60      C5 = 72      C3 = 48
每个半音 +1：C4=60  C#4=61  D4=62  D#4=63  E4=64  F4=65
              F#4=66 G4=67  G#4=68  A4=69  A#4=70 B4=71
```

**换算公式**（够用一辈子）：

```
MIDI = 12 × (八度 + 1) + 半音序号      // C 调：八度 4 的 C = 12×5+0 = 60
```

反向：`八度 = floor(MIDI / 12) - 1`，`半音 = MIDI mod 12`。

⚠️ **Scratch 的可用范围比 MIDI 标准窄**：标准是 0~127，
但 Scratch 的 `play note` 会把输入 **clamp 到 48~72**（4 个八度：C3~C5）附近，
超出会被截断 —— 所以**不要指望用 24（C1）做低音**，低音要用「降八度 + 低音乐器」实现。

## §307 「音乐转乐器」的核心：变量驱动音色

这是本册的中心技巧。**同一段旋律换乐器，不复制脚本，只改变量**：

```scratch
设定乐器为 (乐器)          // 乐器 是一个变量，1~21
演奏音符 (第 i 个音高) (节拍) 拍
```

因为 `INSTRUMENT` 槽位接受数字/变量，所以：

```
设 乐器 = 1   → 钢琴版
设 乐器 = 17  → 八音盒版
设 乐器 = 19  → 马林巴版
```

**这就是「音乐转乐器」的全部秘密** —— 不需要为每种乐器写一套脚本。

### 实测证据

本工程的校验里，把变量设成 5 / 1 / 21，VM 里读到的状态分别是 4 / 0 / 20
（0-based），证明切换真实生效：

```
node scripts/music_behavior_check.mjs  →  MUSIC_LOGIC_OK
```

⚠️ **越界不是钳制，是环绕**：设 `乐器 = 99` 会得到内部值 `14`（99−1=98，98 mod 21 = 14），
不是「最后一个乐器」。所以**给乐器变量赋值前一定要校验范围**。

## §308 简谱解析：一张偏移表就够

C 大调的简谱 `1 2 3 4 5 6 7` 对应半音偏移：

```
1=C(0)  2=D(2)  3=E(4)  4=F(5)  5=G(7)  6=A(9)  7=B(11)
```

存成列表 `偏移表 = [0,2,4,5,7,9,11]`（索引 1~7），解析就是两行：

```
偏移 = 偏移表[简谱[i]]
MIDI = 60 + 偏移 + 12 × (八度 − 4)
```

**实测**：`1 1 5 5 6 6 5`（C 调 4 组）→ `60 60 67 67 69 69 67` ✓

### 处理变调（升/降号）

`#4`（升 F）就是 `5 + 1 = 6`。做法：给简谱加一个「升降」平行列表，
或者把 `#` 编码进数字（如 `41` 表示 `#4`）。**不要为每种变调写一套表**。

### 休止符

用 `0` 表示。解析时写成 `0`（不是 60），演奏时判断：

```
如果 音高 = 0 → 休止 节拍
否则        → 演奏音符 音高 节拍
```

## §309 旋律数据化：三个平行列表

```scratch
音高表 = [60, 60, 67, 67, 69, 69, 67]     // MIDI
时值表 = [0.5, 0.5, 0.5, 0.5, 0.5, 0.5, 1] // 拍
力度表 = []                                 // Scratch 不支持力度，留作扩展
```

**为什么用平行列表而不是「一个字符串 `"60:0.5,60:0.5"`」**：
- 平行列表可以直接用下标访问，不用每次解析字符串
- 改一个音只改一个元素
- **列表监视器可以直接看**（调试时非常有用）

⚠️ 三个列表**长度必须始终相等**。改谱子时要三个一起改，否则下标越界读到空值。

## §310 多声部：每个角色一份乐器状态

**关键事实**：Scratch 的音乐状态是**每个 target（角色）一份**，不是全局的。

这意味着多声部非常自然：

```
角色「旋律」：设定乐器为 (乐器)      → 主旋律
角色「和声」：设定乐器为 (乐器 + 2)   → 三度叠音
角色「低音」：设定乐器为 6           → 贝斯，音高 −12
```

三个角色各自 `演奏音符`，同时跑就是三重奏。

⚠️ **不要在同一个角色里切换乐器做多声部**：`演奏音符` 是阻塞的，
一个角色只能一条时间线；切乐器会让整段旋律变成「同一件乐器换音色」，
不是真正的多声部。

⚠️ **多声部要错开起始时刻**：低音比旋律晚 0.1 秒进入，听感才「稳」。
完全同时开始会有轻微的相位感（同一份采样）。

## §311 和弦：三度叠置 + 分解

### 三和弦（同时响）

一个角色无法同时演奏三个音（阻塞），只能：
- **三个角色各奏一个音**（真正的和弦）
- 或 **快速琶音**（`演奏音符 C 0.05拍` → `E 0.05拍` → `G 0.05拍`），听感近似和弦

### 分解和弦（琶音）

```
对 每个和弦音 in [0, 4, 7]:        // 大三和弦的半音偏移
    演奏音符 (根音 + 和弦音) 0.25 拍
```

**四个万能和弦**（半音偏移，以根音为 0）：

| 和弦 | 偏移 | 听感 |
|---|---|---|
| 大三 | `0 4 7` | 明亮、稳定 |
| 小三 | `0 3 7` | 忧郁、温柔 |
| 属七 | `0 4 7 10` | 紧张、要解决 |
| 大七 | `0 4 7 11` | 梦幻、爵士 |

## §312 节奏：鼓组编号 + 三条万能 pattern

`演奏鼓 [DRUM] [BEATS] 拍`，鼓编号 1~18（小军鼓/底鼓/踩镲/拍手…，**具体编号以编辑器下拉为准**，
不同版本的音色顺序略有差异，交付前务必在编辑器里听一遍）。

三条够用的 pattern（一拍 = 1 BEATS）：

```
④ 四踩（最通用）
  底鼓 1 拍 → 踩镲 0.5 拍 ×2 → 小军鼓 1 拍 → 踩镲 0.5 拍 ×2

进行曲
  底鼓 0.5 → 小军鼓 0.5 → 底鼓 0.5 → 小军鼓 0.5（循环）

慢摇
  底鼓 1 → 踩镲 0.25 ×4 → 小军鼓 1 → 踩镲 0.25 ×4
```

⚠️ **鼓点必须用「休止」对齐**：`演奏鼓 1 拍` 已经占了一拍，后面直接接下一个鼓就对了；
但如果你在循环里又加了 `等待`，会越跑越偏。

## §313 速度与量化：BPM 决定一切

`节拍` 是「这个音占几拍」，`节奏(tempo)` 是「一分钟多少拍」。

```
一个音的秒数 = (60 / BPM) × 拍数
```

- `BPM = 120`，一拍 = 0.5 秒
- `节拍 = 1` → 0.5 秒；`节拍 = 0.25` → 0.125 秒

⚠️ **改变 BPM 不会改变已经排好的谱子**，只影响播放速度 —— 这是好事，
可以用一个变量 `演奏速度` 让玩家调节快慢，谱子不用动。

⚠️ **不要在 `演奏音符` 之后再加 `等待`**：积木本身已经在等了。加了就变成「双倍时长」。

## §314 段落与循环：AABA 就够

```
A 段（8 小节）：主旋律
A 段：重复
B 段（8 小节）：变化（升高三度 / 换和弦）
A 段：回到主题
```

实现：把「当前段落」做成变量，`广播 [播放A] / [播放B]`，每段播完再决定下一段。

⚠️ **循环点要落在小节线上**：如果 A 段长度不是整数小节，循环会「卡半拍」，
玩家听着别扭但说不出哪不对。

## §315 音色搭配：三层就够

| 层 | 乐器 | 音域 | 作用 |
|---|---|---|---|
| 旋律 | 1 钢琴 / 12 长笛 / 19 马林巴 | C4~C6 | 主线条，要清楚 |
| 和声 | 21 铺底 / 15 合唱 | C3~C5 | 填满中频，音量要低 |
| 低音 | 6 贝斯 / 8 大提琴 | C2~C3 | 稳住节奏根音 |

**三条搭配原则**：
1. **音域要分开**：三个层都挤在 C4 附近会糊
2. **音量要分层**：旋律 100、和声 60、低音 80（用 `设音量为` 控制角色音量）
3. **音色要互补**：一个「有颗粒」（马林巴/拨弦）+ 一个「持续」（铺底/合唱）最好听

## §316 演奏是阻塞的：一条时间线只能做一件事

`演奏音符` 会**等到时值结束**才执行下一条。

后果：
- 一个角色里不能「边演奏边响应点击」—— 点击要放在另一个角色
- 长音期间改乐器**不会影响正在响的音**（音色已经定了）
- **不要在主循环里直接演奏**：会卡住整个循环，画面不动

**正确做法**：
```
角色「播放器」：只负责演奏（阻塞没关系）
角色「界面」：负责按钮、显示（不演奏）
用广播协调：「播放器」收到 [演奏] 才开始
```

## §317 实时合成 vs 音频素材：什么时候用哪个

| | 实时合成（音乐扩展） | 音频素材（`gen_audio.py` / 第二十九册） |
|---|---|---|
| 换乐器 | **一个变量** | 要重新生成文件 |
| 变速度 | `设节奏为` | 要变速处理 |
| 体积 | 0（内置音色） | 每个 WAV 20~200 KB |
| 音质 | 一般（采样拼接） | **可控制**（可加混响/滤波） |
| 适合 | **交互式演奏 / 跟着玩家变的音乐** | 固定的 BGM / 音效 |

**结论**：**BGM 用音频素材，交互演奏用扩展**。
「音乐转乐器」这种要实时换音色的场景，只能用扩展。

## §318 校验 + 十个坑

### 三条硬校验（`MUSIC_LOGIC_OK`）

`node scripts/music_behavior_check.mjs <music_band.sb3>`

| 检查 | 期望 |
|---|---|
| 简谱 → MIDI | `1 1 5 5 6 6 5`（八度 4）→ `60 60 67 67 69 69 67` |
| 休止符 | `1 0 5` → `60 0 67`（不是 60 60 67） |
| 八度偏移 | 八度 5 全部 +12；八度 3 首音 = 48 |
| 乐器切换 | 变量 5 / 1 / 21 → 内部 `currentInstrument` = 4 / 0 / 20 |

**第 4 条是怎么测的**（本册最有用的技巧）：
scratch-vm 把音乐状态存在 `target.getCustomState("Scratch.music")`，
而 `_setInstrument` **没有 audioEngine 守卫** —— 所以无头环境也能读到「乐器换了没」：

```js
const st = target.getCustomState("Scratch.music");
st.currentInstrument   // 0-based，用户编号减 1
```

⚠️ 但 `演奏音符` **有** `audioEngine === null` 守卫（不会出声），
而且它按**虚拟时间阻塞** —— 所以校验**不要触发演奏**，否则测一首长谱直接超时。
演奏是否正确，靠「音高表」间接验证。

### 十个坑

| # | 坑 | 症状 | 修法 |
|---|---|---|---|
| 1 | 乐器编号从 0 开始 | 选钢琴出来是小提琴 | Scratch 是 1~21，内部才 0-based |
| 2 | 越界以为会「钳到两端」 | 设 99 得到 14 | `wrapClamp` 是**环绕**，赋值前自己判范围 |
| 3 | 用 24 做低音 | 声音发闷或被截断 | Scratch 音域有限，低音用「降八度 + 贝斯」 |
| 4 | `演奏音符` 后面又加 `等待` | 每个音都双倍长 | 积木本身已经等了 |
| 5 | 一个角色切乐器做多声部 | 变成「同一乐器换音色」 | 每个声部一个角色（状态是 target 级） |
| 6 | 在主循环里演奏 | 画面卡住不动 | 演奏放独立角色 |
| 7 | 循环长度不是整数小节 | 循环点卡半拍 | 段落长度对齐小节 |
| 8 | 三个声部音域重叠 | 糊成一团 | 旋律 C4+ / 和声 C3 / 低音 C2 |
| 9 | 休止符写成 60 | 该停的地方响了 | 休止用 0，演奏时判断 |
| 10 | 校验里触发演奏 | 超时 | 只测音高表 + 乐器状态 |

### 交付前自检（6 问）

1. 旋律是**数据**（列表）还是硬编码的一串积木？
2. 换乐器是用**变量**还是复制了一份脚本？
3. 乐器编号核对过吗（1=钢琴）？越界判过吗？
4. 多声部是**多个角色**吗？
5. 演奏脚本和界面脚本是不是分开了？
6. `node scripts/music_behavior_check.mjs` → **`MUSIC_LOGIC_OK`**？

## §319 音频转乐器：把一段录音变成能演奏的音符（`audio2notes.py`）

前 14 节讲的是「已经有乐谱（简谱/音名）怎么演奏」。
这一节解决另一半问题：**手里只有一段音频**（自己唱的、手机录的、网上下的），
想用 Scratch 的乐器重新演奏它 —— 换音色、变速、加声部。

`scripts/audio2notes.py` 就是干这个的，纯 Python，不依赖 numpy / scipy。

### 整条链路（七个步骤，每步都有公式）

```
WAV → ① 单声道 → ② 降采样到 8 kHz → ③ 分帧(256 样本 / 跳步 128)
    → ④ 自相关估基频 → ⑤ 抛物线插值 + 中值滤波 → ⑥ 音符切分 → ⑦ 量化到拍
```

**① 单声道**：多声道取平均。基频检测只看一条曲线。

**② 降采样到 8 kHz**：基频 ≤ 1.2 kHz，8 kHz 采样足够；数据量降到 1/5.5，纯 Python 也跑得动。

```
抽取倍数 step = 原采样率 / 8000
先做窗口 = step 的移动平均（抗混叠），再每 step 个取一个
```

⚠️ **不做抗混叠直接抽取，高频会折叠到低频**，检出的音高会偏低一个八度以上。

**③ 分帧**：帧长 256（32 ms），跳步 128（50% 重叠）。

| 帧长 | 后果 |
|---|---|
| 太长（512 = 64ms） | **分辨不出短音符和音符间隙** → 同音高连音粘成一个长音 |
| 太短（128 = 16ms） | 低音（C3 = 130Hz，周期 7.7ms）只装得下 2 个周期，测不准 |

**32 ms 是权衡点**：C3 能装 4 个周期，C5 能装 16 个。

**④ 自相关估基频**：对每帧算

```
r(τ) = Σ x[i]·x[i+τ] / (N − τ)     τ ∈ [rate/1200, rate/60]
```

除以 `N−τ` 是**归一化**：不除的话长 lag 天然偏小，「第一个峰」会找错。

**⑤ 取「第一个显著峰」，不是最大峰**：

```
从 τ 最小往大扫，第一个满足 r(τ) ≥ 0.45 × max(r) 的局部极大，就是基频周期
```

⚠️ **这是防「低八度错误」的关键**：取全局最大常常落在 **2 倍周期**处
（因为 2 个周期也完全自相似），结果整个旋律低了一个八度。

**抛物线插值**把 lag 精度从 1 个样本提到 0.01 个样本：

```
δ = 0.5 × (y₋₁ − y₊₁) / (y₋₁ − 2y₀ + y₊₁)
f₀ = rate / (τ + δ)
```

不加这一步，8 kHz 下 C5（523Hz，lag≈15.3）会被量化到 lag=15 → 533Hz，偏 33 音分（听得出来）。

**⑥ 中值滤波（窗口 5）+ 音符切分**：

```
MIDI = round(69 + 12 × log₂(f₀ / 440))
```

切分用**两个条件**，缺一不可：

```
MIDI 变了        → 断音
能量低于阈值      → 也断音     ← 否则「C5 C5」会粘成一个长音
```

⚠️ **中值滤波必须让「静音帧」保持静音**：如果把 None 用邻居的值补上，
静音间隙就被填平了，同音高连音照样粘在一起（这个坑本脚本踩过，见下）。

**⑦ 量化到拍**：

```
拍数 = max(0.25, round((时长 / (60000/BPM)) / 0.25) × 0.25)
```

### 实测：三个闭环自测

`python scripts/audio2notes.py --selftest`（合成已知旋律 → 识别 → 逐音比对）

| 用例 | 期望 MIDI | 识别结果 |
|---|---|---|
| C 大调音阶 C5 D5 E5 F5 G5 | 72 74 76 77 79 | **72 74 76 77 79** |
| 小星星开头 C5 C5 G5 G5 A5 A5 G5 | 72 72 79 79 81 81 79 | **72 72 79 79 81 81 79** |
| 低音区 C4 E4 G4 | 60 64 67 | **60 64 67** |

### 三条硬限制（必须告诉用户）

| 限制 | 原因 | 应对 |
|---|---|---|
| **同音高连音需要一个 ≥50ms 的能量低谷** | 帧长 32ms，间隙更短就分不开 | 演奏/录制时刻意断开；或接受合并后再手工补 |
| **同时响的音（和弦）只能识别出最响的那个** | 单基频检测，不是多音高分析 | 分开录；或用多轨 |
| **噪声/混响/打击乐会污染结果** | 自相关找的是周期性 | 只对人声/单音乐器用；先降噪 |

**实测证据**：用 `gen_audio.py melody` 生成的旋律（音符间隙只有 20ms），
小星星被识别成 `72 79 81 79`（4 个音，重复音全合并）；
而同样旋律在间隙 50ms 时能完整识别 7 个音。
**这不是 bug，是输入条件不满足** —— 手册里必须写清楚，否则用户会以为程序坏了。

### 用法

```bash
# 直接看音符表
python scripts/audio2notes.py 我的旋律.wav

# 输出可粘进 IR 的格式（音高表 / 时值表 / 简谱 / 演奏伪代码）
python scripts/audio2notes.py 我的旋律.wav --scratch

# 存 JSON，指定 BPM 做量化
python scripts/audio2notes.py 我的旋律.wav --bpm 100 --json notes.json

# 自测（三条用例）
python scripts/audio2notes.py --selftest
```

`--scratch` 的输出长这样，**可以直接粘进工程的列表**：

```
# 音高表（MIDI）
音高表: [72, 72, 79, 79, 81, 81, 79]

# 时值表（拍）
时值表: [0.75, 0.75, 0.75, 0.75, 0.75, 0.75, 0.75]

# 简谱（C 大调）
1 1 5 5 6 6 5

# 演奏（配合 §307 的变量换乐器）
设定乐器为 (乐器)
演奏音符 72 0.75 拍
...
```

### 和 §307 的关系

`audio2notes.py` 只负责「音频 → 音高表」这一段。
拿到音高表之后，接的正是 §307 的 `设定乐器为 (变量)`：

```
[音频] --audio2notes--> [音高表/时值表] --变量换乐器--> [任意音色演奏]
```

**这就是完整的「音乐转乐器」链路**：素材进、乐器出，中间是一张数字列表。
