## §277 三个层次：算得对、显示对、判得对

数学类作品出问题，一定在这三层之一：

| 层 | 症状 | 例子 |
|---|---|---|
| **算得对** | 结果错，但界面正常 | 8 皇后数出 14 个解（正确是 92） |
| **显示对** | 算对了，显示成 `5.000000001` 或 `1e+21` | 分数化简没取整 |
| **判得对** | 玩家答案对，判错 | `0.1+0.2 == 0.3` → false |

**先保证第一层，再管第二层，最后才是第三层。** 顺序反了会浪费大量时间在调显示上。

## §278 浮点：Scratch 的数字是双精度，不是整数

Scratch 的变量不区分整数/小数，内部一律 IEEE-754 双精度。三个直接后果：

### ① 不精确的小数

```
0.1 + 0.2 = 0.30000000000000004
0.1 + 0.2 == 0.3        → false
```

**判等必须带容差**：

```
❌ 如果 <答案 = 0.3>
✅ 如果 <(abs(答案 - 0.3)) < 0.0001>
```

容差取多少？看量级：金额/分数用 `1e-9`，物理量用 `1e-3`，像素坐标用 `0.5`。

### ② `round` 是「四舍五入到最近整数」，`.5` 向上

```
round(2.5) = 3    round(-2.5) = -2     round(2.4) = 2
```

⚠️ `round(-2.5) = -2`（不是 −3）：Scratch 用 `Math.round`，规则是「向 +∞ 取最近」。
做「负数四舍五入」时要注意这个不对称。

### ③ `floor` 与 `ceiling` 对负数

```
floor(-2.3) = -3      ceiling(-2.3) = -2
```

「整除」用 `floor`，不要用 `round` —— `round(2.6/2) = 1`，但 `floor(2.6/2) = 1`，
差别在 `round(3/2) = 2` vs `floor(3/2) = 1`。

## §279 整数除法：Scratch 只有一种除法，你必须自己取整

Scratch 的 `/` 永远是浮点除：`7/2 = 3.5`。

三种「整数除法」的语义完全不同：

| 语义 | 写法 | 7/2 | −7/2 | 用在哪 |
|---|---|---|---|---|
| 截断（向零） | `trunc(a/b)` | 3 | −3 | C 语言风格 |
| 向下取整 | `floor(a/b)` | 3 | −4 | **数组下标、分页** |
| 四舍五入 | `round(a/b)` | 4 | −4 | 只用于「化简后的值」 |

⚠️ **本册最重要的一条实践结论**：

```
化简分数时，分子 = round(分子 / gcd)      ← 必须 round
而不是        分子 = 分子 / gcd             ← 会得到 5.000000000000001
```

为什么用 `round` 而不是 `floor`：分子/gcd 在数学上一定整除，浮点误差是 `±1e-15` 量级，
`round` 能把 `4.999999999999999` 拉回 `5`，而 `floor` 会把它变成 `4`（灾难）。

**实测**：`gen_math_lab.py` 里 4 个分数用例（含负数、需约分的），
全部用 `ROUND(DIV(分子, g))`，校验输出精确为 `5/6`、`7/12`、`1/1`、`1/2`。

## §280 `mathop` 只有 14 个函数：缺的都得自己造

Scratch 的 `[ ] 的 [ ]` 积木只支持这 14 个：

```
abs  floor  ceiling  sqrt  sin  cos  tan  asin  acos  atan  ln  log  e^  10^
```

**没有**：`pow`（任意底数幂）、`log2`、`gcd`、`lcm`、阶乘、组合数、`atan2`。

### 自己造 pow（x^y）

```
x^y = e^(ln(x) · y)        （要求 x > 0）
```

⚠️ 三个坑：
1. `x = 0` 时 `ln(0)` 无定义 → 要单独判 `y > 0 ? 0 : 1`
2. `x < 0` 时 `ln(x)` 无定义 → 负底数只能拆成「符号 + 绝对值」
3. `y` 是整数且不大时，**循环连乘更准**（`e^ln` 有精度损失）

```scratch
如果 <y = 0>: 结果 = 1
否则如果 <y > 0 且 y 是整数>:
  结果 = 1; 重复 y 次: 结果 = 结果 × x       // 最准
否则:
  结果 = e ^ (ln(x) × y)
```

### 自己造 gcd（辗转相除）

```
当 tmp ≠ 0:
  r   = g mod tmp
  g   = tmp
  tmp = r
```

⚠️ **必须先取绝对值**：`gcd(-12, 18)` 的 `mod` 结果符号依赖语言，
先 `abs` 再算，最后按需要加符号。

### 自己造 log2

```
log2(x) = ln(x) / ln(2)      或      log(x) / log(10) × log2(10)
```

⚠️ Scratch 的 `log` 是**以 10 为底**（不是自然对数），`ln` 才是自然对数。这两个搞反是高频错。

## §281 数值范围：double 能存到 1e308，但显示会变样

| 现象 | 原因 | 处理 |
|---|---|---|
| 显示 `1e+21` | 超过 21 位自动科学计数法 | 大数拆成「万/亿」单位显示 |
| 显示 `5.000000001` | 浮点尾数 | 显示前 `round(x*1000)/1000` |
| `0.1+0.2` 判等失败 | 精度 | 带容差比较（§278） |
| 巨大阶乘变 `Infinity` | 超过 1.8e308 | 阶乘最多算到 170!，再大就取对数 |

**阶乘的实用上限**：

```
12! = 479001600        （能精确显示）
20! = 2432902008176640000   （已经超过 2^53，整数精度丢了）
170! ≈ 7.26e306        （double 上限）
171! = Infinity
```

做「排列组合」时，`C(n,k)` 要**边乘边除**，不要先算 `n!` 再除（会溢出）：

```
C(n,k):
  r = 1
  重复 k 次(i 从 1):
    r = r × (n - k + i) / i      // 每一步都是整数，不会溢出
```

## §282 `mod` 的符号：Scratch 和 Python 一样，和 C 不一样

```
 7 mod 3  =  1
-7 mod 3  =  2      ← 结果符号跟「除数」
 7 mod -3 = -2
-7 mod -3 = -1
```

**为什么要管这个**：
- 「循环取第 i 个」用 `(i mod n) + 1`，`i` 为负时会得到负数下标 → 列表取空
- 时钟/角度用 `mod 360`，负角度会变成 350 而不是 −10（这通常是**想要的**）

⚠️ 但「判断奇偶」用 `x mod 2 = 0`，负数也对（−4 mod 2 = 0）✓

## §283 迭代回溯：Scratch 没有递归，只能手动维护栈

Scratch 的自定义积木**没有返回值**，也不能真正递归（会栈溢出）。
所有「递归算法」都要改写成**迭代 + 显式状态**。

以 N 皇后为例。递归版（Python）：

```python
def solve(row):
    if row > n: return 1          # 找到一个解
    total = 0
    for col in 1..n:
        if ok(row, col):
            place(row, col)
            total += solve(row + 1)
    return total
```

迭代版（状态 = 「当前行 + 每行放在哪列」）：

```
行 = 1
重复执行直到 行 < 1:
    试用 = 皇后列[行] + 1              ← 从上一轮的下一个列开始
    找本行第一个不冲突的列
    找到 → 皇后列[行] = 试用; 行 += 1
           如果 行 > n: 解数 += 1; 行 = n     ← 找到解后回到最后一行
    找不到 → 皇后列[行] = 0; 行 -= 1          ← 回退
```

**核心转换**：递归的「返回上一层」= 迭代的 `行 -= 1`；
递归的「换下一个候选」= 迭代的 `皇后列[行] + 1`。

## §284 回溯的三个致命细节（本册踩到的真 bug）

### ⚠️ 坑 1：回退时多做一次 `+1`，解数少一半

第一版回退写成了：

```
找不到 → 皇后列[行] = 0
        行 -= 1
        皇后列[行] += 1        ← 这个 +1 是多余的
```

而循环开头已经有 `试用 = 皇后列[行] + 1`，于是**每次回退跳过两个候选列**。

后果：8 皇后得 **14** 个解（正确 92），4 皇后得 **1** 个（正确 2）。
**画面完全正常**，只是数字错了 —— 这就是「算错了看不出来」。

**修法**：回退只做「清空本行 + 行减一」。上一层的「下一列」由循环开头统一负责。

> 这条规则可以推广：**「推进到下一个候选」只在一个地方写**。
> 两个地方都写，就会跳步。

### ⚠️ 坑 2：找到一个解后，`行` 变成 `n+1` 就再也回不来

```
找到 → 皇后列[行] = 试用; 行 += 1
       如果 行 > n: 解数 += 1
```

如果只加解数不处理 `行`，下一轮 `皇后列[行]` 会读到列表越界（返回空），
`试用` 变成空值，`试用 > n` 判假，进入死循环。

**修法**：找到解后显式 `行 = n`，让下一轮从「最后一行的下一个列」继续。

### ⚠️ 坑 3：列表长度和 `n` 不同步

`n` 是可变的（4/6/8），但列表 `皇后列` 是固定长度的话，改 `n` 后 `皇后列[i]` 会越界。

**修法**：每次开始前 `删掉全部 + 重复 n 次添加 0` 重建列表。

⚠️ 而且**校验时必须检查列表长度**：本工程的行为校验就有一条
`皇后列.length === n`，能抓住「重建时多加了一项」。

### 实测数据（可作为性能参考）

| n | 解数 | 访问节点 | 无头环境步数 |
|---|---|---|---|
| 4 | 2 | 31 | 6 |
| 5 | 10 | 97 | 9 |
| 6 | 4 | 301 | 15 |
| 8 | 92 | 4021 | 140 |

**节点数 = Python 基线**（4021）说明积木翻译是一比一的 ——
这是验证「翻译没走样」最硬的证据。

## §285 埃氏筛：两个「为什么」决定对不对

```
筛表[1..n] = 1
筛表[1] = 0
i = 2
重复执行直到 i*i > n:
    如果 筛表[i] = 1:
        j = i*i
        重复执行直到 j > n: 筛表[j] = 0; j += i
    i += 1
```

### 为什么从 `i*i` 开始划

`i` 的倍数里，`2i, 3i, ..., (i-1)i` 都已经被比 `i` 小的质数划掉了。
从 `i*i` 开始，一个不漏，而且省掉一半以上的重复操作。

### 为什么只筛到 `√n`

如果 `n` 是合数，它必有一个 ≤ `√n` 的质因子。
所以筛完 `√n` 以内的质数，剩下的未标记数全是质数。

⚠️ 写成 `i <= n` 也能出正确结果，只是慢 2~3 倍。**这不是正确性问题，是性能问题**，
但在 Scratch 里性能就是正确性 —— 太慢会导致卡帧、看起来像死机。

**实测**：1~100 筛出 25 个质数，前 5 个 `2,3,5,7,11`，第 25 个 `97`。

## §286 辗转相除：循环不变量是「gcd 不变」

```
g = |a|;  tmp = |b|
重复执行直到 tmp = 0:
    r = g mod tmp
    g = tmp
    tmp = r
结果 = g            （g = gcd(a,b)）
```

**为什么对**：`gcd(a,b) = gcd(b, a mod b)` 是欧几里得定理。
每次循环保持「gcd(g,tmp) 不变」，直到 `tmp=0`，此时 `g` 就是答案。

三个易错点：

1. **必须先取绝对值**（`mod` 的符号跟除数走，负数会算错）
2. **`tmp=0` 要作为退出条件**（不是 `g=0`）
3. **`gcd(0,0)` 返回 0**，作为分母会除零 → 化简前 `如果 g=0 则 g=1`

## §287 几何：能不开方就不开方

### 距离比较

判断「A 是否在 B 的 r 范围内」：

```
❌ 如果 <sqrt((ax-bx)^2 + (ay-by)^2) < r>
✅ 如果 <((ax-bx)^2 + (ay-by)^2) < r*r>
```

平方比较省一次开方，而且**避免 `sqrt` 的精度损失**。在每帧要判几百次碰撞时，这个差别很明显。

### 点到直线的距离（矩形碰撞够用了）

```
最近点 x = clamp(px, rect.x, rect.x + rect.w)
最近点 y = clamp(py, rect.y, rect.y + rect.h)
距离平方 = (px - 最近点x)^2 + (py - 最近点y)^2
```

### 角度：`atan` 只有单参数，没有 `atan2`

```
atan(dy/dx) 只能给出 (−90°, 90°)
```

要「从 A 指向 B 的角度」，直接用 Scratch 的 `面向 [B]` 积木（内部就是 atan2），
或者自己分象限处理：

```
如果 dx > 0: 角度 = atan(dy/dx)
如果 dx < 0: 角度 = atan(dy/dx) + 180
如果 dx = 0: 角度 = (dy > 0) ? 90 : -90
```

⚠️ Scratch 的 `atan` 返回值是**角度**（不是弧度），`sin/cos` 的输入也是角度。
这一点和大多数编程语言相反，写公式时特别容易错。

## §288 排列组合与概率：抽样要「无放回」

### 无放回抽样（抽奖/发牌/出题不重复）

```
❌ 循环 n 次: 随机取一个        ← 会重复
✅ 洗牌后取前 k 个：
   对 i 从 1 到 n-1:
       j = 随机(i, n)
       交换 列表[i] 和 列表[j]
```

Fisher-Yates 洗牌是唯一正确的「无放回」做法，且**每个排列等概率**。

⚠️ 常见错误写法「随机取一个，如果在结果里就重取」：
当 `k` 接近 `n` 时会大量空转，最后几个数可能卡死。

### 概率显示的「手感」

`随机数(1,10) = 1` 触发「10% 概率」在数学上对，但玩家会觉得「怎么连着出三次」。

如果要做「保底」，用**计数器**而不是改概率：

```
如果 未中次数 >= 9: 必中，未中次数 = 0
否则: 未中次数 += 1
```

这样期望不变，但体验稳定得多（这也是真实游戏的做法）。

## §289 算法可视化：什么时候画、每帧画多少

| 算法 | 每帧画几次 | 为什么 |
|---|---|---|
| 回溯搜索 | **只在找到一个解时画** | 每步都画会拖慢 20 倍，而且玩家看不清中间态 |
| 排序 | 每次交换画一次 | 交换是「有意义的瞬间」 |
| 寻路 | 每帧画 20~50 个格子 | 太少看不出扩散，太多卡 |

⚠️ **画笔重绘要 `全部擦除` 后重画，不要「擦一笔画一笔」** ——
擦除是 O(笔迹数)，逐笔擦会越跑越慢。

⚠️ 回溯类算法**不要每帧重画整个棋盘**：8×8 有 64 个格子 + 8 个棋子，
92 个解就是 92 次全量重绘，在 Scratch 里足够卡到 10 fps 以下。

本工程的做法：回溯跑完后**只画最后一个解**（`收到 [画棋盘]`），
既不拖慢算法，玩家也看得到结果。

## §290 校验方法：用已知答案当断言（这是数学类最大的优势）

### 为什么数学类最好校验

UI 类作品只能验「元素在不在」，玩法类只能验「状态对不对」；
**数学类有唯一正确答案，可以直接断言**：

| 题目 | 已知答案 | 来源 |
|---|---|---|
| N 皇后 n=4 | 2 | OEIS A000170 |
| N 皇后 n=8 | 92 | 同上 |
| 1/2 + 1/3 | 5/6 | —— |
| 1..100 质数个数 | 25 | —— |
| 第 25 个质数 | 97 | —— |

这些数字**写死在校验里**，程序算错就红。

### 三步校验法

1. **先用 Python 跑对**（`math_reference.py`），得到「解数 + 节点数」两个基线
2. **翻成积木**，用 `MATH_LOGIC_OK` 比对**解数**
3. **比对节点数** —— 节点数一致 = 执行路径一致 = 翻译没走样

第 3 步是本册最有价值的一条：**解数对但节点数不对，说明剪枝逻辑变了**，
现在没出错只是运气。

### 十个致命坑（按踩坑频率）

| # | 坑 | 症状 | 修法 |
|---|---|---|---|
| 1 | 回退时多 `+1` | 解数少一半（8 皇后 14 个） | 「推进候选」只写一处 |
| 2 | 找到解后 `行` 不归位 | 死循环 / 列表越界 | 显式 `行 = n` |
| 3 | 列表长度 ≠ `n` | 越界读到空值 | 每次重建列表 |
| 4 | 化简不 `round` | 显示 `5.000000001` | `round(分子/g)` |
| 5 | `mod` 负数没取绝对值 | gcd 算出负数 | 先 `abs` |
| 6 | `log` 当成自然对数 | 所有指数计算全错 | `ln` 是自然对数 |
| 7 | 判等不带容差 | `0.1+0.2 ≠ 0.3` | `abs(差) < 1e-9` |
| 8 | 筛法从 `2i` 开始 | 结果对但慢一倍 | 从 `i*i` 开始 |
| 9 | 无放回抽样用「重取」 | 最后几个数卡死 | Fisher-Yates 洗牌 |
| 10 | 每帧全量重绘 | 92 个解卡到 10 fps | 只在关键节点画 |

2. 校验里是不是写死了**已知答案**（不是「跑出来的值」）？
3. 节点数/步数和 Python 基线一致吗？
4. 所有除法结果要不要 `round`/`floor`？想清楚了吗？
5. 判等是不是都带了容差？
6. `node scripts/math_behavior_check.mjs` → **`MATH_LOGIC_OK`**？
