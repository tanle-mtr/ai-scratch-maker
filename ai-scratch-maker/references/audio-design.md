# 声音设计：让作品「有质感」的另一半（第二十九册，§263–§276）

> **用户说「作品看起来/听起来廉价」「没有游戏感」「像课件」时，声音和画面一样重要。**
>
> 第二十六册管**画面动效**，第二十八册管**UI 素材**，这一册管**声音**：
> 什么时候该响、响多大声、响多长、以及哪些声音**根本不该有**。
>
> 配套工具（都在 `scripts/`）：
> - `gen_sfx_kit.py` → `examples/assets/audio/`（**22 个分层音效** + `manifest.json`）
> - `check_audio_assets.py` → `AUDIO_ASSETS_OK`（波形级合规闸门）
> - `gen_audio.py`（底层合成：振荡器 / 噪声 / 低通 / 包络 / 程序化 BGM）

## §263 静音的作品，代码再好也像半成品

一个残酷的事实：**玩家判断「这是不是个正经游戏」的前 3 秒，靠的是声音**。

三个最常见的「静音型廉价感」：

| 症状 | 原因 | 在哪一节修 |
|---|---|---|
| 点了按钮没反应 | 没有点击音，或音效太轻听不见 | §264 §276 |
| 玩两分钟就关声音 | **所有音效一样响**（都归一化到同一峰值） | §264 |
| 声音很「脏」/有咔哒声 | 首尾没归零、DC 偏移 | §267 §274 |
| 音乐和音效打架 | 没有音量总线，音乐不 ducking | §271 |
| 听得出是「现成素材拼的」 | 音色不统一（一个正弦一个方波一个采样） | §266 |

**必须先接受一条**：声音不是「加个音效文件」，是**一套有层级的信息系统**。

## §264 四层响度：这是「好听」与「业余」的分水岭

业余做法：所有音效都 `normalize(peak=0.85)`。
结果：**点一下按钮和爆炸一样响**。玩家第一个反应是关声音。

专业做法：按**信息重要度**分四层，层间差 6~9 dB：

| 层 | 目标峰值 | 触发频率 | 典型音效 | 为什么是这个响度 |
|---|---|---|---|---|
| `ui` | **−18 dBFS** | 每秒可能好几次 | 悬停、点击、返回、开关 | 最高频 = 必须最轻，否则吵 |
| `fx` | **−9 dBFS** | 每几秒一次 | 金币、跳跃、落地、受击 | 主要反馈层，要清楚但不压过事件 |
| `ev` | **−3 dBFS** | 一局几次 | 开门、升级、胜利、失败、警报 | 低频次 = 可以响，要「有分量」 |
| `amb` | **−15 dBFS** | 持续 | 雨、风、人群 | 铺底，**绝对不能抢戏** |

```
ui    −18  ┐
           ├ 9 dB
fx     −9  ┐
           ├ 6 dB
ev     −3  ┘
amb   −15  （独立层，靠音量积木压到 25~40 再播）
```

**实测数据**：`gen_sfx_kit.py` 生成的 22 个音效，峰值精确落在 −18.0 / −9.0 / −3.0 / −15.0 dBFS（`check_audio_assets.py` 逐文件核对，容差 ±2 dB）。

⚠️ **层内也要有微差**。同为 `fx`，`fx_hit`（0.200s）比 `fx_coin`（0.180s）听感更重，
不是靠更响，而是靠**低频成分**和**更长衰减**。同层用同一峰值，靠频谱和时长做区分。

## §265 时长预算：短音效「短」是设计要求，不是省事

| 层 | 时长区间 | 超出会怎样 |
|---|---|---|
| `ui` | **30~250 ms** | 点击音超过 250ms 就像「拖音」，连点会糊成一片 |
| `fx` | **80~600 ms** | 超过 600ms 会盖住下一个音效，密集操作时糊 |
| `ev` | **300~1600 ms** | 太短没分量；超过 2s 玩家会等它播完 |
| `amb` | **1000~4000 ms**（循环） | 太短循环点明显（能听出「重复」） |

具体参考（本套件的真实值）：

```
ui_hover    0.045s    ← 只是「我在这儿」
ui_click    0.060s    ← 一个音头
ui_back     0.070s
ui_error    0.190s    ← 错误要让玩家「意识到」，所以最长
fx_coin     0.180s
fx_jump     0.160s
fx_land     0.120s
fx_hit      0.200s
ev_open     0.480s
ev_win      1.080s    ← 胜利可以长，玩家愿意听完
ev_alarm    0.700s
amb_rain    2.000s    ← 循环用
```

**一条硬规则**：`ui` 层的音效**绝对不能超过 0.25 秒**。玩家连点五次菜单，五个 0.5 秒的音效叠在一起就是噪音。

## §266 音色一致性：一套音效要「同源」

听着像「从三个素材站各下一个」的原因：

| 维度 | 不一致的表现 | 统一做法 |
|---|---|---|
| 波形 | 有的是纯正弦，有的是方波，有的是采样 | **同层用同一族波形**：ui=sine / fx=tri 或 sine / ev=square / amb=滤波噪声 |
| 起音 | 有的 1ms 硬起，有的 30ms 渐入 | ui 层 1~3ms（脆）/ ev 层 10~20ms（厚） |
| 混响 | 有的干，有的带空间 | **全部干声**（Scratch 里没法加混响，素材带混响会显得脏） |
| 音高基准 | A4=440 与 A4=432 混用 | 全用 440 |
| 噪声成分 | 有的加噪声有的不加 | **只有「撞击/摩擦/风」类才加噪声**，其余一律干净 |

`gen_sfx_kit.py` 的分组波形约定：

```python
ui_*   → sine（纯净、无噪声、无低频）
fx_*   → sine / tri + 少量噪声（只有 hit/land/swipe 加）
ev_*   → square（有厚度，多段结构）
amb_*  → 滤波噪声（唯一天然含噪声的层）
```

## §267 包络：首尾必须归零，否则一定有咔哒

**咔哒声（click/pop）的物理原因**：波形从 0 突然跳到 0.8（或反过来），
扬声器振膜瞬间位移 → 你听到「咔」。

```
❌ 硬切：  0, 0, 0.8, 0.7, ... , 0.6, 0.5, 0     ← 首尾各一个突变
✅ 淡入淡出：0, 0.1, 0.35, 0.7, 0.8, ... , 0.3, 0.1, 0
```

**淡入淡出长度**：`min(10ms, 总时长 × 15%)`。

- 45ms 的 `ui_hover` → 6.75ms 淡入（占 15%）
- 1.08s 的 `ev_win` → 10ms（封顶）

⚠️ **不要对短音效用固定 8ms 淡入**：45ms 的音效被 8ms 淡入吃掉 18%，会变得「软」、没有音头。

### DC 偏移：另一个隐形杀手

如果整段波形平均值不是 0（比如一直是 +0.3），Scratch 播放时会有低频「嗡」，
而且和别的音效叠加会**提前削波**（明明每个都没超 0 dBFS，合起来爆了）。

```
DC 偏移 = mean(samples)，必须 |mean| < 0.01
```

产生原因通常是：只用了正弦的正半周、或噪声没有去直流。`gen_audio.py` 的 `noise()` 已去直流。

## §268 音高方向 = 语义（这是最省事的「游戏感」）

玩家不需要教程就能理解音高方向：

| 方向 | 含义 | 例子 |
|---|---|---|
| **上行**（低→高） | 获得、变强、成功、开启 | 金币、升级、跳跃、开门、胜利 |
| **下行**（高→低） | 失去、变弱、失败、关闭 | 受伤、失败、返回、关门 |
| **先上后下** | 撞击、弹跳 | 落地、球弹 |
| **平 + 颤音** | 警告、持续危险 | 警报、低血量 |

本套件的实现：

```
fx_coin    C6 → E6        上行（奖励）
fx_jump    400 → 900 Hz    上行（身体向上）
ui_back    1200 → 700 Hz   下行（返回）
ev_lose    A4 → G4 → F4 → E4   连续下行（失败）
ev_alarm   660Hz + 18Hz 颤音    平 + 颤（警报）
```

**⚠️ 反例**：升级音用下行、受伤音用上行。玩家会觉得「哪里不对」但说不出为什么。
这就是最典型的「AI 生成的音效」问题 —— 音色对了，方向反了。

## §269 「不要做」清单：比「做什么」更重要

| # | 别做 | 为什么 |
|---|---|---|
| 1 | **不要给每个动作都配音** | 走路每一步都响 = 噪音。脚步用「间隔采样」（每 3~4 步响一次） |
| 2 | **不要悬停音效无节流** | 鼠标划过一排按钮会「哒哒哒哒」连响。**悬停音最少间隔 120ms** |
| 3 | **不要同时响 3 个以上音效** | 频谱糊成一团。同帧多事件时，只播优先级最高的一个 |
| 4 | **不要用 0.5s 以上的 UI 音** | 连点会叠（§265） |
| 5 | **不要让 BGM 从头播到尾不变化** | 8 小节循环 + 音量随状态起伏（战斗 60 → 探索 35） |
| 6 | **不要循环 < 1s 的环境音** | 循环点会形成「哒哒哒」的节奏感 |
| 7 | **不要在暂停时继续播环境音** | 暂停要连声音一起停（广播 `暂停` 里 `stop all sounds`） |
| 8 | **不要用「播放声音直到结束」播 UI 音** | 它会**阻塞脚本**，按钮会卡住。UI 音一律用「播放声音」（不等待） |

第 8 条是 Scratch 特有的坑：
```
❌ 播放声音 [点击] 直到结束   ← 阻塞，脚本卡 60ms
✅ 播放声音 [点击]            ← 立即返回
```

## §270 程序化 BGM：4 小节循环 + 和弦进行

`gen_audio.py bgm --mood chase --bars 4` 生成可无缝循环的 BGM。

**无缝循环的三个条件**：
1. **总长度 = 整数小节**（否则循环点切在半拍上）
2. **首尾样本都归零**（同 §267）
3. **最后一小节不能有「收束和弦」**（否则听起来像「结束了又重来」）

`gen_audio.py` 内置 7 个 mood，各有明确的和弦/音型：

| mood | 音型 | 每拍 | 用途 |
|---|---|---|---|
| `happy` | C-E-G 跳跃三音 | 0.26s | 休闲、儿童向 |
| `chase` | 快速八分音符 + 低音推进 | 0.16s | 追逐、紧张 |
| `spooky` | 小调 + 失谐 | 0.5s | 悬疑、鬼屋 |
| `calm` | 长音铺底 | 0.75s | 解谜、菜单 |
| `victory` | 上行小号 | 0.24s | 结算（**不循环**） |
| `defeat` | 下行三音 | 0.42s | 失败（**不循环**） |
| `explore` | 五声音阶 | 0.22s | 探索、地图 |

**和弦进行的通用套路**（够用一辈子）：
```
明亮：I - V - vi - IV     （C-G-Am-F）
紧张：i - VI - III - VII   （Am-F-C-G）
温柔：I - vi - IV - V      （C-Am-F-G）
```

## §271 音量总线：让音乐给音效让路（ducking）

Scratch 的音量是「角色音量 × 全局音量」，范围 0~100。做一个简单的三层总线：

```
总音量 = 全局音量积木（0~100）

BGM 角色：        设音量为 全局 × 0.35        （铺底，35%）
环境音角色：      设音量为 全局 × 0.30
音效（一次性）：  设音量为 全局 × 1.0
```

**ducking（闪避）**：播重要事件音（`ev_*`）时，把 BGM 音量瞬间压到 40%，0.3 秒后恢复。

```
当收到 [播放事件音]
  设 BGM 音量 = 全局 × 0.35 × 0.4
  播放声音 [ev_win] 直到结束
  重复 15 次: 设 BGM 音量 += (全局×0.35 - 当前) × 0.3; 等待 0.02   // 缓动恢复
```

⚠️ **不要用「等待 0.3 秒再恢复」**（硬切回来会「窜一下」），用缓动（§223 的 `x += (目标-x)*0.3`）。

**设置里的音量开关**要同时管三层：广播 `静音` → 所有音频角色 `设音量为 0`。

## §272 Scratch 里的播放方式（四个积木的正确用法）

| 积木 | 什么时候用 | 坑 |
|---|---|---|
| `播放声音 [X]` | **UI 音、短音效** | 不等待，可叠加；适合高频短音 |
| `播放声音 [X] 直到结束` | **事件音、BGM 一次** | **会阻塞脚本**，别用在 UI 上 |
| `停止所有声音` | 切场景、暂停、结算 | 会连 BGM 一起停，之后要重启 |
| `设音量为 N` | 总线、ducking | 是「角色音量」，不是全局 |

**BGM 循环**：把「播放声音 直到结束」放在 `重复执行` 里，或直接用「播放声音」+ 音效本身循环。

⚠️ **Scratch 会把所有音频预加载到内存**。22 个音效 + 3 个 BGM ≈ 2~3 MB，
手机端加载会慢 1~2 秒。**不要把 BGM 做成 3 分钟**（渲染成 44.1k 单声道约 16 MB），
4~8 小节循环足够。

## §273 音频素材规范（照这个做就不会错）

| 项 | 值 | 理由 |
|---|---|---|
| 采样率 | **44100 Hz** | Scratch 内部统一 44.1k，别的会被重采样（多一次损失） |
| 声道 | **单声道** | Scratch 混成单声道，双声道白占一倍体积 |
| 位深 | **16 bit** | CD 标准；24bit 会被降，32bit float 不认 |
| 峰值 | 见 §264 分层 | 不要都归一到 0.85 |
| 首尾 | 必须为 0 | §267 |
| 命名 | `{层}_{名}.wav`（`ui_click` / `fx_coin` / `ev_win` / `amb_rain`） | 层前缀 = 响度归属，脚本可自动套音量 |

**为什么层前缀要写进文件名**：这样「批量设音量」可以按前缀分组处理，
也让 `check_audio_assets.py` 能自动判断该用哪条响度标准。

## §274 波形级校验：五类听感问题都能测

`python scripts/check_audio_assets.py` → `AUDIO_ASSETS_OK`

它查七项：

| 检查 | 判据 | 抓的是 |
|---|---|---|
| 格式 | 44100 / 单声道 / 16bit | 重采样损失、体积浪费 |
| **分层响度** | 峰值在所属层 ±2 dB 内 | 「点击和爆炸一样响」 |
| **首尾归零** | `|s[0]|`、`|s[-1]|` < 0.02 | 起播/结束的「咔哒」 |
| **尾部衰减** | 末 10% 的 RMS 不高于整体 RMS × 1.6 | 硬切（不是淡出） |
| **DC 偏移** | `|mean|` < 0.01 | 低频嗡嗡、提前削波 |
| 削波 | 峰值 ≤ 0.99 | 刺耳的方波失真 |
| 时长 | 在所属层区间内 | 拖音、糊成一团 |

**实测**：本套件 22 个音效 0 错 0 警；
反向测试（故意造 3 个坏文件）抓到 5 类问题：
`首样本 0.900 不为 0`、`末样本 0.900 不为 0`、`DC 偏移 0.9`、`峰值 -3.0 偏离本层 -18`、`中间有 200ms 连续静音`。

⚠️ 校验器**只能保证「不难听」**，不能保证「好听」。好听要靠 §264~§268 的设计。

## §275 廉价 vs 专业：听感对照

| 场景 | 廉价做法 | 专业做法 |
|---|---|---|
| 点按钮 | 一个 0.5 秒的「叮」，和爆炸一样响 | 60ms 的 `ui_click`，−18 dBFS |
| 悬停 | 没有，或每像素都响 | 45ms `ui_hover`，≥120ms 节流 |
| 得金币 | 一个通用「叮」 | 两音上行 C6→E6，−9 dBFS |
| 受伤 | 和金币同一个音，只是更响 | 噪声+低频，200ms，带衰减 |
| 胜利 | 直接播 BGM | 大三和弦 + 高八度琶音，1.08s，ducking 压 BGM |
| 背景 | 一首 3 分钟的歌循环 | 4 小节 35% 音量，按状态变化 |
| 设置里的音量 | 只有开/关 | 0~100 滑杆 + 分三层总线 |

## §276 音效与 UI 的配合时机（20 毫秒决定手感）

| 交互 | 音效时机 | 常见错误 |
|---|---|---|
| 按钮点击 | **按下瞬间**（不是松开） | 等松开才响 → 感觉「迟钝」 |
| 按钮悬停 | 进入瞬间 | 每帧检测 → 连响 |
| 开关切换 | 状态**改变后** | 先响再改 → 音画不同步 |
| 弹窗打开 | 面板出现**同时** | 延迟一帧 → 「不跟手」 |
| 金币 | 碰撞判定**当帧** | 等动画播完 → 感觉没吃到 |
| 失败 | 血条归零**后** 0.1s | 立刻响 → 抢在视觉前面，突兀 |

**「按下瞬间就响」为什么重要**：人的听觉对 20ms 内的延迟不敏感，
但对「视觉已反馈、声音晚到 100ms」非常敏感（会觉得「卡」）。
所以**音效要绑在「状态改变的当帧」，不要绑在动画结束**。

### 与第二十八册的配合

UI 素材的四状态（§254）与音效是一对的：

```
hover  造型 → 同时播 ui_hover
pressed 造型 → 同时播 ui_click
 disabled → 不播（或播 ui_error）
弹窗打开 → ev_open（低频、有分量），不是 ui_click
```

**按钮按下时不要再放大缩小**（§231 说的是尺度很小的 1.05/0.95），
有了音效 + 换造型，视觉上已经「按下去了」，再加缩放会显得浮夸。
