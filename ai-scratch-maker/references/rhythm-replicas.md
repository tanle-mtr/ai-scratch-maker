# 第三十九册：代表作音游复刻手册（§457–§479）

> 目标：**照着这一册能复刻五款代表作的核心玩法**。
> 前置：第三十八册 `rhythm-games.md`（唯一时钟 / 帧量化 / 判定纯函数 / 谱面平行列表）。
> 本册只讲「每款代表作多出来的那部分」：**轨道模型、音符、判定线（圈）、判定方式、判定逻辑**。
>
> 覆盖：**无轨 Phigros / 定轨 PJSK（世界计划）/ 不定轨 Milthm / 亚音游 跳舞的线、滚动的天空**。

## §457 五款总览：先分清「判定体」是什么

用户说的「轨道 / 音符 / 判断线（圈）/ 判定方式」，在五款里含义完全不同。
复刻前先填这张表，填错一个就会把整个引擎做歪：

| 作品 | 轨道模型 | 判定体 | 音符运动 | 输入 | 判定主维度 |
|---|---|---|---|---|---|
| **Phigros** | **无轨**（没有固定列） | **可动判定线**（线段，可平移/旋转/增减/隐藏） | 相对判定线法向下落 | 点击 / 按住 / 滑动 / 触碰 | 时间 + 「点击在判定线上的切向投影」 |
| **PJSK** | **定轨 12 格网格** | 固定水平判定线（底部） | 竖直下落 | 点击 / 长按 / 方向滑动 / 划过 | 时间 + **格号匹配** + 方向 |
| **Milthm** | **不定轨**（判定圈位置会移动） | **判定圈**（圆，出现在画面各处） | 沿轨迹飞向判定圈 | 击打 / 滞留手指 / 接住 | 时间 + **圆内命中** |
| **跳舞的线** | 无轨、无线 | **无判定线**（路径转角就是判定点） | 线自动前进 | **单键点击** | 时间（转向窗口）+ 路径段合法性 |
| **滚动的天空** | **5 列离散赛道** | **无判定线**（球所在格 × 障碍格） | 球自动前进、场景后退 | 左右拖动换列 | **位置 × 拍点**（不是误差分级） |

**三种判定体**：
```
① 线段（Phigros / PJSK）：命中 = 输入点在「以线为基准的条带/格」内
② 圆  （Milthm）      ：命中 = 输入点到圆心距离 ≤ 有效半径
③ 格 / 路径（亚音游） ：命中 = 离散位置是否合法，没有「误差毫秒」这回事
```

⚠️ **两款亚音游不是「判定误差」类音游**。它们没有 Perfect/Great/Good 分级，
只有「在正确的拍点处于正确的位置 = 通过 / 否则失败」。
硬套第三十八册的四档判定会做出一个四不像。

## §458 统一抽象：判定体 × 时间 × 输入动作

五款能共用一个引擎，只要把差异做成**数据**：

```
模式        1 Phigros / 2 PJSK / 3 Milthm / 4 跳舞的线 / 5 滚动的天空
谱面        目标时刻[i] / 类型[i] / 位置[i] / 参数[i] / 已判定[i]   （五条平行列表）
判定体      类型(1线 2圈 3格 4路径) + 中心(x,y) + 角度 / 半径 / 列数
输入        时刻 / x / y / 轨道或列 / 动作(1点 2按 3松 4滑) / 滑动方向
窗口        窗1..窗5（该模式的档位边界，ms）
```

判定分**三层**，顺序不能反：

```
① 空间命中：输入落在哪个音符的判定区？（§475 几何）
② 时间判定：该音符的误差 = 输入时刻 − 目标时刻，落哪一档？
③ 类型判定：这个音符要求的动作/滞留是否满足？
```

⚠️ 常见错是「先比时间再找音符」。那样同一时刻多个音符（同时押、Phigros 多线）
会永远命中第一个。**先空间筛选、再在候选里取时间最近的**。

## §459 Phigros：无轨 = 判定线本身是实体

**核心创新**：别的音游「轨道固定、判定线固定」，
Phigros 里**判定线有 1~多条，能任意平移、旋转、增加、消失、改透明度、改速度**，
音符是**挂在某条判定线上**的，从线的法线方向落向它。

所以数据结构里**必须先有判定线表，再有音符表**：

```
判定线表: 线号 / 中心X / 中心Y / 角度 / 不透明度 / 速度倍率 / 该线BPM
事件表  : 线号 / 事件类型(1移动 2旋转 3透明度 4速度) / 起始时刻 / 结束时刻 / 起值 / 终值
音符表  : 线号 / 目标时刻 / 类型 / positionX / 时长 / 速度 / 上落or下落(±1)
```

官谱 JSON（`formatVersion: 3`）就是这个结构：

```json
{ "formatVersion": 3, "offset": 0.0,
  "judgeLineList": [{
    "bpm": 100,
    "notesAbove": [ {"type":1,"time":1,"holdTime":0,"speed":1.0,"positionX":0} ],
    "notesBelow": [],
    "speedEvents": [], "judgeLineMoveEvents": [],
    "judgeLineRotateEvents": [], "judgeLineDisappearEvents": []
  }] }
```

| 字段 | 含义 | 复刻要点 |
|---|---|---|
| `bpm` | **每条线自己的 BPM** | 不是全局！不同线可以有不同 BPM |
| `time` | 单位 **T = 1.875/bpm 秒 = 60/32/bpm（128 分音符）** | `目标ms = time × 1875 / bpm` |
| `positionX` | 音符距判定线中心的横向位置，单位 **宽度单位 = 0.05625 × 渲染宽度** | 换算成像素后再用 |
| `holdTime` | 长按持续时间，单位 T | Hold 头速度恒 1，`speed` 是尾速度 |
| `type` | 1 Tap / 2 Drag / 3 Hold / 4 Flick | 见 §462 |
| `notesAbove/Below` | 正面 / 反面下落 | 决定法向符号 ±1 |

⚠️ **官谱 JSON 没有缓动概念**，所有事件线性插值，谱师用多段线性事件叠出缓动。
RPEJson（社区编辑器格式）才有 easing、事件节点、BPMList、独立 X/Y 事件。
**复刻时先把「线性插值」做对，别一上来加贝塞尔缓动**。

## §460 Phigros 判定线事件与坐标数学

每个事件是 `[startTime, endTime, startValue, endValue]`，运行期按 songTime 线性求值：

```
求值(事件, t):
    若 t ≤ start → startValue
    若 t ≥ end   → endValue
    否则          → start + (end−start) × (t−start)/(end−start)     # ★ 线性，无 easing
```

每个事件层**独立求值再叠加**：

```
线中心X(t) = 初值 + Σ 移动X事件求值
线中心Y(t) = 初值 + Σ 移动Y事件求值
线角度(t)  = 初值 + Σ 旋转事件求值        # 0 = 水平，正 = 顺时针
不透明度(t)= 初值 + Σ 消失事件求值        # ≤0 时线不渲染，音符也可能隐藏
速度(t)    = 初值 + Σ 速度事件求值
```

⚠️ **不透明度 ≤ 0 时判定仍然生效**（隐藏判定线是常见谱面手法，
例如「两个音符重合时打击」就是把一条与 Note 重合的线隐藏实现的）。
**只关渲染，不要关判定** —— 这是复刻 Phigros 最容易翻车的一条。

音符位置（渲染）：
```
切向单位向量 u = (cosθ, sinθ)
法向单位向量 v = (−sinθ, cosθ)
音符中心 = C + u × (positionX × 宽度单位)
                + v × (±1) × ((目标时刻 − songTime) × 速度 × 像素每ms)
```
`±1` 来自 `notesAbove / notesBelow`。⚠️ 判定线旋转后，**下落方向也要跟着法向转**，
不能永远朝屏幕下方。

## §461 Phigros 的空间命中：不是「点到线的距离」

这是全网最容易讲错的一条。官方说明：
> 「判定区域为一个**与判定线垂直的、向两边无限延展的矩形区域**。」

意思是：判定区是**沿判定线法线方向无限延伸**的条带，
**沿切线方向宽度有限**（= 音符的判定宽度，固定，不随视觉宽度设置改变）。

```
d = 输入点 − 线中心 C
切向坐标 t = d·u = dx·cosθ + dy·sinθ        # ★ 决定命中哪个音符
法向坐标 n = d·v = −dx·sinθ + dy·cosθ      # 只用于渲染，不参与命中

命中音符 i  ⇔  |t − positionX[i]×宽度单位| ≤ 音符半宽
```

⚠️ **不要写 `点到线段距离 < 阈值`**：那条带在法向上无限长，
玩家在离判定线很远处点击，只要**切向坐标对**，照样命中。
（游戏里「判定区域是固定的」指的就是这个半宽，音符视觉宽度可调但判定宽不变。）

**多条判定线同时存在时**：输入要对每条线各算一次切向坐标，
在**所有线的候选音符**里取时间最近的那个。

## §462 Phigros 四种音符的判定逻辑

| 类型 | 官方叫法 | 判定方式 | 档位 | 常见实现错误 |
|---|---|---|---|---|
| **Tap** | 蓝键 | 与判定线重合时点击判定区 | P / Good / Bad / Miss | 把 Bad 当成不断连击 |
| **Hold** | 长条 | 头与线重合时点击并按住，直到结束前始终有手指在判定区 | **无 Bad** | 只看按下不检查滞留 |
| **Drag** | 黄键 | 重合时**有手指在判定区即可**，可换手 | **仅 P / Miss** | 要求「点击」动作（错） |
| **Flick** | 粉/红键 | 重合时在判定区向**任意方向滑动** | **仅 P / Miss**（课题模式同） | 限定方向；一根手指一次滑动判多次 |

判定窗口（普通模式；资料版本间有 ±10~40ms 出入，按目标版本定）：

```
Perfect  |误差| ≤ 80 ms
Good     80 < |误差| ≤ 180 ms
Bad      180 < |误差| ≤ 220 ms   → 断连击
Miss     超窗 / 未击中            → 断连击
课题模式 Perfect ≤ 40 ms
Hold 允许提前 80ms 松手（课题 40ms）
```

⚠️ **「单次点击只能判定一个 Tap/Hold 音符」**：
同帧多个候选时，取「最早出现且可判定」的一个，其余留给下一次输入。
不写这条会让双押一次点击全中。

⚠️ **Drag 与 Flick 的「一次输入只判一个」语义不同**：
Drag 是「有手指在区内」的**状态**（可换手、可同时覆盖多个 Drag）；
Flick 是「一根手指向一个方向滑动**仅能判定一次**」的**事件**（连续左右快滑可连判多个）。
用同一个 `按下沿` 处理两者必错。

## §463 Phigros 评分：100 万分两段

```
总分 = 判定分(900,000) + 连击分(100,000)

判定分 = 900000 × Σ(权重) / 物量
          Perfect = 100% ，Good = 65% ，其余 = 0
连击分 = floor(最大连击 / 总物量 × 100000)
```

| 评级 | 条件 |
|---|---|
| **φ (Phi)** | 全部 Perfect（All Perfect） |
| **蓝 V / 白 V** | 全连 / 高分（不同版本文案不同） |
| **F** | 未通关 |

⚠️ **「最大连击 / 总物量」而不是「连击次数 / 判定次数」**：
中途断一次，即使后面全连，连击分也拿不满。
⚠️ 课题模式**只算判定分**，没有连击分。

## §464 PJSK：定轨 = 12 格网格 + 固定判定线

**轨道模型**：底部一条**固定水平判定线**，横向是 **12 格网格**（不是 5 条轨）。
音符落点用「格号 + 宽度（跨几格）」描述，所以能做出 5 线谱的观感、
也能做出宽音符、斜向排列的滑条。

```
谱面音符: 时刻 / 起始格(0..11) / 宽度(格) / 类型 / 尾时刻 / 方向 / 是否Critical
空间命中: 输入格 ∈ [起始格, 起始格+宽度)        # ★ 区间匹配，不是单格相等
```

⚠️ 常见错：把它做成 5 条固定轨。那样宽音符、跨格滑条、APPEND 多指谱全都做不出来。
**用 12 格网格存，渲染时画成几条线随你**。

判定窗口（Sekaipedia 精确值，单位 ms）：

| 档 | 窗口 | 得分 | Life | 断连击 |
|---|---|---|---|---|
| PERFECT | ±41.7 | 100% | ±0 | 否 |
| GREAT | 41.7–83.3 | 70% | ±0 | 否 |
| GOOD | 83.3–108.3 | 50% | ±0 | **是** |
| BAD | 108.3–125 | 0% | −50 | **是** |
| MISS | >125 / 漏按 | 0% | −80（Hold 中途 −40） | **是** |

⚠️ **GOOD 断连击**（很多音游是 GOOD 续连）——这是 PJSK 手感偏硬的关键。
⚠️ **PERFECT 与 GREAT 都续连击**，Combo 定义就是「连续 P/G 的个数」。
⚠️ Life 初始 1000（上限 2000），归零后**仍可继续打**，但后续得分变 1/10 且不再回血。

## §465 PJSK 四类音符 + 尾判 + Critical

| 类型 | 判定方式 | 复刻要点 |
|---|---|---|
| **Tap**（蓝/紫） | 到线时点击对应格 | 基础 |
| **Hold / Slide**（绿长条） | 头到线时点击并按住，**尾到线时松开或按尾端类型操作** | **Start / End 各算一个判定物量**；Sustain 每 1/8 拍记 0.1 权重 |
| **Flick**（红，带箭头） | 到线时**按箭头方向滑动** | 方向错 = 不命中；不能只判「有滑动」 |
| **Trace**（细绿条） | 到线时**划过即可**，不要求精确时刻；同 lane 的 Hold 也算接触 | **只出 PERFECT 或 MISS**；不要给它算误差档 |
| **Critical**（金色） | 上述四类都可以是金色 | 权重 ×2（Flick ×3），**判定逻辑完全不变** |

**Hold 的三种尾**：
```
① 平尾：尾到线时松手 → 尾判
② Flick 尾：尾到线时向指定方向滑动
③ Trace 尾：尾到线时保持接触划过
```
⚠️ **Hold 尾必须单独判定**。只判头会让「按住不放到底」拿满分。

**同时判定顺序**：同刻的 Trace / Flick / Tap 各自独立结算；
闪电类（见 Milthm）才是「最后判」，PJSK 没有这层。

**得分公式**（复刻排行榜才需要，做玩法可简化）：
```
score = baseNoteScore × noteWeight × judgement × skill × combo × fever
combo = 1 + 0.01 × floor(连击/100)   （上限 1.1）
fever = 1.5（Multi Live 的 Fever 期间），否则 1
```

## §466 Milthm：不定轨 = 判定圈会跑

**判定体是圆**，而且圆心**随谱面在画面各处移动**（中央、底部、两侧切换），
音符沿轨迹线飞向它。所以叫「不定轨」——不是没有轨，是**判定区不固定在一条线上**。

```
判定圈: 圆心(cx, cy) + 半径 r + 轨迹事件（圆心随时间移动）
音符  : 目标时刻 / 类型 / 轨迹ID / 到达角度或落点
命中  : (px−cx)² + (py−cy)² ≤ 有效半径²
```

⚠️ **判定范围比视觉大**：官方说明可点区域比看见的更大，
且是「轨道判定，近似一半的垂直判定」。复刻时用 `有效半径 = 视觉半径 × 1.2~1.5`，
**别让视觉半径直接当判定半径**。

⚠️ 官方明说：**《Milthm》不存在传统长条音符**。雨丝不是 Hold（§469），
照抄 PJSK 的 Hold 逻辑一定错。

## §467 Milthm 六档判定定义与双序列（官方）

官方文档《判定定义》给出的精确窗口（击打偏差 = 操作时刻 − 普通判定点，ms）：

| 等级 | 区间 | 宽度 | AccV2 |
|---|---|---|---|
| **Exact (s)** | [−35, 35] | 70ms | 100% |
| **Perfect (p)** | [−70,−35) ∪ (35,70] | 70ms | 100% |
| **Great (g)** | [−105,−70) ∪ (70,105] | 70ms | 60% |
| **Good (n)** | [−140,−105) ∪ (105,140] | 70ms | 30% |
| **Bad (b)** | [−155,−140) ∪ (140,155] | 30ms | 15% |
| **Miss (m)** | 其余 / 未击中 | — | 0% |

```
AccV2 = ( Σ Ajudge(ξi) ) / N          # Ajudge: s/p=100%, g=60%, n=30%, b=15%, m=0%
TA = ACC_N                            # 全曲准确率
最大 100% ⇔ 每个判定都是 Exact 或 Perfect
```

⚠️ **区间是「并集」不是简单阈值**：写成 `a≤35 → s, a≤70 → p` 是对的（取 abs），
但要注意 **Bad 之后直接 Miss，没有更宽的档**，且 Good/Bad 断连击。
⚠️ 旧版资料是五档（大P ±35 / 小P ±70 / Good ±140 / Bad ±155），
**以官方六档为准**；手册实现用六档，旧版差异写在配置开关里。

**双判定序列**（Milthm 最独特的设计）：

```
Ξ = 普通判定序列（雨露 / 雨丝 / 雨滴）  → ScoreV3 / AccV2 / 普通连击 / AP / FC
Φ = 闪电判定序列（Lightning / Fracture）→ 独立，不进 Ξ，不计物量 N
```

| 音符 | 判定方式 | 结果 |
|---|---|---|
| **雨露 Dew** | 与判定圈重合时准确击打 | 六档 |
| **雨丝 Drizzle** | 底部与圈重合时按住，结束时释放 | 六档 + 水面反射 |
| **雨滴 Raindrop** | 到达判定圈时「接住」即可 | 六档（同雨露但无精确击打要求） |
| **闪电 Lightning** | 独立 | **只有 Lightning Exact / Lightning Miss** |

⚠️ **闪电最后判定**：闪电与其他音符同刻时，先结算普通音符再结算闪电。
⚠️ **闪电 Miss 消耗闪电血量**；伤害「溢出」（超出剩余血量）才可能降低 ScoreV3 的连击分状态，
**不影响 AP / FC 达成条件**。别把闪电 Miss 写进 Ξ 或普通 Combo。

**结算**：理论值 **1,010,000**（全 Exact 且未击中闪电 → R / Rhythm of Rain），
构成 ≈ 准度分 100 万 + 连击分 0.5 万 + AP 附加 0.5 万；
AP = 全 s/p，FC = 无 Bad/Miss。

## §468 水面反射：雨丝不是 Hold

官方三条规则，逐条翻译成代码：

```
① 命中雨丝时：该音符判定范围扩展至「整个屏幕」
   → 有效半径 = ∞（或全屏矩形），手指在屏幕上移动不会造成 Miss
② 只要屏幕上「仍有雨丝与判定圈接触」：至少一根手指必须留在屏幕上
   → 维持条件 = (存在 active 雨丝) AND (按下手指计数 ≥ 1)
③ 当不再有雨丝接触判定圈：应全部抬手；继续按住不惩罚，但不再产生判定/得分
```

**关键差异表**：

| | 传统 Hold（PJSK/Phigros） | 雨丝 Drizzle |
|---|---|---|
| 绑定 | 绑定某个 lane / positionX | **不绑定位置**，命中后全屏有效 |
| 换手 | 通常不允许 | **允许中途换手** |
| 多指 | 每个 Hold 各要一根手指 | 多个雨丝**只要至少一根手指** |
| 松手 | 立即断 | 只在「仍有雨丝接触圈」时要求至少一根 |
| 尾判 | 有 | 无独立尾判，靠「接触结束」收尾 |

实现：
```
状态: 活跃雨丝数 A, 屏上手指计数 F
每帧:
    A = count(雨丝 i : 头时刻 ≤ songTime ≤ 尾时刻 且 已命中)
    若 A > 0 且 F = 0 → 所有活跃雨丝判 Miss
    若 A = 0 → 清空「已命中」暂存；继续按住不产生判定
判一击(雨丝候选):
    若 已在「全屏命中」状态 → 空间判定直接通过（忽略圆半径）
```

⚠️ **「闪电最后判定」在这种状态下也不能断尾**：
同刻结算闪电时，不得重置 `A` 或刷新活跃雨丝的命中状态。

## §469 跳舞的线：单键 + 路径事件序列

**没有音符、没有判定线、没有轨道**。只有一条自动前进的线，
玩家**点一下 → 线在当前拐点转 90°**，走错/没转就撞墙或掉出路径。

```
关卡 = 路径段序列
段 k: 起点 / 方向(±X 或 ±Y) / 长度(格) / 目标时刻(拍)
事件: 转角点 k 的目标时刻 T_k（由 BPM 和长度反推）
线位置: 沿路径按「速度 × songTime」推进（弧长参数化）
```

**判定不是误差分级，是「转向窗口」**：

```
当前转角 k 的窗口 = [T_k − W, T_k + W]
输入 = 单次点击（无位置、无方向，只有时刻）
判一转:
    若 点击时刻 ∈ 窗口 且 该转角尚未使用:
        方向 = 方向 × 旋转90°（固定朝下一路径段）
        段索引 += 1；结果 = 成功
    否则:
        结果 = 失败（撞墙 / 出界）→ 从最近存档点重开
```

⚠️ **「连点」= 连续多个相邻拐点**，窗口会紧挨着甚至重叠，
必须用「扫描指针 + 已使用标记」保证一次点击只消费一个转角（第三十八册 §442 同款）。
⚠️ **视角变化 / 引导线 / 存档点是关卡表现层**，不参与判定；
但存档点决定失败后 `songTime` 回退到哪一拍，要存 `检查点时刻`。
⚠️ 路径是**手工设计的折线**，不是程序化生成；BGM 的重音 = 转角点。

**最小可复刻数据结构**：
```
时刻[k] / 方向码[k] / 段长[k] / 已转[k] / 检查点标记[k]
当前段 / 段内进度 / 线速度(格每秒) / 当前方向 / 失败计数
```

## §470 滚动的天空：5 列离散网格 + 自动前进

**没有判定线、没有音符下落**。球以固定速度自动向前滚，
玩家**左右拖动切换列**，在正确的拍点处于安全的列。

```
赛道 = 5 列网格
关卡 = 按「拍」排列的行（row）
每行: 拍号 / 哪些列有地板 / 哪些列有障碍 / 哪些列是跳板 / 收集品
球  : 当前行(由 songTime × 速度算出) / 当前列(0..4) / 是否腾空
```

**判定 = 位置 × 拍点的离散碰撞**（无误差档）：

```
每帧:
    row = floor(songTime / 每行ms)
    col = 玩家当前列（拖动时按格插值，落地时取整）
    若 腾空:
        跳过地面障碍；按跳跃曲线算高度
    否则:
        若 地板[row][col] = 0            → 坠落，失败
        若 障碍[row][col] = 1            → 撞击，失败
        若 跳板[row][col] = 1            → 腾空，跳跃高度 3 格 / 前进 4 格
        若 收集品[row][col] = 1          → 收集
```

**官方 Wiki 确认的规则**：
- **5 格赛道**；横摆锤攻击范围横向 3 格；滚轮在 5 格内往返
- **普通跳板**：跳 3 格高、4 格远；**短距离跳板**：2 格高、2 格远
- **任何障碍必须有一个地板提供支撑，否则无伤害判定**（玻璃地板掉落时其上的障碍也掉落）
- 地板类型：普通 / 玻璃 / 移动地板；移动地板会改变后续行的安全列
- 障碍按 **BPM 拍点手工放置**：一记鼓 = 一堵墙，低音 = 一个洞，副歌 = 变速或视觉转场
- 速度随关卡上升（约 60 → 140+ BPM），后期靠背板

⚠️ **不是「按节奏点击」，是「按节奏移动到正确列」**。
所以没有 Perfect/Great，只有「通过 / 失败」；评价是完成度、钻石、皇冠。
⚠️ **拖动是连续量、判定是离散量**：拖动过程中 `col` 用浮点插值，
但**碰撞判定要把 col 取整到最近列**，且取整时机在「球中心进入该行」的那一帧。
写成每帧都用浮点碰撞会出现「明明在缝隙里却撞了」。

## §471 亚音游怎么复用音游引擎

两款亚音游可以复用第三十八册的**时间轴与谱面生成**，但要换掉判定层：

```
复用: songTime / BPM→拍长 / 谱面按拍生成 / 唯一时钟 / 对象池 / 结算页
替换: 判定函数 → 「状态合法性检查」
     四档窗口 → 单一通过窗口（跳舞的线）或无窗口（滚动的天空）
     分数评级 → 完成度 / 收集品 / 检查点进度
```

| | 跳舞的线 | 滚动的天空 |
|---|---|---|
| 时间轴作用 | 决定何时到达转角 | 决定球在哪一行 |
| 输入 | 单键点击（只有时刻） | 左右拖动（只有列） |
| 空间 | 无（路径唯一） | 5 列离散 |
| 失败 | 撞墙 / 出界 → 回检查点 | 撞障碍 / 坠落 → 重开 |
| 判定结果 | 成功 / 失败 | 成功 / 失败 / 收集 |
| 节奏点来源 | BGM 重音 = 转角 | 鼓点 = 墙，低音 = 洞 |

⚠️ **别给亚音游加 Combo 与准确率**：它们的正反馈是「走得更远 / 收集更全」，
硬加分数分级会破坏「背板—肌肉记忆」的核心循环。

## §474 命中数学汇总（可直接抄）

```
# ① 旋转线段（Phigros / PJSK 通用；PJSK θ=0）
u = (cosθ, sinθ);  v = (−sinθ, cosθ)
d = (px−cx, py−cy)
t = d·u = dx·cosθ + dy·sinθ
n = d·v = −dx·sinθ + dy·cosθ
Phigros 命中: |t − posX×宽度单位| ≤ 半宽         # n 不参与
PJSK   命中: 起始格 ≤ floor((t + W/2)/格宽) < 起始格+宽度

# ② 圆（Milthm）
有效半径 R = 视觉半径 × 1.2~1.5
若 该音符已处于「水面反射/全屏」→ R = ∞
命中: dx² + dy² ≤ R²

# ③ 路径转角（跳舞的线）
命中: |输入时刻 − T_k| ≤ W 且 已转[k]=0      # 无空间项

# ④ 离散列（滚动的天空）
row = floor(songTime / 每行ms)
col = round(连续列坐标)                       # ★ 取整后再查表
命中: 地板[row][col] 且 非障碍[row][col]
```

⚠️ **三角函数用角度不用弧度**（Scratch `sin/cos` 吃角度，见第三十册）；
若用弧度要先 `× 180/π`。
⚠️ **Scratch 没有 `atan2`**，判定线角度由谱面事件直接给，不要反算。

## §475 复刻工作流：每款的最小可玩步骤

| 作品 | 第 1 步 | 第 2 步 | 第 3 步 | 最容易卡住 |
|---|---|---|---|---|
| **Phigros** | 官谱 JSON 解析（T→ms） | 判定线事件线性求值 | 切向投影命中 + 四音符 | 隐藏线仍要判定、多角度下落 |
| **PJSK** | 12 格网格渲染 | 五档窗口 + Life/Combo | Hold 头尾 + Flick 方向 + Trace | GOOD 断连、Trace 只 P/Miss |
| **Milthm** | 判定圈轨迹事件 | 六档 + Ξ/Φ 双序列 | 水面反射 + 闪电最后判 | 雨丝≠Hold、可换手、全屏判定 |
| **跳舞的线** | 折线路径 + 弧长推进 | 转角窗口 + 扫描指针 | 检查点/视角/引导线 | 连点窗口重叠、一次点击只消费一个 |

## §476 校验清单（24 条）

**Phigros**
1. `目标ms = time × 1875 / bpm`（官谱 T 单位）；每条线用自己的 BPM。
2. 事件按 songTime **线性插值**，无缓动；不透明度 ≤0 **仍参与判定**。
3. 旋转 θ 后下落方向跟法向转，不是永远朝下。
4. 命中用**切向投影**，法向距离不参与；多线时在所有线候选中取时间最近。
5. 单次点击只判一个 Tap/Hold；Drag 可换手；Flick 任意方向且一次滑动只判一次。
6. Drag/Flick **只有 P/Miss**；Hold **无 Bad**、允许提前 80ms 松手。
7. 分数 = 判定分 90 万（P 100%/Good 65%）+ 连击分 10 万（最大连击/物量）。

**PJSK**
8. 五档边界 ±41.7 / 83.3 / 108.3 / 125 逐档命中。
9. **GOOD 断连击**；PERFECT 与 GREAT 续连击。
10. BAD −50 / MISS −80 / Hold 中途 −40 Life；Life 归零后得分 1/10。
11. 12 格**区间匹配**（宽音符跨格）。
12. Hold Start/End 各一次判定；尾可以是平尾/Flick 尾/Trace 尾。
13. Trace **只出 P/Miss**、任何接触（含同 lane 的 Hold）都算。
14. Flick 方向错不命中；Critical 只改权重不改判定。

**Milthm**
15. 六档边界 35/70/105/140/155 逐档命中（用 abs，区间是并集）。
16. AccV2 权重 s/p 100%、g 60%、n 30%、b 15%、m 0%。
17. 闪电 **不进 Ξ、不计物量 N**；闪电 Miss 不影响 AP/FC。
18. 同时判定时**闪电最后**；有活跃雨丝时闪电判定不断尾。
19. 水面反射：命中雨丝后全屏有效、可换手、多个雨丝只需一根手指。
20. 无活跃雨丝仍按住 → 不惩罚但也不产生判定/得分。

**亚音游**
21. 跳舞的线：一次点击只消费一个转角；连点窗口重叠不乱序。
22. 跳舞的线：失败回最近检查点，不是回开头。
23. 滚动的天空：5 列、列坐标**取整后**查表；无地板 = 坠落。
24. 滚动的天空：障碍无支撑地板则无伤害；跳板 3 高 4 远、短跳板 2 高 2 远。

## §477 十六个坑

1. **把「无轨」理解成「没有判定线」** → Phigros 恰恰是**判定线最多、最活**的那个。
2. **Phigros 隐藏线时关掉判定** → 官方用隐藏线做「两音符重合」，关判定会整段吃 Miss。
3. **用点到线段距离做 Phigros 命中** → 判定区法向无限延伸，正确的是切向投影。
4. **给官谱事件加贝塞尔缓动** → 官谱 JSON 只有线性，缓动是谱师用多段事件叠的。
5. **把 PJSK 做成 5 条轨** → 宽音符、跨格滑条、APPEND 谱全废；要 12 格网格。
6. **PJSK 的 GOOD 续连击** → 官方是 GOOD 及以下断连。
7. **Trace 算时间误差档** → 它只有 PERFECT/MISS，任何接触即通过。
8. **Hold 只判头** → 尾判、Sustain、尾端 Flick/Trace 全丢。
9. **把 Milthm 雨丝当 Hold** → 官方明说「不存在传统长条音符」；雨丝不绑位置、可换手、全屏判定。
10. **雨丝要求每个各一根手指** → 实际只需「至少一根手指留在屏幕上」。
11. **闪电写进普通 Ξ 序列** → 物量、准确率、AP/FC 全错。
12. **闪电先于普通音符判定** → 官方规定最后判定，且有雨丝时不得断尾。
13. **Milthm 用旧版五档** → 官方现行是六档（加了 Great）；要做版本开关。
14. **给亚音游加 Perfect/Great 分级** → 它们只有「通过/失败」，节奏体现在障碍与转角的拍点位置。
15. **滚动的天空用浮点列直接碰撞** → 拖到两列之间会误判；必须取整。
16. **滚动的天空给空中障碍伤害判定** → 官方规则：无支撑地板的障碍**无伤害判定**。

> 一句话：**先把「判定体」做成数据，再把「档位窗口」做成表，最后把「音符类型」做成处理函数。**
> 五款代表作看起来是五个游戏，实际上就是这三张表的不同取值。
