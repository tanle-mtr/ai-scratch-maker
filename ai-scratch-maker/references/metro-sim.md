- **§167 一条线就是一张数据表（别把站名写进脚本）**
  广州3号线把整条线摊成 4 个平行列表：`站名`（29 项）/ `换乘线路`（29 项）/ `英站名` /
  `支线站名`，再加坐标表。脚本里**一个站名都不硬编码**，全部按 `站编号` 索引取值：
  ```yaml
  - set_variable: {var: 下一站, value: {item_of_list: {list: 站名, index: {add: [{var: 站编号}, 1]}}}}
  ```
  好处：加站 = 往列表加一行；做支线 = 换一张「支线站名」再跑同一套逻辑。
  **数据表字段建议**：`站名 / 里程(米) / x / y / 换乘 / 停车时长 / 是否快车`。
  缺 `里程` 就做不了真车物理，缺 `x,y` 就画不了线路图 —— 这两个字段是必须的。

- **§168 里程是唯一真相（速度积分 + 单位换算）**
  广州3号线的主变量是 `距离 = 5746`（**米**，剩余距离）、`速度 = 120`（**km/h**）、`限速 = 120`。
  **列车的屏幕位置永远由里程算出来，绝不直接改 x/y**——否则到站判定和线路图会各说各话。
  ```yaml
  # 每帧：档位 1=牵引 0=惰行 -1=制动
  - change_variable: {var: 速度, by: {multiply: [{var: 档位}, 0.6]}}     # 0.6 km/h 每帧
  - if: {cond: {less_than: [{var: 速度}, 0]}, do: [{set_variable: {var: 速度, value: 0}}]}
  - if: {cond: {greater_than: [{var: 速度}, {var: 限速}]}, do: [{set_variable: {var: 速度, value: {var: 限速}}]}
  # 关键换算：km/h → 米/秒 → 每帧米（dt = 0.0333s）
  - change_variable: {var: 里程, by: {multiply: [{divide: [{var: 速度}, 3.6]}, 0.0333]}}
  ```
  ⚠️ **`速度/3.6` 这一步是 90% 的人漏掉的**。漏掉的后果：速度 120 时每帧走 120 米，
  800 米的站间距离一帧就飞过去了，到站判定永远不触发。记住：**km/h ÷ 3.6 = m/s**。
  加速度取值参考：城市轨道常用「牵引 ≤ 1.0 m/s²、常用制动 ≤ 1.0 m/s²、紧急制动 1.2~1.5 m/s²」，
  换成每帧 km/h 就是 1.0 × 3.6 × 0.0333 ≈ **0.12 km/h/帧**（想手感快点可以放大到 0.5~1）。

- **§169 里程 → 屏幕坐标：折线插值（真车定位的核心）**
  线路不是直线时，用「相邻站之间线性插值」。先算累计里程，再查里程落在哪一段：
  ```yaml
  # 站在第 k 段（里程 k 起点 ≤ 里程 < 里程 k+1 起点）
  - set_variable: {var: t, value: {divide: [
       {subtract: [{var: 里程}, {item_of_list: {list: 站里程, index: {var: 段}}}]},
       {subtract: [{item_of_list: {list: 站里程, index: {add: [{var: 段}, 1]}}},
                   {item_of_list: {list: 站里程, index: {var: 段}}}]}
     ]}}
  - set_variable: {var: 列车x, value: {add: [
       {item_of_list: {list: 站x, index: {var: 段}}},
       {multiply: [{subtract: [{item_of_list: {list: 站x, index: {add: [{var: 段}, 1]}}},
                                {item_of_list: {list: 站x, index: {var: 段}}}]}, {var: t}]}
     ]}}
  ```
  这样即使线路是 S 形、环形、支线，逻辑都只改坐标表，代码不动。
  `广佛地铁广佛线全段` 就是靠这套把 30+ 站画在城市地图上。

- **§170 到站判定与「对标」停车（本册最有含金量的机制）**
  广州3号线专门做了一个叫 **`对标`** 的角色（4 个造型）——停车精度就是它的全部工作：
  `等待直到` 满足条件后换造型，给玩家「车头对上门」的实时反馈。
  判定分两条，**必须同时成立**：
  ```yaml
  - if: {cond: {and: [
       {less_than: [{mathop: {operator: abs, num: {subtract: [{var: 里程}, {var: 站里程_下一站}]}}}, 15]},  # 距停车点 <15m
       {less_than: [{var: 速度}, 2]}                                                                    # 基本停稳
     ]}, do: [
       - set_variable: {var: 停车偏差, value: {round: [{subtract: [{var: 里程}, {var: 站里程_下一站}]}]}},
       - broadcast: {message: 到站}      # → 触发开关门状态机
     ]}
  ```
  只有「位置到了」没「停稳」→ 会边滑边开门；只有「停稳」没「位置」→ 停半路也开门。
  **停车偏差**单独存一个变量：`|偏差| ≤ 0.5m` 判「完美对标」（加分），否则扣分/重开——
  这是地铁模拟唯一的「操作水平」体现，没有它就只是个播片。
  ⚠️ 用 `abs` 数学函数，**别写 `里程-站里程 < 15 且 站里程-里程 < 15`** 两遍，
  容易漏一半导致「冲过头不停车」。

- **§171 开关门是四态状态机，不是一个布尔值**
  广州3号线用了 `车门 = 关` 变量 + 4 个门角色（`左门`/`右门`/`左屏蔽门`/`右屏蔽门`），
  广播 `开门` / `关门` / `重新关门`，其中 `重新关门` 是给「乘客被夹到」准备的第二次机会。
  状态机（`车门状态` 0关 1开门中 2已开 3关门中）：
  ```yaml
  - when_receive: {message: 帧}
  - if: {cond: {equals: [{var: 车门状态}, 1]}, do: [        # 开门中：每帧滑一点
      - change_variable: {var: 门开度, by: 4},
      - if: {cond: {greater_than: [{var: 门开度}, 100]}, do: [
          - set_variable: {var: 门开度, value: 100},
          - set_variable: {var: 车门状态, value: 2},
          - set_variable: {var: 停站计时, value: 150}]}}]     # 150 帧 ≈ 5 秒
  - if: {cond: {equals: [{var: 车门状态}, 2]}, do: [
      - change_variable: {var: 停站计时, by: -1},
      - if: {cond: {less_than: [{var: 停站计时}, 1]}, do: [
          - set_variable: {var: 车门状态, value: 3},         # 转关门中
          - broadcast: {message: 关门}}]}]
  ```
  **门的位移用 `门开度` 一个变量驱动所有门**：`左门 x = 门x - 门开度`、`右门 x = 门x + 门开度`，
  屏蔽门同款但慢 20%（`门开度 × 0.8`）——真实地铁屏蔽门和车门不是同时开完的。
  ⚠️ **门开到一半别允许发车**：`允许牵引 = (车门状态 == 0)`，否则玩家能在门开着时把车开走。

- **§172 信号机与限速（把「红灯」变成可玩的约束）**
  广州3号线有 `信号 = 2758`、`信号消息 = 黄灯`、`限速 = 120`、`灯`（3 个造型）角色。
  做法：信号机在数据表里有一串「位置 + 状态」，列车里程越过它就更新：
  ```yaml
  - if: {cond: {greater_than: [{var: 里程}, {var: 信号位置}]}, do: [
      - set_variable: {var: 信号消息, value: 黄灯},
      - set_variable: {var: 限速, value: 60},          # 黄灯限 60
      - 灯: 换造型 黄]}
  ```
  超速惩罚：`速度 > 限速 + 5` → 累计 `超速计时`，超时 → 紧急制动 + 扣分。
  这一条让「会不会开」变成有后果的事——地铁模拟的玩法深度全靠它。

- **§173 速度表盘：指针角度映射（一个乘法搞定）**
  广州3号线有 `速度显示盘` + `速度显示针` 两个角色。指针就是一个旋转：
  ```yaml
  # 表盘刻度 0~限速 对应 -90°~+90°（半圆表）
  - point_in_direction: {direction: {subtract: [
       {multiply: [{divide: [{var: 速度}, {var: 表盘满量程}]}, 180]}, 90]}}
  ```
  ⚠️ **Scratch 的方向是 90 = 右、0 = 上**，所以「竖直向上」是 0，「正右」是 90。
  想让指针在 0 速度时朝**左上**（-90 = 270）就写 `速度/满量程*180 - 90`。
  套用 `旋转方式 = 不旋转`（`set_rotation_style: dont-rotate`）会**让指针不转**——指针角色必须
  保持默认「任意旋转」。

- **§174 报站与线路图（进度条）**
  ```yaml
  - set_variable: {var: 下一站, value: {item_of_list: {list: 站名, index: {add: [{var: 站编号}, 1]}}}}
  - set_variable: {var: 报站词, value: {join: {a: 下一站是, b: {var: 下一站}}}}
  ```
  线路图进度：`本段进度 = (里程 - 站里程[所在段]) / (站里程[下一段] - 站里程[所在段])`，
  画一条横线 + 一个小圆点，`圆点x = 起点x + 本段进度 × 线长`。
  **每一站一个小圆点角色**（克隆 29 个），已过站换「实心」造型 —— 这就是社区线路图的标准做法。

- **§175 客流：克隆体上下车（让它「活」起来）**
  广州3号线的 `人物`（4 造型，2 个克隆体脚本）做上下车客流，`站台状态` 变量控制是否放人。
  ```yaml
  - when_receive: {message: 开门}
  - repeat: {times: 6, do: [
      - create_clone_of: {clone: _myself_},
      - wait: {secs: 0.2}]}
  # 克隆体：从站台走向车门 → 到门边隐藏（"上车"）
  ```
  ⚠️ 客流克隆体**必须自己删除**（`delete_this_clone`），并且要挡住 `是克隆` 守卫（铁律 11）。
  300 上限（铁律 12）在客流场景特别容易撞：一次开门放 20 人 + 关门不删 → 几站就满。

- **§176 五个致命坑**：
  1. **漏掉 `÷3.6` 的单位换算**（§168）→ 一帧飞过整站，到站判定永不触发。
     自检：`速度=80` 时，一帧里程增量应该是 `80/3.6×0.0333 ≈ 0.74 米`，不是 80。
  2. **到站判定只判位置不判速度**（§170）→ 高速通过也算「到站」，直接开门。必须 `AND` 两个条件。
  3. **门没关就允许牵引**（§171）→ 车开着门跑。用 `允许牵引` 变量闸住，别靠人肉自觉。
  4. **列车位置直接改 x/y、不用里程算**（§169）→ 线路图、到站判定、报站三处数据打架。
     **里程是唯一真相**，x/y 永远是它的派生量。
  5. **指针角色设了「不旋转」**（§173）→ 表针纹丝不动，但变量在变，极难排查。
     同源坑：`change_effect` 的 effect 值必须大写，`stop` 的选项值必须是英文。
