## 体素沙盒（§187–§190）

- **§187 世界生成：高度图 + 分层填充（不要随机撒方块）**
  `我的世界S` 的世界是 800 × 125 = `地图（方块ID） len=100000`，
  另有 `地图（海拔）len=800`、`地图（初始高度）len=800`、`地图（生物群系）len=801`、
  `#地图 seed = 54228`、`=随机数 len=100000`（**预生成的随机数表**）。
  `挖矿猫4` 同款：`Blocks.type len=180000`、`Blocks.ground height len=60`、
  `Biomes.deepth = [-30,-70,-125,-200,-300]`（按深度切生物群系）。
  正确流程（三步，顺序不能反）：
  ```yaml
  # ① 每列算一个海拔（噪声叠加比纯随机自然得多）
  - 海拔[x] = 55 + sin(x×0.08)×8 + sin(x×0.031)×14 + random(-1,1)
  # ② 按高度填方块：表层 / 次表层 / 石头，按「距地表的深度」选 ID
  - for y in 0..高:
      若 y ≥ 海拔[x]        → 空气
      否则若 y ≥ 海拔[x]-1  → 草方块
      否则若 y ≥ 海拔[x]-4  → 泥土
      否则                  → 石头
  # ③ 才挖洞、放矿、放水
  ```
  ⚠️ **先挖洞再填地形 = 洞被填掉**。所有「修改地形」的步骤必须在地形生成之后。
  ⚠️ **每帧调 `random` 会让世界抖动**：`我的世界S` 用 `=随机数` 预生成 10 万个随机数就是为了这个。
  要「同一个种子生成同一个世界」就自己写线性同余 `种子 = (种子×1103515245 + 12345) mod 2147483648`。

- **§188 光照传播：迭代松弛（不用队列也能做）**
  `我的世界S` 有 `地图（光照）len=100000` + 4 个专用积木：
  `map:光照更新 (光源亮度, 光源x, 光源y)`、`map:设置 x y 的光照等级为 N`、
  `map:获取 x y 光照`、`map：洞穴光照 (x,y,方向,亮度,虚像,dx,dy)`、
  `光照等级渲染 (x钳制基准,y钳制基准,x钳制,y钳制)`。`挖矿猫4` 有 `Blocks.light len=180000`。
  Scratch 里不要写 BFS 队列（列表当队列性能很差），用**迭代松弛**：
  ```yaml
  - repeat: {times: 12, do: [
      - set_variable: {var: x, value: 0},
      - repeat: {times: {var: 宽}, do: [
          - change_variable: {var: x, by: 1},
          - set_variable: {var: y, value: 0},
          - repeat: {times: {var: 高}, do: [
              - change_variable: {var: y, by: 1},
              # 本轮光照 = max(自身, 邻居中最亮的 - 1)
              - 更新光照(x, y)]]}]}
  ```
  `更新光照` 内部取「左/右/上/下 四个邻居的光照值」的最大值，减 1，与自身取大。
  12 轮足够让光传 12 格。**渲染时按光照值选透明度**：
  `set_effect {effect: BRIGHTNESS, value: 光照×8 - 100}`，别用一堆造型去切。
  ⚠️ 方块挡住光 → 邻居取不到值时按 `-1` 处理（不是 0），否则光会「穿过」石头继续算。

- **§189 挖掘：硬度表 + 进度累加 + 掉落**
  `#方块属性（挖掘硬度）` 里基岩是 `100000`（永远挖不动），草方块 `30`，石头 `90`。
  `+光标破坏 破坏进度` 每帧累加 `1/硬度`，到 1 就替换方块。
  ```yaml
  - if: {cond: {and: [{mousedown: null}, {equals: [{var: 光标方块ID}, {var: 目标方块ID}]}]}, do: [
      - change_variable: {var: 破坏进度, by: {divide: [{var: 挖掘速度}, {var: 硬度}]}},
      - if: {cond: {greater_than: [{var: 破坏进度}, 1]}, do: [
          - map替换: {x: {var: 光标x}, y: {var: 光标y}, ID: 0},   # 变成空气
          - 挖掘掉落物设置: {方块id: {var: 目标方块ID}, 方块名称: ..., 光标x: ..., 光标y: ...},
          - set_variable: {var: 破坏进度, value: 0}}]}
  ```
  ⚠️ **换目标方块要清零进度**（`光标方块ID ≠ 上次方块ID → 进度=0`），
  否则「挖一半换块」会瞬间挖穿新方块。
  ⚠️ 硬度为 0 或空 → `1/0` 得 Infinity，进度直接爆表；先判 `硬度 > 0`。

- **§190 背包：平铺列表 + 定长步长（stride）**
  `我的世界S` 的 `背包 len=108`（27 格 × 4 字段），配套积木：
  `交换 临时 n1 n2` / `交换 背包 n1 n2 (开启堆叠?)` / `交换 背包 背包 n1 n2` /
  `加入背包 (东西, 数量, 属性)` / `减去背包(模糊检索) (东西, 数量)`。
  `挖矿猫4` 用 4 条平行列表：`Inventory_Item.type` / `inventort_item.amount` / …（注意原作拼写就错，别抄）。
  **推荐用平行列表**（比 stride 好读、好查、不容易越界）：
  ```
  背包名称 / 背包数量 / 背包属性      ← 三个等长列表，索引即格子号
  ```
  交换两格 = 三个列表各做一次三项 swap：
  ```yaml
  - set_variable: {var: 临时, value: {item_of_list: {list: 背包名称, index: {var: n1}}}}
  - replace_item_of_list: {list: 背包名称, index: {var: n1},
                           item: {item_of_list: {list: 背包名称, index: {var: n2}}}}
  - replace_item_of_list: {list: 背包名称, index: {var: n2}, item: {var: 临时}}
  # 数量、属性两个列表照抄一遍（三项必须同时换，漏一个就串味）
  ```
  ⚠️ **swap 必须用临时变量**，直接对调会丢一个值（和 C 语言 swap 同理）。
  ⚠️ 加入背包前先「模糊检索」同名同属性格子，能堆叠就 `数量+`，否则找空格 —— 否则背包瞬间满。

## 光路解谜（§191–§192）

- **§191 关卡用「单字符编码」压缩，一个字符就是一格**
  `光线 v8` 的 `关卡` 列表只有 19 项，每项是一个 64 字符的字符串：
  ```
  151111111111111111    ← 8×8 地图，每字符 = 一格类型
  151111311111111111
  131113311111111113
  ```
  `[总] 地图东西` = `["无","光源","反射镜","墙","接受器", …]`（类型枚举表），
  `模块：解析关卡 %s (码)` 逐字符转成 `地图（东西）/ 地图（方向）/ 地图（x）/ 地图（y）` 四个 len=64 的列表。
  ```yaml
  - define: {name: 解析关卡, params: [码]}
  - set_variable: {var: i, value: 0}
  - repeat: {times: 64, do: [
      - change_variable: {var: i, by: 1},
      - replace_item_of_list: {list: 地图（东西）, index: {var: i},
          item: {item_of_list: {list: [总] 地图东西,
                  index: {letter_of: {letter: {var: i}, word: {var: 码}}}}}}]}
  ```
  **价值**：19 关 × 64 格 = 1216 格数据，只用 19 个列表项存完。
  加一关 = 加一行字符串。这是所有解谜类作品都该用的关卡格式。
  ⚠️ `letter_of` 的索引是 **1-based**，地图索引也是 1-based，别再多减 1（这是最常见的差一位）。

- **§192 反射角：`出射 = 2×法线 - 入射`（两个式子解决全部镜面）**
  `光线 v8` 的 4 个专用积木：`光线计算》反射镜角度`、`光线计算》确定`、
  `模块：光线计算简化 (射入角度1, 射入角度2, 射出角度, ?)`、`模块：光线1/2 (粗细, 透明度)`。
  Scratch 的方向约定：**0 = 上、90 = 右、180 = 下、-90/270 = 左**（顺时针）。
  - `/` 型镜面（法线 45°）：**`出射 = 90 - 入射`**
  - `\` 型镜面（法线 135°）：**`出射 = 270 - 入射`**
  ```yaml
  - if: {cond: {equals: [{var: 镜子类型}, 1]}, do: [        # '/' 镜
      - set_variable: {var: 新方向, value: {subtract: [90, {var: 方向}]}}]}
  - if: {cond: {equals: [{var: 镜子类型}, 2]}, do: [        # '\' 镜
      - set_variable: {var: 新方向, value: {subtract: [270, {var: 方向}]}}]}
  ```
  验算（`/` 镜）：入射上(0) → 出射右(90) ✓；入射右(90) → 出射上(0) ✓；
  入射下(180) → 出射 `90-180 = -90` = 左 ✓；入射左(-90) → 出射 `90+90 = 180` = 下 ✓。
  求出方向后**取模归一到 0~360**：`新方向 = ((出射 mod 360) + 360) mod 360`，
  Scratch 里 `mod` 负数会得负数，不归一的话下一步查表会查不到。

- **§192b 光线步进：一格一格走，走到出事为止**
  不要算交点（Scratch 里又慢又难写），**按格步进**：
  ```yaml
  - set_variable: {var: 光线状态, value: 进行中}
  - repeat: {times: 64, do: [
      - if: {cond: {equals: [{var: 光线状态}, 结束]}, do: [{stop: {option: this script}}]},
      - 按方向走一格: ...,                       # 0/90/180/270 各改一次 x 或 y
      - set_variable: {var: 格子类型, value: {item_of_list: {list: 地图（东西）, index: {var: 格索引}}}},
      - if: {cond: {equals: [{var: 格子类型}, 墙]}, do: [{set_variable: {var: 光线状态, value: 结束}}]},
      - if: {cond: {equals: [{var: 格子类型}, 反射镜]}, do: [ 改方向 ]},
      - if: {cond: {equals: [{var: 格子类型}, 接受器]}, do: [
          - 点亮接受器: ..., - set_variable: {var: 光线状态, value: 结束}}]}]
  ```
  `repeat 64` 是**硬上限**（防止两个镜子对射造成死循环）——这个上限不是可选项，是必须的。
  光线渲染：`模块：画光线` 用 `pen` 把走过的格子连成线，`光线缓存（i,x,y,方向）` 存轨迹供撤销/重绘。
  分光（半透镜）：同时开两条光线，`模块：光线1 (粗细,透明度)` / `模块：光线2` 各走一条，透明度区分强弱。

## 层叠消除（§193）

- **§193 羊了个羊的核心是「遮挡判定」，不是匹配算法**
  `羊了个羊` 只有 204 块，数据结构是 4 条平行列表：
  `位置号列表 len=216` / `层号列表 len=216` / `造型列表 len=230` / `活跃列表 len=216`，
  每个克隆体带私有变量 `位置号 / 层号 / 行号 / 列号 / id / 是否最上层`。
  作者原注释（原文照录，把算法说透了）：
  > 根据层号，和行列号，判断自己是否是需要进行亮度更新的潜在方格。只有被点击的方格的下一层，
  > 且位置在被点击方格的九宫格内的，才是需要检查亮度的。根据活跃列表，即还没有被删除的克隆体 id 列表，
  > 来检查是否有自己九宫格位置内的其他克隆体，且对方的层号比自己大，如果遍历完成后没有发现这样的
  > 邻居克隆体存在，…
  **「可点」的判定 = 我的 3×3 邻域里，没有「层号比我大且还活着」的方块**：
  ```yaml
  - set_variable: {var: 被压住, value: 0}
  - set_variable: {var: i, value: 0}
  - repeat: {times: {length_of_list: {list: 活跃列表}}, do: [
      - change_variable: {var: i, by: 1},
      - set_variable: {var: 对方id, value: {item_of_list: {list: 活跃列表, index: {var: i}}}},
      # 对方层号更大 + 行列差都 ≤1 → 我被压住
      - if: {cond: {and: [
           {greater_than: [{var: 对方层号}, {var: 层号}]},
           {less_than: [{mathop: {operator: abs, num: {subtract: [{var: 对方行}, {var: 行号}]}}}, 1.5]},
           {less_than: [{mathop: {operator: abs, num: {subtract: [{var: 对方列}, {var: 列号}]}}}, 1.5]}
         ]}, do: [{set_variable: {var: 被压住, value: 1}}]}]
  - set_variable: {var: 是否最上层, value: {subtract: [1, {var: 被压住}]}}
  ```
  亮度渲染：`被压住 = 1` → `set_effect {effect: BRIGHTNESS, value: -30}`（灰掉）。
  **优化（原作者的关键洞察）**：消除后**不要全场重算**，只重算「被消除格的下一层 + 九宫格内」那十几个。
  216 个克隆体全场重算 = 216×216 = 46656 次比较，每帧都做必然卡死。
  位置号 → 坐标用自制积木 `移到 %s 号位置 (n)` 一次性算好，别每帧算。
  ⚠️ **造型列表长度（230）> 位置号列表（216）是故意的**：造型池比格子多，才能保证牌面随机后仍够用。

## 等距视错觉（§194）

- **§194 纪念碑谷不做真 3D，做的是「遮挡图 + 可行区重算」**
  `纪念碑谷S 瀑布` 的关卡组织方式非常直接：**每关一组角色**，靠广播控制显隐
  （`关2` / `关3顶` / `关3底` / `关3梯子` / `关3左柱` / `关3台子` / `关4机关` / `关5机关1`…）。
  空间关系的全部秘密在**遮挡层**：`关3遮挡` / `关3遮挡2` / `关3遮挡3` / `关3外框遮挡` ——
  用不同颜色的遮挡块把「本该被挡住的通路」盖掉，玩家大脑自己补完 3D。
  交互核心是 `旋钮` / `旋钮3`（`当角色被点击` → 旋转机构）+ `可行区` / `禁行区` 两个区域角色，
  `寻路` 角色（1054 块）在旋转后**重算可行区里还连不连通**。
  ```yaml
  # 旋钮：点击 → 转 90° → 广播重算通路
  - when_this_sprite_clicked: null
  - turn_right: {degrees: 90}          # 或用 重复4次 微步旋转做动画
  - broadcast: {message: 重算通路}
  ```
  **落地建议**：① 每关独立角色组 + `广播-显隐`，别试图用一个通用引擎吃所有关；
  ② 遮挡层用纯色块，`移到最前` 保证压住；③ 「可行区」用 `碰到 可行区 角色` 判定（这是少数
  可以用 `碰到` 的场合——可行区是角色，不是背景，符合铁律 4）。

## 模拟经营 / 养成数值（§195）

- **§195 属性平铺成一张表，存档、显示、结算全部复用它**
  `UP主模拟器 RC` 的全部玩家属性就是 `游戏数据-玩家数值 len=12`：
  ```
  [100, 150, 500, 1.5, 1000, …]     ← 粉丝/钱/体力/倍率…按固定下标访问
  ```
  配套变量：`游戏数值_时间-天 = 1` / `游戏数值_时间-小时 = 8` / `INT-切换时间` /
  `游戏_当前场景 = 室内-手机-每日新闻`（字符串状态机）/ `游戏数值_难度` /
  `游戏数据-成就 len=9`（全是 0/1 标记）/ `游戏数据-计划 len=4`。
  **时间推进 + 数值增长**（挂机的本质）：
  ```yaml
  - when_receive: {message: 帧}
  - change_variable: {var: 时间-小时, by: 0.02}          # 每帧 0.02 小时 ≈ 0.6 游戏分钟
  - if: {cond: {greater_than: [{var: 时间-小时}, 24]}, do: [
      - change_variable: {var: 时间-小时, by: -24},
      - change_variable: {var: 时间-天, by: 1},
      - 结算每日收益: ...]}
  ```
  **难度/倍率不要散落各处**：`收益 = 基础 × 难度倍率 × 装备倍率`，倍率统一从一个表读。
  ⚠️ **浮点误差会累积**：`时间-小时` 用 `+0.02` 累加 50 次不等于 1，到「24 小时」判定时会
  差一点点导致永远差一帧不换天。修法：判定用 `≥ 23.98`，或全程用整数「分钟」计数，
  只在显示时除 60。
  ⚠️ 成就/计划这类 0-1 标记表**必须显式初始化**（绿旗清空后按模板重填），
  否则上一局的成就会串到新档里。

## 五个致命坑（§196）

1. **先挖洞后填地形**（§187）→ 洞穴全被埋。生成顺序：高度图 → 填充 → 洞穴 → 矿脉 → 水/植被。
2. **光照邻居缺值按 0 算**（§188）→ 光穿过石头照亮整张地图。缺值必须按 `-1`。
3. **反射角没归一**（§192）→ 出射 `-90` 之后查方向表查不到，光线直接消失。
   `新方向 = ((出射 mod 360) + 360) mod 360`。
4. **层叠消除每帧全场重算**（§193）→ 216 个克隆体互相比较，帧率崩到个位数。
   只在消除后重算受影响的十几个。
5. **累积量用小数加法**（§195）→ 时间/经验/金币差一点点永远不触发阈值。
   计数用整数，只在显示时换算。
