# 地铁驾驶模拟：从里程到 ATP（第二十五册，§207–§221）

> **用户要做「地铁/列车驾驶模拟、ATP、对标停车、开关门、移动闭塞、报站」时先读这一册。**
> 本册是对真实工程 **《深圳地铁5号线》**（TurboWarp，126 MB，**150 角色 / 14134 块 / 854 造型 / 218 音效**）
> 的逐块反编译结论 —— 这是社区里驾驶模拟品类的天花板作品，也是「AI 一次写不出来」的典型：
> 它的难度**不在单条公式，而在 6 个子系统靠一个数字（剩余里程）互相同步**。
>
> 配套可运行工程 `examples/metro_drive.yaml`（`scripts/metro_drive_behavior_check.mjs` → `METRO_DRIVE_LOGIC_OK`）。
> 入门版见第二十一册 `references/metro-sim.md`（§167–§176，累计里程 + 折线插值 + 四态门）。
> 反编译工具：`scripts/decompile_sb3.py`（`--all` 导出全部脚本，`--target 名称` 单角色）。

**读这一册前先记住这张表** —— 五个子系统，一个共享变量：

| 子系统 | 读什么 | 写什么 |
|---|---|---|
| 物理 Tick | `速度` | `剩余里程` |
| 牵引手柄 | 指针位移 | `速度` |
| ATP / 推荐速度 | `剩余里程`、`信号`、`间距` | `推荐速度`（只读量） |
| 到站握手 | `剩余里程`、`速度`、`车门` | `站点`、`剩余里程`（重置） |
| 前车模拟 | `前车速度` | `前车里程`、`间距` |

**`剩余里程` 是这一册的唯一真相**。它同时是：到站误差、HUD 距离、限速梯度时钟、制动曲线输入、
报站触发条件。少一个派生量，就少一处「三个脚本各说各话」的 bug。

## §207 用「剩余里程」而不是「累计里程」

入门教程几乎都写「累计里程从 0 往上加，到站判定 `|里程 - 站里程| < 15`」。
深圳5号线**反过来**：`距离nned` 是**本段剩余里程**，出站时等于整段长度，到站时趋近 0。

```
出站：剩余里程 = 站距[站点]        # 例如 12500
运行：剩余里程 -= 速度 / 4.9       # 每帧递减
到站：剩余里程 ≈ 0                 # 完美停车窗口 |剩余里程| ≤ 5
冲标：剩余里程 < 0                 # 负值 = 冲过停车标
```

这一个选择换来四件事，全是白送的：

1. **误差信号不用另算** —— `剩余里程` 本身就是「离停车标还有多远」，`|d| ≤ 5` 即对标成功。
2. **冲标天然可表示** —— `d = -18` 就是冲标 18 米；累计里程还得再减一次才知道偏差。
3. **HUD 直接显示** —— `距离nned` 加个 `m` 就是「距下一站 1250m」。
4. **限速梯度有了时钟** —— `d mod 35` 就是「每 35 米降 1 km/h」的距离触发器（§217）。

⚠️ **不要同时维护「累计里程」和「剩余里程」两个变量**。原工程只在跨站时用一次累计换算
（`将前车里程 设为「站之前所有站距和 + 额外数字」`，用 `repeatUntil` 累加站距），平时只留剩余里程。
两个都留着，迟早有一个忘了更新。

## §208 主 Tick 只有一行（常数决定时间压缩比）

整个 126 MB 工程的物理核心，是 `7 速 度` 角色里的**一行**：

```scratch
当绿旗被点击
重复执行
  将 [距离nned] 增加 (0 - (速度 / 4.9))
```

就这一行。没有加速度积分、没有阻力、没有 dt —— 因为**速度由手柄直接改写**（§209），
里程只做一次积分。工程里 91 个全局变量、14134 块积木，全部挂在这行上面。

**`4.9` 是什么？** 是**时间压缩比**。真物理下 `Δd = (v/3.6)·Δt`，`Δt = 1/30 s` 时每帧走 `v/108` 米；
这里走 `v/4.9` 米，等价于：

```
Δt_等效 = 3.6 / 4.9 = 0.735 秒/帧     →  时间压缩 0.735 / 0.0333 ≈ 22 倍
```

所以：**同一行代码，换常数就是换玩法节奏**。

| 常数 | 每帧等效时间 | 压缩比 | 适合 |
|---|---|---|---|
| `108` | 0.0333 s | 1× 真物理 | 教学演示、物理课 |
| `36` | 0.1 s | 3× 慢放 | **推荐给游戏**（看得清制动过程） |
| `12` | 0.3 s | 9× | 快节奏小游戏 |
| `4.9` | 0.735 s | 22× | 深圳5号线：41 站全段 20 分钟跑完 |

⚠️ **常数只影响节奏，不影响制动距离公式**。制动距离永远是 `v²/(2a)`（米），
所以「什么时候开始制动」不能拍脑袋，必须由 §211 的曲线算。

## §209 牵引手柄：位移 → 加速度，不是档位 → 加速度

几乎所有教程都做「按上箭头 → 档位=1 → 速度 += 0.6」。
深圳5号线做的是**真手柄**：玩家按住手柄上下拖，**拖多远就加多大加速度**。

反编译原文（`23 拉 杆`，`当收到 toggle`）：

```scratch
如果 <鼠标x > x>                          // 只认右侧拖拽（防反向）
  如果 速度 > 80: 速度 = 80               // 硬限速
  如果 <鼠标y > (y + 1)>                  // 向上拖 = 牵引，1px 死区
    如果 速度 < 80:
      如果 <鼠标y < (y + 11)>             // 10px 内：连续量
        速度 += ((鼠标y - y) / 10)        // 拖 5px → +0.5 km/h/帧
      否则:
        速度 += 1                         // 超过 10px：饱和，最大 +1
  否则:
    如果 <鼠标y < (y - 1)>                // 向下拖 = 制动
      如果 <鼠标y > (y - 10)>
        速度 += ((鼠标y - y) / 10)        // 拖 -5px → -0.5
      否则:
        速度 += -1.5                      // 制动饱和值比牵引大（真车就是这样）
```

四个设计点，缺一个手感就废：

1. **1 px 死区**（`> y+1` / `< y-1`）：手抖不算输入。没有死区，松手瞬间速度会跳。
2. **10 px 线性区**：`(鼠标y - y)/10` 让手柄位置**就是**加速度指令，玩家能「感觉」到档位深浅。
3. **饱和（clamp）**：拖过 10 px 不再增加，防止一甩手加速到天上。
4. **制动强于牵引（1.5 vs 1.0）**：这不是平衡性，是物理事实 —— 制动率 > 牵引率，
   所以「松手惰行 + 点刹」比「猛推猛拉」更省事，玩家会自己发现这一点。

**为什么不是档位？** 档位只有 3 个离散值，玩家只能「点一下、等一下」；
连续位移让「微调」成为可能 —— 这正是驾驶模拟的核心乐趣。

> 游戏里同时要支持键盘：原工程给键盘路径**复制了一整份同样的逻辑**
> （`当收到 toggle无鼠标`，把 `鼠标y` 换成 `tmp鼠标y坐标`）。
> 重复代码不好看，但比「一个脚本里两套条件嵌套」可读得多 —— 大工程里这是对的取舍。

## §210 方向状态存在「造型」里

手柄要区分「向前档 / 向后档」，但原工程**没有用变量存这个状态**，而是用造型名：

```scratch
如果 <造型编号名 = 向后>:
  速度 += ((鼠标y - y) / -10)      // 向后档：拖动方向取反
否则:
  速度 += ((鼠标y - y) / 10)
...
如果 <(距离nned < 5) 且 (速度 = 0)>: 换成造型 [向后]     // 停稳 → 允许倒车
如果 <(非 (距离nned < 5)) 且 (速度 = 0)>: 换成造型 [向前]
```

**造型即状态**（costume-as-state）。好处：少一个变量、造型和逻辑天然不会不同步、
玩家看到的手柄姿态就是真实状态。代价：**改逻辑必须先看造型表**，
新人接手容易漏；且造型名一旦被翻译/改名，逻辑全崩。

**什么时候可以这么干**：状态**只对玩家可见**且**只有 2~3 个取值**（向前/向后、开/关、亮/灭）。
什么时候不行：状态要参与存档、要跨角色读、取值会超过 4 个 —— 那时候必须用变量。

## §211 制动曲线：`t = 0.185 · d / v²`（原工程的落地公式）

这是整册最值钱的一段。原工程在**三个地方**（ATO 进站、前车模拟、大站快车）用了同一个公式：

```scratch
重复执行直到 <<速度 < 4> 或 <距离nned < 39>>
  将 [速度] 增加 -1
  等待 (((距离nned / 速度) / 速度) * 0.185)
```

**它是什么**：不是连续减速，而是**离散步进**——每次降 1 km/h，然后等一段时间。
等待时间 `∝ d / v²`，于是：

- **离停车标越远，等得越久**（降速越慢）→ 高速段松、低速段密；
- **离得越近，等得越短**（降速越快）→ 自动收敛到停车点；
- 不需要解微分方程，不需要 sqrt，**两个除法一个乘法**，TurboWarp 里也不卡。

**为什么是 `d/v²`？** 等减速运动有 `d = v²/(2a)`，反解得 `v = √(2ad)`，
即**允许速度 ∝ √d**。要让「每降 1 km/h 走多远」保持恒定，就得让时间步随 `d/v²` 缩放。
`0.185` 是把这个比例调到「80 km/h → 约 2800 米内停住」的经验系数（原线最长站距 37 km，
必须留够余量；换线路要重调）。

**但离散步进会「停在半路」** —— 循环退出条件 `速度 < 4 或 d < 39` 保证了它一定退出，
剩下 39 米交给**三段收尾**：

```scratch
// ① 把残速压到 5 以下
如果 速度 > 5: 重复执行直到 (非 (速度 > 5)): 速度 += -1; 等待 0.15
// ② 爬行到最后 6 米
等待直到 距离nned < 6
// ③ 逐 1 km/h 刹停
重复执行直到 速度 < 1: 速度 += -1; 等待 0.1
速度 = 0
```

**三段式 = 高速跟曲线 + 低速爬行 + 末端硬刹**。任何「一步到位」的写法都会在
「速度已经很小但还差 30 米」时卡住（等太短冲过去，等太久玩家以为死机）。

⚠️ **本示例的写法**：因为用广播驱动帧（无 `等待`），我把曲线写成**闭式**
`推荐速度 = 3.6·√(2a·max(0, d-5))`，交给玩家跟、ATP 超速时自动干预。
两种写法等价（一个是「按时间降速」，一个是「按时算上限」），**闭式更好调试、更好做 HUD**；
离散步进更好还原「司机一档一档推拉」的手感。选哪个取决于你要「开」还是「算」。

## §212 到站是三方握手，用「不变量」同步而不是标志位

这是原工程最精妙、也是 AI 最容易写崩的地方。到站不是一段脚本，而是**三个脚本互相等**：

```scratch
// 脚本 A（1 背景程序）—— 出站相位守卫
重复执行
  等待直到 (((车门 = 车门：关) 且 (速度 > 0)) 且 ((距离nned < (站距[站点] - 1)) 且 (距离nned > (站距[站点] - 200))))
  等待 5.5                                    // 出站 5.5 秒后报站
  播放声音 [下一站]
  等待直到 距离nned < 10                       // 快到站了
  站点 += 1                                   // ★ 先推进站点
  等待直到 ((距离nned > (站距[站点] - 10)) 且 (速度 = 0))   // ★ 等「里程被重置」

// 脚本 B（6 提示）—— 停车判定与重置
重复执行
  如果 距离nned < 4500: 提示 = 减速进站
  如果 <(速度 = 0) 且 (-5 < 距离nned) 且 (距离nned < 5)>:
    提示 = 打开车门
    等待直到 车门 = 车门：开
    距离nned = 站距[站点]                      // ★ 重置本段里程（此时站点已是下一站）
    等待直到 车门 = 车门：关
    提示 = 等待限速提高后出发
  否则:
    如果 距离nned < -5: 提示 = 列车停车失误，冲标！
    等待直到 距离nned > -6                     // 等玩家退回来

// 脚本 C（5 门 灯）—— 门状态机
当收到 [666]
  车门 = 车门即将关闭; 等待 2.2
  如果 提前关门 = 0: 车门 = 谨防夹伤; 等待 2.1 ...   // 四级嵌套 if 做可取消序列
```

**关键点：`站点 += 1` 发生在停车之前（`d < 10` 时），而 `站距[站点]` 已经变成下一段长度。**
于是脚本 A 的等待条件 `距离nned > 站距[新站点] - 10` —— 此刻 `距离nned ≈ 0`，
条件为假，**一直等**；直到脚本 B 执行 `距离nned = 站距[站点]`（重置成新段全长），
条件立刻为真，A 才继续报站。

```
站点 += 1  →  距[站点] 变成下一段长度（比如 12500）
                ↓
        A 等 d > 12500-10  ←── 卡在这里
                ↓
        B 开门后 d = 站距[站点] = 12500
                ↓
        A 的条件成立 → 报站 → 进入下一段
```

**为什么用不变量而不用标志位**：标志位会「卡死」—— 玩家中途退出、脚本被 `停止其他脚本` 杀掉、
重置没清干净，标志就永远是 1，后面全乱。而 `d > 站距-10` 是**从数据本身推出来的事实**，
无论中间发生什么，只要数据回到合法状态，流程自动继续。**这叫自愈式同步。**

代价：**调试时看不懂**。你不知道谁在等谁，只知道「卡住了」。所以：
给每个等待条件写 `comment`，说明它在等哪个变量变成什么。原工程的作者注释就写着
`// 等里程重置`，这是必须的。

## §213 冲标与欠标：负里程是特性，不是 bug

`剩余里程` 会变负（速度不为 0 时继续积分）。原工程把负值当成**停车失误**来用：

```scratch
如果 距离nned < -5: 提示 = 列车停车失误，冲标！
等待直到 距离nned > -6         // 等玩家倒车退回
```

于是「冲标」不需要单独判定、不需要额外变量 —— **`d < -5` 就是冲标**。
玩家必须**倒车**（手柄换「向后」档，速度变负，`d` 回升）退回到 `(-5, 5)` 窗口里，
才能开门。这比「冲标就扣分、直接过关」真实得多，也是这个工程被称为高质量作品的原因之一。

⚠️ **注意 `d` 变负会破坏 §217 的 `d mod 35` 时钟**（负数取模在 Scratch 里是正数：
`-7 mod 35 = 28`）。所以限速梯度必须先判 `d > 0`。

## §214 三显示移动闭塞（绿 / 黄 / 红）

原工程的信号不是「前方有没有车」，而是**移动闭塞的追踪距离**：

```scratch
// 134 前车模拟（每帧）
与前车里程差距 = round((前车里程 - (本车里程 + 1400)))    // 1400 = 车长 + 安全余量

// 86 信号灯
如果 与前车里程差距 > 9000: 换成造型 [绿灯提示]
否则:
  如果 与前车里程差距 > 5000: 换成造型 [黄灯提示]
  否则: 换成造型 [红灯提示]
```

**1400 是什么**：列车本身占用的线路长度（闭塞分区最小长度 + 车长）。
`前车里程 - 本车里程` 是**中心距**，减掉 1400 才是**净空**。
漏掉这一步 → 两车「看着还挺远」就撞了。

**三显示的含义**（和真地铁一致）：

| 灯 | 净空 | 含义 | 允许速度 |
|---|---|---|---|
| 绿 | > 9000 | 前方两个闭塞空闲 | 区间限速 |
| 黄 | 5000–9000 | 前方一个闭塞有车 | 降速（本例 45） |
| 红 | < 5000 | 前方闭塞被占 | 0（停车） |

而且 `推荐速度` 要**取三者最小**（§215），信号灯只是其中一项。

## §215 推荐速度 = min(区间限速, 制动曲线, 信号限速, 前车净空)

这是 ATP 的全部内容。**一个 min，四个输入**：

```
推荐速度 = 区间限速
推荐速度 = min(推荐速度, 3.6·√(2a·max(0, d - 5)))        // 本车到停车标
推荐速度 = min(推荐速度, 3.6·√(2a·max(0, 间距 - 100)))    // 到前车
推荐速度 = 信号=绿 ? 区间限速 : (信号=黄 ? 45 : 0)
```

原工程的做法更「土」但等价：它不 min，而是**用 `等待` 把速度往推荐值上贴**，
并且每条曲线前都加一个**信号门禁**：

```scratch
重复执行直到 <<非 (速度 < 限速[站点])> 或 <<非 (距离nned > 5000)> 且 <<速度 > 39> 或 <速度 > tmp降速>>>>
  如果 <<信号灯 造型 > 4> 且 <信号灯 造型 < 7>>      // 黄灯（5 或 6）
    速度 += 0.5; 等待 0.07
  否则:
    停止这个脚本                                      // ★ 红灯 = ATO 退出，交还人工
```

**「红灯就让 ATO 停止脚本」是最重要的安全设计**：自动驾驶不是「无所不能」，
它只在自己有权限（黄灯以上）时工作；一旦前方红灯，它**主动退出**，
让玩家接手。没这条，ATO 会带着玩家闯红灯。

**超速保护**（`70 超速` + `64 急停`）：

```scratch
// 报警：每帧检查，超了就循环报警直到降下来
如果 <(floor(速度) > 限速)>: 换成造型 [超了]; 重复执行直到 <非 (floor(速度) > 限速)>: 广播 [报警]

// 紧急制动：1 km/h 每 0.035 秒（≈28.6 km/h/s），并做「过零回补」
如果 <<速度 > 0> 且 <ATO 造型 = 1>>:
  重复执行直到 <<速度 < 1> 或 <ATO 造型 = 2>>: 速度 += -1; 等待 0.035
  重复执行直到 <<速度 > -1> 或 <ATO 造型 = 2>>: 速度 += 1; 等待 0.035   // ★ 回补
  如果 <ATO 造型 = 1>: 速度 = 0                                       // ★ 夹到 0
```

**「过零回补 + 夹零」这两步必写**：`速度 += -1` 每次减 1，从 `0.4` 会减到 `-0.6`；
不补，列车会「倒着走」；不夹，会永远停在 `-0.6` 抖动。
任何「按常数步进直到 0」的地方都要写这两步。

## §216 ATO 状态机：`zt` 三态与「连续 ATO」

`zt` 只有一个变量，三个值，全工程的门禁都看它：

| `zt` | 含义 | 谁在写 |
|---|---|---|
| `-1` | ATO 正在控车（牵引/制动中） | ATO 加速段、制动段 |
| `0` | 惰行（到速了，滑行） | 到速之后、进站前 |
| `1` | 已停稳 / 允许开门 | 刹停之后 |

配套的是 `连续ATO`（0/1）：到站后是否**自动继续下一段**。
`连续ATO = 0` 时，ATO 停稳就 `bcast ATO2` 退出，玩家必须手动给牵引；
`= 1` 时自动 `bcast 666 → 等 10 → 提前关门 → bcast 跳过开关门 → bcast ATO1` 跑下一段。
**这是一个「演示模式」开关**，做驾驶模拟一定要有：玩家想看风景时开自动，想自己开时关掉。

⚠️ **`zt` 用数字而不用布尔**，是因为「惰行」这个中间态必须存在 ——
只有「开/关」两个值时，玩家分不清「ATO 没在控车」和「ATO 控着车但正好不需要出力」。

## §217 限速梯度用「距离时钟」`d mod N`，不用计时器

进站前限速要从 80 逐级降到 40（真实地铁的「分级限速」）。原工程没用计时器：

```scratch
重复执行
  等待直到 距离nned < 2000
  等待直到 推荐速度 < (限速 - 7)
  广播 [限速变换]
  重复执行直到 限速 < 41:
    等待直到 ((round(距离nned) mod 35) < 15)     // ★ 每 35 米触发一次
    限速 += -1
    等待直到 (非 ((round(距离nned) mod 35) < 15))
  广播 [限速变换]
  等待直到 距离nned > (站距[站点] - 100)
```

**`d mod N < 阈值` 是一个「每 N 米发生一次」的触发器**：
`d` 递减经过 `35, 70, 105…` 时，`d mod 35` 会扫过 `0~15` 这个窗口，条件为真；
其余时间为假。配合「等待直到为真 → 做事 → 等待直到为假」就是**上升沿触发**。

三个好处：
1. **与速度无关** —— 快车慢车都在同样的**位置**降速，视觉上一致；
2. **复位即同步** —— 重开一局 `d` 变回站距，时钟自动对齐，不用清计时器；
3. **省一个变量** —— 不需要 `上次触发里程`。

⚠️ 两个坑：① `d` 为负（冲标）时 `mod` 行为变化，必须先判 `d > 0`；
② 阈值必须 **< N/2**，否则窗口重叠，每帧都触发。

## §218 车门机械缓动：线性累加器 + 平方位移

车门开合是**梯形速度曲线**（加速 → 匀速 → 减速），原工程用 3 个 `repeat` 硬拼出来，
没有一个缓动函数：

```scratch
// 开门（3 左车门，当收到 KAI）
tmp速度 = 0
重复 20 次:  移动 (tmp速度 * tmp速度) 步;  tmp速度 += 0.042     // 加速段：位移 ∝ t²
重复 34 次:  移动 (tmp速度 * tmp速度) 步                        // 匀速段
重复 30 次:  移动 (tmp速度 * tmp速度) 步;  tmp速度 += -0.028    // 减速段
播放声音 [Hit]                                                  // 到位的机械撞击声
```

**原理**：`位移 = 累加器²`，而累加器线性增长 → 位移是**二次曲线**，即匀加速运动；
累加器不再增长 → 匀速；累加器线性减小 → 匀减速。**这就是物理正确的缓动，而且不需要 sin/cos/幂函数。**

四段参数就是手感的全部（本例写法）：
- 加速段步数 × 增量 → 起步多"重"（地铁门很重：20 步 × 0.042）
- 匀速段步数 → 行程主体
- 减速段增量 → 到位多"软"（0.028 < 0.042，减速比加速慢 = 液压缓冲）
- 末尾 5 次微调 + `Hit` 音效 → 到位感

⚠️ **`tmp速度` 必须是角色私有变量**（铁律 9）。左右两扇门共用全局 `tmp速度` 会互相打断，
一扇门永远关不上。

## §219 两套坐标系：里程是真值，像素是假滚动

这是最容易被误判的一点。原工程里：

```scratch
// 所有"世界"角色每帧统一左移
当绿旗: 移到最前面; 重复执行: 移动 (0 - 速度) 步        // 5 门灯 / 88 停车位置 / 站台…

// 但到站前 40~80 米，突然钉死在屏幕固定位置
如果 <<距离nned < 80> 且 <距离nned > 64>>:
  显示; 移到 x:(站台头部位置 - 32) y:15
  重复执行直到 <<距离nned > (站距[站点] - 200)> 且 <距离nned < (站距[站点] - 1)>>
    如果 <非 (速度 = 0)>: x = (站台头部位置 - 32)      // ★ 钉住
    如果 x < -250: 隐藏 否则: 显示
```

**为什么钉住**：`速度` 是 km/h，`移动 速度 步` 是像素 —— 两者**没有比例关系**。
80 km/h 时每帧移 80 px，一屏 480 px 只够走 6 帧，视觉上是糊的；
而且「走了多少像素」和「走了多少米」完全对不上，永远无法做精确对标。

**所以原工程放弃了真滚动**：远景用「速度 px/帧」做**氛围滚动**（够快就行，不需要精确），
近景（站台/屏蔽门/停车标）在**到站前固定距离窗口**内直接 `goto` 到固定屏幕坐标，
把「视觉对标」退化成「数值对标」。

**这是游戏工程的正确取舍**，不是偷懒。给 AI 的结论：

> 驾驶模拟里，**里程负责一切判定，像素只负责氛围**。需要精确的地方（停车标、屏蔽门）
> 用「距离窗口 + 钉死坐标」，不要试图让滚动像素去对齐米。

## §220 音效的距离衰减与「报站时机」

三个距离驱动的音频技巧，全是白送的沉浸感：

```scratch
// ① 报站音量随距离升高（3 左车门）
等待直到 距离nned < 5000
播放声音 [SZMC 5 to 赤湾]
重复执行: 音量 = ((5000 - 距离nned) * 0.5)          // 出站时轻，进站时响

// ② 隧道明暗（Stage，塘坑/水贝/六约/梨园四站）
如果 下一站 = 塘坑:
  等待直到 <<距离nned < 3000> 且 <距离nned > 2500>>
  如果 下一站 = 塘坑: 广播 [黑]; 重复 10 次: 亮度 += -10; 等待 0.5
  等待直到 <<距离nned > 5000> 且 <距离nned < 7000>>

// ③ 出站 5.5 秒后报「下一站」
等待直到 (车门=关 且 速度>0 且 站距-200 < d < 站距-1)   // 刚启动 1~200 米
等待 5.5
播放声音 [下一站]
```

⚠️ **① 的 `音量` 必须每帧重设**，而且要在 `重复执行` 里 —— 只设一次，进站时不会变响。
⚠️ **② 的二次 `如果` 是必须的**：`等待直到` 可能等了几十秒，期间玩家可能已经跳站了，
所以醒来后要**再判一次**当前条件。这是所有「长等待之后」的通用防御写法。

## §221 十一个致命坑（按踩坑频率排序）

1. **漏 `÷3.6`**：速度 80 直接当 m/s 用 → 一帧飞过整站，到站判定永不触发。
   本工程用 `÷4.9` 是**压缩后的等效值**，不是漏了 3.6（§208）。
2. **同时维护累计里程和剩余里程**：两个都更新迟早漏一个；只留剩余里程（§207）。
3. **到站用标志位同步**：玩家中途退出/脚本被杀 → 标志卡死，整局不动。用不变量（§212）。
4. **`站点 += 1` 放在停车之后**：那 `站距[站点]` 还是本段长度，重置出来的里程是错的。
   必须先 `+= 1`（`d < 10` 时），再重置（§212）。
5. **停车判定只看距离不看速度**：`|d| < 5` 但速度还有 20，会「边滑边开门」。
   必须 `速度 = 0` **且** `|d| ≤ 5`。
6. **忘记 `1400` 车长**：`前车里程 - 本车里程` 是中心距，不减车长两车会穿模（§214）。
7. **按常数步进到 0 不做回补**：`速度 += -1` 从 0.4 减到 -0.6，列车倒着走（§215）。
8. **限速梯度用计时器**：快车慢车降速位置不一致；用 `d mod N` 距离时钟（§217）。
9. **车门 `tmp速度` 用全局变量**：左右门互相打断，一扇永远关不上（§218）。
10. **长 `等待直到` 之后不复查条件**：醒来时世界已经变了（§220 ②）。
11. **`d` 为负时用 `mod`**：Scratch 负数取模返回正数，`-7 mod 35 = 28`，时钟立刻错乱（§213/§217）。
